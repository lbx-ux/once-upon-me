# Domain Docs

工程技能在探索代码库之前，按这份文件消费本仓库的领域文档。

## 探索前先读这些

- **`GLOSSARY.md`**（仓库根）—— 领域词汇的唯一来源
- **`docs/adr/`** —— 读与本次工作涉及的区域相关的 ADR

这些文件不存在时**直接继续，不要提**、也不要主动建议创建。
它们由 `/domain-modeling`（经 `/grill-with-docs` 与 `/improve-codebase-architecture` 到达）
在术语或决策**真的被定下来**的那一刻惰性创建。

## 文件结构：single-context

```
/
├── GLOSSARY.md
├── docs/adr/
└── src/
```

> ⚠️ 判定这条时踩过一个假阳性：仓库根有 `pnpm-workspace.yaml`，
> 那是 **pnpm 10.6+ 的设置文件**（只放了 `allowBuilds`，供应链白名单），
> **没有 `packages:` 字段**，不是 workspace 定义。本仓库是单包单上下文，
> 不要建 `GLOSSARY-MAP.md`。

## 用词汇表里的词

输出（工单标题、重构提案、假设、测试名）里点到某个领域概念时，
用 `GLOSSARY.md` 定义的术语，**不要漂移到它明确回避的同义词**。

如果需要的概念还不在词汇表里，那是一个信号：要么你在发明本项目不用的说法（重新想想），
要么是真缺口（记下来交给 `/domain-modeling`）。

## 与 README 的关系

`README.md` 的「五、已知取舍」已经写死了大量**决策**（为什么不引 shadcn/ui、
`min-width` 为什么落在首页容器而不是 `body`、交接段那三个数为什么必须一起改）。
那些内容**留在 README**，面向评委与读者；`docs/adr/` 只收**会影响写代码时选 A 还是选 B**
且理由不在 README 里说清楚的那类决定。同一件事不要在两处各写一份——两份迟早分叉。

## ADR 冲突要明说

输出与既有 ADR 矛盾时，明确指出来，不要静默覆盖：

> _与 ADR-000N（……）冲突，但值得重开，因为……_
