# 角色卡是文件资产，不是数据库行，也不是一段提示词

「角色卡资产化」（评分表 #8）有三种可能的实现：一段每次重拼的提示词、
数据库里的一行、一份带 ID 与内容指纹的落盘文件。本项目选第三种，两个理由。

**为什么不是一段提示词**：那正是市面上"能换名字换不了形象"的做法。
第 7 页要描述孩子一次、第 8 页再描述一次，两次描述不完全一样，
于是 20 页里出现 3 张不同的脸。没有 ID 就没有"被引用"，
没有"被引用"就没有"改一次处处变"，也没有跨书复用。

**为什么不是数据库行**：赛道规则 10.3.1 写明后端"仅作为 AI 能力的接入层，
不作为重点考察对象"。为一个参赛项目引入建库、迁移、备份、连接池，
换来的是"角色卡有主键"——而主键这件事文件名就能给。
更要紧的是**内容寻址**：`ref.22d46f111c37.webp` 的文件名本身就是指纹，
改一个像素必然换名，旧图不会被覆盖；数据库行做不到这一点，
除非再存一张哈希表。而 ADR-0003 要求"预生成资产要有版本与失效管理"，
文件 + 指纹天然满足，且**能随代码包一起交给评委**。

代价说清：① 没有事务，删一半失败会留下孤儿文件——所以 `deleteChild` 必须
**返回删掉的条数**（删除凭据要写"各存储位置各删了多少条"，
不报数的删除实现写不出那张凭据）；② 没有索引，`summaries()` 是一次前缀扫描，
量级到几千张卡要换实现；③ 依赖文件系统，若日后上对象存储，
换的是 `AssetStore` 适配器，`character-card/` 一行不动——这正是 ADR-0002 的回报。

**一条比实现更重要的不变式：卡里出现的每一项都必须跨页不变。**
姿势、表情、场景、光线属于页级 prompt。把"爱笑"写进锚点，
下一页哭的那页就会被一致性判不合格。所以锚点分硬/软两档，
且校验器会拦下常见的页级词。

- Status: accepted
- Considered Options: 提示词片段（无 ID、无复用，是本项目要解决的那个问题本身）；
  数据库行（为一个非考察项引入整套基础设施，且拿不到内容寻址）；
  向量库存"形象"（形象是**约束**不是**语义相似**，检索会返回"差不多"的孩子，
  而我们要的是逐条核对的清单）
- Consequences: ① 一致性核对清单与画面 prompt **必须出自同一份锚点**
  （`checklistOf` / `promptFragmentOf` 同源于 `card.anchors`），
  否则"画的时候按 A 画、查的时候按 B 查"，一致性分失去意义；
  ② 微调 = 新 revision，**不覆盖**旧版，否则旧书的出处被抹掉；
  ③ 原始照片不进卡，只进 `sourcePhoto{usedAt, deletedAt}` 这个事实
