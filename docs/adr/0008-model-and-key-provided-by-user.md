# 模型与密钥由用户自带，产品不绑定任何一家

> ★ **2026-10-16 已被 [ADR-0009](0009-model-and-key-issued-by-operator.md) 取代。**
> 用户在界面上自己填 api-key 的那条路整条删掉了：密钥改由**站长**分配、按账号发能力。
> 这份不删，因为下面那些论据（"我们替你选好一家"是产品的脆弱点、模型零硬编码）
> **一条都没过时**——变的是"谁持有密钥"，不是"引擎要不要知道供应商是谁"。
> 读它的时候请把"用户"两个字换成"站长"。

2026-10-13 用户定的口径：**不做模型对比选型了**——产品形态是
"用户自己输入喜欢的模型 + 自己提供 API key"，我们给的任何推荐都只是**默认值**，
不是产品的边界。

这件事不是临时省事，它和两条已成立的设计是同一条线：

- 「**平台而非聚合**」本来就是项目立场（CLAUDE.md 里"一个 node 脚本要能跑完整本生成"
  是它的技术证据）。聚合站替用户选模型，平台让模型可换。
- 「模型名零硬编码」（ADR-0005 的落地形态）已经做到位：
  `registry.ts` 的 `Env` 是**参数**而不是 `process.env`，模型、key、BASE_URL
  全部从调用方注入。也就是说用户自带的模型与密钥不需要改任何引擎代码——
  W2 的创作流只要把"用户填的表单"拼成一张 per-request 的 `Env` 传进去。

而 W1 的横评恰好给出了**为什么必须这样做**的实测论据，比任何架构观点都硬：
同一个引擎、同一份 prompt，在不同模型上的失败方式完全不同——
树形不合法（3 家）、思考链吃光 token 预算（正文 0 字符）、
`REASONING_REQUIRED` 不许关思考（glm-5.3-flash）、单本 100–320 秒（kimi-k2.6）。
**"我们替你选好一家"本身就是产品的脆弱点**：供应商改一次默认值或下线一个型号，
产品就坏一次；反过来，把"任意模型会以各种方式坏"当成产品前提，
`explainEmptyContent` 这类把错误翻译成"该调参数还是该找平台"的错误路径，
就从内部细节升级为**产品能力**。

## 密钥的处理（这条不商量）

用户提供的 key：**只在内存里活一次请求的生命周期**——不落盘、不进日志、
不进录制文件（ADR-0003 的 manifest 不得包含 key）、不回显到前端以外的任何地方。
我们自己的开发 key 仍然只写 `.env.local`（仓库公开，这条不变）。
这与隐私设计的"一键删除"承诺同源：拿不到的东西不需要承诺删除。

## 代价与后果

- **横评的结论降级但不是作废**：从"选型定稿"变成"默认推荐 + 兼容性证据"。
  `tech-selection.md` §7 / §9 的实测数字还是那份——它现在答的问题是
  "默认推荐填哪个、引擎在哪些模型上验过"，不再答"产品只能用哪个"。
  判据 2（语感盲评）随之从**定稿闸门**降为**推荐依据**，可做可不做。
- **W2 创作流多一步"模型与密钥"**：填模型名、key（、可选 BASE_URL），
  没填时用默认推荐值。这一步的三个态（加载 / 空 / 错误）正好是 #16 的验收面。
- **错误消息出现了第二个读者**：`registry.ts` 里"真实密钥只写 `.env.local`"
  这类话是对开发者说的；BYO 之后终端用户也会看到错误——消息要能直接指导
  "你填的这个 key / 这个模型哪里不对、怎么办"，而不是教用户去改仓库文件。
- **竞赛技术文档的"选型理由"章改口径**：从"我们选了 X，理由如下"变成
  "我们怎么让任意 OpenAI 兼容模型都能跑 + 默认推荐哪个、依据哪些实测 +
  兜底策略是什么"。实测横评数据反而是更好写的素材——它证明的是引擎的健壮性。
- **代价诚实写**：放弃"开箱即用"的统一体验；用户填错 key、选到思考模型时会
  看到错误。默认推荐值的存在就是缓解这条的（预填我们验证过的组合）。

- Status: accepted（2026-10-13，用户在 W1 收口时拍板）
- Considered Options: 继续横评选型并硬编码进产品（省事、体验统一，但供应商一改动
  产品就坏，且与已成立的零硬编码纪律矛盾）；只允许横评验证过的模型（安全，但把
  "平台"做成"白名单"，用户带自己的 key 也没有意义）
- Consequences: §7/§8/§9 的"定稿"改写为"默认推荐"；W2 排期新增"模型与密钥"步骤；
  录制/回放与日志需要一次"不含 key"的检查；TTS（§8）同样按此口径办——
  候选与默认推荐照常保留，选型实测推迟到需要时再做
