# 不引 Vercel AI SDK，生成过程的事件流自己写

官方技术栈表把 Vercel AI SDK 列成「推荐首选」，所以这条要解释为什么不用。
它的价值集中在 React 侧：`useChat` / 生成式 UI / 工具调用结果的流式渲染——
**为对话式界面设计的**。而本项目的形态不是对话：一轮创作是一条
「规划 → 逐页生成 → 逐页校验 → 重画」的**批处理流水线**，前端要的是
`{page: 7, stage: 'illustrating'} / {page: 9, stage: 'retrying', reason: '相似度 0.71'}` 这种
自定义事件，不是 message 数组。三条理由：

1. **引擎不许 import React**（`lib/engine/` 的硬约束，验收方式是 node 脚本跑完整本生成），
   而 AI SDK 的收益恰恰长在 React 那一侧。
2. **供应商是国内的**，且都走 OpenAI 兼容 HTTP。中间加一层 SDK 只是多一个
   要知道内部实现才能调对的依赖。
3. **事件协议是自研的**：它同时要喂前端可视化、喂 MCP 工具返回、喂技术文档里的
   过程日志。套进通用消息模型反而要绕。

留一条翻案条件而不是把话说死：**若 W2 首周实测发现"流式解析 + Schema 校验 + 重试"
这三样自己写超过约 200 行且开始重复**，再引 `ai` 核心包（它是框架无关的，
只用它的 `streamText` / `generateObject`，不引 React 那一半）。ADR 状态就是为这种情况留的。

- Status: **superseded（2026-10-15）** —— 翻案条件成立，见下面「翻案与替代范围」
- Considered Options: 用 Vercel AI SDK 全量（多一个运行时依赖 + 与"引擎不碰 React"的主张冲突）；用 LangChain.js（更重，链式抽象层对一条固定流水线是纯负担）
- Consequences: 结构化输出、重试、流式解析这三件事要自己写，并各自有测试缝
  （`tdd` 的适用范围正是这些**确定性校验逻辑**，不是模型输出本身）

## 翻案与替代范围（2026-10-15）

上面那条翻案条件的**两个条件都量到成立**（判据、命令与逐文件行数见
[`.scratch/w2-solo-flow/issues/01-adr0004-threshold.md`](../../.scratch/w2-solo-flow/issues/01-adr0004-threshold.md)）：

| 条件       | 量到的                                                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 行数 > 200 | 流式 375 + Schema 320 + 重试 115 = **810** 行（加 `tree.ts` 的口径是 953）                                                                  |
| 重复 ≥ 1   | **1 处**：`providers/openai-vision.ts` 的 `parseLooseJson` 与 `schemas/schema.ts` 的 `extractJson` 是同一段"转义感知的括号扫描器"（已合并） |

★ 判据是原文那条 **AND**，不是"行数够了就翻"。写这份判决时专门核对过：
把它当 OR 执行，判决就会在还没量重复之前落地——那正是这张工单 §1.4 明令禁止的做法。

### 替代的是哪一部分（**不是全部**）

按 `ai` 当前版本的文档核过（`ai@7.0.141`，2026-10-15；**不是**凭记忆）：

- **换掉**：传输那一层——我们手写的 HTTP + SSE 解析 + 两个超时（207 行）。
  `ai@7` 的 `streamText` 有 `timeout: { totalMs, chunkMs, firstChunkMs }`，
  与我们手搓的两个超时**同构**，还多一个"到第一个有内容的输出为止"（TTFT）。
- **换不掉，仍然是我们的**：
  - `schemas/schema.ts` 的"一份定义两用"——`Output.object` 能吃标准 JSON Schema
    （文档原话），所以定义留得住；但 JSON Schema 仍要我们生成，能换的只有运行时校验那一半。
  - **带反馈的重试**（把上一轮的具体失败贴回 prompt）。官方文档只写了抛
    `NoObjectGeneratedError`，没有这类机制；而它是本项目判据 1 的主体。
  - 事件协议、`replay` 双适配器、`buildTree` 的树形语义、增量抽取。
- **代价**：`ai`（8.2 MB 解包体积）+ `@ai-sdk/openai-compatible` + **zod**（peer），
  而 `ai` 自己还拖着 `@ai-sdk/gateway`（即使不用 Vercel 的网关）。
- ★ ADR 原文点名的 `generateObject`，在当前版本的文档里已经不在那一页上了——
  结构化输出改成了 `generateText / streamText` + `Output.object({schema})`。
  照着一份 2026 年初的记忆去引，会引到一个不存在的 API。

### 落地排在 W3，理由写在这里

1. **W1 横评的数字走的是我们这条传输层**。换掉它，那批通过率/时延数字就失去了同一性
   ——要么重跑，要么在文档里注明"换之前量的"。**数字要能复现**比省 200 行重要。
2. **离线回放要重写成"套在 SDK 模型接口外的一层"**，而它是演示当天的保险；
   收口前动它，等于拿验过的通路换新写的通路。
3. 换掉之后仍然省不下 schema 定义与带反馈的重试，所以收益比行数看着的小。

**在那之前，代码仍按"自己写"那一版跑**：本 ADR 的状态改了（决定改了），
实现一单排进 W3，两者不是一回事。
