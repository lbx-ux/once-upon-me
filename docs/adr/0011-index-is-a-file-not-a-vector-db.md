# 检索的索引就是一个文件，不引向量数据库服务

「RAG 技术应用」（评分表 #3）落地时，检索这一层有三种做法：
一台向量数据库服务、一份进程内的向量索引（faiss / hnswlib 那一族）、
或**一个随仓库提交的 JSON 文件 + 一份词法排序**。本项目选第三种。

★ 这是同一个判断的**第三次**（[ADR-0003](0003-pregenerated-assets-decouple-demo-from-api.md)
「预生成资产」→ [ADR-0007](0007-character-card-as-asset.md)「角色卡是文件资产」→ 本份）。
三次的题目不同，形状一样：**能落成一份可逐字节比对的文件，就别落成一台要运维的东西。**
第三次还这么判，本身就值得记一笔——它不是惯性，是同一个取舍在这三个地方都成立。

**为什么不是向量数据库服务**
两个理由，一个是实测的、一个是关于"索引会跟内容不同步"的。
① **嵌入在这条网关上不存在**：2026-10-19 的探针逐个数过目录里 26 个已服务的模型，
**没有一个能做嵌入**（`POST /v1/embeddings` 的路由是活的——用不存在的路径与确定能对话的
模型做过判别对照——但每一个模型都回"不支持该能力"）。引一台向量库，等于引一个
**今天空转**的依赖：装上了、连上了、一条向量也写不进去。
② **索引与内容不同步是必然会发生的一件事**（删一本书、改一版草稿），
而"检索到一本已经不存在的书"是这个功能最难查的坏法。文件 + 内容指纹让这件事**可判定**
（`corpusVersion` 对不上就是没重建），服务化之后它是两处状态之间的一个静默漂移。
再加一条部署面的：赛道规则 10.3.1 写明后端"仅作为 AI 能力的接入层"，
而 ADR-0003 的演示路径要求**断网也能跑完一本书**——索引随仓库提交，
`node scripts/engine-run.mts --mode=stub` 今天就能证明这一点。

**为什么不是进程内向量索引**
它绕开了"运维一台服务"，但没绕开"要有向量"。承上的①：**没有嵌入模型**，
所以它今天是一份写不进去的代码。而它的收益是召回率——那件事**没有被量出来**，
代价（一次构建依赖、一份要在启动时载入的内存结构、一个与内容同步的问题）是真的。

**为什么不是"干脆全塞进上下文"**
这是最诚实的一个反选项，值得写下来：种子语料只有 96 跨页 ≈ **4.3k token**，一次塞得进。
**但"塞得进"不等于"该塞"**：这一栏的正当性押在**②创作史**上——那是这个家庭自己
一本本攒出来的文本，会随这个孩子长大，几十本之后一次塞不进、也不该塞。
今天这个文件索引在 500 条量级上是"读盘 + 切块 + 打分 = 毫秒级"（`rag/corpus.ts` 写着这条判断），
换实现的那一天由当时的量决定，现在不预设。

- Status: accepted
- Considered Options: 向量数据库服务（pgvector / Qdrant / Chroma 或托管版）——
  在这条网关上今天没有嵌入可用，且引入两处状态之间的漂移；
  进程内向量索引（faiss / hnswlib）——同样依赖一个不存在的嵌入能力，
  而它的收益（召回）没有被量出来；
  "把语料全塞进上下文，不做检索"——种子塞得进，**②会随这个孩子长大**，
  而这一栏的正当性恰恰押在②上；**一个 JSON 文件 + bigram/BM25 词法排序**（选中）
- Consequences: ① **召回弱**：字符 bigram 不认同义词、长词与改写
  （"雪橇"与"滑雪板"在字符层几乎不相干）——这是选词法档要付的价，写在
  [`docs/known-tradeoffs.md`](../known-tradeoffs.md)；
  ② **②创作史不建持久索引**，每次现场扫（几百本以后要换实现，换的点写在 `rag/corpus.ts`）；
  ③ 语料变了要**重跑生成脚本**（`scripts/build-rag-index.mts`，语料没变它不重写文件），
  指纹随内容走——这条保证"这本书是哪一版语料检索出来的"答得出来；
  ④ **换档条件**：若 `neohorse-1-9b`（那次探针里唯一一个"没开通所以问不出能力"的模型）
  被证实是嵌入模型并开通，混合档才有第一档可比——**那时**才加 `providers/embeddings.ts`
  与 `provenance.mode`；今天加它们等于给下一个人留一个读不懂的空壳
