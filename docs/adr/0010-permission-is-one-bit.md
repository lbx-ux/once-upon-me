# 权限收成一位：注册即全开，站长只留一个收回开关

2026-10-18 用户定的口径：

> 没有登录的人是没有权限进行创作，但是登录之后就可以使用各种模型了，不用站长分配，
> 在站长的管理那，还是可以看到用户创作了几本，有几个人物，后面的选项就变为是否有权限，
> 默认注册的用户都有权限

这份 ADR **推翻 [ADR-0009](0009-model-and-key-issued-by-operator.md) 里"按账号发能力"
那一半**（"四个开关由管理页勾、用户那侧申请一次"），所以先说清楚推翻的是什么、
以及**什么没有被推翻**。

## 之前是怎么定的，为什么改了

ADR-0009 的口径是：密钥由站长配一次，**能力按账号发**——四个开关（文字 / 图像 /
视觉 / 语音）在管理页一个个勾，新号默认四个全关，用户看到一个「帮助」弹窗，
在里面点一下提交申请，站长在管理页的申请队列里批或拒。

那套形状是为"我得控制谁在花我的钱"设计的。它成立的前提是**要花很多钱、要防陌生人**。
实际跑下来，这个前提在本项目的使用场景里不成立：

- 站是**给评委和演示**看的，注册进来的都是被邀请的人；
- 一个四个开关全关的新号，**什么也看不到**——他点「开始创作」只得到一句
  "当前用户没有权限，请联系管理员"，而这一轮的目的大半是让他看见生成过程；
- 于是"注册 → 找站长开权限 → 再回来"里，中间那一步是纯粹的等待，
  而它每天都会发生一次（每个新号一次）。

所以改成：**注册即全开**，站长手里留一个开关，用来**把某个人的权限收回来**。

## 改了什么

- **一个人有没有创作权 = 一位**（`user_permissions.allowed`）。
  原来那四列（`can_text` / `can_image` / `can_vision` / `can_speech`）退场：
  四项同真同假之后，四个必然一起动的列只长成"看起来能分开配"的样子。
- **默认给上**：建号 / 注册时就写上 `1`；已经建过的库由 `SchemaUpgrades` 补这一列，
  `NOT NULL DEFAULT 1`——那一句就是"**老账号自动给上**"（他们当初是全关的，
  只因为那时候要站长手工开）。
- **管理页那一排四个开关收成一格**「权限 / 能否创作」。
- **「帮助」那一格整条拆掉**，连同它里面的**权限申请**：没有人需要申请之后，
  一个永远收不到东西的队列比没有这一栏更坏（它会让人以为"是不是没人找过我"）。
  申请那套的 BFF 路由、Java 的 `PermissionRequest*`、建表语句一起删；
  ★ **老库里的 `permission_requests` 表与数据留着**（`SchemaUpgrades` 刻意不 DROP），
  只是没有代码再读写它。
- **没权限那句话一个字没改**：「当前用户没有权限，请联系管理员」——它现在只在
  "站长把这个人关掉了"时出现。

## 四位 → 一位之后，「能力」这个词在哪儿还活着

它没有消失，但只剩两种用法，**都不是**"这个人有没有"：

| 在哪                                     | 是什么                                               |
| ---------------------------------------- | ---------------------------------------------------- |
| `GET /api/auth/me` 的 `configured`       | **站里配没配**这一项（密钥在不在），四项仍然各自独立 |
| `requireCapability(req, caps)` 的 `caps` | **这条路由要什么**能力（写需求，不写判据）           |

★ 这一条是要紧的：界面上那句"站里今天还没配齐创作要的模型"仍然说得出，
而它与"你的账号没有权限"是**两个不同的下一步**（等一等 vs 找站长）。
把 `configured` 也一起收成一位，就会把这两件事合成一句假话。

## 代价与遗留（都写在这里，因为它们是真的）

- **`caps` 现在不改变结果**。`requireCapability(req, ['image'])` 与 `['text']`
  判的都是那一位。留着这个参数是因为它记着"这条路由要什么"——回到按能力授权时，
  改的是那一道闸，不是三十个调用点。★ 代价是它**看起来**像在分别判四项。
- **老库上留着没有读者的东西**：`user_permissions` 的四列 `can_*`、
  以及 `permission_requests` 整张表。这是一笔明账（数据不丢），
  代价是下一个人会在库里看到它们，所以 `schema.sql` 与那份文件头都写明了这件事。
- **花钱的防线变薄了**：以前"谁在用我的密钥"由四个开关兜着；现在是"注册就有"。
  站长能做的只剩两件：关掉注册、把某个人收回来。
  ★ 这与 ADR-0009 里那条遗留（"配额是手工的"）是同一条，只是手工的那一档更粗了。
- **申请那条路没有了**：被收回权限的人**没有任何界面手段**再要回来。
  这是用户选的结果（帮助整条删掉），不是漏掉的一步。

## 没有变的

- **密钥仍然只有服务端一个来源**（`serverEnv()` / ADR-0009 那一半一字不动）。
- **权限每次问后端**，不从票里读：站长把权限收回去之后，那个人**下一次点「开始创作」**
  就生效，不必等 7 天的票过期（`AuthService#allowedOf`，每次请求现读）。
- **"没权限"与"站里没配"继续分开说**，两句话各自指向不同的下一步。
- **判不了就不放行**：后端连不上时回 503，不是放行。
