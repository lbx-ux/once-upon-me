# 演示绘本《小宇的云》：配音稿与录音说明

> 用途：W1 引擎那一步「逐页配音」的**稿子范式** —— 正文逐字稿、朗读标注、
> 时长与体积预算、录音朝向，写成一份可以直接照着念的文档。
> 它先在演示书上手工走一遍全流程（[`demo-book-art-prompts.md`](demo-book-art-prompts.md)
> 管画面，这份管朗读），引擎落地时照这张形状生成。
>
> ★ 2026-10-18：**这份稿子有消费它的前端了** —— 首页第二屏那本滚动演示书的朗读钮
> （`components/book/StorybookFlip.tsx`），闸门在 `lib/demo-book-audio.ts`。
> 所以 §五 的落盘位置与命名是**现在就要照做的**，不再是"以后接的时候再说"。
> ★ 它是"录满才出现"：**5 段少一段，那个钮就整块不出现**（判据 ①，见 §六）。
> 录到一半时页面上没有任何东西可看，那是设计，不是坏了。

## 一、两条纪律，先于一切

### 1. 念的必须就是印的，一个字都不许改

书页上的正文是**真 HTML 文字**（`.book__text`），不是画进图里的。孩子眼睛看到的和耳朵
听到的必须逐字一致 —— 家长临场"讲得生动一点"（加个"哎呀"、把"别的东西"说成"别的东西呀"）
在这一刻是**破功**：

- 屏读念的是同一份文字，口播一改，无障碍版本就和音频对不上；
- 独读版的产品定义就是"全屏一图一句，父母声音朗读那一页的字"，多出来的字不在图里；
- 而 W1 之后引擎会**自动**做这件事，家长没有临场发挥的余地 —— 现在养成"逐字"的习惯，
  后面就不用返工。

**要加东西，走下面那条：口播独有内容。**

### 2. 有一类话只说、不印，全部标了「🗣 口播独有」

共读版的定义里写着：选择点插入**引导性提问**，把「看故事」变成「聊故事」，
而且孩子不识字，所以选项要走「大图标 + **语音朗读**」双通道。这些话**故意不印在书上** ——
印了就变成给孩子读字，那是"看故事"；说出来才是"聊故事"。

所以每一页分两块：**印的**（逐字照念）与 **🗣 口播独有**（共读版才念，独读版跳过）。

## 二、时长与体积预算

按 3.2 字/秒的慢读 + 标注里的停顿估的。独读版是给睡前准备的，**宁慢不快**。

| 页                   | 印的字数 | 目标时长  | 上限  | AAC 64kbps 体积 |
| -------------------- | -------- | --------- | ----- | --------------- |
| 封面（可选开场）     | —        | 6 秒      | 8 秒  | 48 KB           |
| P1 像什么？          | 33       | 10 秒     | 13 秒 | 80 KB           |
| P2 上去了            | 28       | 9 秒      | 12 秒 | 72 KB           |
| P3 往哪朵云去        | 36       | 11 秒     | 14 秒 | 88 KB           |
| P4a 爬上恐龙的背     | 29       | 9 秒      | 12 秒 | 72 KB           |
| P4b 坐进船帆里       | 34       | 11 秒     | 14 秒 | 88 KB           |
| 收尾                 | —        | 5 秒      | 7 秒  | 40 KB           |
| **合计（不含可选）** | **160**  | **50 秒** | —     | **约 400 KB**   |

单张上限 200 KB（与 `make-webp.py` 那三个预设同一种"先定预算再选参数"的写法），
按 64 kbps 数一遍全部有余量。**超上限就降到 48 kbps**，人声在 48 kbps AAC 下听不出差别。

★ P4b 是全篇最静的一页，**要念得比 P4a 慢**：那页的落点是"玩累了坐一会儿"，
读快了就把这一页读没了。

---

## 三、标注怎么读

| 记号     | 意思                             |
| -------- | -------------------------------- |
| `／`     | 短停，约 0.4 秒（逗号级的呼吸）  |
| `／／`   | 长停，约 1 秒（让画面被看一眼）  |
| **粗体** | 重音，稍微抬高一点、说慢一点     |
| `——`     | 拖住，别急着收，让那句话悬在空中 |

## 四、稿子

### 封面 · 可选开场（🗣 口播独有，印的只有书名）

书上印的是「小宇的云」与「以小宇为主角 · 用你的声音朗读」—— 那是**给评审看的话术**，
不是给孩子念的。所以封面这一拍要么不出声，要么念这句：

```
这本故事呀，／ 主角是**小宇**。
```

录不进也没关系：封面**本来就不该有配音** —— 书还没打开，没有哪一页在念。
引擎那边同理，封面/封底不进配音队列。

### P1 ·「像什么？」→ `spread-1.m4a`

**印的（逐字照念）**

```
草地上的午后，小宇一动不动地躺着。
天上的云，慢慢变成了别的东西——
```

**朗读标注**

```
草地上的午后，／ 小宇**一动不动**地躺着。／／
天上的云，／ 慢慢变成了**别的东西**——
```

> 「别的东西」后面是破折号，**拖住别收**。这一页的钩子就是那半句没说完的话，
> 孩子会自己往下猜。

**🗣 口播独有（共读版）**

```
你猜猜，那朵云像什么呀？
```

### P2 ·「上去了」→ `spread-2.m4a`

**印的**

```
他伸手够到最近的一朵，坐了上去。
云软软的，只比草坡高一点点。
```

**朗读标注**

```
他伸手／ 够到**最近的一朵**，坐了上去。／／
云**软软的**，／ 只比草坡高**一点点**。
```

> 「一点点」要**真的说得很小** —— 这一页的硬要求是"云必须低"，
> 画面里下方还看得见草坡，声音也得跟上，不能念出一种飞上天的高度感。

**🗣 口播独有**

```
如果你坐上去，会是什么感觉？
```

### P3 ·「往哪朵云去」→ `spread-3.m4a`（选择点）

**印的**

```
前面有两朵云。
一朵像恐龙的背，宽得可以骑上去；一朵像船的肚子，坐进去正好。
```

**朗读标注**

```
前面有**两朵云**。／／
一朵像**恐龙的背**，／ 宽得可以骑上去；／
一朵像**船的肚子**，／ 坐进去**正好**。
```

> 两个「一朵」的**音高要分开**：说恐龙云时往左指（画面左边就是那朵），
> 说船云时往右。孩子不识字，方位是靠你的手指和语气给的，不是靠字。

**🗣 口播独有 —— 这一段是选择点的全部机制**

```
你想去哪一朵？／
这朵长长的，／ 像什么呀？／／
想骑到恐龙背上的，就按左边；想坐进帆船里的，就按右边。
```

> ★ 选项的读法必须与画面、与按钮**同一个左右**：左 = 🦕 恐龙云，右 = ⛵ 帆船云。
> 这个方位在出图阶段就被钉死了（`demo-book-art-prompts.md` §一），
> 念反了孩子看图、看按钮会读成两件事。

### P4a ·「爬上恐龙的背」→ `spread-4a.m4a`

**印的**

```
小宇爬上了恐龙云的脖子。
每一步都软软的，像踩在晒过太阳的被子卷上。
```

**朗读标注**

```
小宇爬上了／ 恐龙云的**脖子**。／／
每一步都**软软的**，／ 像踩在**晒过太阳的被子卷**上。
```

> 「晒过太阳的被子卷」是这一页唯一一次出现家里的东西，**慢一点、暖一点**，
> 它是整本书"想象其实来自生活"的落点。

**🗣 口播独有**

```
爬那么高，／ 小狗敢不敢跟上来呀？
```

### P4b ·「坐进船帆里」→ `spread-4b.m4a`

**印的**

```
小宇坐进帆船云里，两条腿晃啊晃。
小狗趴在他腿上睡着了。云慢慢地飘，风轻轻地吹。
```

**朗读标注**

```
小宇坐进帆船云里，／ 两条腿**晃啊晃**。／／
小狗趴在他腿上／ **睡着了**。／／
云**慢慢地**飘，／ 风**轻轻地**吹。
```

> 最后两句**音量往下收**，像怕吵醒那条狗。这一页是全篇最静的一页，
> 念到后面几乎是气声 —— 独读版用它收尾，孩子就差不多睡了。

**🗣 口播独有**

```
风轻轻地吹，／ 小船会飘到哪儿去呀？
```

### 收尾 · 可选（🗣 口播独有）

书上印的是「每一页，都是同一个他。」—— 那是**给评审的论点**，不是对孩子说的。
孩子那句用这句：

```
明天，／ 你还想去哪一朵云上坐坐？
```

## 五、怎么录（不用器材）

| 项     | 怎么做                                                                         | 为什么                                                                       |
| ------ | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| 设备   | 手机自带的语音备忘录就够                                                       | 人声在 48–64 kbps 下手机麦完全够；真正毁音质的是房间不是麦克风               |
| 房间   | 关窗、关风扇、**挂满衣服的衣柜前**录                                           | 衣服是最便宜的吸音板；空房间的混响压不掉，任何降噪算法都救不回来             |
| 距离   | 离手机 15–20cm，**别正对着话筒**                                               | 正对会喷麦；稍微偏一点侧着说                                                 |
| 分段   | **一页一个文件**，别一次录完五页                                               | 与引擎的形状一致（按页合成、按页重试、按页缓存），也方便只重录出问题的那一页 |
| 一遍过 | 念错了**停两秒再接着念对的那句**，别中断录音                                   | 停顿会被剪掉或干脆留着；重录整页的代价大得多                                 |
| 逐字   | 照着「印的」那块念，一个字都别改                                               | 见 §一 第 1 条                                                               |
| 格式   | 导出 `.m4a`（AAC）；iPhone 默认就是                                            | Safari / Chrome / Firefox 全覆盖，不用引 WebAudio 也不用转码                 |
| 命名   | `spread-1 / -2 / -3 / -4a / -4b`，与 `public/book/spread-*` **同名**只差扩展名 | 对不上就得写映射表，映射表一定会过期                                         |

**落盘位置：`public/book/`**（就是那几张图所在的目录，和它们挨着放）。
名字是**从图推出来的**，一个字都不用另记：第 k 个跨页的图是 `spread-k.webp`，
那它的朗读就叫 `spread-k.m4a` —— 同目录、同序号、只差扩展名
（`lib/demo-book-audio.ts` 就是这么找的：它 `readdir` 这个目录，按图名去比对）。
`.mp3` 也认（次序上 `.m4a` 优先），但**新录的那一本请按规格出 AAC**。

★ 那 5 个基名认全了才生效，少一段朗读钮整块不出现 —— 见 §六，以及
`lib/demo-book-audio.ts` 文件头"闸门"那一段（它连 4a/4b **两支**都算进去：
只录了 4a 的书，孩子选了帆船云会当场哑掉，而那正是要挡住的那种"部分能响"）。

录完不用改任何代码。想自己验一遍（真的会响、翻页会停、选哪朵云念哪一段）：

```bash
node scripts/chk-book-narration.mjs http://127.0.0.1:3324
```

## 六、要录就五页全录，别只录第一页

**五页全录只要 50 秒的朗读、五分钟的时间**，换来的是：

- 演示从"我们做了一页配音"变成"**整本都是你的声音**" —— 后者才是产品承诺本身；
- 「每一页都是同一个他」这句话，从只有画面在证明，变成画面和声音**同时**在证明；
- 睡前场景（独读版）第一次在 demo 里真的成立 —— 一页配音撑不起"睡前"两个字。

> 首页那条播放条**做过→拆了→2026-10-18 按满配做回来**，中间那一次拆的理由正是
> "只录得到第 1 页"：一个只对四分之一能响的控件，证的是"每一页都是同一个他"的反面。
> 所以这一节的建议不是"先凑一页上线"，而是**要么录满，要么先不做** ——
> 做回来的那个钮就是把这条建议变成了代码里的闸门（5 段全在才出现）。
> 引擎那边"缺页"的降级路径仍然要有 —— 一本正在生成的书本来就会有几页配音还没到 ——
> 但那属于 W1，不属于首页。

## 七、这份稿子在真实产品里由谁产生

演示稿是人写的。产品里不写 —— 它是引擎的产物，形状与 §五 的"一页一个文件"完全一致：

```
规划 Agent → 分镜（全部正文）→ 校验
                ├─→ 逐页生图   （慢、会失败、要重试）
                └─→ 逐页配音   （快、便宜，挂在正文上，不挂在画面上）
                     ↓
                   manifest：pageId → {audioUrl, durationMs}
```

两条链是**兄弟**不是父子：旁白依赖正文，正文在分镜阶段就一次性定完了，
所以配音完全不必等任何一张图。按页的理由有四条，都记在这里免得日后翻案：

1. **重试粒度** —— 配音的典型失败是念错孩子的名字、某页太长、语气怪，
   这些都要单页换参数重试，不是整本重来。
2. **时长要回灌** —— 每页量 `durationMs`，超了就把那一页退回规划 Agent 改文。
   批量到末尾再量，反馈回路是糊的。
3. **共读版是棵树** —— 选择点**之前**那段主干被两条路共享，按 `(voiceId, textHash)`
   去重天然只合成一次；换一条分支重读不用重付。（选择点之后两条路各有一份，
   而两份都要配——那是"走不到的那一支"的价钱，见 docs/known-tradeoffs.md。）
4. **边生成边能读** —— 第 1 页图文齐了就能翻开，不用等第 20 页画完。

批量接口（若供应商有）用在**传输层**：攒一次提交、按 `pageId` 落回各自槽位。
工作单位与缓存单位始终是页。声纹模型是**每本书建一次**（`ensureVoiceModel(样本)` → `voiceId`），
必须放在两条 fan-out 之前，否则并发会撞出 N 个重复模型。

### W1 选型时要验的三条

| 要验的                        | 为什么是硬指标                                                                         |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| 单页延迟与并发上限            | 决定要不要那个攒批的传输优化                                                           |
| **中文名 / 小名的发音正确率** | 念错孩子的名字，整本书就废了。测的时候备一批真实小名：豆豆、囡囡、小满、叠字、带儿化的 |
| 时长可控性                    | 能不能指定语速/停顿，或至少稳定预测"这段字要念多久"。不能预测就没法做 §二 那张预算表   |

> ⚠️ 演示稿避开了这个坑：**「小宇」没有任何多音字和难读的姓**。
> 所以这份录音**测不出名字发音的风险**。要测，另外拿一页用家里人的小名替一遍念试试。
