# 商业潜力 —— 成本、定价、变现路径与竞品

## §0 一句话

**一本 20 页绘本的 API 成本是 8–12 元**（实测边界 5.8–11.6 元，取决于两个可调的旋钮）；
其中**七成是出图、三成是"核对这张图像不像"**，文本与语音加起来不到 2%。

而竞品的价格锚点在另一个量级：定制纸质童书 **$29.99–39.99 / 本**（≈ ¥210–280），
免费 DIY 手工链要家长自己动手 **4–8 小时**。
所以这门生意的形状不是"内容电商"，是**把一件按传统工艺计价的东西，做成按 API 计价的东西**——
而按 API 计价之后，定价的约束从"印刷与物流"变成"**生成次数**"。

### 1.1 成本的五项，各自的单价与出处

★ **克隆那一项不影响单本成本**，所以那一格空着不挡事：它是**一次性的**
（一个家长的声音克隆一次，`voices` 表里就是一条记录），之后每本书都复用同一个 `voiceId`。
摊到第 2 本之后就是 0——这也是 §6.2 那条"边际成本不增长"的一半。
**唯独要记住它的失效条件**：克隆出来的音色**绑死在创建它时的模型上**
（跨模型实测 400 `[411]`），所以换语音模型会让手里已有的音色**当场失效**，
要么重新克隆（再付一次那笔未量到的钱），要么不动它。

★ 另外三条不显然的：

1. **图像是"一口价"，所以成本只由"画了几张"决定**，与画多大、多精细无关。
   这就是为什么下面所有的省钱杠杆都指向"少画一张"，而不是"画小一点"。
2. **这家网关的 `/v1/models` 目录里带单价字段**（`effective_input_price_per_million`、
   `effective_output_price_per_million`、`effective_cache_read_price_per_million`）。
   所以文本与视觉的单价**不用抄别人的价目表**——一条免费的 `GET` 就能拿到，
   而且拿到的是**这台账号实际生效的价**（含折扣后的 `effective_*`）。
3. **语音的计费字符不是文本长度**。实测规则是 **汉字 × 2 + 非汉字 × 1**，
   全角标点算 1（`小宇，下雨。` 与 `小宇,下雨.` 都回 10；`小宇ab` 回 6）。
   这条规则原来是**从一个样本推的**（17 汉字 + 3 标点 = 37），而那个样本判别力不够——
   「非 ASCII ×2 + ASCII ×1」同样拟合它。`scripts/cost-model.mts` 的第四段用
   **能判别的一对样本**重测了它。★ 差别本身不大（一本 20 页里几十个标点 ⇒ 几十个计费字符），
   **但报价要照着事实来**：推出来的规则一旦错，错的是每一本的数。

★ **`每次/页` 就是重画率那个 r 的另一种写法**（`1 + r`）：它等于
「出图次数 ÷ (节点数 + 1 张封面)」。五本落在 **1.33–2.00** ——
也就是说，**今天这条流水线画的图，有四分之一到一半是画完又被替掉的**（一致性核对没过）。
这一列是本文档里最值钱的一列，§2.2 与 §3.3 都会回到它。

★ **书清单里的 `stats.totalCostCny` 只有图像那一项**（`illustrate.ts` 把每次响应里的
`costCny` 加起来）。文本、视觉、语音都不在里面——所以"每本成本"必须自己拼，
这就是 `scripts/cost-model.mts` 存在的原因。

### 1.3 视觉那一路：一页两问

`illustrate.ts` 里一页**至少**两次视觉调用：③-a **一致性比对**（送两张图：参考图 + 本页）
与 ③-b **画面审核**（送一张图，查有没有不该出现的东西）。两次实测：

| 调用       | 送图 | 输入  | 输出（含思考）                      | 一次的钱（`kimi-k2.6`） |
| ---------- | ---- | ----- | ----------------------------------- | ----------------------- |
| 一致性比对 | 2 张 | 3,590 | 1,200 / 2,805（思考 1,106 / 2,745） | ¥0.056 / ¥0.099         |
| 画面审核   | 1 张 | 2,494 | 862 / 1,398（思考 781 / 1,353）     | ¥0.037 / ¥0.041         |

⇒ **一页两问 ¥0.097–0.137**。量法：实测 token × 目录单价（`scripts/cost-model.mts` 的第三段）；
两次之间的差是**思考链长度**在抖，不是两次测了不同的东西。

★ 画面审核**不是每张图都跑**：一致性判了 `fail` 而还有重画次数时**跳过**
（那一张马上就要被替掉，给它审等于买一份关于废纸的报告）。
反过来说：**每一次重画都会多付一次比对的钱**——重画不只多画一张图。

### 1.4 文本那一路：便宜到可以忽略，但重试是真的

一次 20 页独读版的规划：**975–1,038 输入 + 1,770–2,163 输出** token／次。
同一张卡、同一个主题跑两次，一次**1 次调用**过、一次**3 次调用**过
（Schema 没过就整篇重发）。

| 情形   | 合计                 | 钱         |
| ------ | -------------------- | ---------- |
| 1 次过 | 975 in + 2,163 out   | **¥0.003** |
| 3 次过 | 3,051 in + 5,550 out | **¥0.009** |

★ 结论有两条，方向相反，都要说：
①**文本不是成本问题**——一次规划的钱是 ¥0.003–0.009，**不到一张图的十分之一**，
重试三次也还是 1 分钱；
②但**"重试是整篇重发"这件事本身**值得记一笔：提示词越长，重试越贵。
检索（RAG）往提示词里加的那几段范例，成本影响就在这里，而不在别的什么地方。

★ **共读版不是这一组数**（2026-10-22 起）：它走两步——先写提纲（每页一句），再分三段展开
（主干 / A 支 / B 支）。20 页实测 **4–5 次调用、约 21–26 秒**（`deepseek-flash`，见
`docs/known-tradeoffs.md`）。它每次写的页数比独读版少，所以"重试是整篇重发"这条在共读版上
不成立：重试只重发**那一段**。

### 1.5 拼起来：一本 20 页独读版

固定项：文本 ¥0.003–0.009 · 语音 ¥0.125（实测每页 62.6 计费字符 × 20 页）。

| 每次/页 | 视觉模型            | 图（张 × ¥0.2） | 视觉（比对 + 审核） | 文本 + 语音 | **合计**   | 图像占比 |
| ------- | ------------------- | --------------- | ------------------- | ----------- | ---------- | -------- |
| 1.33    | `kimi-k2.6`（现值） | ¥5.59（28 张）  | ¥2.35               | ¥0.128      | **¥8.06**  | 69%      |
| 1.33    | `qwen3.8-flash`     | ¥5.59（28 张）  | ¥0.12               | ¥0.128      | **¥5.84**  | 96%      |
| 2.00    | `kimi-k2.6`（现值） | ¥8.40（42 张）  | ¥3.10               | ¥0.128      | **¥11.63** | 72%      |
| 2.00    | `qwen3.8-flash`     | ¥8.40（42 张）  | ¥0.16               | ¥0.128      | **¥8.69**  | 97%      |

**⇒ 每本 20 页的 API 成本：¥5.8 – ¥11.6。**

> **这张表里有一个必须承认的假设**：视觉那一列的"换一台模型"只换了单价，
> **token 数照抄现值**。换模型会换掉"判得像不像"这件事本身，而一致性阈值是
> **标定出来的**（`illustrate.ts` 的 `threshold`）。所以那一行给的是**上限**，
> 要真拿它做决定，得先把判据重量一遍。这是本文档里**唯一一处"算了但没测"**。

### 1.6 成本之外的那个成本：时间

实测一本的生成用时是 **12.5 – 174.2 分钟**（上表最后一列）。
它不进钱账，但它决定三件事：

- **生成是"下单之后等"的过程**，所以界面必须有画桌与阶段轨（已经有了）；
- 时间几乎全花在**串行出图 + 核对 + 重画**上（出图那一步实测 ≈154 s/页，
  见 [known-tradeoffs.md](known-tradeoffs.md)），所以"更快"与"更便宜"是同一个方向
  （少一次重画同时省一张图、一次比对与 154 秒）；
- 它也是**预生成**（[ADR-0003](adr/0003-pregenerated-assets-decouple-demo-from-api.md)）
  这笔账的正当性：**阅读那一刻零调用、零等待**，孩子翻页不需要等任何模型。
  代价就是这 20 分钟到 3 小时不等的等待，以及 §2.1 那条"走不到的那一支也要画"。

★ 用时那一列的抖动**不是"画得慢"，是撞在别的东西上**：同一批书里 174.2 分钟那本，
与 60.6 分钟那本节点数只差 2 个。真实原因（视觉调用超时、网关排队、本机负载）
**本轮没有逐页归因**——所以这一列**只能当量级读，不能当 SLA**。

## §2 成本结构里两处必须直说的地方

### 2.1 共读版：走不到的那一支，也是预生成的价钱

共读版是**一棵树、恰好一个选择点、两支各自收尾**
（[ADR-0006](adr/0006-one-tree-two-forms.md)）。两条支**不可能汇合**——
这是 `buildTree` 三条规则合起来的一条结构推论，不是"还没做"。
所以**一条支必须自带到结尾的全部页，每加一层就多付一整条尾巴**。

实测（2026-10-18，`--pages=5` 真跑一本）：

```
同一本书：独读版 = 5 个节点、5 张图
          共读版 = 8 个节点（选择点在第 2 页）——多出来的 3 页，孩子永远读不到其中一支
```

⇒ **共读版比同长度的独读版贵 1.6 倍**（8/5），而这 1.6 倍**不是浪费**：
它是"孩子真的能选"这件事的价钱，而产品的两个形态分别对应两个真实场景
（睡前独读 / 白天陪玩）。界面把这句话**写在花钱的那一刻**——故事闸门那一屏写着
「读下来 N 页，一共要画 M 页的图（含走不到的那一支）」。

★ 为什么不干脆做成多层分支：`GLOSSARY` 的「共读版」那一条里有那张表——
1 层时 27% 的书那个孩子永远读不到，2 层 43%，3 层 64%。**选择的上界是年龄给的，
不是页数给的**（孩子不识字，两个选项已经够）。

### 2.2 重画：唯一一处"花了钱还没拿到东西"的地方

五本真书的首次通过率（`stats.firstPassCount ÷ stats.nodesGenerated`）：
**2/11、4/12、5/10、3/6、4/5**。也就是说，一致性那个 Agent 每天在干的事，
有相当一部分是**画完、核对、判不过、再画一遍**。

按 §1.5 的两档算，**把"每次/页"从 2.0 压到 1.0 能省 ¥1.8–5.3**，
**换一台便宜的视觉模型能省 ¥2.2–3.5**——两者量级相当，谁省得多取决于重画率压到多低。
但前者还**同时省时间**：每页少 154 秒，一本 20 页就从一小时量级掉到半小时量级。

这件事已经有落点，而且是本项目里性价比最高的一处未做项：
`illustrate.ts` 的重画**用的是同一个提示词**——逐锚点的核对结论（"哪一撮头发不对"）
只进了给**人**看的 retry 事件，**没有回灌给模型**（`.scratch` 里的 B7 工单，约 20 行）。
**"拿同一张指令再抽一次签"与"按结论改一版"是两种重画**，而今天这条流水线只会前者。

★ **2026-10-20：那 20 行已经落地，而这笔账能不能兑现还没量出来**，照实记在这里：
量具是 `scripts/anchor-note-cases.mts`——两页（真书上失败过的 p8/p10）× 12 张/组，
A 组是**空对照**（今天的提示词）、B 组只多那一句结论，逐张过同一个核对、阈值不重标定。
读数：p8 **33% → 36%**（差 3 pp）、p10 **58% → 75%**（差 17 pp），
**两页的 Wilson 区间都交叠**，也就是**这一档判不出来**。
12 张/组能看见的最小差是 **41–51 pp**；要看见 p10 那 17 pp，每组得抬到 **≈117 张**（约 10 倍）。
★ 顺带量出一条更要紧的：核对这把尺子**自己会跨过阈值翻边**——
p8 那张无提示重画的图，**同一份字节连打 3 次得 0.9 / 0.5 / 0.5**（阈值 0.75），
所以那一页的"通过率"不完全是图的属性。
**结论**：这一格现在的措辞只能是「**试了、并且算出了要多大才试得出来**」，
**不是**"实测省了 ¥1.8–5.3"（与计划表里 RAG 那一项同一个口径）。推导在
[`known-tradeoffs.md`](known-tradeoffs.md) 的「锚点回灌」那一节。

## §3 定价

### 3.1 锚点

| 对照物                                    | 价格                                   | 性质                                                        | 出处                                                                       |
| ----------------------------------------- | -------------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------- |
| **Wonderbly**（个性化童书标杆）           | **$29.99 – $39.99 / 本**（≈ ¥210–280） | 纸质精装，名字 + 献词嵌进**预先画好**的插图；**没有数字版** | 【外部事实】官网首页，抓取 2026-10-19                                      |
| **豆包 + 即梦 + 剪映**（免费 DIY 手工链） | ¥0 + **4–8 小时/本**的人工             | 家长自己写、自己出图、自己配、自己剪                        | 【本项目口径】README「解决什么问题」；**人工工时未计时，是工时下界的估计** |
| **本产品（定价，见 §9.1）**               | **¥39 / 本**（数字版）                 | 生成即得，可反复读、可断网播、可印                          | 本文档                                                                     |

★ 这三行放在一起，就是这一栏要的"相比传统方案有明显优势"：
**比纸质个性化便宜 5–7 倍**，而手工链那 **4–8 小时是家长的"动手"时间**——
我们这边家长只花一句话，剩下的是**等待**（12–174 分钟，机器在跑）。
交付物也**可以立刻读**：纸质那家要等印刷与物流，手工链要家长熬一个晚上。

★ 也要诚实说**我们弱在哪**：没有实体书的手感、没有品牌、没有渠道与线下货架，
也没有"印出来送人"这个最强的付费动机。**纸质档不是不能做，是今天的成本表里
没有印刷与物流这两项**——它们要问印厂，而本项目**没有问过**（§6 待办）。

### 3.2 三档定价与它各自的毛利（用实测成本算）

设每本成本 **C = 7 元**（换视觉档后的中位）与 **C = 10 元**（现值组合的中位）：

| 档位              | 给什么                                | 成本      | 毛利（C=7） | 毛利（C=10） |
| ----------------- | ------------------------------------- | --------- | ----------- | ------------ |
| 单本 · ¥39        | 一本 20 页数字绘本，永久可读          | 7 / 10    | 82%         | 74%          |
| 月订阅 · ¥39/月   | 每月 **2 本**（额度按本数，不按时间） | 14 / 20   | 64%         | 49%          |
| 年订阅 · ¥399/年  | 一年 **24 本**                        | 168 / 240 | 58%         | 40%          |
| 机构版 · 按班年费 | 见 §4.3                               | —         | —           | —            |

★ **这里有一条由成本结构直接决定的产品规则**：**额度必须按"本数"，不能按"时间"。**
因为边际成本随本数**线性**增长（每多一本就是 7–12 元），一个"不限量"的档位
在今天的成本曲线下**毛利必然崩**：给 2 本有 49–64%，给 10 本就要亏。
所以"每月 2 本"不是一个保守的营销设置，是**成本算出来的边界**。

### 3.3 §10.3 那条判据今天不成立，以及要它成立得做什么

`docs/tech-selection.md` §10.3 当初留了一句建议判据：
**「每本 API 成本 ≤ 定价的 1/10」**。按今天的数：

- C = 10、P = ¥39 ⇒ 成本占售价 **26%**，**不成立**；
- 要让它成立，定价得到 **¥100 以上**（≈ 纸质/礼盒档），或者把 C 压到 ¥4 以下。

**所以那条判据要在数字版价格带成立，只有三条路**，按每本省的钱排序：

| #   | 杠杆                                                    | 每本省       | 要不要改代码             | 代价                             |
| --- | ------------------------------------------------------- | ------------ | ------------------------ | -------------------------------- |
| 1   | **把"每次/页"从 2.0 压到 1.0**（锚点回灌，B7 那 20 行） | **¥1.8–5.3** | 是（约 20 行）           | 要先量"首次通过率"有没有真提高   |
| 2   | **换一台便宜的多模态模型做核对**                        | **¥2.2–3.5** | **否**（改一个环境变量） | 判据要重标定（见 §1.5 那条假设） |
| 3   | 页数 20 → 12                                            | ¥3.1–4.4     | 是（产品口径）           | 故事变短，产品定义要跟着改       |

★ 一个反直觉的结论：**这三条里最省事的是第 2 条——它一行代码都不用改**，
因为模型名从来不在代码里（`providers/registry.ts` 只认 `LLM_MODEL` / `IMAGE_MODEL` /
`VISION_MODEL`）。急的话今晚就能换；不急的话第 1 条更值，因为它连**时间**一起省。

## §4 三种变现

三种都要回答同一个问题：**谁掏钱、掏给谁、我们这边成本落在谁账上。**
今天这个答案是清楚的：**密钥由站长（部署者）持有**（[ADR-0009](adr/0009-model-and-key-issued-by-operator.md)），
所以**API 成本落在运营方**，收入必须从用户侧来。这也是本项目的自评里写的那句
"当前的商业模式字面上是**别人付钱**"——工程阶段合理，但不是商业模式。

### 4.1 按本付费（To C 单买）

- **形状**：充值与单本购买；一本 ¥29–49，按页数或形态分档。
- **成本**：C = 7–12 元/本，见 §1.5。
- **现有代码落点**：**书架**（`/shelf`，作品按账号归属、服务端渲染）已经是"我的东西"的
  那个心智模型；**账号与权限**（`user_permissions`，**一位**：能不能创作）就是"谁付过钱"的
  天然挂载点；生成入口的书号是**内容指纹**（卡 + 形态 + 主题），所以同一主题**造不出第二本**
  ——那原本是为了防止误点重画整本，副作用是**系统层面做不了"同一本买两次"**：
  想再来一本必须改一个字（换主题）。这条对"防重付"是好事，对"复购"是一个要记住的约束。
- **缺的**：**支付**（一分钱都没有）、**发票/合规**、**订单与退款的台账**。

### 4.2 订阅（To C 月/年）

- **形状**：¥39/月 含 2 本，或 ¥399/年 含 24 本（§3.2）。
- **为什么这档特别适合这个产品**：孩子的兴趣是**持续**的（12 个主题墙就是按月换题材的
  天然货架），而书是**攒起来**的——书架越长，退订的代价越高。
- **成本**：随本数线性：2 本/月 = ¥14–24。
- **现有代码落点**：**音色库**（`voices` 表 + 角色卡）：家长的声音与孩子的形象是
  **一次性投入、长期复用**的资产——这是订阅留存最好的东西，因为它在书架之外还锁住了"这个人"。
  角色卡跨页、跨书、跨形态复用（[ADR-0007](adr/0007-character-card-as-asset.md)）。
- **缺的**：**创作额度**（见下）、订阅状态机、续费与到期。
- ★ **额度这一件已经有先例，不用从零想**：短信那一路已经做成了
  **用量 + 全站每日硬顶 + 注册开关**（`SmsRateLimiter` / `AdminOverview.smsToday` /
  `smsDailyCap`，管理页上就写着「237 / 300」）。创作这一侧要的是**同一个形状**：
  每账号每月本数 + 全站硬顶 + 一个能立刻关掉的开关。
  ★ 而这件事今天还有一个**真实的风险面**：演示账号是**唯一一个口令写死在代码里的账号**
  （`123456`/`123456`，四个能力全开），站上公网之后**知道这两行字的人都能花站长的钱**。
  管理页已经把它标出来了（`AdminOverview.demoAccount`，就写在"谁在花我的钱"那一屏），
  评审期留着是对的——**评审一结束就该删掉它**。

### 4.3 机构版（幼儿园 + 公益组织）

- **形状**：按班 / 按校包年；机构统一采购、老师批量生成、家长领回。
- **为什么机构会买**：幼儿园与绘本馆要的是**每个孩子都有一本自己的书**——
  这件事在传统工艺下是"人均一本定制书"，价格上根本不可能；
  而在这里它是**同一个流程跑 N 次**，成本是 N × C。
- **成本与定价（假设）**：一个班 30 个孩子 × 一年 2 本 = 60 本 ⇒ 成本 ¥420–720；
  按 ¥2000–3000/班/年定价，毛利 64–86%。**【假设】**——单价与转化**没有与任何机构谈过**。
- **公益那一档不一样，要说清**：留守儿童场景的钱**不应该来自家庭**。
  正确形状是**由公益项目/基金会按本包采购**，家庭侧零成本。
  ★ 而这一档有两个现成的减配优势：① 用**预置音色**（童声/亲切音）而不是克隆家长的，
  省掉一次授权与一条隐私承诺；② **灵感书单那 12 本样书**可以先读后做，
  策划成本是沉没的。
  ★ **必须承认**：本项目**没有与任何公益组织或学校接触过**，这一档是**设想的路径**，
  不是已验证的渠道。要把它变成事实，第一件事是**去找一家谈**——而在那之前，
  这一节里的每一个百分比都只是算术，不是生意。

### 4.4 第四种可能：机构自建（软件在我这儿，账在他们那儿）

[ADR-0008](adr/0008-model-and-key-provided-by-user.md) 那条"用户自带密钥"
在**产品内**已经被 [ADR-0009](adr/0009-model-and-key-issued-by-operator.md) 取代了，
但它描述的**另一种卖法**没有过期：引擎**零硬编码模型 id**、
`registry.ts` 的 `Env` 是**参数**不是 `process.env`，所以一台机构自己的部署
可以带自己的密钥、自己的模型、自己的资产目录（`ASSET_ROOT`）。
这种卖法下**成本不落在我们账上**，收入是部署与维护费，毛利结构与前三档完全不同。
★ 它是**唯一一条成本不随用量增长的路**，也是唯一一条不需要先有支付系统的路。

## §5 目标市场

### 5.1 亲子绘本（基本盘）

**付钱的理由很朴素**：孩子有一本"自己的"书，这件事在情感上值钱，
而个性化的门槛今天高得离谱（要么 ¥210 起一本的纸质定制，要么家长熬一个晚上）。
我们做的是**把"孩子当主角"从奢侈品变成日用品**。

**分母**：中国 0–14 岁人口 **253,383,938**（17.95%）——【外部事实】2020 年第七次全国人口普查，
2021-05-11 发布。3–8 岁那一段普查**没有单独给**，按年龄段均匀分布粗推约 **1.0 亿人**，
对应**上千万到上亿个家庭**（取决于每户几个孩子，**【假设】**）。
★ 这是**推算不是统计**，且人口在变，**要用就该拿最新口径重算**。

### 5.2 留守家庭（社会价值那一栏的商业面）

**产品承诺**：在外打工的父母录 30 秒声音，孩子在家听爸妈读一本自己当主角的绘本。
**声音可以跨越距离**——这是 [README](../README.md) §一「社会价值」那一段的原话。

**两个口径的数字**（都要写出来，因为它们差一个数量级）：

| 口径                  | 数字                                                | 出处                                                                                                           |
| --------------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 六普推算              | **6102.55 万**（占农村儿童 37.7%、全国儿童 21.88%） | 【外部事实】维基百科「留守儿童」条，引 2010 年第六次人口普查推算                                               |
| 2016 年后的官方窄口径 | **本文档不引用**（记不准）                          | 【未核到】口径在 2016 年前后收窄过一次（"父母双方外出"这一类），**具体数字与定义原文本次都没有核到**，所以留空 |

★ **这条要专门说一句**：本项目**没有做过任何一家留守家庭的访谈**
（`.scratch` 里把它记成"社会价值那 5 分最硬的证据"，也一直挂着"没做"）。
所以这一节是**基于产品能力与公开统计的推断**，不是调研结论。
**没有的东西直说没有**——这比编一段"我们走访了 N 个家庭"诚实。

★ 但有一条**已经成立**的东西可以说：**生成**那一步不需要一行新代码。
它用的就是同一套：录 30 秒 → 克隆 → 预生成 → 落盘的字节，
离线回放（ADR-0003 的 replay 包 + `public/demo/books/`）已经随仓库发布（§7.1）。

★ 而**送过去**那一步今天不成：孩子那边打开是 404。这条比生成那一头更要紧，
写在 §5.4——那里是这一整条路的触达账，按三个通道各算一遍。

### 5.3 一个"先读后买"的免费档（已经做好了）

**灵感书单 12 本样书**（`/booklist`，12 个主题 × 8 个跨页 = 96 跨页，
带朗读、只读、不写书架）。它是**零边际成本**的获客面：
读一本样书不发生任何生成调用，而它证明的正是这个产品最想证明的那件事——
**一本成品长什么样**。付费转化发生在"我要一本**我孩子**的"那一刻。

### 5.4 触达：谁把它送到孩子手里

这一节只回答一件事：**一个孩子今天怎么才能读到一本**。
所以每一栏都分两半——「今天有的」只写仓库里指得出来的东西（文件、命令、读数），
「缺的」直说缺，不写成"下一步可以做"。证据等级照 [tech-selection.md](tech-selection.md)
那张表：**A** = 本仓库已实证（有读数、有量法），**B** = 已核实的外部事实，
**C** = 未核实的认知（现场必须当场核实）。

三个通道不是三套产品，是**同一条流水线的三种交付形态**：做完的一本书是盘上的字节
（图 + 朗读 + 清单），谁打开它、用哪台设备打开，就是这三种形态的分界。
★ 而它们**共用同一处断裂**——最后那一段「三条通道缺的是同一条」说的是这件事。

#### 通道一 · 学校或公益机构代发

**发生于**：一个老师或一个公益机构，替一群孩子把号建好、把书做出来。

| 三件事       | 今天支持到哪一步                                                                                                                                                                                                                                                                                                                                                                                                                                                           | 缺哪一步                                                                                                                                                                                                                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **网络条件** | 读一本**做完的**书不调任何模型接口：每一页的图、每一段朗读都是盘上的文件，断的是模型供应商那一头（ADR-0003），不是整条网。站架在哪台机器上，翻页就只问那台机器——架在教室里，外网断了也翻得动。【A】2026-10-21 在本机那一台上量：未登录读 `public/demo/books/` 里那两本，`/reader/<书号>` = **200**，图那一头 `/demo/books/<书号>/page-1-a1.webp` = 200、162,564 字节                                                                                                       | **真·离线包没有。** 那些字节是静态的，但翻页那一层是 Next 的一个路由（`src/app/reader/[bookId]/page.tsx`）：没有 service worker、没有 PWA manifest、没有"导出一个双击就能打开的文件"。【A：`grep -rn serviceWorker src public` 空】**导出成视频**那条路一个字都没写——没有 ffmpeg、没有截图导出、没有打印 |

#### 通道二 · 探亲那几天，家长用自己手机做

**发生于**：在外打工的父母回家几天，或者视频里教着做一次。这一条最贴合 §5.2 那个场景。

| 三件事       | 今天支持到哪一步                                                                                                                                                                                                                                                                                                                                                              | 缺哪一步                                                                                                                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **网络条件** | 整条链路是异步的：出图实测 ≈154 秒一张（`mcp/README.md`），一本 20 页的书要几十分钟，所以不必守着屏幕。进度走 SSE，刷新或断线之后能从 `/api/books/<书号>/events` 把这一轮**重放**出来（`src/app/api/books/[bookId]/events/route.ts`，帧格式与实时流逐字一样）【A：路由与文件都在】。书与声音绑账号、不绑设备：换手机、换浏览器，登录还是同一份（资产在 `u/<userId>/` 那一片） | 出图那一路要连模型厂商。一次重画就是一张图的钱，而 §2.2 那五本真书的首次通过率是 2/11–4/5——重试是**真的花钱**的，村里的网络恰恰是重试最多的那种环境。这一条没有在弱网下量过——**没有数**，不猜 |
| **支付**     | 免费档能跑到底：12 本样书（`/booklist`）与演示书都不需要账号、也不需要钱【A：2026-10-21 未登录实测 200】                                                                                                                                                                                                                                                                      | **完全没有支付**：今天这条路一分钱收不到，也没有一处记「谁付过钱」（§7.2 第 1、3 条）。不是"没打通"，是没有                                                                                   |
| **使用能力** | 不识字也能读：每一页的朗读、选择点的提问都有声（`ReaderPage.audioUrl` / `StoryChoiceView.promptAudioUrl`），设置里那一档「自动朗读」按一次就一页页自己念、念完自己翻（`components/shell/SettingsDialog.tsx` 的 `turnMode`）。★ 对祖辈带养这一档，这是最要紧的一条：孩子那边不需要有人会操作                                                                                   | ★★ 2026-10-29 起有一条**只读分享链接**：对方不用登录就能读，30 天到期、可随时收回。**仍然缺**离线包与打印——见下面那张表与本图末尾                                                             |

**「送过去」这一段是本节的结论**。书的归属是硬的：运行期的书只有它的主人在登录状态下读得到。
2026-10-21 在本机那一台上，同一本书（`xiaoman-r1-638df001b4e9`）反复问了一遍：

| 谁打开 `/reader/<书号>`              | 结果    |
| ------------------------------------ | ------- |
| 未登录                               | **404** |
| 书的主人（带他自己那张会话票）       | 200     |
| 另一个账号（拿 A 的票开 B 的书）     | **404** |
| 未登录读 `public/demo/books/` 那一本 | 200     |

```bash
# 量法：不带票、带票各一次。票是本地 HMAC 签的（`src/lib/auth/session.ts` 的 `verifyToken`），
# 里面的 `sub` 就是 `u/<那个数字>` 的这一段
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3311/reader/xiaoman-r1-638df001b4e9
```

于是"把孩子做进书里"这件事，今天能成立的唯一形态是：**手上这台机器的主人跑一条命令**，
把它导成随站发布的演示书——

```bash
node scripts/export-demo-book.mts --book=<书号>
```

落进 `public/demo/books/<书号>/`，那之后谁打开都读得到（上表最后一行）。
这条命令**能跑通**，包括书住在 `u/<userId>/books/` 之后的新布局（脚本两种布局都认，
2026-10-21 用错书号探过一次，它把四片里的八本书都列了出来）。
但**产品里没有这条"导出"的按钮**：它是运维动作，而且导出去的那一份是"随仓库提交的资产"，
不是"这个人的书"。再往上一层还有一件更前面的：**创作要账号，而账号今天只能由站长在管理页建**。

★ **2026-10-29 补上的是另一种东西，不要与上面这条混为一谈**：书架每本成品多了一颗「分享」，
生成一条 `/r/<票>` 的**只读链接**——对方不用登录、不用装任何东西，打开就是这台阅读器；
链接默认 30 天到期，家长可以随时收回（收回之后页面与图同时 404）。
它解决的是"他手上那台设备能读到"，**没有解决**"把字节交给他 / 印出来"：
离线包、导出文件、打印仍然没有。
票是 HMAC 签的，盘上只存哈希（`src/lib/share/token.ts` 文件头），
所以链接**只在生成那一刻显示一次**——丢了就重新生成，旧的那条随之作废。
判据在 `scripts/chk-share-link.mts`：匿名 200、过期/收回/改一个字节都 404、
页面里没有写操作按钮、打开分享页 `events.jsonl` 一个字节都不动。

#### 通道三 · 手机上只用浏览器，不装 App

**发生于**：孩子那边或祖辈那边，一台普通安卓机，没有任何安装步骤。

### 6.2 一句话说明"为什么不是套壳"

**同一个孩子的第 2 本书、第 10 本书，成本结构与第 1 本不一样**：
角色卡（形象）与音色是**复用**的，而它们是这个产品里最贵的一次投入
（角色卡要一张参考图 + 一次派生；音色要一次克隆）。
个性化的价值随**本书**增长，而它的边际成本不增长——这是"引擎"与"聚合"的分界，
也是为什么这门生意有留存可言。

### 6.3 与"直接对着通用大模型聊"比

一个家长完全可以让通用模型写一个故事。差在三件事，而三件都是工程：
**① 每一页都是同一个孩子**（跨页一致性核对 + 重画闭环，实测首次通过率 2/11–4/5）；
**② 声音是家长的**（克隆 + 情绪标签）；
**③ 交付物是一本书**（tree、资产、清单、可断网重放），而不是一段聊天记录。
官方的评分口径里，后两条对应"多模态能力"与"实用性"——
而这里的差别不是"用没用模型"，是**有没有把这些变成一个可复用的产物**。

## §9 收入侧的四件

前面八节是**成本侧**与**已有的东西**。这一节是收入侧，四件：
定价决策（9.1）、合规（9.2）、市场空间（9.3）、时间的商业含义（9.4）。

★ 标注规矩（与 [tech-selection.md](tech-selection.md) 的 A/B/C 同一套，只多一个标记）：

| 标记           | 含义                                                     |
| -------------- | -------------------------------------------------------- |
| **【A】**      | 本仓库**已实证**：有落盘产物、有实测数字、有可复现的量法 |
| **【B】**      | **已核实的外部事实**：附来源与核实日期                   |
| **【假设】**   | 我们自己的推算或设定，**不是调研结论**，写明假设了什么   |
| **【决策】**   | 我们自己**定下来**的选择。它不是事实，附上"什么条件下改" |
| **【未核到】** | 该有而本轮没有的东西。**留空写出来，不编**               |

### 9.1 定价决策

§3.1 那张锚点表里这一行原来叫"**建议价**"，§3.2 的三档毛利是照它算的。
**从这一节起它是定价**：价格是我们定下来的，理由、边界与改价条件写在下面。

**【决策】三档**：单本 **¥39** · 月订 **¥39/月（2 本）** · 年订 **¥399/年（24 本）** ·
机构版 **按班年费**（¥2000–3000/班/年，**【假设】**，见 9.1 那条渠道）。

**这三个数的来处**（不是拍的）：

| 依据                                                                                  | 读数                                               | 等级                          |
| ------------------------------------------------------------------------------------- | -------------------------------------------------- | ----------------------------- |
| 与纸质个性化（Wonderbly 类）比，便宜 **5–7 倍**，且**立刻可读**（那边要等印刷与物流） | $29.99–39.99/本（≈ ¥210–280）                      | 【B】2026-10-19 抓官网        |
| 毛利：单本 **74–82%**、月订 **49–64%**、年订 **40–58%**（成本侧是实测的）             | C = 7–10 元/本，一本 20 页独读版 ¥5.8–11.6（实测） | 【A】`scripts/cost-model.mts` |
| **额度按本数、不按时间**：边际成本随本数线性长，给 10 本的档位毛利必然崩              | 每多一本就是 7–12 元                               | 【A】§3.2（毛利按实测成本算） |

★ 第三条是**成本结构逼出来的规则**，不是营销选择：所以"每月 2 本"这种看着保守的数字，
其实是一个**上界**。想加量只能先降价——降价那三条杠杆在 §3.3（其中第 2 条一行代码都不用改）。

**【决策】第一次售卖发生在机构/公益那一格，不在官网自助。** 这不是偏好，是被两张表挤出来的：

- 官网自助要**支付通道**（下单 / 回调 / 对账 / 退款台账），而今天**一件都没有**（§7.2 第 1 条）——
  它是一整套工程，不是"接一个 SDK"；【A】`find src/app/api -name route.ts` 里没有一条支付相关的路由。
- 机构那一格今天就能收一笔**对公转账**：一个班 30 个孩子按 ¥2000–3000/班/年（**【假设】**，
  没有与任何机构谈过，见 §4.3），成本 60 本 × 7–12 元 = ¥420–720。它**绕开了支付系统**，
  而它需要的东西是另外两件：**一个能开票的主体**（见 9.2）与**一个愿意买的机构**（今天：零）。
- 所以这条决策的准确读法是：**第一条真实收入最可能来自机构，而它到今天为止是零**。
  免费档（12 本样书，§5.3）不是渠道，是获客面——它不收钱，也不留联系方式。

**【决策】改价的条件**（写下来是为了让下一次改价有依据，而不是凭手感）：

| 触发条件                                         | 怎么改                                    | 依据             |
| ------------------------------------------------ | ----------------------------------------- | ---------------- |
| 视觉档换到便宜的那一档，C 掉到 **≤ ¥4**          | 单本可以下探 ¥29 并改走"走量"             | §3.3 第 2 条杠杆 |
| 「每次/页」从 2.0 压到 1.0（锚点回灌，约 20 行） | 月订毛利回到 64% 以上，年订可以加到 30 本 | §2.2 的 ¥1.8–5.3 |
| 印刷与物流**问过价**                             | 才谈纸质档（今天没有问过，所以不谈）      | §8 第 7 条       |

### 9.2 合规

`/privacy` 那一屏已经把**告知**与**删除**两件事落地了，可查、有读数。
这一节只说它**没有覆盖**的那一块，以及**资质**这一件绕不过去的事。

**已经有、且能自己验的**【A】：

| 做了的                                                                 | 在哪儿 / 怎么验                                                             |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 孩子的照片原图、家长的录音样本**没有落盘**                             | `pnpm check:family`：真跑那两条路，再满盘搜，两根"应该被找到"的对照针一起判 |
| 编故事时的逐字增量**不进日志**                                         | `pnpm test -- route-stream`                                                 |
| 资产按人分片，删除按位置报数                                           | `u/<userId>/` 分片 + `src/lib/child-deletion.ts` 的 `DeletionReceipt`       |
| 三个删除入口（孩子 / 书 / 音色），音色那个会向厂商解绑、失败照实说失败 | `/character`、`/shelf`、`/voice`，界面就在那儿                              |
| 一页给家长看的白话说明 + 一句"这个站是自己架的"                        | `/privacy`                                                                  |

**缺的，直说**：

- **同意这一环是空的**。今天"家长注册并自己上传照片"是**事实上的**同意，但它不是一份
  **可勾选、可留存、可打印**的同意书——没有勾选框、没有时间戳、没有那一页纸。【A：`/privacy` 里没有它，
  注册流程里也没有】
- **声音的授权是单独的一件事**：克隆的是**家长本人**的声音（不是孩子的），今天同样只有"注册即用"。
  ★ 它比照片那一件轻一档（那是成年人自己的声音），但**授权仍然该有一条明文**。【假设】
- **未成年人个人信息的"监护人单独同意"**：这一条按常识要写进材料，
  但 **具体法条与要件本轮没有核实**（这一轮没有联网核过原文）——**【未核到】**，
  要写进正式材料之前先查原文，别照记忆抄条款号。
- **没有自动过期**（不删就一直在）——`/privacy` 第四节原文就是这么写的。
- **资质**：今天这台站是"站长自己架的一台机器"，不是经营主体。To B 采购要**合同与发票**，
  这两样都要主体；**公益那一档也要**（基金会的钱进不来一个自然人账户）。**【A：仓库里没有任何主体信息】**

**怎么解**（按"今天能不能做"排，不排"愿景"）：

1. **产品里能补的那一环：同意。** 一句可留存的勾选（谁、什么时候、同意了哪几条），
   加一页可打印的说明。工作量小、判据清楚（**勾选记录查得出来**），
   而且它正好补上"告知—**同意**—删除"这条链里唯一缺的那一节。
2. **主体那一步是投入问题，不是工程问题。** 一个能开票的主体 + 域名与 HTTPS
   （README 里"域名与 HTTPS 是下一步"说的是同一件事）。**这一步不做，
   §9.1 那条"第一次售卖走机构"就只能停在设想上**——这一句必须写在这儿，
   否则 9.1 读起来像一条能立刻执行的路。
3. **资质的量法**：不是"我们合规吗"这种答不上来的问题，而是三个可勾的格子——
   能开票的主体 / 能收款的账户 / 一份写了留存期的用户协议。三个格子今天**都是空的**。

### 9.3 市场空间

**这一节的每个转化率都是拍的，写出来是为了让人一眼看见"哪些数是假设"。**
分母不是。

| 层      | 数字                                                                                             | 等级 / 说明                                                                       |
| ------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| 分母    | 0–14 岁 **253,383,938**（17.95%）；3–8 岁那一段普查**没有单列**，按年龄均匀分布粗推 **≈ 1.0 亿** | 【B】第七次全国人口普查，2021-05-11 发布；3–8 岁那一段是**【假设】**的推算        |
| **TAM** | 3–8 岁约 1.0 亿孩子，"一年得到一本个性化数字绘本"的比例 × ¥39/本                                 | 见下面那张敏感性表。**比例全是假设**                                              |
| **SAM** | 今天**真正能服务**的那一格：机构按班采购，¥2000–3000/班/年                                       | 【假设】；它比 TAM 小**两个数量级**，而它是**唯一今天就能收钱**的一格（对公转账） |
| **SOM** | **0**                                                                                            | 【A】零用户、零渠道、零主体。这不是悲观，是读数                                   |

**TAM 的敏感性**（不是单点估值——分母本身是粗推，单点估值的精度是假的）：

| 一年里付费的孩子占比 | 本数     | 金额（× ¥39）   |
| -------------------- | -------- | --------------- |
| **0.1%**             | 10 万本  | **¥390 万/年**  |
| **1%**               | 100 万本 | **¥3900 万/年** |
| **5%**               | 500 万本 | **¥1.95 亿/年** |

★ 这张表**故意不写成一个单点结论**：三行之间差 50 倍，而**没有任何数据能告诉你该看哪一行**
（§7.2 第 6 条：CAC / 留存 / 转化率一个数都没有）。所以正确的用法是反过来读——
**TAM 这一栏不该被引用为金额，只能被引用为"分母是谁"**。
单价那一头是硬的（¥39 是【决策】，成本是【A】），比例那一头是软的；
**软的一头乘上去，整句话都不硬。**

★ §7.2 第 6 条那句话在这里再说一遍，因为它是这一节的结论：
**上面所有毛利数字都是单位经济学，而单位经济学乘以零个用户仍然是零。**
今天这个项目有的是一台能跑的机器**和零个用户**。

### 9.4 时间的商业含义：12–174 分钟意味着什么

读数（**【A】**，§1.6）：一本的生成用时 **12.5 – 174.2 分钟**，出图那一步实测 ≈154 s/页，
时间几乎全花在"串行出图 + 核对 + 重画"上。★ 抖动不是"画得慢"，是撞在超时 / 网关排队 /
本机负载上（同一批里 174.2 分钟那本与 60.6 分钟那本只差 2 个节点），所以这一列
**只能当量级读，不能当 SLA**。

**三条商业含义**：

1. **它把产品从"实时工具"变成"下单—等待—收货"。**
   付费那一刻**不能要求用户在场**。界面上已经有画桌与阶段轨（【A】），
   但**"做好了告诉你"这一件今天完全没有**：没有邮件、没有站内信、没有推送——
   `User` 表里只有 `phone`（短账号那一档 `phone` 是 `null`），短信那条通道只用于**登录验证码**。
   【A：`grep` 全仓没有 `nodemailer` / `webpush` / 任何用户侧通知】
   ★ 所以"加个异步通知"这句话的真实成本不是"发一条短信"，而是**先有一个能到达用户的地址**，
   而且短信那条路还有 §5.4 那个**每日 300 条**的硬顶。
   今天用户拿到的"做好了"信号只有两个：自己回来刷新，或者 `/api/books/<书号>/events` 把这一轮重放一遍。
2. **等待的长度直接划出两档产品的分界。**
   12–20 分钟（页数少、不重画）用户能守着屏幕——那可以做成"下单即等"；
   1–3 小时（20 页 + 几次重画）**必须异步**，而且要异步得诚实：告诉用户去干别的，好了再回来。
   所以"单本让用户守着、年订必须异步"不是 UX 偏好，是**时间读数逼出来的结构**。
3. **它同时是护城河与天花板。**
   护城河：因为钱在生成那一刻就花完了，**读的时候零调用、零等待**——这条别人抄不走，
   它靠的是预生成（[ADR-0003](adr/0003-pregenerated-assets-decouple-demo-from-api.md)）与
   13 条 ADR 里那些取舍；天花板：一台机器一夜能跑的本数 = 并发 × 时长，是**有上限的**，
   所以规模化的第一步不是加用户，是加机器——而加机器的成本落在 §3.3 那三条杠杆上。

**这一条怎么反过来动优先级**（D-47 的修法里点名要说的那件事）：

| 受影响的              | 动法                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------- |
| **D-09 创作额度**     | **优先级上升**。一次跑错的生成要花 7–12 元、20 分钟到 3 小时——**没有额度就是没有任何刹车**  |
| **D-03 流断了的兜底** | **优先级上升**。等待 3 小时的会话里断线是常态，而"做好了"这个信号今天**只能靠用户自己回来** |
| 异步通知（若要做）    | 它排在**"有一个能到达用户的地址"**之后，而后者今天不存在（`User` 表里没有 email）           |
