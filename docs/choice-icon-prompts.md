# 选择点那 20 枚小图标 —— 出图提示词与验收记录

> 用途：共读版选择点的两颗按钮。阅读器里图在按钮左端那一格 `.book-choice__icon`
> ——**56px 见方**（`src/components/book/storybook-flip.css`），缺图时同一格退化成 26px 的
> `.book-choice__glyph`（emoji）。
> ★ **闸门那一屏不出图**：`StorySheet` 的 `.ss__glyph`（34px）摆的是 emoji 预览——
> 家长在那一屏改的是"这个词配哪个 key"，图标本身要到孩子读的时候才出现。
> 产物：`public/book/choice-{key}.webp`，**盘上现在只有两枚**（`dino` / `ship`），其余 18 枚按本文出。
> 转换脚本：[`scripts/make-webp.py`](../scripts/make-webp.py) `--preset book-icon`
> （1:1 / 192px / ≤15KB / **不留 alpha**）。
> 词表与中文名的唯一出处：`src/lib/engine/domain.ts` 的 `CHOICE_ICONS` / `CHOICE_ICON_LABELS`；
> 地址的唯一出处：`src/lib/choice-icons.ts` 的 `iconUrlOf(key)`。**三处不许各写一份。**
> 关联：工单 [`.scratch/w3-shared-reading/issues/02-choice-icons.md`](../.scratch/w3-shared-reading/issues/02-choice-icons.md)、
> [`docs/demo-book-art-prompts.md`](demo-book-art-prompts.md) §四 **P7**（盘上那两枚就是那一条出的，
> 本文是它的续批，不是重做）。

---

## 一、★ 这一批 20 枚**必须都是"一朵云"**

这一条是本文最要紧的判断，先说清楚，因为**每一张的提示词都从它长出来**。

盘上已有的两枚（`choice-dino` / `choice-ship`）不是"一只恐龙""一艘船"，
是**一朵云的轮廓长得像恐龙 / 像帆船**——那是首页第二屏那本演示书的题目
（「草地上的想象」，P7 的原文：「它仍然是云，不是真恐龙（真船）」）。
另外 18 枚跟着它走，理由三条：

1. **必须跟**：这三颗按钮**永远成对出现**（A 一枚、B 一枚，并排在一行里）。
   如果 A 是云、B 是写实水彩实物，孩子看到的是**两种东西**，不是两个选项。
   工单的边界写着"不重出首页那两枚"（那本演示书一行不动），所以**方向只能由它们定**。
2. **认得出来**：云家族有一件 emoji 没有的东西——**轮廓**。emoji 是扁平色块，
   而 56px 上真正读得出来的是剪影。`choice-dino` 在 56px 上仍然是一只长脖子，
   正是因为它只靠轮廓说话（这也解释了为什么下面每条都要写"只保留认出来所需的三处轮廓"）。
3. **一句话说得清这一套是什么**：`cloud` 就在词表里（第 11 个）——它是这个家族的**本形**，
   其余 19 枚是它的变体。词表因此不是"20 张无关的小图"，是**一个题目下的 20 句话**。

**代价，写下来**：有几枚的剪影天生弱（`door` / `lamp` / `drum` / `cake`），
云做出来的形状不如实物直白。处置不是"这几枚改成实物"（那会破第 1 条），
而是**每一枚都点名"认出来靠哪三处"**，并且按 P7 那条终审：**缩到 64px 还认得出**。
认不出的那一枚就重出，不许"看着还行"放过——它是家长改选项时唯一看得见的东西。

## 二、这批图要同时满足的五条约束

前四条来自已经定稿的实现，不是审美偏好：

| 约束                                   | 来源                                                                  | 对提示词的要求                                                                                                                                                          |
| -------------------------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **显示只有 56px 见方**                 | `.book-choice__icon` 的 56×56（`storybook-flip.css`）                 | 只保留认出来所需的**三处轮廓**；五官、鳞片、木纹这些在 56px 上全是噪点，一律不要                                                                                        |
| **与盘上那两枚是一套**                 | 它们并排在同一行，而且**永远成对**                                    | 每张都带 `choice-dino.webp` 作参考图（**只借笔与天色，不借形状**）；【风格】段逐字不改                                                                                  |
| **它是一枚 UI 图，不是书里的一页**     | 按钮里还有 `label` 与 `spoken` 两道通道，图标只负责"一眼分组"         | 不画场景、不画人物、不画故事；**一枚一个物件**，居中                                                                                                                    |
| **天不是白的，云也不是靠颜色分出来的** | 从盘上那两枚量出来的数（见 §四）：四角是 (251,231,224)～(252,253,241) | 背景写死是**同一套浅底暖光天色**；负面清单里禁纯白底、禁白边                                                                                                            |
| **20 枚里每一枚都能当任一侧的选项**    | 工单的三条口径之一                                                    | 不画方向（箭头、上/下、左/右）。侧向的物件一律**朝右**（与盘上恐龙云的头向一致）——★ 这条与"不要方向词"**不是**同一件事：那条说的是 `key` 的名字里不许出现 `left` / `up` |

★ "朝右"这条要留一句：它**不是**在表达"右边更好"。图标是**物件不是角色**，
不要求两颗互相看；统一朝向只是为了"一半朝左一半朝右看着像两套"。

## 三、通用骨架（每张都用这一段）

复制这一段，把【参考图】与【主体】两段换成 §五 对应那一条，就是一张完整的提示词。

```
儿童绘本里的一枚小图标插画：一朵云的方形小画。一张完整画面
（不是拼贴、不是多格分镜、不是书的样机、不是 UI 图标、不是贴纸、不是徽章）。

【参考图】
附上 public/book/choice-dino.webp。★ 只借它的**笔触、天色与收形线**，不借它的形状：
这一张要像的是「⟨形状⟩」，不是恐龙。
必须与它一致：云的白色与絮状边缘的画法、天空从上到下极淡的那一层过渡、
细彩铅收形线的粗细与深浅、整张的明度（很高调、几乎没有重色）。

【主体】
画面正中一朵云，轮廓像⟨形状⟩。
它仍然是一朵云，不是⟨真的东西⟩：边缘有絮状的消散，身体里有水汽的半透明感。
★ 只保留认出来所需的这三处轮廓：⟨要点一⟩、⟨要点二⟩、⟨要点三⟩。
不许出现⟨这类物件上最容易被模型补出来的真实细节⟩。

【构图 · 图标专用】
- 云居中，占画面宽度约 70%，视觉重心在画面正中 ±4%。
- 云的外缘离画面四边各留约 12% 的天空，但天空要**画满到最外一个像素**。
- 背景是浅底暖光的粉彩天空，与参考图同一套天色：上缘极淡的粉、往下极淡的奶白，
  底缘偏右一小团暖金。**不要纯白底、不要渐变到白、不要白边、不要画框、不要色板底板。**
- ★ 只画这一朵云：不要小孩、不要大人、不要手、不要草地、不要别的云、不要第二件东西。
  它最终只有 56 像素见方，多一样东西就成一团噪音。
- 统一光源来自左上方，云的右下方略暗。

【风格】
温暖的手绘绘本风：水彩铺色打底 + 细彩铅轮廓线收形，可见纸质纹理，笔触松弛但不潦草。
高明度、低饱和的粉彩色板，只用一个暖色重音（天空底缘那一团极淡的暖金）。
阴影柔和无硬边。统一光源来自左上方，色温暖白。
与首页那两枚选择点图标是同一位画师、同一套颜料、同一次绘制。

【文字】
画面内不出现任何文字、字母、数字、签名或水印。

【输出】
正方形，1:1（1024×1024）。

【负面】
不要任何文字/字母/数字/水印/签名；不要品牌 Logo、卡通 IP 角色、商标或商品包装；
不要恐怖、阴森、暴力、受伤、哭泣、争吵、或被冷落孤单的形象；
不要深色压抑、赛博朋克、霓虹或高饱和撞色；不要杂乱堆砌的背景细节；
不要多格分镜、拼贴、样机、画框或阴影底板；不要强透视导致的形变。
★ 不要把云画成写实的⟨东西⟩：不许出现鳞片、眼睛、牙齿、木纹、铆钉、缆绳、
  金属反光、塑料光泽、橡胶质感——质地必须仍然是云，只有**轮廓**是那个东西。
不要给云加五官（眼睛、鼻子、嘴、睫毛、腮红）。这批图标靠轮廓读，不靠脸。
不要纯白背景、不要白边、不要把云摆在一张白纸、卡片或托盘上。
不要第二个物件、不要场景、不要人物、不要手。
—— 以下是这一批与共用清单**故意相反**的两条 ——
主体**必须居中**：「不得落在画面水平 46%–54%」那条是给书脊留的，图标没有书脊穿过。
「每一页都要留一个真实线索（野餐垫、小狗、草坡）」**不适用**：这里只画一朵云。
```

★ **【风格】那一段里括号内的暖色重音，是从 P7 那句改来的**，这是本文唯一改动共用锚点的地方：
P7 / 跨页那批写的是「正午阳光落在草地上的暖金，与野餐垫上那一小块砖红格纹」——
那两样东西在图标里**一件都不在**（图标没有草地、没有野餐垫）。照抄的后果是模型真的往
云底下画一块格纹毯子。这一改不算破"风格段一字不改"那条纪律：改的是**暖色重音是什么**，
不是笔、颜料、明度与光源——那四样一个字没动。

★ **【负面】里那两条"故意相反"**是从 P7 那张表抄下来的，理由也一样：
每写一条"不要 X"，就得同时写"要是 Y"，否则模型会自己挑一个折中方案。

## 四、从盘上那两枚读出来的数（★ 出图前先看）

```bash
python -I -c "
from PIL import Image
for f in ['public/book/choice-dino.webp','public/book/choice-ship.webp']:
    im = Image.open(f).convert('RGB'); w, h = im.size
    px = list(im.getdata()); lum = [(r+g+b)//3 for r,g,b in px]
    dark = [p for p,l in zip(px,lum) if l < 200]
    mid = im.crop((w//4, h//4, w*3//4, h*3//4)); cpx = list(mid.getdata())
    mean = lambda q: tuple(sum(c[i] for c in q)//len(q) for i in range(3))
    print(f, im.size, len(open(f,'rb').read()), 'B 四角',
          [im.getpixel(p) for p in [(2,2),(w-3,2),(2,h-3),(w-3,h-3)]],
          '中心均色', mean(cpx), '全图均色', mean(px), '最暗', min(lum),
          '暗于200', '%.2f%%' % (100*len(dark)/len(lum)), '暗像素均色', mean(dark))
"
```

2026-10-18 量到的（就是上面这段跑出来的）：

| 文件               | 体积    | 尺寸    | 四角（左上 → 右下）                                           | 中心均色      | 全图均色      | 暗于 200 的像素 | 那条收形线             |
| ------------------ | ------- | ------- | ------------------------------------------------------------- | ------------- | ------------- | --------------- | ---------------------- |
| `choice-dino.webp` | 1,254 B | 192×192 | (251,231,224) / (252,233,221) / (250,250,236) / (252,253,241) | (242,234,220) | (249,238,225) | 1.12%           | 均色 **(189,191,186)** |
| `choice-ship.webp` | 1,394 B | 192×192 | (249,236,234) / (254,237,229) / (252,253,243) / (250,252,244) | (241,240,232) | (249,242,231) | 0.54%           | 均色 **(191,191,184)** |

三条结论，每一条都直接变成了提示词里的一句话：

1. **天不是白的，而且上暖下更亮**：左上角偏粉（R−B ≈ 27），下缘近奶白。
   所以骨架里写的是"上缘极淡的粉、往下极淡的奶白"——这是量出来的，不是形容出来的。
2. **云与天的色差很小**（中心均色 242,234,220 对四角 251,231,224），
   真正把云读出来的是**那条中性灰细线**（均色 ≈ 190，占 0.5%–1.1% 的像素）。
   ★ 于是有一条硬要求：**收形线不许省**。"靠明暗对比让云浮出来"在这里是不成立的——
   天本身就接近白，没有那条线就是一坨白。
3. **整张是高调、几乎没有重色**（最暗 137 / 153，暗像素不到 1.2%）。
   所以负面清单里禁金属反光、塑料光泽、橡胶质感——**不是怕不好看，是这一档里放不下重色**：
   一枚 56px 的图标把最暗的一档用在轮胎上，云的轮廓就再也读不出来了。

★ 顺带一个数：**1.25 KB / 1.39 KB，离 15KB 的上限还差一个数量级**。
15KB 是**预算不是目标**——出图时不要为"用满额度"加细节。这一档真正的上限是
"缩到 64px 还认得出"，比字节数紧得多。

## 五、20 张的形状要点

顺序与 `CHOICE_ICONS` 一字不差。每张给出要替换进骨架的那两段（【参考图】/【主体】）。
★ **加粗的那一句是这一张单独要盯的地方**——模型最容易在这里出错。

★ 出图时把 `public/book/choice-dino.webp`（或 `choice-ship.webp`）一起作为参考图传进去。

---

### 1. 恐龙 → `dino.webp` —— **已有，不重出**

盘上那一枚就是它（P7 出的，见 [`demo-book-art-prompts.md`](demo-book-art-prompts.md) §四 P7）。
**这一张一行都不要动**：首页第二屏那本演示书直接引用 `/book/choice-dino.webp`。

---

### 2. 帆船 → `ship.webp` —— **已有，不重出**

同上。★ 落盘那一批的源目录里**不要**放 `choice-dino` / `choice-ship`，
否则 `--match 'choice-*'` 会把这两枚覆盖掉（见 §八）。

### 3. 火箭 → `rocket.webp`

**【参考图】** 同骨架。

**【主体】**
画面正中一朵云，轮廓像一枚**竖着朝上的小火箭**：尖头朝正上方、机身是瘦长的圆角柱、
底部两侧各一片对称的尾翼。
它仍然是一朵云，不是真的火箭：边缘有絮状的消散，身体里有水汽的半透明感。
★ 只保留认出来所需的这三处轮廓：**朝上的尖头、瘦长的身、底部两片尾翼**。
★ 尾焰不画火：**底部往下拖出一小撮被风吹散的云絮**（它是这朵云的一部分，同一种白）。
不许出现铆钉、舱窗、金属反光、喷口、编号与任何文字。

★ **最容易翻车**：模型会把它画成金属火箭 + 橙色火焰。看到火焰、铆钉、舷窗就重出——
这一枚里**没有一处重色**。

---

### 4. 小鸟 → `bird.webp`

**【参考图】** 同骨架。

**【主体】**
画面正中一朵云，轮廓像一只**侧身朝右的小鸟**：圆圆的头、一个短而尖的喙、
一只向上张开的小翅膀、身后三片短尾羽。
它仍然是一朵云，不是真的鸟：边缘有絮状的消散，身体里有水汽的半透明感。
★ 只保留认出来所需的这三处轮廓：**尖喙、张开的翅膀、翘起的尾羽**。
★ **不画眼睛、不画爪子、不画羽毛的层次**——56px 上眼睛只是一个黑点，会把它读成"怪物"。
不许出现羽毛纹路、鸟爪、树枝。

★ **最容易翻车**：模型会忍不住补一只眼睛。这一枚靠喙与翅膀读，**靠眼睛读是错的方向**。

---

### 5. 小猫 → `cat.webp`

**【参考图】** 同骨架。

**【主体】**
画面正中一朵云，轮廓像一只**正面坐着的猫**：头顶两只尖耳朵、两侧各两根本须、
身后一条向上卷起的尾巴。
它仍然是一朵云，不是真的猫：边缘有絮状的消散，身体里有水汽的半透明感。
★ 只保留认出来所需的这三处轮廓：**两只尖耳朵、四根胡须、卷起的尾巴**。
★ **不画脸**（没有眼睛、鼻子、嘴、腮红）；不画爪子、项圈、铃铛。

★ **最容易翻车**：胡须与耳朵是它唯一的身分证明，模型却最爱先画一张可爱的猫脸。
★ 胡须**不要画成黑色**：用与收形线同一种中性灰，四根就够，再多在 56px 上就是一团毛。

### 6. 小鱼 → `fish.webp`

**【参考图】** 同骨架。

**【主体】**
画面正中一朵云，轮廓像一条**侧身朝右的小鱼**：纺锤形的身、身后一片分叉的尾鳍、
背上竖起一片小背鳍。
它仍然是一朵云，不是真的鱼：边缘有絮状的消散，身体里有水汽的半透明感。
★ 只保留认出来所需的这三处轮廓：**分叉的尾鳍、背鳍、朝右的圆头**。
不许出现鳞片、眼睛、鱼鳃线、水泡、水草。

★ **最容易翻车**：模型会画出一片片鳞。这一枚的判据是"尾鳍分不分叉"——
分叉读得出鱼，不分叉就只是一团云。

### 7. 月亮 → `moon.webp`

**【参考图】** 同骨架。

**【主体】**
画面正中一朵云，轮廓像一弯**朝左上开口的月牙**（云的右侧被"啃"掉一口，缺口圆润）。
它仍然是一朵云，不是真的月亮：边缘有絮状的消散，身体里有水汽的半透明感。
★ 只保留认出来所需的这两处轮廓：**那个圆润的缺口、两头收尖的月牙身**。
不许画满月、不许画脸、不许画星星、不许画夜空与深蓝底色。

★ **最容易翻车**：一是不敢啃那个口（出来是个圆团，读成"云"不读成"月亮"）；
二是顺手画成"月亮上睡着的小人"。**这一枚只有那个缺口在说话。**

### 8. 星星 → `star.webp`

**【参考图】** 同骨架。

**【主体】**
画面正中一朵云，轮廓像一颗**五只角的星星**：五个角朝外，角与角之间的凹口是**圆润**的弧，

## 八、落地：缩档与命名

源图（正方形 PNG/JPG，按 `choice-{key}` 命名）先落到一个目录，比如 `~/icons-src/`：

```bash
python -I scripts/make-webp.py ~/icons-src public/book --preset book-icon --match 'choice-*'
```

| 项     | 值                                                                                                                                      |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| 文件名 | `public/book/choice-{rocket,bird,cat,fish,moon,star,tree,house,cloud,door,bridge,lamp,flower,car,kite,balloon,cake,drum}.webp`（18 枚） |
| 预设   | `book-icon`：1:1 / 目标宽 192 / 单张上限 15 KB（**上限是预算**）                                                                        |
| 实测   | 盘上那两枚 **1,254 B / 1,394 B**（§四）——离上限一个数量级，所以"用满额度"不是目标                                                       |
| 比例   | 源图就是 1:1，预设也是 1:1，这一步**不裁**（与跨页那档同一条：恒等变换）                                                                |
| 格式   | WebP **lossy**（`VP8 `），不留 alpha                                                                                                    |
| 接入   | `iconUrlOf(key)`——文件名只由 key 决定，与 `artPath()` / `figurePath()` 同一条约定                                                       |

★ **跑之前先记录那两枚的时间戳**，跑完确认它们没被覆盖：

```bash
ls -la --time-style=+%F_%T public/book/choice-dino.webp public/book/choice-ship.webp
```

`--match 'choice-*'` 会把源目录里所有 `choice-` 开头的都收进来，
所以**源目录里不要放 `choice-dino` / `choice-ship`**——那两枚是首页那本演示书的，
覆盖掉它们等于把那本书里的两朵云换成两朵别的云（`demoBook.ts` 直接引用它们的地址）。

★ 不走 `/api/assets?w=`：静态 `public/` 走不到那条通路（Next 直接发盘上的字节，
查询串它看不懂，挂 `?w=` 会静悄悄回原图）——与立绘那批同一条，所以预生成。

## 九、验收

工单那三条 + 这一批加的两条。**下面这张表每一格都要出完图量了才填**，
量不到的写"没测"，不许预填：

| #   | 判据                                                               | 怎么量                                                                                 | 结果                                                                                  |
| --- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 1   | 每枚 ≤15KB、192×192、`RGB`（不留 alpha）                           | `python -I -c` 读 RIFF 头 + VP8 帧头（§四那段脚本就是）                                | **过**：新落盘 13 枚 882–1,788 B（合计 15,676 B）                                     |
| 2   | ★ **图没到位时露 emoji，不留裂图**：用一个词表外的 key 实测一遍    | 把 `.out/fake-llm.mjs` 的 `iconA` 改成一个不存在的词（如 `'dragon-back'`）跑一遍，截图 | **过**：13/13 判据，两道闸门都真跑过（下文）                                          |
| 3   | 20 枚并排**是一套**（同一支笔、同一套天色、同一个白）              | 缩到 64px 排成一行，与 `choice-dino` / `choice-ship` 并排；看不出"两批"才算过          | **不过，且已定不改**：盘上 15 枚是一套；另 5 枚 2026-10-19 决定不重出（§十 废弃批次） |
| 4   | 每一枚**缩到 64px 还认得出**（P7 那条终审）                        | 逐张缩到 64px 打印或放大看；§五 那些"数一数"的判据在源图上过一遍                       | **13 过 / 5 不落盘**（量的是 56px，比 64 更严）                                       |
| 5   | 每一枚都能当**任一侧**的选项（没有方向词、没有"只能放左边"的形状） | 与 `CHOICE_ICONS` 对照：20 个 key 里没有一个含 `left` / `right` / `up` / `down` 语义   | **过**：20 个 key 全是名词                                                            |

★ 第 2 条是工单里那条"兜底是退路，不是死代码"的实测。它的机制在
`src/lib/choice-icons.ts` 的文件头：`iconUrlOf` 对词表外的 key 回 `null`，
界面上那一格就只剩 emoji；而 `alt=""` 的 `<img>` 在 404 时什么都不画，所以不会留碎图标。
**两条都必须成立**：回 null 那条有测试，404 那条要真跑一遍才算。

### 9.1 第 2 条是怎么跑的（★ 比原定的"跑一遍截个图"强，理由在下面）

原定做法是改 `.out/fake-llm.mjs` 的 `iconA` 跑一遍、看截图。**截图证明不了是哪一层在画**：
emoji 与 404 的 `<img>` 占的是同一格，一张照片上看不出那点淡影是图画的还是 emoji 的。所以换成
`.out/chk-choice-icon-fallback.mjs`：隔离 dev server（3311 + `.next-session`）+ headless Chrome
直连 CDP，翻到选择点那一屏，对**同一格**连拍四张相减——
`A`（都在）/ `A2`（同状态再拍，取噪声底）/ `B`（把 `<img>` 移出树）/ `C`（把 emoji 藏掉）。
差值就是"这一层到底往屏幕上放了什么"。**连跑两遍都是 13 / 13 过，噪声底两次都是 0 像素。**

| 这一格是哪种情况                           | 实测                                                                                            |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| 词表内 + 盘上有图（`dino`，对照）          | `naturalWidth` 192；图的墨 **21,817 px / 均 27.83**；图在时藏 emoji 差 **0**（盖住了）          |
| 词表外（`not-in-the-list`）                | 连 `<img>` 都不出现（`src === null`），emoji 的墨 2,712 px / 均 14.77                           |
| ★ 词表内 + **盘上没文件**（`kite`，闸门②） | `<img>` 真出现、地址 `choice-kite.webp`、网络上真 **404**；它交给屏幕的是 **3,126 px / 均 6.0** |
| 红对照① 同一格只把 `alt` 改成一句话        | Chrome 当场补替代文字：**6,216 px / 均 31.55**，横跨 86% × 79%                                  |
| 红对照② 同一格给它一层底色                 | **26,582 px / 均 170.2**，铺满整格                                                              |

三条读法：**① `alt=""` 是真在干活的**——不写它，`<img>` 一 404 就会自己长出一行替代文字，
比 emoji 还显眼；**② 判据落在量级上，不落在"是不是 0"上**：404 那点差异是抗锯齿级的抖动
（均 6.0）对真图的 27.83、底色的 170.2，各差一个档；早先写成"恰好 0 像素"时它跑出过一次
3,126 px，**同一条判据两次读数不一致，那判据本身就不合格**；**③ 量具自己先被证会红**——
两条红对照都是"把被测对象按坏的样子摆回去"，读数当场跳了两三个档。

★ 顺带排除一层：`.book-choice__art` 上挂着 `filter`，怀疑那点淡影是合成层造出来的。
红对照③（把 `filter` 关掉）读数**一模一样**（3,226 px / 均 6.81 → 3,226 px / 均 6.81），
所以不是它。**这是排除法的结论，不是"filter 没问题"的结论。**

### 9.2 第 3、4 条：量在哪一档上，以及为什么 5 枚没过

### 9.4 第 5 条：三枚带固有朝向，但没有一枚是箭头

20 个 key 全是名词，没有一个含 `left` / `right` / `up` / `down`。诚实补一笔：

（§五 要的"朝右的车头 / 朝右的圆头"）。它们是"这东西本来朝哪边"，不是"读者该往哪边"；
20 枚里没有一枚是箭头，也没有一枚把选项方位画进了图里。**所以这一条过，但那三枚的朝向
要在下一次重出时保持原样**——把它们转个方向就等于改了 §五 的专属判据。

★ 另记一条**代码注释与事实不符**（这一批留下的，没有改，先记着）：
`src/lib/choice-icons.ts` 里 `iconUrlOf` 的注释写着"不回一个指向 404 的地址"、
