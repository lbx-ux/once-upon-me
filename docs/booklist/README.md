# 灵感书单 · 12 本样书 —— 出图与配音总纲

> 用途：工作台侧栏「灵感书单」里那 12 本只读样书（`/booklist`，代码在  
> `src/components/booklist/`）。**一本一个主题**，与首页环上那 12 张封面  
> （`docs/cover-art-prompts.md`）一一对应。  
> 产物：`public/booklist/{key}/` 下的 9 张图 + 8 段音频，每本一个目录。
>
> 风格库模板：**`illustration-art-style`**（与首屏 12 张封面、首页演示书同一模板，  
> 风格连续）。封面构图参考 **`poster-layout-system`**，但**不在图里放字**（理由见  
> [`cover-art-prompts.md`](cover-art-prompts.md) §七）。

## 一、一本样书的形状（8 个跨页 = 16 个书页）

```
翻开一屏 = 1 张 3:2 的连续画面（横跨左右两个书页）+ 正文叠在左页下角
                  ┌───────────┬───────────┐
                  │  正文叠在   │           │
                  │  左页下角   │  画面延续  │
                  └───────────┴───────────┘
                   第 1 页      第 2 页
```

| 项   | 数量 | 说明                                                                       |
| ---- | ---- | -------------------------------------------------------------------------- |
| 封面 | 1    | 3:4 竖版，与书页同比例，落进去不裁                                         |
| 跨页 | 8    | 3:2 横版，**一张图横跨两个书页**，半页不切文件                             |
| 书页 | 16   | 8 跨页 × 2。界面上的页码读作"第 3–4 页 · 共 16 页"                         |
| 配音 | 8    | **一张图一段**，与图同名（`p3.webp` ↔ `p3.m4a`／`p3.mp3`），封面封底不配音 |

★ **一跨页只有一张图**。"一张图跨两个书页"与"一页一张图"不是一回事：前者翻开是  
一幅连续的画面（首页那本《小宇的云》就是这个形状），后者翻开会看到两张并排的画。  
这 12 本一律是前者 —— 出图时**不要**把一页画成左右两格。

★ **半页不切文件**：前端把同一张 3:2 的图挂两次，靠 `background-size: 200% 100%` 各取一半  
（`src/components/book/flip.ts` 顶部那段叶模型）。所以磁盘上第 3 个跨页就只有 `p3.webp`  
一个文件。

## 二、共用骨架（每一张都逐字带上）

### 2.1 风格段（一个字都不要改）

```
温暖的手绘绘本风：水彩铺色打底 + 细彩铅轮廓线收形，可见纸质纹理，笔触松弛但不潦草。
高明度、低饱和的粉彩色板，每张只用一个暖色重音。阴影柔和无硬边。
统一光源来自左上方，色温暖白。
与同一系列已完成的 12 张绘本封面、以及首页那本演示绘本是同一位画师、同一套颜料、同一次绘制。
```

### 2.2 负面清单

```
不要任何文字/字母/数字/水印/签名；不要品牌 Logo、卡通 IP 角色、商标或商品包装；
不要恐怖、阴森、暴力、受伤、哭泣、争吵、或被冷落孤单的形象；
不要危险动作（明火、高处无防护、深水涉水、无成年人看护的独处险境）；
不要写实到失真的人脸；不要深色压抑、赛博朋克、霓虹或高饱和撞色；
不要杂乱堆砌的背景细节；不要多格分镜、拼贴、样机、画框或阴影底板；
不要强透视导致的形变。
—— 以下为这套样书共用 ——
不要把画面画成"一本打开的书"的样子：不要书脊、纸张边缘、桌面、底板、投影背景板，只要插画本身。
不要出现真实世界的品牌物件、屏幕、手机、玩具广告或商品包装。
不要第二个孩子（除本书设定里写明的那一位），也不要成人的手或身体入画。
```

### 2.3 三条"画完就救不回来"的硬约束

这三条与首页那批同源（血泪账记在 [`demo-book-art-prompts.md`](demo-book-art-prompts.md) §一），  
**每一条提示词的【构图】里都要逐字带上**，负面清单里也要再写一次：

```
★ 画面必须铺满整张画布，四边出血：不得出现白边、纸边、画框、装裱、留白或渐隐到白。
  天空（背景）一直画到最外缘的每一个像素，边缘处的颜色与纹理要有水彩颗粒，不许平涂留白。
  "安全边距"只指重要内容离画面边缘保持距离，**不是在边缘留空白**——边缘要画满景物。
★ 整幅是一张**连续**的画面：画面中央（水平 50% 处）不得出现任何竖向接缝、折痕、装订沟、
  分格线或纸张边缘；左右两半必须能无缝拼在一起，不许出现"两张图并排"那种颜色与明暗突变。
  书脊是成品书加上的，不是画面里画出来的。
★ 主体（孩子的脸与身体主干）不得落在画面水平 46%–54% 这条带上——那是书脊会穿过的地方。
  每一条提示词都要写死主体的水平位置。这是全套里唯一一条**画完就救不回来**的约束：
  裁切、压缩、前端都改不了它。
```

### 2.4 第三条怎么验（出图之后、收进 `public/` 之前）

这句话**肉眼看整张跨页是估不准的**，把中央带裁出来拼一张图也不行——  
8 条带子平摊不到 700px 宽，一条只有约 78px，脸上的东西根本分辨不出。改用能算的量，三项一起看：

| 量                     | 怎么算                                                                                                                  | 判过                                                                  |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| **头发**（脸的代理）   | 列方向 100px 滑窗，数 `V<90 且饱和<0.35` 的像素（乌黑的头发；细彩铅轮廓线比它浅、比它灰）。比中缝那一窗与画面最密那一窗 | 中缝/最密 **< 0.35**（首本实测 0.00–0.02）                            |
| **外套**（身体的代理） | 同一个滑窗，数色相 5–45°、饱和 ≥0.43、V ≥150 的像素。最密那一窗的中心，就是孩子在画面里的水平位置                       | 中心落在提示词写死的那个百分比附近（首本七张 25.8%–38.3%；★ p6 见下） |
| **中缝带的强橙**       | 只看饱和 ≥0.65、色相 8–40°（**外套布那种橙**），按 2% 一格数水平分布                                                    | 中缝那几格**没有成片**（首本 ≤1,129px、≤带宽 0.9%）                   |

★ 记一个坑：**暖色不等于外套**。龙颈上那层阳光、以及褐色的落叶层，色相与外套是重叠的。  
把两类分开靠**饱和度**——首本实测外套命中像素的中位色约 (215,135,55)、饱和 0.75，  
而中缝带里的暖色约 (180,147,90)、饱和 0.50，是阳光打在苔绿与落叶上的颜色。  
所以"中缝上有暖色"本身**不是**违规：龙的身体与脖子跨过中缝正是提示词**要求**的  
（P3「中央只许穿过脖子」、P4「它的身体横跨中央」、P6 连续长弧跨过中央）。  
违规的是**成片的孩子**——饱和的那一类，加上她头顶那团黑。

★ **但这个"靠饱和度分开"的办法不够，别当成定论**（2026-10-16 补）：入库脚本在 dino p6 上  
给出外套窗中心 **48.4%**（落在书脊带里），把阈值从饱和 0.43 一路提到 0.75 都还在 48%。  
裁图放大才看清楚：**孩子的小橙外套确实在约 28–30%**（与提示词一致），  
中央那一大团是**长颈龙的脖子与腹甲**——龙身在那张图里的橙比外套更饱和，饱和这一维分不开它。  
两条更能说明问题的旁证：① 同一页的头发代理是 0.20（<0.35），孩子那团黑也不在中缝；  
② p6 的外套命中像素只有 2,983，是别页（4.2k–4.8k）的七折——**代理在这一张上证据本来就薄**。  
所以规矩是：**代理只是筛子，落在带里或像素数明显偏少的那几张要裁图看**。  
"数字说它在带里"和"它真的在带里"是两件事，p6 是前者不是后者。

> 这三行是**可复现的**：上表里的量都在入库脚本 `scripts/check-booklist-art.py` 里  
> （`--subject-hair` 量头发、`--subject-coat` 量外套那一窗的中心与"中缝带强橙"那一栏，  
> 阈值与判定原文写在脚本头部与 §2.5）。换一本重跑同一条命令即可，不要另写一个一次性的。

```bash
python -I scripts/check-booklist-art.py public/booklist/dino --subject-hair --subject-coat
```

### 2.5 第一条与第二条怎么验（★ 一条 1px 的折痕曾经从判据里漏过去）

§2.4 那三项是**第三条**（主体别压中缝）。第一条（四边出血）与第二条（中央不得有接缝/折痕）  
也是纯几何，同一条命令一起量，判据写在脚本头部：

```
python -I scripts/check-booklist-art.py public/booklist/{key}
```

**第一条**：外缘 8% 里三通道都 ≥250 的纯白比例、≥235 的近白比例——四边都得是 `0.0`。  
这一条救不回来（裁掉就少一块画面），所以出图后第一眼就看它。

**第二条**：这一条**走过一次弯路，值得记下来**。

最早的判据是「中缝带内/带外的**列差滑窗峰值**比」（就是现在那一栏 `③`，阈值 1.8×）。  
它在恐龙那本上给出 0.29×–1.26×，于是我当时判了"② 通过"。**这个判断是错的**：  
滑窗宽 100px，而折痕只有 **1–2px 宽**，一条 33 级的台阶摊进 100 列只剩 0.33 的贡献，  
被窗口里任何一片柔和的物体边淹没。**窗口把尖峰稀释掉了**——量的是"中缝带里有没有成片的  
色块变化"，不是"中缝上有没有一条线"。所以 `③` 这一栏现在只在脚本里留作旁证，  
判 ② 要靠下面这个量。

现在的量法换成**减掉趋势**：左右各取 4 列做锚点、中间线性插值成一条"这一行本该有的亮度"，  
再看中央 ±3 列里最偏的那一列**偏离这条趋势线多少级**，并要求**逐行同号**：

| 判据                 | 值                                                                  |
| -------------------- | ------------------------------------------------------------------- |
| 偏离量级             | **≥ 8 级**（一张图的整幅噪声在 0.3–4.2 级，见下）                   |
| 贯穿度               | 同号行 **≥ 90%**（一条线是"整列都偏"，物体边与光照是"符号互抵"）    |
| 是不是本图最陡的一处 | 同一量在别处 20 个位置量一遍，中央必须**排第 1 且超过控制位最大值** |

三项都满足才算折痕。**16 张已交付的跨页实测分得很开**：

| 类别          | 偏离                          | 同号    | 名次      | 相对控制位均值 |
| ------------- | ----------------------------- | ------- | --------- | -------------- |
| 有折痕的 6 张 | −24.5 … −32.8 / +12.4 … +19.0 | 89–100% | 1 / 16    | 7.7 – 12.4×    |
| 干净的那些    | 0.6 … 4.2                     | 48–60%  | 4–17 / 16 | 0.2 – 1.8×     |

两边之间是 4.2 与 12.4 之间一个**六倍的空档**，不需要凭感觉定阈值。  
位置清一色落在**水平 50.0%–50.1%**、宽度 1–3 列——正是"书脊会被折到这里"的地方。

★ **还有一类要单独判：半条线。** 月亮那本 p2 偏离 −10.09 级（够 8 级）、名次也第 1，  
但只有 **70%** 的行同号。这时看**少数符号的行是否成段**：

| 页           | 偏离   |         | 偏离               | ≤4 的行 | 少数符号行数 / 段数 |
| ------------ | ------ | ------- | ------------------ | ------- | ------------------- |
| dino p1      | −29.13 | 3%      | 6 行 / 4 段        |
| dino p2      | −32.80 | 0%      | 0 行               |
| dino p3      | −31.96 | 2%      | 7 行 / 3 段        |
| moon p6      | +18.98 | 3%      | 3 行 / 3 段        |
| **moon p2**  | −10.09 | **37%** | **113 行 / 60 段** |
| **paint p8** | −15.30 | **50%** | **95 行 / 27 段**  |

折痕被前景物体遮住的那几行是**成段**的（每段几行到几十行）；moon p2 的少数符号散成 60 段、  
每段不到 2 行、37% 的行根本没有偏离，paint p8 是 27 段 / 最长 14 行 / 50% 的行没偏离——  
两页都是**画面正中本身有断续的陡边**（moon 那本里是床沿与窗帘的竖边；  
paint p8 是**那张跨中缝的纸上的蜡笔线**，而纸按提示词本来就被允许压着书脊）。  
**"名次第一"不等于"是折痕"**，这一条别省。

★ 一页是"半条线"还是一种**偏差更大的假警报**也顺手记下：paint **cover** 的少数符号行是  
**180 / 1092**（封面高 1365，只有 1092 行该量——★ 这个分母第一次写错过，  
按"和跨页一样 819 行"填的，是错的）、42 段 / 最长 23 行，而它的偏离只有 **+0.07 级**，  
连 8 级那条线都够不着，压根不在灰区里。所以那一张既不满足①也不满足③，**不必再裁图**。

★ 表里 dino/moon 那几行与 paint p8 的偏离都出自 `check-booklist-art.py`（**峰列的列均值偏离**）；  
`paint-halfline.py` 那支报的 −8.59 是另一个量（峰列**逐行偏离的均值**）。两个数都对，  
但**不能互相填格**——差一倍看着像"数变了"，其实只是换了把尺子。

★ 顺带纠一次错：本书（`dino.md`）§六当时记的「中缝无接缝：带内外列差比 0.29×–1.26×」  
是**用错判据得出的错结论**。正确结论是：恐龙那本 p1、p2、p3、p4 **四张都有折痕**  
（p3 连旧的"逐行台阶 + 同号"版判据也漏过），月亮那本 p5、p6 有。  
16 张里 **6 张**不合格。上游提示词 §2.3 里那句禁令**没能拦住它**——这一条得在出图之后量，  
不能只在提示词里写。

### 2.6 量出来之后：局部修还是重出

修是**确定性的**（把被污染的那几列按左右干净邻居逐行线性插值补回来，不含任何生成），  
所以"能不能修"是有答案的，但**修不修由出图的人定**。入库脚本把三笔代价一起报出来，  
默认**只报数不落盘**（加 `--out DIR` 才写副本，★ 它绝不动 `public/`）：

```bash
python -I scripts/repair-booklist-crease.py public/booklist/dino public/booklist/moon
```

2026-10-16 在这 6 张上实测，刀口取「|偏离| ≥ 25% 峰值」的连续段（★ 用相对比例而不是固定的  
8 级：固定 8 级那一版把折痕的**肩部**也算进去，一次要改 8–12 列；收到 25% 只要 5–10 列，  
而同一把尺子照样判干净）：

| 页      | 修前（偏离/同号/名次/倍数） | 替换列             | 修后（从副本重读） | ① 拿掉的行的形状   | ② 边界新台阶 | ③ 重编码      |
| ------- | --------------------------- | ------------------ | ------------------ | ------------------ | ------------ | ------------- |
| dino p1 | −29.13 / 98% / 1 / 8.18×    | 10 列 49.67–50.26% | −1.82 / 15/16      | 82.2%，最长 269 行 | 0.1× 噪声    | q74 220,916 B |
| dino p2 | −32.80 / 100% / 1 / 12.43×  | 9 列 49.67–50.20%  | −3.50 / 6/16       | 96.2%，最长 327 行 | 0.1× 噪声    | q78 218,232 B |
| dino p3 | −31.96 / 99% / 1 / 11.39×   | 10 列 49.67–50.26% | −2.74 / 5/16       | 87.2%，最长 307 行 | 0.2× 噪声    | q78 169,858 B |
| dino p4 | −24.46 / 92% / 1 / 11.71×   | 8 列 49.61–50.07%  | −5.79 / 2/16       | 67.4%，最长 137 行 | 0.4× 噪声    | q78 162,316 B |
| moon p5 | +12.38 / 93% / 1 / 7.71×    | 5 列 50.07–50.33%  | −6.03 / **1/16**   | 30.0%，最长 42 行  | 0.5× 噪声    | q78 115,920 B |
| moon p6 | +18.98 / 99% / 1 / 8.75×    | 7 列 49.93–50.33%  | −4.40 / 3/16       | 70.1%，最长 155 行 | 0.2× 噪声    | q78 154,288 B |

（"修后"那一列是从 `--out` 写出的**副本重读**量的，含重编码那一次的噪声；  
表里的倍数/名次都出自同一把尺子，判据就是 §2.5 那三条。）

三笔代价读作：

- **① 拿掉的是一条线，不是画面里的东西。** 判法是"整高都在变 = 线；只有几段在变 = 东西"：  
  六张里被改动 >15 级的行占 67–96%、最长连续 137–327 行（占画面高度 17–40%），  
  只有 moon p5 是 30%——它的折痕本来就只有 2 列、断续，所以补回去也只碰到一部分行。  
  ★ 这个形状判据是**在像素上量**的，不靠"看图觉得没少东西"。
- **② 不会修出一道新棱。** 带的两条边界上的台阶是 0.1×–0.5× 这张图自己的列间噪声。  
  （横向插值的隐含风险是左右邻居本身差得远，补出来的斜坡在边界留台阶；  
  量出来在噪声底之下，就是看不出来的。）
- **③ 修完不是零，是压到线下；而且更胖。** 六张都过了三条件，但 dino p4 仍排第 2、  
  **moon p5 仍排第 1**（−6.03 级，离 8 级那条线只差 2 级）。隔一次有损解码再存，  
  同画质下体积反而涨——dino p1 要降到 q74 才塞进 220KB 预算（220,916 B，贴着上限）。

所以结论不是"修比不修好"，而是分场景：**纹理重的（dino 那四张蕨叶与雾）修得干净；  
平滑夜色上的（moon p5）修完还是那张图最偏的一处**，那一张更适合重出。  
★ 六张的处置都由出图的人定，仓库里没有一张"修过的成品图"。

## 三、出图规格与落盘

| 项       | 值                                                                      |
| -------- | ----------------------------------------------------------------------- |
| 封面     | 先出 2:3（1024×1536），由脚本居中裁到 **3:4**；单张 ≤ 150KB             |
| 跨页     | 按 **3:2（1536×1024）**&#x51FA;图，**不裁**；单张 ≤ 220KB               |

## 四、配音规格（一张图一段）

| 项       | 怎么做                                                                                                                       |
| -------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 一图一段 | 8 段一本，命名 `p1.m4a` … `p8.m4a`，**与图同名**放在同一个目录                                                               |
| 念什么   | 每本那一页的【印的正文】，**一个字都不许改**（屏上写的就是耳朵里听的）                                                       |
| 封面封底 | **不配音**。书没打开，没有哪一页在念                                                                                         |
| 格式     | 规格是 `.m4a`（AAC），**`.mp3` 也认**（下面那条 ★）；音量与房间见 [`demo-narration-script.md`](demo-narration-script.md) §五 |
| 时长     | 每段 **14–21 秒**（正文 42–60 字，按 3.2 字/秒的慢读估）；单段 ≤ 200KB                                                       |
| 朗读标注 | `／` 短停 0.4 秒 · `／／` 长停 1 秒 · **粗体**重音 · `——` 拖住不收                                                           |

★ **`.m4a` 与 `.mp3` 都收，`.m4a` 优先**（`AUDIO_EXTS`，`src/components/booklist/booklist.ts`）。
这条约定的差事是"第 3 张图的音频是哪个"——**同一个目录、同一个序号**，与容器格式无关；
一个只认 AAC 的读盘会让一本 8 段都躺在那儿的书看起来"还没有录朗读"。但**新录的请按规格出 `.m4a`**：
"反正都认"不该变成第三种格式的开端。

★ **第三种容器不是"也认"，是"完全不认"**（2026-10-16 在 paint 那本上实测）：
那一本有 7 段 `.mp3` 和 1 段 **`.mp4`**（声音本身是 mp3 装进了 mp4 壳——
`ffprobe` 读出来八段都是 mp3／单声道／24 kbps／48 kHz，只有容器不同）。
`AUDIO_EXTS = ['m4a','mp3']` 里没有 `mp4`，读盘那条（`src/lib/booklist-assets.ts`
用 `AUDIO_EXTS.find`）于是**只认出 7/8 段**，而朗读按钮的判据是"整本都在" ——
结果是**这一本的朗读控件整本不出现**，看起来像"还没录"。损失不是 1/8，是 8/8。
所以交付时**别用别的后缀**：`.m4a`，必要时 `.mp3`，除此之外没有第三个。
（paint 那一段**当天就改回来了**：走的是无损改容器
`ffmpeg -v error -i p5.mp4 -c copy p5.mp3`，音频一个字节没重编，
改完真路由 `/booklist/paint` 返 200 且 SSR 里重新出现 `▶ 朗读` 控件——
同一条路由上 rocket（0 段）与 dino（8 段）的读数分别是 0 / 1，可见这个判据是有判别力的。
★ 但对**新录的**仍然要求 `.m4a`，别把这次救场读成"反正改一下就行"。）

★ **要么整本 8 段都录，要么先不录**：阅读器里那颗朗读按钮的判据是"整本都能响"
（与首页拆掉播放条、"只对几页能响的按钮证的是反面"是同一条）。缺段时界面会如实写
"这本书只有 3/8 段有朗读，所以没有给朗读控件"，而**不会**给一颗只对三页有用的按钮。

### 为什么每页就 42–60 字，不能再长

这个数**不是审美，是版面容量**：正文叠在左页下角一块纸色渐变上，三行是它
"不盖住画"的上限（推导与那两个数写在 `booklist-reader.css` 的 `.blr__text` 上，
`src/components/booklist/booklist.test.ts` 摁着"每行 ≤ 22 字、合计 ≤ 60 字"）。
再长就要把渐变加高、压掉画面 —— 那是**另一个取舍**（加跨页、加图），不是加字。

2026-10-15 这一档是**加长过一次**的：用户听完第一版说"音频有点短"，
于是从"每页 18–42 字 / 6–13 秒"整体加长到"42–60 字 / 14–21 秒"，一本从 1 分 10 秒
变成约 2 分 10 秒。长句是**加细节**（露水、光斑、脚步、呼吸），不是加事件 ——
每一页的画面说明因此不用重画。

★ **但 14–21 秒这个数按现在的声音达不到**（2026-10-16 实测三本 24 段）：
上面那条时长是按 **3.2 字/秒** 估的，而三本实测的语速是 **3.6–4.7 字/秒**
（paint 3.87、dino 与 moon 3.9–4.5；`ffprobe` 读时长 ÷ 印的字数，逐段列在
[paint.md](paint.md) §七）。版面又把每页压在 ≤60 字，于是 **60 ÷ 3.9 ≈ 15.4 秒是天花板**，
"14–21 秒"与"42–60 字"**不可能同时满足**。三本已交付的音频都落在 11.0–12.7 秒，
**全部短于表里写的 13–16 秒**。→ 这是**待定的规格决策**（出图的人定）：
**A** 把规格改成按字数、时长只做旁证；**B** 让 TTS 放慢到 3.2 字/秒；**C** 承认
11–15 秒是这一套的实际时长，把上面那张表与各本的 §五 表一起改写。
**在定下来之前，各本 §五 那张表照旧不改 —— 但别把"表里的数"当成已经达到的事。**

## 六、出图顺序：先两本定调

按 [`cover-art-prompts.md`](cover-art-prompts.md) §六 那条老经验：**先出 2 本**——
一本白天的（恐龙）、一本夜里的（月亮），一次性暴露色温与明度的问题。确认画风之后
再批量推进其余 10 本，比出完 108 张再来改便宜得多。

**一致性靠参考图，不靠形容词**：每一本的第 2 张起，把这一本已确认的图作为参考图一起传，
提示词里明确写「保持参考图的画风、纸质纹理、轮廓线粗细与角色形象不变」。
角色一致性的锚点表写在每一本的文档里，**先出一张角色设定表（P0），之后以 P0 为准**。
