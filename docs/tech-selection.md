## §3 设计系统与样式（已定稿）

### 3.1 令牌

**令牌的唯一来源是 `src/app/globals.css` 的 `:root`，通过 `@theme inline` 暴露给 Tailwind。**
组件层只消费 `var(--x)`，改配色只动那一块。这是本仓库四条硬约束之一，已在三屏上执行。

| 项       | 约定                                                                                               | 依据                                             |
| -------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 令牌     | 语义令牌（`--color-*` 一类）在 `@theme` 里注册，用 `bg-primary` 而不是 `bg-[var(--color-primary)]` | B：`stacks/html-tailwind.csv`（2026-08-13 核实） |
| 类名     | 保持**静态可检出**：`colorMap[color]` 映射到完整类名，**不要 `bg-${c}-500` 插值**                  | B：同上                                          |
| 组件样式 | 与组件同目录同名（`Foo.tsx` / `foo.css`），`globals.css` 里 `@import`；**不用 CSS Modules**        | A：README §二 分层约定                           |

### 3.2 字体：零 Web 字体的决定

`--font-sans` 是**中文优先的系统字体栈**：
`'PingFang SC', 'Microsoft YaHei', 'Noto Sans SC', system-ui, -apple-system, sans-serif`。
`--font-serif` 是 `Georgia, 'Songti SC', 'STSong', 'Noto Serif SC', 'SimSun', serif`
（第三屏大标题与品牌英文用它）。**一个 Web 字体都不加载。**

这条决定要写进技术文档，因为评委一定会问"为什么字体这么朴素"：

- **中文 Web 字体是兆字节级**，子集化也救不回来；全量中文字体 5–10 MB。
  首屏加载速度是**评分子项**（前端性能优化 3 分）。
- `globals.css` 里已经写下另一半理由：**不用 `next/font` 拉 Noto Sans SC，
  因为它构建期需要联网**——一个构建期的外部依赖，对一个要交代码包的参赛项目是净负债。
- **零字体 = 零 FOUT、零 CLS、零字体授权问题**，也顺手避开了第三方字体 CDN 的可用性风险
  （在线演示要求评审期间可用）。
- 代价说清：跨设备字形不完全一致（macOS 拿到 PingFang，Windows 拿到雅黑），
  衬线档同样（Songti SC vs SimSun）。

> **已知重复，标记为待清理**：`hero-orbit.css` 的 `.hero__brand .serif` 与
> `highlights-reel.css` 的兜底数字各有一份**手写的 serif 栈**，没有走 `var(--font-serif)`。
> 这是已交付代码里的既有重复，按本仓库「迁移是单独一个提交、行为必须一字不变」的纪律
> **本次不动**，但它是一条记在账上的债。

> **诚实标注（B）**：`ui-ux-pro-max` 的 `typography` 库里那 74 组搭配**全是拉丁字体**
> （Varela Round / Nunito / Fredoka 一类），**没有 CJK 搭配方案**。
> 所以中文字体这一档不是"查出来的"，是按上面的成本与合规判据推出来的。
> 查询记录见 §14。

### 3.3 儿童产品的可用性底线（B，含一处修正）

`ui-ux-pro-max` 的 UX 准则库里有一条**值得抄进 checklist 的修正**：

| 平台    | 触控目标下限                         |
| ------- | ------------------------------------ |
| iOS     | 44pt                                 |
| Android | 48dp                                 |
| **Web** | **WCAG Target Size 规则：24 CSS px** |

出处在 `ux-guidelines.csv`（2026-08-13 核实），原文特别强调
**不要把某一个平台的数字当成普适最小**。我们自己的 19 项 checklist 里写的是
"触控热区 ≥44px"（W3 共读版选择点）——**那个 44 是产品判断不是合规下限，两个都要留下**：
44px 是"4 岁孩子的手指能稳定点中"的经验值，WCAG 的 24px 是"不能更小"的合规线。
写技术文档时报前者（我们的选择），别报成后者（会显得没读过规范）。
★ 2026-10-18 按交付核对过：那一颗按钮的真身是 `.book-choice__btn`
（`components/book/storybook-flip.css`，两台阅读器共用），内含 56px 的图标位
加 `9px` 上下内边距——**实测 79px**（`chk-demo-shared.mjs` 里就量着这一条，
读数是 `[79,79]`），大于 44，不是"刚好压线"。

另一条同时命中的准则：**不要让重要操作只靠 hover**（`ux-guidelines.csv`，
"Don't rely only on hover for important actions"）。第三屏"自动轮播的暂停手段"
现在只剩 hover 与 Tab 焦点两条路径，这条准则与 docs/known-tradeoffs.md 记的那条 WCAG 2.2.2 让步
是同一件事，**已在两处分别记录**，不要在 W5 才想起来。

## §4 动效边界（已定稿）

### 4.1 谁用、谁不用

**GSAP 只出现在第三屏（`HighlightsReel`）与将来的阅读器 / 创作流过程动效。**
前两屏的滚动驱动仍然是 `useScrollDriver`，**不重写**——那两屏的每个数字都是实测出来的，
重写等于把已交付的东西重新变成未验证的。

| 屏 / 场景          | 驱动              | 理由                                                     |
| ------------------ | ----------------- | -------------------------------------------------------- |
| 首屏环形轨道       | `useScrollDriver` | 已交付 + 每处细节对应一次踩坑（帧率窗口、`setVar` 去重） |
| 第二屏滚动翻页绘本 | `useScrollDriver` | 同上                                                     |
| 第三屏亮点轮播     | **GSAP**          | 每帧跟随指针的 `quickTo` 比自写 rAF 平滑稳               |
| 阅读器翻页（W2）   | **GSAP Flip**     | FLIP 是它存在的理由                                      |
| 过程可视化（W4）   | **GSAP** 时间轴   | 见 4.3 的禁令                                            |

### 4.2 版本事实（B）

**GSAP 3.15 全部插件免费**（ScrollTrigger / Flip / SplitText / MorphSVG / MotionPath /
Draggable / Observer / DrawSVG / ScrambleText / TextPlugin / Inertia / ScrollTo /
ScrollSmoother / CustomEase …）。出处：`gsap` 技能文档（本会话核实）。
从前"SplitText 是会员插件"的记忆已过期——**技术文档里别写错这一条**。

### 4.3 ★ SplitText 的使用禁令（B，与 W4 计划冲突，以本条为准）

19 项 checklist 的 W4 写的是「用 `gsap`（SplitText / 时间轴）做**逐字打出**与
'正在重画'的过程动效」。`gsap` 技能的动效库里有一条明确的反例：

> **Don't:** split-animate long paragraphs; reserve for short headlines (under ~8 words)
> **Performance:** splitting text creates one element per character

所以**拆开**：

| 场景                                | 用什么                                                    | 不用什么     |
| ----------------------------------- | --------------------------------------------------------- | ------------ |
| 故事正文的流式打出（一页 30–60 字） | **增量文本 + 光标**（首屏 `HeroTypewriter` 已是这个先例） | ❌ SplitText |
| 短标题 / 关键词逐字入场（≤8 词）    | SplitText + stagger                                       | —            |
| "正在重画第 9 页" 的过程提示        | 时间轴 + 缓动                                             | —            |

理由：一本 20 页的书，正文逐字拆分会瞬间造出上千个 DOM 节点，而 #12（性能 3 分）
要求 Lighthouse ≥ 90。另外 **SplitText 用完必须 `revert()`**，
否则读屏与爬虫拿到的是被拆碎的字符节点。

### 4.4 性能红线（B，抄进 W5 复查项）

- 只动 `transform` 与 `opacity`，**不要动触发布局重排的属性**（`left` / `top` / `width`）
- `prefers-reduced-motion` 下**渲染静止终态**，不是"启动后再停"
- 移动端降级：低端设备关掉复杂动效
- 卸载纪律：`gsap.context()` + `ctx.revert()`（本仓库**不引 `@gsap/react`**：
  为一个 hook 多加一个运行时依赖不值，而 `context` 在核心包里）

## §5 AI 接入层与事件流（已定稿）

**自写 SSE 事件协议 + 自写结构化输出校验与重试；不引 Vercel AI SDK。**

★ **状态更新（2026-10-15）**：那条翻案阈值**被触发过**——三样手写代码量到 810 行
（加 `tree.ts` 的口径 953 行）、并量到 1 处真实重复（同一段括号扫描器写了两遍，
已经合并）。所以 ADR-0004 的 Status 已改成 **`superseded`**，
替代方案的范围、代价与**落地排在 W3 的理由**都写在那个 ADR 的附录里。
**这一页的选型结论本身不变**：这件事仍然是自写的，落地是另一单工作。
（量法与逐文件行数在 `.scratch/w2-solo-flow/issues/01-adr0004-threshold.md`。）

事件流是 W2 的硬任务（checklist 铁律第 2 条：**不许推迟**，因为 #2 Agent 8 分 +
#17 AI 交互 3 分共 11 分压在它上面）。选型层面只需要确认三条：

1. **传输**：`text/event-stream`（Next.js Route Handler 的 `ReadableStream`），
   不用 WebSocket——单向、可断线重连、能过大多数中间层。
2. **事件形状**：至少能表达 `{ page, stage, attempt, reason, score }` 这五个字段，
   因为"正在重画第 9 页，相似度 0.71"这句话的每个成分都要能被界面与日志消费。
3. **失败语义**：一步失败**不终止整条流**，前端要能显示"这一页退回了"而不是整页报错。

## §6 供应商适配层（已定稿）

见 [ADR-0002](adr/0002-provider-adapter-layer.md)。落地形态：

```
src/lib/engine/
├─ providers/
│  ├─ types.ts          ← 能力接口（规划 / 生成 / 合成 / 视觉比对 / 生命周期）
│  ├─ image/<vendor>.ts ← 每家一个适配器
│  ├─ tts/<vendor>.ts
│  └─ llm/<vendor>.ts
└─ index.ts             ← 按 env 选择实现；读不到 key 时给"未配置"的显式错误，不静默降级
```

**环境变量按能力命名**（`.env.example` 已经是这个约定，本次定稿确认它不变）：
`LLM_API_KEY` / `LLM_BASE_URL` / `IMAGE_API_KEY` / `IMAGE_BASE_URL` /
`TTS_API_KEY` / `TTS_BASE_URL`。**不出现厂商名**——换供应商只改 `.env.local` 与一个适配器文件。

**生命周期方法是一等公民**：能力接口里必须包含"删除/解绑"，
因为隐私设计承诺了「删孩子 → 调厂商 API 解绑 voice_id」。选型时这条是硬约束（§8.3）。

> 写过一句"纯文字锚点**撑不住**跨页一致性"。**这句作废**——
> 随后 ≥3 人的人工判读说两组都"像同一个孩子"（§7.5），判据 1 本来就是人说了算。
>
> 两边不可能都对，而**错的一方是机器**：一致性分是按 6 条锚点**逐条**核的，
> 0.5 = 中 3 条、0.3 = 中 2 条，而阈值 0.75 等于**要求 6 条里中 5 条**；
> 人认一个小孩是**整体认**的——脸对、发型对、衣服对就够了。
> 再叠上 §9.1.4 那条"膝盖晒黑印多数构图根本拍不到"，
> 机器就在拿放大镜挑锚点，而判据要的是肉眼认人。
>
> **所以 `r_redraw ≈ 0.75` 这个数被一个校准过严的比对器抬高了**，
> 里面有多少是"真不像"、多少是"左上那撮翘毛没画对"，现在分不开。
> 这正是 GLOSSARY「一致性分是判据不是事实，**阈值靠人工判读校准**」等的那个校准事件——
> 结论见 §7.6 最后一段（它没有推翻人工判读，但也没归零）。

### 7.4 翻案条件

**10/13 更新**：这一节原来写的是"主选 GPT-Image-2 在横评中被任一家超过就换"，
但 W1 实际跑的不是那场横评——当前接入的供应商只有 `wan2.7-image` 与
`qwen-image-2.0` 两个图像模型（§7.0），GPT-Image-2 手里那 26 张成图是**画风证据**，
从来没跟这两家同台比过一致性。所以翻案条件按实际改写成三条：

1. **`qwen-image-2.0` 在细节锚点上反复不对**（尤其"左上方翘着一撮"那条——
   机器分 0.61 对 0.83 就是往这个方向指的）→ 换回 `wan2.7-image`，
   只改 `.env.local` 的 `IMAGE_MODEL`，不改代码。
2. **人工判读只覆盖了 `xiaoyu-r1`（男孩）那张卡**；若 `xiaolu-r1`（女孩）或
   后续真孩子的卡出现"不像"，那是**卡的问题**，不是模型的问题——
   先回去看锚点清单（§9.1.4 的可见性问题），别急着换模型。
3. **儿童内容审核拦截率高到影响正常题材** → 换。这条还没测（§12.2 判据 5），
   是这一节目前唯一真正空着的翻案条件。

只被价格超过不构成翻案（两家都是 0.20 元/张，本来也没差）。
判据 1 是一票否决，但它已经过了——**过了不等于永久有效**，
上面第 1、2 条就是它最可能的失效方式。

### 7.5 判据 1 人工判读结果（A，2026-10-13 ≥3 人）

盲评包 `.out/bakeoff-image/blind/`（`set-1` / `set-2`，目录与文件名不含候选名），
**≥3 人已独立判读**。揭盲对照表在 `.out/bakeoff-image/image-bakeoff.json`
（seed=1791870109610）：

| 盲评标签 | 实际模型         | 人工判读           | 机器分（对照）          | 单张出图耗时 |
| -------- | ---------------- | ------------------ | ----------------------- | ------------ |
| set-1    | `wan2.7-image`   | **认作同一个孩子** | 均值 0.83（3/5 页判成） | 21–24 秒     |
| set-2    | `qwen-image-2.0` | **认作同一个孩子** | 均值 0.61（4/5 页判成） | 7–13 秒      |

★ **这一条结论的边界要写清楚，别读成"两张卡都行"**：

- 人工判读**只覆盖了男孩那张卡**（`xiaoyu-r1`）。另一张 `xiaolu-r1` 未经这一轮判读。
- 判读给的是**整体结论**（"像同一个孩子"），**没有留逐页计数**。
  §12.3 的量法写的是"5 页里 ≥5 页"，所以严格说这个 go 是**按人话结论记的，
  不是按逐页打点记的**。要拿它当答辩证据，下次判读要留表。
- 三人在判读时是否完全盲（没见过候选名），按用户口径为是。

### 7.6 默认推荐：图像模型取 `qwen-image-2.0`

> 按 [ADR-0008](adr/0008-model-and-key-provided-by-user.md)，这是**预填给用户的默认值**，
> 不是产品边界——用户可以在创作流里换成任何 OpenAI 兼容的图像端点。
> 所以这一节的作用是"默认推荐哪个、为什么"，而不是"只能用哪个"。
> 换模型仍然只改一处 `Env`（`IMAGE_MODEL`），不改代码。

判据 1 两组都过、**它不区分它们**，所以按下一位判据破平：

| 判据             | wan2.7-image | qwen-image-2.0 | 谁赢                |
| ---------------- | ------------ | -------------- | ------------------- |
| 1 一致性（人工） | 过           | 过             | 平                  |
| 单价             | 0.20 元/张   | 0.20 元/张     | 平                  |
| 单张耗时         | 21–24 秒     | **7–13 秒**    | **qwen，快 2–3 倍** |
| 机器一致性分     | 0.83         | 0.61           | wan（但见下）       |

**取 `qwen-image-2.0`**，`wan2.7-image` 作退路（同一条接口，换模型只改 `.env.local` 的
`IMAGE_MODEL`，不改代码——这就是 registry 那条"模型名不写死"的兑现处）。

★ **最后那一行是往反方向指的，要如实记着**：机器分说 wan 更像角色卡（0.83 对 0.61）。
但**这个分现在不可信**——三个人用眼睛说"像同一个孩子"，而机器给其中一组 0.61，
说明它在校准错了的方向上打分（见 §9.1.3 与 §9.1.4：6 条锚点逐条硬核、
阈值 0.75 ≈ 要求中 5 条，而人是整体认的）。
**所以它不足以推翻人工判读，但它不是零信息**：如果后面发现 `qwen` 出的页
在"左上翘着一撮"这类细节上反复不对，那就是这条信号是真的，按 §7.4 翻案回 `wan`。

## §8 语音合成（默认推荐，可被用户替换）

> ★ **2026-10-13：这一节的实测被推迟，不是被取消。** 用户口径："TTS 等需要的时候
> 我再给你候选和 key。"所以本节**仍然只是候选名单（C 级）**，五个候选一个都没跑过，
> `VoiceSynthesizer` 适配器是 `voice: null`。
> 后果要说清，不许含糊：
>
> - **W2 不因此停摆**——阅读器与创作流照常做，声音那一层走既有的 `voice: null` seam
>   （ADR 口径：一个适配器是假想 seam，两个才是真 seam；这里的第二实现 W4 才来）。
> - **但 W2 不许出现"演示用播放条"**。首页那条配音播放条**已经因为同样的理由拆掉了**
>   （全篇只录得到第 1 页，一个只对四分之一能响的控件证的是反面）——
>   同一个错不许在阅读器里再犯一次。
> - **§8.3 那条硬约束可以先做，且不花钱**：候选必须支持「上传样本 → 返回 `voice_id`
>   → 可解绑/删除」，**查文档就能否掉一个候选，不用跑音频**。
>   它和隐私设计的删除承诺直接冲突，是全篇最便宜的一次淘汰。
> - 它还需要 ≥3 人盲听（产出物 2），是**要排人时间的长杆**——W4 一开工就要，别拖到 W4 末尾。

产品承诺是**「录三十秒，让孩子听你的声音讲完」**，所以候选必须能做到 30 秒样本的
中文音色克隆。

### 8.3 ★ 硬约束：解绑能力（A，来自本项目自己的隐私设计）

隐私设计文档里写死了一条承诺：**删孩子时调厂商 API 解绑 voice_id**，
并且「30 秒声音样本（原始）**不保留**，拿到 voice_id 后立即删」。

所以 TTS 候选必须同时满足：**上传样本 → 返回 voice_id → 支持解绑/删除该 voice_id**。
不满足这条的候选**直接淘汰，不进盲听**——这不是偏好，是已承诺的产品行为。

### 9.1.1 已实测：思考链会吃掉整个 token 预算（A）

★ 这条**不是某个候选的毛病，是引擎参数的事**，七个候选全中，所以放在候选表前面。
复现脚本：`scripts/probe-thinking-budget.mts`。同一份 prompt，只改一个参数：

| 配置                       | HTTP | 正文长度     | 思考链长度 | finish_reason | completion_tokens |
| -------------------------- | ---- | ------------ | ---------- | ------------- | ----------------- |
| qwen3.8-max · 预算 4096    | 200  | **0**        | 9072       | length        | 4096              |
| qwen3.8-max · 预算 16000   | 504  | —            | —          | —             | —                 |
| qwen3.8-max · `关思考`     | 200  | 2800         | —          | stop          | **847**           |
| qwen3.8-flash · 预算 4096  | 200  | **0**        | 9407       | length        | 4096              |
| qwen3.8-flash · 预算 16000 | 200  | 1138         | 11507      | stop          | 5373              |
| glm-5.3-flash · 预算 4096  | 200  | **键都没有** | 10552      | length        | 4096              |
| glm-5.3-flash · 预算 16000 | 200  | 1832         | 15608      | stop          | 7417              |
| seed-2.1-pro · 预算 4096   | 504  | —            | —          | —             | —                 |
| seed-2.1-pro · 预算 16000  | 504  | —            | —          | —             | —                 |
| seed-2.1-pro · `关思考`    | 200  | 1050         | —          | stop          | **555**           |

四条结论：

1. **预算 4096 配上思考模型 = 一个字都写不出来。** 思考链把预算吃光
   （completion 数正好卡在 4096），正文是空串或干脆没有这个键，`finish_reason=length`。
   它**不是**"这家不会出 JSON"——所以 `openai-text.ts` 现在把三种空正文分开报，
   合并报的话这一栏会被读成格式能力差，选型结论直接反掉。
2. **`enable_thinking: false` 是这条平台上真有的字段**，六个候选实测可用
   （qwen3.8-flash / deepseek-flash / mimo-v2.6-pro / qwen3.8-max / seed-2.1-pro；
   kimi-k2.6 那次探到 503 `LITELLM_UNAVAILABLE`，**算没测出来**，
   但它在本轮横评里以关思考跑出 7/7，所以实际可用）。
   关掉之后同一批模型 **555–847 tokens** 写完一张表，比开思考便宜 5–7 倍。
   值域是三值的（平台原话：`只支持开启、关闭或自动`），还有一个 `auto`——
   **未验证字面量，暂不用也不写进注册表**。
3. ★ **`glm-5.3-flash` 不允许关思考**：送 `false` 回
   `HTTP 400 · REASONING_REQUIRED · 当前模型必须开启深度思考`。
   而它开着思考在 4096 预算下又写不出正文。
   所以这一家只有一条活路：`LLM_THINKING=on` **且** `LLM_MAX_TOKENS=16000`。
   注册表缺省 `off` 会让它**整家打不通**——是响亮的 400，不是静默降级，这是可以接受的；
   但**选型时它是一个独立的扣分项**，不在判据 1 里（它不是格式能力差，
   是"我们对它的参数面还没配通"）。
4. **放大预算不是普适解**：qwen3.8-max 与 seed-2.1-pro 在 16000 档返回 504
   （网关等不及，不是参数被拒）。seed-2.1-pro 连 4096 档也 504——
   这是**稳定性**问题（§12.3 的可达性），与格式能力是两条判据。

> ★★ **这里更正过一次自己的结论，错法值得留着。**上一版写的是
> "七个候选全认 `enable_thinking`，缺省关思考可以安全地对全体生效"。
> 那句是从一个**免费**探针得来的：送一个错值，七家都回 `UNSUPPORTED_FIELD`。
> 随后正式跑测立刻打脸——`glm-5.3-flash` 十本全灭，`REASONING_REQUIRED`。
> 错在**判据的量法**：送错值只能证明"字段名存在"，证明不了"这个值被允许"。
> 当初选错值图的是"不花钱"，那就是**在拿成本决定判据的强度**——
> 和这个项目一直在修的"拿'裁判没到场'判'选手没跑'"是同一类错。
> 现在探针送真值，并且把判据拆成三值（允许 / 拒绝 / **不知道**）：
> 503 是平台抖动，把它并进"拒绝"就是冤枉一家（kimi-k2.6 被这么冤枉过一次）。

**落到的代码**：预算随**模型**走，不随阶段走。`plan.ts` 不再写死 `maxTokens`；
适配器缺省 4096，`.env.local` 的 `LLM_MAX_TOKENS` / `LLM_THINKING` 决定实际值，
缺省 `LLM_THINKING=off`——**与平台默认相反**，因为按平台默认出厂、
预算又停在 4096 的配置是坏的。
`/api/health` 会把这四项（模型 / 思考 / 预算 / jsonMode）一起报出来。

★ 未测量：关思考对**判据 2（语感）**的影响。省 5–7 倍 token 是实测的，
"思考让故事更好"是**假设**。要让它能被推翻，得把同一批主题在两种模式下各跑一遍
再让人读——见 §9.2 判据 2 的待办。

### 9.1.3 端到端真跑一本（live）测到的一致性事实（A）

`node scripts/engine-run.mts --mode=live --form=solo --pages=N`，两次共 8 页计划、
15 次图像调用。这一节是 §12.2 产出物 4（`r_redraw`）的**原始数据**，
也是 W1 里第一次让一致性 Agent 真做判断。

| 事实             | 读数                                                 |
| ---------------- | ---------------------------------------------------- |
| 拿到判决的页     | 4 / 8（另 4 页比对调用没跑成：504 / `fetch failed`） |
| 首次通过         | **1 / 4 = 25%**                                      |
| 需要重画         | 3 / 4 → `r_redraw ≈ 0.75`                            |
| 每页平均图像调用 | 15 / 8 ≈ **1.9 次/页**                               |
| 一致性分         | 1.00、0.95、0.30、0.10                               |

三条要记住的：

1. **分数是双峰的，阈值 0.75 正落在空隙里。** 通过的两页是 1.00 / 0.95，
   不通过的两页是 0.30 / 0.10，中间没有值。所以 GLOSSARY「一致性分」那句
   "它是判据不是事实"在这里可以放心用——**比对模型是果断的，不是吵的**，
   阈值往 0.6 或 0.9 挪都不会改变这四页的归属。
2. ★ **`r_redraw` 这个数现在还不能定稿**：分母只有 4，
   而且**一半的页根本没判成**（比对模型不稳）。把它当方向，别当结论。
   真正卡住这条测量的是视觉比对的载荷——两张 1440² 的图约 7 MB base64，
   要先有图像处理库把图缩到 768 再送（见 §7.0 与 §12.2 待办）。
3. ★ **有一页请求 2 页却拿到 3 页，`buildTree` 收了。**
   连同横评里 `mimo-v2.6-pro` 那本 7 页（要求 6），这是**两次独立复现**：
   引擎不校验页数。判据 1 量的是"每页 4 字段"，页数不在其中——
   这是一处**已知缺口**，不是通过。

### 9.1.4 角色卡锚点的可见性问题（A，来自 §9.1.3 那两次真跑）

四条"不通过"的理由里反复出现同一句：**"膝盖未见晒黑印记"**。

```
肤色：暖黄偏深的肤色，膝盖有晒黑的印
→ "待审页中人物膝盖未呈现晒黑印记，不符合锚点清单中关于肤型的硬性要求"
→ "膝盖处也无晒黑印记"
```

而锚点清单（`checklistOf(card)`）把每条锚点都当**必核项**——于是
**一条在多数构图里根本拍不到的锚点，必然判 fail**，白烧重画。
`r_redraw ≈ 0.75` 里有多少是模型的错、有多少是这条锚点的错，现在分不开。

**规则**：锚点要能当硬判据，前提是**它在页面上可见**。
坐下、穿长裤、构图裁掉膝盖——任意一条成立，这条锚点就不可核。
所以角色卡的锚点集需要区分"每页必核"与"可见才核"（GLOSSARY 里
硬锚点/软锚点那条分类已经存在，缺的是把"可见性"作为归类的判据）。

★ 本轮**没有**动两张卡的锚点定义：改锚点会改 `promptFragmentOf(card)` 的输出，
而横评的纪律是"两个候选拿到逐字节相同的角色段"——改了就要重跑整轮图像横评。
记在这里，等图像判据 1 的人工盲读做完再决定。

## §10 成本模型（公式已定稿，单价待回填）

**预算上限在本次定稿时尚未确定**（用户答复："还不确定"），
所以本节定的是**公式与填数纪律**，不是数字。

### 10.1 每本成本

```
每本成本 =  C_llm × N_plan
          + C_img × 20 × (1 + r_redraw)
          + C_llm × N_check  × 20
          + C_tts × W_page  × 20
          + C_vision × 20            ← 一致性比对的视觉模型调用

其中：
  N_plan   = 规划调用次数（1 次规划 + 树的分支数）
  r_redraw = 重画率（W1 实测拿到，一致性 Agent 的重试数据直接复用）
  N_check  = 每页校验调用次数（现设计为 3 个 Agent）
  W_page   = 每页正文平均字数（现稿约 30–60 字，见 docs/demo-narration-script.md）
```

共读版是**树**，选择点之前那段主干被两条路共享，按 `(voiceId, textHash)` 去重可少合成——
成本公式按独读版 20 页算**上界**。（★ 2026-10-18 落地口径：**恰好一个选择点**、
两支各自收尾，所以"共享"只发生在选择点之前那一段；选择点之后的页两条路各有一份，
而两份都要出图与配音——见 docs/known-tradeoffs.md 那笔账。）

### 10.2 填数纪律

- **单价一律现场查官方文档填，写清查询日期与出处**。本文档不预置任何价格数字（§0 已说明）。
- 免费额度优先：对比实验（W1）用免费额度跑，**重画兜底与端到端实测留付费额度**
  （官方特别说明第 4 条鼓励用免费额度）。
- 实测出的每本成本要回填到**本表 + 技术文档的成本章节**，
  它是 #14「解决方案有效性 5 分」验收里"记录真实耗时与成本"那一句的证据。

### 10.3 判据（占位，待上限确定后细化）

> 建议的判据形态：**每本 API 成本 ≤ 定价的 1/10**。
> 定价由 19 项 checklist 的 #19（商业潜力）给，此处不越界替它决定。

## §12 W1 实测协议（照此执行，不另开文档）

**时间盒**：10/14 起测，**10/17 收候选**，**10/20 出 go/no-go**（与 checklist 铁律第 1 条同日）。

### 12.1 固定输入（保证横评可比）

| 项       | 固定值                                                       |
| -------- | ------------------------------------------------------------ |
| 角色卡   | 1 张参考图 + 1 段外貌描述（骨相 / 瞳色 / 头身比 / 那撮翘发） |
| 主题     | 同一主题，同一适龄档                                         |
| 提示词   | 沿用 `docs/cover-art-prompts.md` 的通用骨架，**不改**        |
| 页数     | 5 页（一致性判据）                                           |
| TTS 样本 | 同一段 30 秒录音，同一页正文                                 |
| LLM 输入 | 同一主题 × 10 本分镜                                         |

### 12.2 产出物（缺一不可，就是技术文档的素材）

1. **图像横评表**：每候选一行 —— 5 页一致性通过率、单张成本、支持比例、失败原因
2. **TTS 盲听记录**：≥3 人，每人的判断与本人在不在场（有本人时相似度判断才可信）
3. **LLM 结构化输出表**：10 本 × 每页 4 字段的校验通过率
4. **重画率 r_redraw**：一致性 Agent 首次通过率 X% / 重画后 Y%（#2 的硬证据）
5. **回填**：把上面的数字写进 §7–§10 与 README §二

### 12.3 go/no-go 判据

**5 页里 ≥5 页肉眼可辨为同一个孩子 → go；3–4 页 → 换候选重测（仍在 10/20 之前）；
≤2 页 → 触发降级方案**（checklist §八：换参考图条件更强的模型 / 更风格化画风 /
角色卡锁定 + 家长逐页重画 / 换方向）。**不许"再试两天"。**

> **10/13 结果：go。** ≥3 人独立判读 `.out/bakeoff-image/blind/`，
> 两个候选（`wan2.7-image` / `qwen-image-2.0`）都被认作同一个孩子。
> 定稿与翻案条件见 §7.5 / §7.6。
>
> ★ **但这一条是按"人话结论"记的，不是按 §12.3 的逐页打点记的**——
> 判读没有留下"每组几页/5 页"的分页计数。这不影响 go 的成立（两组都过了，
> 而量法的门槛是 ≥5 页；三人整体判断"像"是对这个门槛的直接回答），
> 但**它撑不起更细的推论**：谁更强、强多少、另一张卡行不行，这三个问题
> 今天这个结果都答不了。下次判读（`xiaolu-r1` 那张、以及 TTS 盲听）
> **要留一张打点表**，别再用"都觉得可以"当记录。

### 12.4 执行 harness（10/13 就位，跑测=一条命令）

协议不再靠手跑，两个脚本把 §12.1 的固定输入钉死在代码里：

| 脚本                                                                           | 产出                                                   | 对应产出物                                     |
| ------------------------------------------------------------------------------ | ------------------------------------------------------ | ---------------------------------------------- |
| `node scripts/w1-image-bakeoff.mts --models=a,b --out=.out/bakeoff-image`      | `.out/bakeoff-image/{image-bakeoff.md, .json, blind/}` | 1（横评表）+ 判据 1 的盲评包                   |
| `node scripts/w1-text-bakeoff.mts --models=a,b,c --books=10 --jsonMode=object` | `.out/bakeoff-text/{text-bakeoff.md, .json}`           | 3（结构化输出表）+ 判据 2 的语感样本           |
| `node scripts/engine-run.mts --mode=live --form=solo --pages=N`                | 一本书 + `manifest.json` + `summary.json`              | 4（重画率，从 `summary.json` 的 stats 直接读） |

两条纪律内建在脚本里：**没有 Key 拒绝运行**（不接受手工填数）、
**盲评包的文件名不含候选名**（避免"看见 wan 就先入为主"）。

★ **10/13 撤掉了 `--yes=1` 确认闸门与预算打印。**这一版之前写的是"不带 `--yes=1`
只打印预算"，现在两者都没有了：口径是额度管够、不必记账、也不必逐次报告
（见 `scripts/env.mts` 文件头）。一个每次都要按的确认键，最后只会变成
条件反射式地敲下去，那时它就不再拦任何东西——**留着它反而让人以为"按过了就没事"**。

★ 两份横评报告都支持**只重出、不重跑**：`--reportOnly=1` 从 json 重放 markdown，
一个模型都不调用、一张图都不出。排版（表格、列表缩进、截断）改错一次，
不该再花一遍调用。**这不是便利功能，是可复现性的一部分**：
`--reportOnly=1` 重出的报告与当初发布的**逐字节一致**（两份都实测过），
这才证得了"报告里的数就是仓库里这个脚本现在能跑出来的数"。
——反过来说，脚本与报告不同步的时候，那格数字是无人可追的孤本。

★ `engine-run.mts` 的汇总行**分开报四档**：有图 / 核对通过 / 核对不通过 / 未核对，
并当场核对后三档之和等于有图。少一档就会漏数（实测 3 页的书报成
"通过 1 · 未核对 1"，第三页在行里凭空消失）。

判据 1 的**人那一半**脚本代替不了：它要 ≥3 人独立看图。
脚本只保证这批图是"同一角色卡 + 同一提示词骨架 + 同一主题"出来的。

## §13 变更流程

本文档只在三种情况下改动：

1. **实测数字回填**（§7–§10 的空格）——随时可改，改完在文末记一行日期与来源
