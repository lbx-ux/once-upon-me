## 一、卡身冷白：换底色**提高**了对比度，不是拿可读性换的

判据仍然是「冷的是光，暖的是物件」，这一轮把它**收窄**了一格：
**卡背是页面的一部分，mat 才是物件。** 上一版把整张卡算成"物件"，于是奶油色
铺满一整块，压在冷天上就是两块色。

数字（`node scripts/check-scrim.mts` 的"卡面上那两层"两行，同一支脚本按 CSS 真值算，
**不是手抄**）：

| 面上                    | `--ink` | `--ink-soft` | `--ink-muted` | `--accent` | `--danger` |
| ----------------------- | ------- | ------------ | ------------- | ---------- | ---------- |
| `--card-paper`（原来）  | 15.65   | 14.98        | 4.67          | 4.54       | 6.12       |
| **`--surface`（现在）** | 17.85   | 17.08        | **5.33**      | **5.18**   | **6.98**   |

五条全部变好 ⇒ 角色墙那屏**一个字色都不用重调**。
★ 这支脚本原来只量天空带与纯纸；这一单**把两层卡面也加进了断言**
（`--surface` / `--card-paper` × 五种墨色）。加断言的理由不是"现在过"，
是下次有人为了好看把卡面调深时**当场红**——手算一遍抄进注释的数是会长腿的。

复算：

```bash
node scripts/check-scrim.mts
```

## 二、整卡可点：z-index 那一半才是重点

- `.cw__open` 是**没有可见内容**的一条链接，铺满整张卡（`position: absolute; inset: 0`）。
  没用现成的 stretched-link（`::after`）那套：`.cw__use::after` 已经被"看这一版"
  用来画 `→`，同一个元素的 `::after` 只能有一份，两条规则同特异度、靠文件顺序决胜——
  那种"改一下顺序就悄悄坏掉"的写法不该留。
- `.cw__actions a` / `.cw__del` / `.cw__detail` 抬到 `z-index: 2`。
  ★ **不抬的话症状是"点『看剩下 3 条』结果跳了页"**：看起来一切正常，只有那一下不对。
- `.cw__open` 带 `aria-hidden` + `tabIndex={-1}`：它是**鼠标的捷径**，
  无障碍路径是动作行里那颗有名字的链接。两个都能 Tab 到的话，键盘用户要按两次。
- 代价写进注释了：覆盖层压在名字/年龄/标签**上面**，那几个字不能被选中。
  不认同的话删掉 `.cw__open` 那一条就退回上一版，别的地方都不用改。

## 三、改档案：`PATCH` + 复用现成的表单

- **新 `src/lib/children-body.ts`**：把 `POST /api/children` 里的 `parseBody` 提出来，
  两个动词共用。不提取的话就是两份"什么算合法的档案"，而两份校验迟早给不同的话。
- `PATCH /api/children/<childId>` 复用同一文件里现成的 `refuse()`，于是
  **示例角色同样改不了**（与删不掉是同一条规矩：**仓库里的东西不改**）。
  合法性判据也不重写——交给 `buildChildRecord` 抛 `profile-invalid`。
- 详情页右栏一格「改基础信息」，直接用 `creation/fields.tsx` 的 `ChildFields`
  （`/character/new` 用的是同一份）。保存 → `router.refresh()`。
- ★ 两句**必须**印在那一格上的实话（不然它就是在骗人）：
  1. 改的是**以后**做的书——已经做出来的那些仍然按当时那份档案（`book.json` 存快照，不是引用）；
  2. 改年龄档**不会重画形象**（卡按七条锚点画，年龄档只在建卡那一次进过提示词）。
- ★ 那一格在 `demoId` 时**不渲染**。但藏起来只是省一次白点，守卫在服务端。

## 四、验证时抓到的两件事（都不是读代码读出来的）

### 1. `updatedAt` 没传 ⇒ 改完的档案看起来"从来没动过"

`NewChildRecord.updatedAt` 的契约写在 `profile.ts` 那句话上：
"**改名时传当前时间；不传就等于没改过**"。第一版没传，于是读回来
`updatedAt === createdAt`。**是读回磁盘对时间戳抓出来的**，不是读代码。

同一条链上还有一个更值得记的读数：`createdAt: Date.now()` 是**故意**传的
（它正好走在 `profile-store.ts` 里"已有档案的 createdAt 不可被改写"那条守卫上），
验证方式就是**读回来确认它没被刷掉**——守卫在别人的用例里生效，不算验过。

### 2. `error` / `notice` 挂在 `current` 挡着的卡片里 ⇒ 删除失败不显示任何话

它们原来写在「想改哪里」那张卡**里面**，而那张卡被 `current` 挡着
（"这个孩子还没有形象"时整张卡不渲染）。于是对**没有形象的孩子**：
删除失败、切版失败、改档案失败——三句"没删掉""没改上"都写进了 state，
**却没有任何地方读它**。界面表现为"点了没反应"。

读代码看不出这个：渲染那句确实在那儿，看着完全正常。
是**在浏览器里对一个没有形象的孩子点保存**时抓出来的。
修法：两条挂到 `.cd__right` 顶上（四个动作共用），不挂在某一格里。

### ★ 没测成的那一条：真视口里的**命中测试**

计划里那三条点击判据（在卡片中心 `elementFromPoint` 命中必须是那条链接；
在「用它做一本」与 `<summary>` 上命中必须是它们自己）**没有测成**。

原因不是元素不对，是**这个会话当前没有打开任何窗口**，预览面板不存在：
`innerWidth/innerHeight` 都是 0，`visibilityState` 是 `hidden`，
卡片的布局退化到宽 128px、那条覆盖层量出来高 1820px。
这个几何量出来的命中结果是噪声，记成"通过"就是自欺。

已经测到的是**机制**那一半（覆盖层 `inset: 0` + `z-index: 1`，
其余可点项 `relative` + `z-index: 2`），它证明的是规则按设计生效；
**没有**证的是"鼠标落在那一点时浏览器真的把事件给了谁"。
两者不是一回事，所以分开写。

要看那三条，把这一页在**有宽度的窗口**里打开（预览面板放到前台，或直接开浏览器），
在控制台里贴这一小段——不需要装任何东西：

```js
const at = (x, y) => {
  const e = document.elementFromPoint(x, y)
  return e ? e.tagName + '.' + e.className : null
}
const mid = (el) => {
  const r = el.getBoundingClientRect()
  return [r.x + r.width / 2, r.y + r.height / 2]
}
const card = document.querySelector('.cw__card')
console.log('卡中心   ', at(...mid(card))) // 期望 A.cw__open
console.log('用它做一本', at(...mid(document.querySelector('.cw__use')))) // 期望 A.cw__use…
console.log('summary ', at(...mid(document.querySelector('summary')))) // 期望 SUMMARY
```

第三行**不是** `A.cw__open` 才算过：那一条就是 `z-index: 2` 那步的判据，
不验等于没做（`<summary>` 在 `.cw__detail` 里面，靠 `.cw__detail` 那一层抬上去）。

同一次里一起看的还有：悬停那四件事（抬升 / 影子散开 / 胶带多掀 / 画推到 1.03）
与 `prefers-reduced-motion` 下的静止终态——**动效在隐藏的面板里量不了**
（`rAF` 与 `transition` 一起冻结，计算值会读到过渡的起点，看着像样式没生效）。
仓库里没有浏览器驱动（`package.json` 只有 vitest），所以这一条**只能人眼过一遍**，
不是"忘了写脚本"。

## 八、这一单**没有**改的（说清楚，不是漏了）

1. **详情页的卡片仍是暖色**（`.cd__card` 用 `--card-paper`）。同一屏上的输入框是
   `--surface`，把卡背改成冷白会让白底输入框在白底卡上消失——那要连输入框一起重新定档，
   不是换一个变量。要不要一起改是用户一句话的事，但那是**另一屏的重新定档**，
   不该混在"角色卡那一屏"里顺手做。
2. **`profile-invalid` 那句共享文案在详情页上指错了地方**。它写着
   「回到第 1 步把名字、名字的读音、年龄档补齐」，而这句是给创作流第 1 步写的——
   在详情页上既没有"第 1 步"，实际的问题也不是"没填"而是"填了一个表里没有的年龄档"
   （只有绕过界面直接把 `7+岁` 发给接口才会碰到，正常点芯片碰不到）。
   ★ **没有顺手改**：`provider-messages.ts` 里那一句是两个入口共用的，
   为了让一个碰不到的场景读起来顺而去改它，会同时改掉创作流里那句话。
   记在这里，等哪天要给 `profile-invalid` 分上下文时一起做。
3. `--card-paper` 令牌本身**没动**（13 个消费者）。这一单只动了角色墙那两个消费者
   （卡身、空态），mat 与标签继续用它。

## 九、第四轮：用户在这张卡的截图上划掉了五处（2026-10-15 当天）

同一张截图回来，用户在卡面上画了叉。划掉的是这五处，都是从**卡面**上删的：

| 划掉的                                            | 原来住哪            | 它原来在说什么                        |
| ------------------------------------------------- | ------------------- | ------------------------------------- |
| 「每一页里那个他，都由这张卡上的几条锚点决定。」  | 页头 `.cw__sub`     | 这一屏的总说明                        |
| 「角色卡 · 第 1 版 · 6 条锚点」                   | 卡上 `.cw__eyebrow` | 版次 + 锚点数                         |
| 读音（`mǎn` / `yǔ`）                              | 卡上 `.cw__reading` | 名字怎么念                            |
| 「4-6 岁 · 水彩形象 · wan2.7-image 画的」         | 卡上 `.cw__meta`    | 年龄 + 画风 + 画它的模型              |
| 「▸ 看剩下 3 条，以及这张卡凭什么算「同一个人」」 | 卡上 `.cw__detail`  | 展开六条锚点的全文 + "画的与查的同源" |
| 「用它做一本 →」                                  | 卡上 `.cw__use`     | 用这张卡开一本新书                    |

卡于是瘦成：**相纸里的脸 + 名字（+「示例」）+ 三条锚点 + 一颗「看这一版」**。

**逐条查过去处**（"删掉的信息去哪了"要有答案，不然就是丢东西）：

- 版次 → 详情页的「版本历史」（同一份 `revisions`，倒序）；
- 六条锚点全文 + 槽位名 → 详情页那张同名的「这张卡凭什么算「同一个人」」（`.cd__anchors`）；
- "画的与查的同源" → 同一张卡的 `.cd__hint`（写着 ADR-0007）；
- 画它的模型 → 详情页 `.cd__foot`（`settings.image.model`，还是活的，不是写死的字符串）；
- 年龄 → 详情页的「改基础信息」里**可读可改**；
- **一条没去处的**：`.cw__photo`（「用过照片，已删除」）留着——它是隐私那一条的**凭据**，
  不是说明文字，删了那条规定就没有可见的证物了。

★ 两个判断记在这里，免得下次有人当成"顺手删多了"：

1. **「用它做一本」删得掉**，是因为查过它**不是唯一的路**：首页 `/home` 那颗角色卡选择器
   走的就是同一个 `/create?card=`（`CreateLanding.tsx:171`），而没有形象的孩子，
   详情页那条「去出一张形象」也还在。这一屏从此只做一件事——**认人**；
   "用他做点什么"从首页发起，那正是第二轮定的口径。
2. **页头那句说明删了之后，`--ink-on-sky` 在这一屏没有消费者了**。
   令牌没变成孤儿（`shelf.css` / `studio.css` / `create-landing.css` 都还在用），

## 十、第五轮：悬停展开那张卡（照 gitee `mao-yongyao/cards`）

用户给了参考源码，要求"实现这样的效果"。那一份只有 `index.html` + `style.scss`（4.3 KB），
下载读过之后，它的机制是一句话：**一只手在牌后面把它撑开**，没有任何真实布局变化。

| 参考实现                                                     | 干什么                                         |
| ------------------------------------------------------------ | ---------------------------------------------- |
| `.show-wrapper { transform: translateY(-25%) }`              | 图 + 标题那一块整体上移                        |
| `.pic-wrapper { transform: scale(0.8) }`                     | 画框**缩小**（不是放大）                       |
| `.title` → `nameAmt` 动到 `translateY(-55%)`                 | 标题上移，去补画框缩掉的那段                   |
| `.show-info { opacity: 0 }`                                  | 静止态那行小字淡出                             |
| `.hover-wrapper` `display:none → flex` + `translateY(-100%)` | 露出那一层从下面滑上来，落在画框底部           |
| `.background { scale(.2,.9) → scale(1.1) }`                  | 一张白面板**从背后撑开**——"卡长大了"全是它说的 |

### 1. 没有照抄的那一处，是布局

参考图那张卡**绝对居中、屏幕上只有一张**，所以它让卡在流里长高，看不出来。
我们是一面网格墙（`gap: 40px 30px`），真长高会让**下面整排跳**。
所以：三条锚点与露出层**共用同一个网格格**（`.cw__fold` 是 `display: grid`，
两层都 `grid-area: 1/1`），这一格的高度自动是两者的较大值——
静止与悬停**卡高完全一样**；
"长大了"那个观感交给 `.cw__card::after`（`inset: 0 -3px -12px -3px`，
`scale(.94) → none`，`z-index: -1`）——只往下溢出 12px，够不到下一排。

★ **第一版是绝对定位**（`bottom: 16px`），写到一半改掉的理由值得记：
露出层高约 62px，而它下方那块地方（标签 + 下内边距）在窄卡上只有约 48px，
所以绝对定位要靠一个**手算的偏移量**才不压到名字——而那个偏移量随卡宽变。
我在这个会话里**没能量到真值**（见第 6 节最后一条），于是没法确认那个数对不对。
换成网格之后，"有没有地方"是**算出来的**：不需要任何魔法数字，
也不需要在窄卡上加一条特例。**量不了的时候，改成不需要量的写法。**

★ 也**没有**采用"留一块空位"那条更省事的写法：静止态卡底会多出约 60px 空白，
读起来像"这里本来有东西、坏了"。现在这 62px 是两层里较高那一层的高度，
标签占一行时确实会多出约 30px 的边空——**那是纸的边空**，比"两层互相压着"好，
也比"悬停时卡突然长高、下面整排跳"好。

### 2. 露出来的两个数是真数，不是编的

参考图上写的是 13k / 14k 的**点赞数**——那种数这个产品永远不会有。
这里露出来的是 **做过的书 N 本 · 最近一本 YYYY-MM-DD**，新接了一条数据：

- `lib/children-list.ts` 加 `listWallItems()`（`ChildListItem` + `books`），
  复用 `listBooks`（`lib/library.ts`）。**只有角色墙读一遍书架**，详情页与创作流不付这份钱。
- 按孩子名下的**全部 cardId** 数（不只当前那张）：一个孩子换过卡号时，
  只数当前那张会把"做过 4 本书"显示成 0，而那个错看着很正常。
- 日期不新写格式化器：`dayKeyOf`（`lib/reading-log.ts`）就是这个仓库对"哪一天"的既有答案。
- **0 本如实说「还没做过书」**，不显示一个 0——一个 0 在那里读起来像"数据没读出来"。

实测（两条独立的数法对上）：

```
① 直接从磁盘数 .out/web/books/*/book.json 的 cardId   → {"xiaolu-r1":1, "xiaoyu-r1":4}
② lib 数出来的                                        → xiaoyu books={count:4, lastCreatedAt:1792058017607}
                                                        xiaoman books={count:0, lastCreatedAt:null}
```

### 3. 换图引起的四个连带改动（不是顺手重做别的屏）

用户在第五轮同时说"生成的人物图片在 `E:\match\public\photo`"。那两张装进去之后
发现一个**必须一起解决**的几何问题：

- 图是 **896×1200（3:4 全身像）**，而卡面那一格是 `aspect-ratio: 1/1` + `cover`。
  按 1:1 中裁每边切 152px，实测**小满的脚切掉 79px（人物高的 8%）、
  小宇的头顶切进去 69px**，而提示词只留了 8% 余量。我把中裁的结果渲染出来看过：
  脚没了、头发顶到画框上沿。
- 改法：`.cw__art` → **`object-fit: contain`**，底色 `--surface-soft`（那是灰）
  → `--surface`。竖构图留下的两条白边正好与图自己的白底（实测四角 252–255）连成一片。
- 缩略图那条路**本来就不裁**（`thumbs.ts` 是 `resize({ width })`），实测确认：
  `?w=768 → 768×1029`、`?w=240 → 240×321`，不是方的。顺带一个读数：
  新图 768 档是 **23.6 KB**（旧的是 1440² PNG，同一档 75.2 KB）。
- 另外三个方框也跟着改（`.cl__pill-face` 24px 圆头像、`.cf__pick-art`/`.cf__picked-art`
  64/96px、`.cf__reuse-thumb` 48px）：`cover` 在 3:4 图上裁出来的是**腰腹那一段**
  （一个没有脸的圆）。这三处是"换了图之后跟着要改的地方"，不是那两屏的重新设计。

### 4. 装图那半条路修了四个坑（都是真跑一次才发现的）

```bash
node scripts/make-demo-cards.mts --out=.out/web --bg=white \
  --images=E:/match/public/photo --model='Google Generative AI'
```

1. **字节一个都不重编码。** 那两张 JPEG 里带着 **C2PA 清单**，实测写着
   `c2pa.created`/「Created by Google Generative AI」与
   `c2pa.edited`/「Applied imperceptible SynthID watermark」。
   补白边到方的要重编码，**那份签名就失效了**——卡上记着"谁画的"，
   而图里那份能核对的凭据被我们抹掉，等于自己剪自己的证据链。
   （所以卡上的 `modelId` 记的是 `Google Generative AI（手工出图）`——
   工具名是 C2PA 自己那句话，不是我们猜的。清单里**没有**模型名，就不写模型名。）
2. **卡已存在时叠一版**（`previous`）。直接 `create` 同一张卡会写出**第二个
   `r1.<指纹>.json`**，而 `store.ts:203` 的 `load()` 是按 `r1.` 前缀取 `keys[0]`——
   两个文件时**取哪个由目录顺序决定**，"这一版到底是哪张图"就答不上来了。
   实测：两卡 `latest=2`，r1 的 JSON 与 PNG 一个字节没动，4 本指着 `xiaoyu-r1` 的书照旧。
3. **`--images` 那条路的 `--model` 不再回落到 `wan2.7-image`**。回落等于**编一个来源**：
   装一张别人用别的工具出的图，卡上会写"wan2.7-image（手工出图）"。
   脚本没有任何办法知道那张图是谁画的，所以默认改成"未记录工具"。
4. **不拿运行期副本盖示例档案。** `children-source.ts:80` 是"同 childId 时运行期那条赢"，
   往 `.out/web/children/` 写一份与 `public/demo/children/` 同名的档案，这两个孩子
   就从 `demo` 变 `runtime`——「示例」两个字消失、**「删掉他」冒出来**，
   点下去服务端还以 `demo-child` 403 拒绝。脚本现在**认出示例档案就不写**。

视觉核对（视觉模型自比，两张都 score=1、**六条锚点零遗漏**）：
新图里六条锚点确实都画出来了，不是"看着挺像"。

### 5. 无障碍：三条路分开说

- **键盘**：名字现在是链（`.cw__name-link`），静止就可见可聚焦 →
  `:focus-within` 把悬停层打开 → 再 Tab 才够得到那两颗。
  静止时露出层是 `visibility: hidden`，所以里面的东西**不进 Tab 序列**——
  否则每张卡会多出两个看不见的停留点。
- **读屏 / 悬停层不是无障碍路径**：它与名字指向同一处，删除入口在详情页也有一份。
  同 `.cw__open` 那条理由——鼠标的捷径可以没有名字，但不能是唯一的路。
- **触屏 / `prefers-reduced-motion`**：这一层**直接停在展开态**。
  ★ 那一档里 `display: grid` 改回 `display: block`：两层叠在同一个格子里时
  要"同时在"就必然互相压住，顺序排下来才对（少动 ≠ 少信息）。
  `prefers-reduced-motion` 要的是**少动**，不是**少信息**——藏起来的操作
  在没有 hover 的设备上等于不存在。

### 6. 验过的与**没验成**的

验过（都是真读出来的数，不是"应该没问题"）：

| 判据                                 | 怎么读的                                         | 读数                                                                                   |
| ------------------------------------ | ------------------------------------------------ | -------------------------------------------------------------------------------------- |
| 图不再被裁                           | `.cw__art` 的计算值                              | `object-fit: contain` · `background: rgb(255,255,255)` ✓                               |
| 缩略图也没被裁                       | 真取 `?w=768` 的字节再量                         | `768×1029`（3:4 保住了）✓                                                              |
| 静止态露出层是藏着的、且在覆盖层之上 | `.cw__reveal` 的计算值                           | `relative` · `opacity: 0` · `visibility: hidden` · `z-index: 2` ✓                      |
| 背后那张面板静止时不画               | `.cw__card::after` 的计算值                      | `opacity: 0` · `transform: matrix(0.94,…)` · `z-index: -1` ✓                           |
| 静止态卡上没有旧的东西               | SSR HTML 逐个探                                  | `cw__actions` / `cw__use--ghost` / `cw__detail` **全无** ✓                             |
| 新的结构与 DOM 顺序                  | SSR HTML（下标单调递增）                         | `show` > `mat` > `name-link` > `fold` > (`tags`, `reveal` > `stats`, `use`) > `open` ✓ |
| 两个数是真数                         | SSR HTML + 磁盘两路对照                          | 「4 本书 · 最近 2026-10-15」／「还没做过书」✓                                          |
| 示例卡不给删除入口                   | 卡面 DOM                                         | 第一张（xiaoman，demo）的露出层里**只有** `cw__use` ✓                                  |
| 三条闸门 + 496 个用例                | `pnpm format:check && lint && typecheck && test` | 全绿 ✓                                                                                 |
| 对比度                               | `node scripts/check-scrim.mts`                   | PASS（这一轮没动任何令牌）✓                                                            |

★ **没验成**的两条，分开写清：

1. **悬停那五件事**（块上移 / 画框缩到 0.9 / 锚点淡出 / 露出层浮现 / 面板撑开）
   与**触屏、`prefers-reduced-motion` 的展开终态**：这个会话**没有打开任何窗口**，
   `innerWidth` 是 0（`getBoundingClientRect` 在这种状态下给的是**错的数**，不是零），
   `preview_resize` 的 mobile preset 也压不进去——`matchMedia('(hover: none)')` 仍是 false。
   所以那两条**只能人眼看**：动效在隐藏的面板里量不了（rAF 与 transition 一起冻结），
   而 `(hover: none)` 那条分支我连模拟都没模拟上。
   要看：把 `localhost:3100/character` 在**前台窗口**里打开（鼠标移上去），
   触屏那条在 DevTools 里切设备模拟；`prefers-reduced-motion` 在系统里打开"减少动态效果"。
   ★ 期间**试过一次绕路**，记下来免得下次再试：在外层文档里建一个
   `width: 372px` 的 iframe、把 `/character` 的 HTML `document.write` 进去，
   想借 iframe 自己的视口量卡片几何。**没成**：外层文档是 0 宽时 iframe 里的
   布局宽度并不听话（量到卡片 790px / 1129px 宽，而那个宽度下卡片是另一副样子），
   而且写进去的样式表是异步加载的（我按"元素出现"轮询，读到的计算值还是默认值
   ——`position: static`、`opacity: 1`）。判据得改成等**样式生效**而不是等元素出现；
   更要紧的是**那个宽度不是真实宽度**，量出来的数不能当成卡片的真值。
   这条绕路的产出是上面第 1 节那个结论：**量不了的时候，改成不需要量的写法。**
2. **自建孩子的卡上有「删掉他」**：这个工作区里**没有**自建孩子（两个都是示例），
   所以那条分支这一轮**没跑到**。那段判断是第四轮验过的，这一轮只是把它挪了位置。
