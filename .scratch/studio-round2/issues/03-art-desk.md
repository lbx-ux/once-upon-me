# 03 · 画桌：一页一格，画出来的每一格都看得见

Status: done（2026-10-15）
依赖：01（配色）、02（主页把三件事收齐了，这一屏才轮到"只剩画"）

用户的第 2 条后半句：「这个创作的这个页面该怎么做呢，我现在没有什么好的思路，
但是不要和现在的一样，一点都不好看，你有什么想法呢」。

## 一、把"过程"从文字改成东西

原来生成那一步是一行一行的文字日志（`cf__log`）。它说的事都对，但**看不见产出**——
20 行的"第 13 页画好了"与一张第 13 页的画，是两件完全不同的事。而"看着一页一页画出来"
正是这一屏唯一能让卖点自己说话的地方（#2 Agent 分压在这儿）。

## 二、四条设计判断

| 判断                               | 具体的坏法（不这么做会怎样）                                                                              |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **空画框就是进度**，不另画百分比条 | 20 格里画好 7 格是**看得见的事实**；一根 35% 的进度条是**编出来的数**。两者在屏幕上一样宽，只有一个是真的 |
| **取不到图时留相纸色的空框**       | `illustration` 的 `assetPath` 与文件落盘之间可能有先后，那一瞬 404 会留下**碎图标**                       |
| **致命错误不藏进格子**             | 藏进去就变成"第 7 页有点小问题"，而实际上是整轮完了                                                       |
| **正在画只有一圈静态描边**         | 引擎**没报**这一页画了多久、还要多久，所以任何转圈的 spinner 都是在编一个不存在的进度                     |

## 三、归格规则是纯函数，单独一个文件

`components/creation/frames.ts` 的 `deskOf(events)`：一串事件 → 一张画桌。
**三条判据**（每条都对应一种真的会错的写法，逐条有测试）：

1. **`illustration` 是覆盖，不是追加**。同一页重画时引擎会再发一条（带 `attempt`），
   而它说的是**同一格**。写成 push 的话，20 页的书重画 3 页会变成 23 格，而标题写着 20 页。
2. **`plan-ready` 一到就把空画框全摆出来**（它带 `nodeCount` 但不带 `pageNo`，所以格子是索引出来的）。
3. **不带 `pageNo` 的阶段事件不占格**——真塞进去会出现"第 21 页：正在装订"。

★ 「哪一格正在画」是**事件说的，不是猜的**：引擎每一页动手前会发一条带 `pageNo` 的
`stage(begin, illustrating)`。写这一层时我按常识以为核对阶段也有同样一条，
**录下真流之后发现没有**（`illustrate.ts` 在 checking 那一段发的是 `consistency`，
而它带着判定结果，意思是"核对完了"）——所以这一层**不声称**"第 N 页正在核对"，
`busy` 也从 `'drawing' | 'checking'` 收成了只有 `'drawing'`。注释里把那句错的推理改掉了。

## 四、测试喂的是**真跑过的那条流**

`components/creation/fixtures/stub-run.events.ts`：`node scripts/engine-run.mts --mode=stub
--pages=5` 的 19 条原始事件，逐条抄下来（只省掉每次都变的 `at`，其余一字未改）。
为此给那支脚本加了 `eventsRaw`——原来它只写**人读的句子**，页码揉在句子里，
任何要按页处理事件的消费者都没法从它还原结构。

★ 这份 fixture **不覆盖**"重画"（stub 的替身永远一次通过，`attempt` 全是 1），
所以那条规则由手写事件钉住。这句话写在 fixture 的文件头里，免得下一个人以为它覆盖了。

## Comments

### 浏览器实测（真事件，不是"看着像"）

`/create` 这一屏的**实时**那段（一次真跑，文本与图像指向本地替身，
因为真 key 按 ADR-0008 只活在内存里、进不了浏览器）：

```
t=0.0s  3 格空框（a=0 b=3）  0 / 3 页画好了   正在编故事…
t=0.4s  3 格空框，1 格 data-busy=true       正在画…
t=1.4s  1 格有图，2 格空      1 / 3 页画好了   正在画…
t=2.5s  2 格有图，1 格空      2 / 3 页画好了   正在画…
t=3.6s  3 格有图，0 格空      3 / 3 页画好了   书做好了：<id>（收成封面 + 翻开来看看）
```

**空画框先出现 → 一页一页填 → 装订 → 封面**，四步都在真事件下走通了。
书名《小宇的云》来自 `plan-ready`，页数 3 来自 `nodeCount`。

### 重画那条规则在**真书**上验过

`.out/web/books/xiaoyu-r1-73cdf2d0051a` 是一本真跑出来的书（3 页，**每页都重画过**：
`page-N-a1` → 核对 fail → retry → `page-N-a2` → 核对 pass）。用刷新重放那条路
（`replayFrames`）喂进画桌：

- 结果正好 **3 格**（不是 6 格），每格显示的都是 **a2** 那张
- 三张图**真的加载出来了**（`naturalWidth = 384`——请求 `?w=320`，
  服务端按封闭档位向上归到 384，与 `lib/thumbs.ts` 那条约定一致）
- 每格**没有**残留"不太像"（最后一次核对是 pass，而新图到了会让上一条让位）
- 旧的那串 `cf__log` 已经不在 DOM 里（`querySelectorAll('.cf__log').length === 0`）

### 取不到图那一格（计划里要求"中途验一次"）

把那本书第 2 页的原图**和它的缩略图缓存**一起挪走（只挪原图没用——
320 档请求会命中已生成的 384 档缓存，实测确认过），再重放：

- `/api/assets/...` → **404**
- 那一格**`<img>` 整个不在 DOM 里**，显示的是 `.dk__blank` 那个相纸色虚线框
- 页面里 `complete && naturalWidth === 0` 的 `<img>` **0 个** —— 没有碎图标

★ 一个**刻意留下的取舍**：这种情形下上面那行仍然写着"3 / 3 页画好了"。
因为 `drawnCount` 数的是"事件说画好了"（`assetPath` 有值），
而不是"浏览器这会儿取得到"。数后者的话，这个数会随网络抖动、还会闪。
代价是"3/3"与那一格空框并排看会有点别扭——**记录在这里**，不是没想到。

### 这轮的验证方式本身也值得写下来

浏览器里跑真模型需要 key，而 key 按 ADR-0008 只活在内存里、刷新即失。
所以这次的做法是：**本地起一个替身供应商**（同时当文本与图像：
文本回录下来的真故事表 `scripts/fixtures/demo-plan.json`，图像回仓库现成的
`public/book/spread-*.webp`，每张人为慢 1.1 秒，好让"一页一页"看得见），
在设置抽屉里填**非密钥**的值指向它。于是**界面那条路整个跑通了**，
而真 key 一次都没进浏览器。

★ 那个替身脚本写在 `.out/`（gitignore 的草稿区），**没有入库**：
它是测试替身、不是量具，与 `scripts/check-scrim.mts` 那种"进了仓库才有人重跑"的东西
不是一类。要复现按上面这段描述写十行就够。

★ 同一份替身第一次跑是**失败**的：`demo-plan.json` 是一棵**共读版**的树（带选择点），
而 `/create` 做的是独读版，schema 校验不过 → 重试三次 → 那一轮没有产出。
把它改成线性形状（丢掉 `via` 分叉、抹掉 `choice`）才跑通。
记在这里，是因为它顺带说明了一件事：**这一屏只做独读版**，
而共读版的树连"跑一遍看看"都还进不来。
