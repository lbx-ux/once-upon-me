# 01 · 冷白与重量

Status: done（2026-10-15）
依赖：无（但它必须先做——底色一换，02/03 每一处文字的对比度归属都要按新表判）

解的是用户那三条里同源的两条：「侧边栏太重、和右侧割裂」与
「一向下滚下面的底色又变成橙色」。

## 一、一处改动，三个消费者

```
--paper:     #faf5ee → #f4f8f9      （250,245,238 → 244,248,249）
--paper-rgb: 250,245,238 → 244,248,249
```

`--paper` 的消费者只有三处（`.sb` 底色、`.sb__veil` 每一档、侧栏那层纸），
所以换它是单点改动。换的理由写在 globals.css 里那段长注释与 README §五：
**接缝不是"被处理掉了"，是"不存在"**——天空带往下混的就是它自己那个颜色。

★ 天那个冷白的来源不是挑的：它是 `scene-1.webp` 顶上两行均值的圆整
（`--sky` 的取值过程，见 studio-sky 工单 01）。纸跟着画面走。

## 二、侧栏 α 0.90 → 0.78

0.90 那一档是"在暖纸上压住天"定的。纸与页面同族之后压住不需要那么厚，
那 12% 就是"太重"的全部来源。

## 三、量具补了一条它没有的断言

原来表里只在脚注写了一句"天空带以下那一段 globals.css 已量过"。
现在**那一段才是灰字与橙字真正的家**，所以把它变成脚本算出来的一行
（四种墨色全断言），不再手抄；并新增 **R−B 冷暖列**与一条硬断言：
**天空带最后一段与下面那块纯纸必须同号**，异号 = 交界处有一次冷→暖的换色，
直接 FAIL。这条断言把用户那句"底色又变橙了"变成了机器能判的东西。

## Comments

- 实测（`node scripts/check-scrim.mts`，1440×900）：十段里最后一段 R−B **−5.0**，
  纯纸 **−5**，同号；整列从第 1 段的 −19.2 单调走到 −5.0，**一次都没跨过 0**。
  换纸前的纯纸是 `250−238 = +12`，所以那次"跨 0"是真的存在过。
- **反直觉的读数**：翻成冷白之后对比度**比原来那颗暖纸还好**
  （16.45/4.92/4.77 → 16.69/4.99/4.84），因为 244,248,249 的整体明度更高。
  两头都赚的改动最该怀疑自己算错了，所以脚本里那四条断言是硬闸门。
- 侧栏减淡之后 `--accent` 从 4.66 掉到 **4.59**，仍过 4.5。这一档之所以还站得住，
  是因为侧栏上唯一直接压着纸的强调色文字是 `.shell__brand-en`（品牌英文名）；
  当前项那枚橙字压的是 `--surface`（4.84）。
- 暖色没有丢：`--card-paper`(#f7efe3) 还在，它才是**物件**的相纸色。
  `.cw__mat`（裱照片的卡纸）与 `.cw__tag`（手写标签）在这一轮明确钉到它上面——
  这两处原本用的是 `--paper`，在那个语义下是**碰巧**对的（当时两个都叫"纸"）。
