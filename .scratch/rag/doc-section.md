# RAG 技术应用（评分表 #3）—— 技术文档·这一节的草稿

> **这一节要回答的是评审的三句话**：**检索什么** / **怎么检索** / **提升多少**。
> 三条各自有落点、有量法、有可复现的命令；读不完的话，只看每节开头那一句粗体即可。
>
> ★ 这一节的数字全部来自仓库里的脚本，命令写在第 §六 节。
> **没量出来的地方写"不显著"**，不写成"质量提升"——这是这个项目的一条纪律。

---

## 一、检索什么：**三份语料，归属各不相同**

| 语料           | 是什么                                  | 归属         | 落在哪                                              | 份量                 |
| -------------- | --------------------------------------- | ------------ | --------------------------------------------------- | -------------------- |
| ① **种子**     | 12 本样书的跨页（人工写好、配好图的书） | 仓库资产     | `src/lib/rag/index.seed.json`（生成物，随仓库提交） | 96 跨页 · 39899 字节 |
| ② **创作史**   | 这个家庭自己写过的书                    | **用户私有** | **不落索引**，每次现场扫                            | 随这个孩子长大       |
| ③ **审核条款** | 内容红线的条款库 + 词表                 | 仓库资产     | 代码即语料（`src/lib/rag/review-corpus.ts`）        | 9 条 · 8 类          |

三份的**归属不同，所以落点、许可、检索时的过滤条件全都不同**。要紧的一条是：
**②一个字节都不进仓库，`owner` 是检索里唯一一道隐私边界**——
`example` 那一侧只取 `library` + 自己，`avoid` 那一侧**只取自己**。
不这么做，症状是「别人家孩子的书正文被喂进了这个模型的上下文」，而它在界面上看不出来。

★ **还有一件必须主动说清的事：我们不声称"12 本样书需要检索"。**
实测：96 个跨页的正文合计 **6031 汉字 ≈ 4.3k token**——**一次全塞进提示词都放得下**。
所以种子语料**不构成** RAG 的正当性，它只是**冷启动**（让模型看见"同一个年龄档、
同一个主题下写完的句子长什么样"）。检索真正的理由是 ②：那是这个家庭一本本攒出来的文本，
**会随这个孩子长大，几十本之后一次塞不进、也不该塞**。
★ 换句话说：这一栏在我们这里的正当性是"**语料会长到塞不进去**"，
而不是"我们要用检索"。这条判断写在 `docs/known-tradeoffs.md` 的「检索那一层」第一节。

## 二、怎么检索：一条**纯函数**流水线

```
查询 = (年龄档, 主题, 形态, 家长那句 wish, 已有草稿)
   │
   ├─ 1. 硬过滤（两个极性的强度不同，见下表）
   │      ★ 过滤不命中 = 空集；**空结果是合法结果**，不许兜底成"随便给几条"
   ├─ 2. 打分：中文字符 bigram 倒排 + BM25（k1=1.2 / b=0.75），一份排序
   ├─ 3. 阈值：按**池子被收窄的程度**分两档（见下）
   └─ 4. 取 top-k（k=3）；**正反两面同一次取出，且不重叠**
```

**两个极性的过滤强度不同**（这一格是"检索策略是否合理"最直接的答卷）：

| 极性      | owner        | 年龄档                   | 主题         | 形态         |
| --------- | ------------ | ------------------------ | ------------ | ------------ |
| `example` | 库 + 自己    | 同档或**相邻一档**或通配 | 同主题或通配 | 同形态或通配 |
| `avoid`   | **只取自己** | **不过滤**               | **不过滤**   | 同形态或通配 |

- `example` 收**相邻一档**：库里 96 条全是 4-6（12 本样书的主角都写着"约 5 岁"），
  只收同档的话，一个 7 岁孩子的请求**一条范例都取不到**——而对四个年龄档里的三个，
  那恰恰是最需要它的场景。
- `avoid` **全都不过滤**：它的语义是「**这个孩子已经读过了**」。读过就是读过，
  上个月读的是独读版 4-6 档、这次要共读版 6-8 档，落点重复一样要避。
- `form` 两侧都要求"同形态或通配"：拿独读版的落点去避共读版的重复是错的。

**阈值分两档（2026-10-19 第二轮改的，依据是实测）**：

| 什么时候                                                  | 用哪一档 |
| --------------------------------------------------------- | -------- |
| 池子是**整座库**（请求里认不出主题 → 只有形态与年龄约束） | 2 分     |
| 池子已被**主题**（`example`）或 **owner**（`avoid`）收窄  | 1 分     |

一句话：**阈值管的是"收窄之后剩下的精度"**；池子已经被元数据收窄过，阈值不必再收窄一遍。
改这一处的依据是量出来的：同一主题那本样书的跨页，按"与家长那句话的字符重合"打分只有
**1.5–1.8**，被一刀切的 2 分全挡在门外——10 个主题里有 3 个**一条范例都取不到**，
那三本的两臂提示词**逐字节相同**（剂量为零，占第一轮样本的 30%）。
而主题在元数据里是**确定的**，字符重合只是它的**代理**；**让代理去否决信号**，是那一处错的形状。
改完的读数：取到范例的主题数 **6/10 → 10/10**。

**为什么不做向量档**（这一条也是"策略是否合理"的一部分）：
`POST /v1/embeddings` 的路由是活的（用不存在的路径与确定能对话的模型做过判别对照），
但这把 key 上**没有一个模型支持嵌入**——目录里 26 个已服务模型逐个测过，0 个 200。
于是**整条向量层被砍掉**：不写 `providers/embeddings.ts`、不加 `EMBEDDING_*`、
不做 RRF 融合（**一档排序做融合是自欺**），`provenance` 里也**没有** `mode` 字段
（只有一个值的字段是常量，而常量字段会让下一个读的人以为"另一档存在，只是这次没走"）。
取舍写成了一份决策记录 [ADR-0011](../docs/adr/0011-index-is-a-file-not-a-vector-db.md)。
词法档的代价写在明处：**字符 bigram 对同义改写与长词召回弱**
（"雪橇"与"滑雪板"在字符层几乎不相干），不引分词器的理由是它是原生依赖，
会破坏"不联网、不跑构建也能跑完一本书"这条引擎硬约束。

**超参不是拍的**：`k ∈ {1,3,5}` × `narrowedMinScore ∈ {0.5,1,2}` 九格表，
**$0 成本、可复现**（`--dryRun=1` 一路不调模型）。定稿 `k=3`（k=1 平均 1.0 条范例、
k=3 是 2.1 条、k=5 是 2.3 条，边际递减的拐点）。

## 三、接在哪：**两个生产消费者**，不是旁挂脚本

| 消费              | 落点                                                          | 它拿到什么                                                         |
| ----------------- | ------------------------------------------------------------- | ------------------------------------------------------------------ |
| **规划**（①）     | `engine/plan.ts` → 提示词 `story-plan@v4` 的检索段            | 正例「可以照着这个节奏写」+ 反例「这些你已经给他写过了，不要重复」 |
| **内容审核**（③） | `engine/review.ts`（纯函数）+ `rag/review-corpus.ts` 的条款库 | 命中的条款 id、命中的词、上下文；`rewrite` 与 `block` 两种处置     |

- **挂在入参上，不在流水线里**：`planBook` 的 `retrieve` 是一个可选入参，
  **不传就是这一轮不检索**——所以"开与关"是同一行代码的两个值，**不是两条流水线**。
  跑测脚本因此可以直接量"只差这一个字段"的两臂（见 §四）。
- **出处可见**：这一版故事是看着哪些旧文本写出来的，记进 `Provenance.retrieval`
  （语料指纹 + 每一条的 chunk id / 出处 / 分数 / 正反哪一侧），
  事件流里报一句「翻到了 3 段可以照着写的」，工作台的运行视图直接消费它。
  ★ 出处的**标识**（书名 + 页码）给模型、也存进出处记录，但**不印在页面上**——
  它是"这句话从哪儿来的"，不是这本书的一部分。
- **一条硬红线写进提示词也写进纪律**：范例**只许参考节奏与用词，不许照抄句子**。
  照抄来的那本书就成了别人的书，而这个产品的第一句话是「以自己孩子为主角」。
  这条线的量法见 §四 的 `④`。
- **出图那条没接**（这一轮的范围之外）：它也**没有留接口**——
  检索现在是纯函数，将来要接就是调一个纯函数，不需要今天先埋一个读不懂的空壳。

## 四、提升多少：**预声明判据 + 配对设计**，以及一个必须如实说的结果

### 4.1 第一轮（v1）：判据在**这个模型上饱和**，两轮读数**变号**

预声明口径（跑之前写在 spec 里）：Schema 一次通过率 **+10 个百分点** 或 平均重试 **−0.3**。

| 轮次   | `off` 一次过 | `lexical` 一次过 | 差                 | `off` 平均重试 | `lexical` 平均重试 |
| ------ | ------------ | ---------------- | ------------------ | -------------- | ------------------ |
| 第一轮 | 10/10        | 10/10            | **0.0 个百分点**   | 1.00           | 1.00               |
| 第二轮 | 9/10         | 10/10            | **+10.0 个百分点** | 1.10           | 1.00               |

**同一个配置，差的那一本在两轮里换了边**——所以报告写的结论行是「**结论不稳定**」，
不是挑好看的那一轮标"显著"。三条量出来的原因：

1. **这个模型在格式上本来就饱和**：两轮 60 次调用只 1 次重试；
2. **n=10 时一本书就等于 10 个百分点**，而阈值正是 10 个百分点；
3. ★ 那唯一一次重试**根本不是格式问题**，是**内容审核**拦下的
   （`R-01`「恐怖」）——也就是说这一栏测的甚至不是"检索让模型更会写 JSON"。

### 4.2 第二轮（v2）：换落点、换语料、换设计（**判据写在跑之前**）

v1 的口径是拿一个饱和的代理量测"质量"，而且三分之一的样本剂量为零。所以：

| 换什么               | 换成什么                                                                                  | 为什么                                                                 |
| -------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **判据落点**         | 主判据 `③`：新书与本主题那本旧书的重复度；副判据 `②`：超长句（>18 字）比例                | 两个端点都落在**文本本身**，且都是产品承诺的直接判据                   |
| **②创作史**          | 由**本流水线自己产出**（先用 `off` 臂每主题生成一本，再当作"他已经读过的书"）             | 手写的旧书落点不是模型会写的那些——那是 `③` 在第一轮**饱和为 0** 的原因 |
| **样本与检验**       | 10 主题 × 每主题 3 次 = **30 本/臂**；配对单位是**主题**，Wilcoxon 符号秩的**精确零分布** | n=10 时一本书=10 个百分点；把 30 本当 30 个独立观测会高估显著性        |
| **门槛（跑前定死）** | 主判据 p<0.025 且效应量 ≥5 个百分点；副判据 p<0.05 且 ≥3 个百分点                         | 两个端点，压住族错误率；同时要求效应量，免得"显著但没用"               |

★ v1 的读数与结论**原样留在报告里**，不覆盖、不重算——v2 是新跑的一轮，
不是拿旧数据换个算法重判。

### 4.3 v2 的读数：**两个端点都没过**，而且"不显著"离"差一点"差了一个数量级

跑法：`--books=10 --repeats=3 --cells=3:2:2`（10 主题 × 每主题 3 次 × 3 臂 + 先造 ②创作史），
**60/60 全部测成**（限流 0、调用失败 0）。成本 114 次文本调用。

| 端点（配对，精确符号秩） | `off` 均值 | `lexical` 均值 | 差                | p    | 门槛           | 判   |
| ------------------------ | ---------- | -------------- | ----------------- | ---- | -------------- | ---- |
| `③` 与本主题旧书的重复度 | 3.3%       | 3.8%           | **+0.5 个百分点** | 0.81 | ≥5pp · p<0.025 | 不过 |
| `②` 超长句（>18 字）比例 | 6.1%       | 5.8%           | **−0.3 个百分点** | 1.00 | ≥3pp · p<0.05  | 不过 |

**功效（事后算的，只用来解释"为什么测不出"，不参与裁决）**：
`③` 的**最小可检测效应是 4.9 个百分点**（主题级差值 SD 5.5pp、10 个主题、α=0.05、功效 0.8），
`②` 是 **16.1 个百分点**。观测到的差是 **1 个百分点上下**——**与设计能看见的量级差了一个数量级**。
也就是说"不显著"在这里不是"差一点"，而是**远在可检测范围之下**：
要让这点差异变成"显著"，样本量得抬高一到两个数量级。

★ **一处我们自己的口径错，写在这里而不是悄悄改掉**：`③` 预声明的效应量门槛是
**≥5 个百分点**，而对照组的基线只有 **3.3 个百分点**（同一主题旧书的 6 字重合率）——
**重复度不可能低于 0，所以那道门槛在数学上就达不到**。门槛是**量出基线之前拍的**，
这是本轮设计里的一处真错误。下一个想测"不重样"的人：**先量基线，再定门槛**。

**③ 这条端点在 v2 里第一次"活了过来"**（这一点值得记）：v1 用它测手写的旧书，
两臂都是 0.0%（**饱和**）；v2 把 ②创作史换成本流水线产出的 10 本之后，
`off` 臂的基线变成 **3.3%**（个别主题到 16.7%）——**"他读过了"这件事第一次真的可测**。
量具修好了，只是**treatment 的效果没被量出来**。

### 4.4 两轮里那几条**方向性**的读数（★ 探索性，**不是判据**，别当结论读）

跑测报告里另有一栏是不参与裁决的描述量。它们在两轮里的方向值得看一眼，
但**p 值都不显著**，所以它们只用来解释"下一步该往哪儿看"：

| 量                                      | `off`      | `lexical`  | 观察                                                                        |
| --------------------------------------- | ---------- | ---------- | --------------------------------------------------------------------------- |
| 落在 12–18 字区间（适龄区间）的句子比例 | 45.5%      | 50.3%      | **+4.7 个百分点**（p=0.63）——方向对，但主题级的抖动有 ±40 个百分点          |
| 与范例的句子重合率（`④`，反向指标）     | 0.3%       | 1.0%       | 仍**远低于**验收线（对照组 +5 个百分点）——**没有照抄污染**                  |
| 内容审核命中（故事踩到内容红线的本数）  | **4 / 30** | **0 / 30** | 开了检索的 30 本**一次都没踩到红线**；3 个主题对 0 个（**不显著**，n 太小） |

★ 最后一行是这一轮里**唯一一个方向一致、且量级看起来不小**的信号：
`off` 臂那 4 次重试全部来自**内容审核**（`R-01`「恐怖」/「狰狞」），
而两条开了检索的臂**一次都没有**。机制上讲得通（范例是人工写好的适龄文本，
模型跟着它写就更不容易越线），但它**没有被预注册、也不显著**，
所以这里只能写成"下一轮值得单独测的一条"，**不能写成"检索提升了安全性"**。

### 4.5 两条护栏（v1 两轮都跑过，v2 一并报）

- **`④` 与范例的句子重合率**（反向指标，验收线 = 对照组 + 5 个百分点）：
  v1 两轮三条臂**全部 0.0%**——**没有照抄污染**，"只许参考节奏"那条红线守住了。
- **`③` 与自家旧书重复度**：v1 **饱和**（对照组本来就 0），测不出差异；
  v2 换成本流水线产出的旧书之后它才**活得起来**（v2 的读数见 4.3）。

## 五、边界与已知缺口（**如实写，不糊弄**）

1. **词表档不是"覆盖红线"**：内容审核的词表能抓**写得明明白白的**那些，
   抓不到谐音、拼音、委婉说法（"睡着了没醒"）、外文与 emoji、以及没有脏字的吓人。
   所以能说的只有：「**命中的一律拦下，这一批词可枚举、可复核；剩下的那几类今天没有判据**」。
   判据脚本 `scripts/review-cases.mts` 的十条里**故意有一条用委婉说法绕过**，
   它**预期就是漏**——那条不是失败，是把这道闸的边界钉在纸上。
2. **适龄字表还没做**（`R-09`）：报告里那个"超纲字比例"用的是**代理量**
   （"这个字在那 96 段人工样书里一次都没出现过"），它只说明"不常见"，不等于"超纲"。
3. **剂量依赖语料**：种子只有 96 跨页；`②创作史` 在真实产品里会长大，
   这一轮里它是流水线跑出来的 10 本（可复现，但规模小）。
4. **采样不可固定**：这条网关上**没有 seed 参数**，所以两臂之间无法固定采样，
   因此用了配对设计 + 多次重复 + 逐本明细（报告里贴散点，不只看均值）。
5. **`scripts/*.mts` 不在 `pnpm typecheck` 的范围内**
   （`tsconfig.json` 的 include 是 `**/*.ts` / `**/*.tsx`）——量具本身只有一个 lint 闸门，
   这一条是 2026-10-19 现场撞到的（一个拼错的名字只在运行到那一步才炸）。

## 六、可复现清单

```bash
# 1) 索引：从 12 本样书重建（同输入同指纹）
node scripts/build-rag-index.mts

# 2) 检索侧的全部读数（预检 / 分数分布 / 超参扫描）——$0，不调模型
node scripts/rag-bakeoff.mts --dryRun=1 --books=10

# 3) 判据 4 的两臂跑测（v2：10 主题 × 3 次 × 3 臂 + 先造 ②创作史）
node scripts/rag-bakeoff.mts --books=10 --repeats=3 --cells=3:2:2 --out=.out/rag-gain-v2
#    报告：.out/rag-gain-v2/report.md（配对表、逐本明细、超参扫描、成本）

# 4) 内容审核那道闸的判据（10 条越线 × 96 段真样书零误拦）
node scripts/review-cases.mts

# 5) 引擎硬约束：不联网、不启浏览器跑完一本书（带 --retrieve 走一遍检索的生产路径）
node scripts/engine-run.mts --mode=stub --form=shared --retrieve
```
