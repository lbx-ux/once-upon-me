> ★ **本单在 2026-10-19 按工单 01 的实测收窄过一次。** 原版写的是
> 「纯函数 + 两档（词法打底 / 向量可选）」，含一个 `Retriever` 能力接口、
> 一个 `providers/embeddings.ts` 与一层 RRF 融合。工单 01 量出**这把 key 上
> 没有任何可用的嵌入模型**（26 个已服务模型逐个测成、0 个 200），

> 一个 `mode: 'lexical' | 'hybrid'` 的字段会让人以为「另一档存在，只是这次没走」，
> 而那是这一栏最不需要的误会（`example-wishes.ts` 里「留一份没人读的表，
> 下一个改的人会漏改它」是同一条纪律）。

## 这一张的产出

`src/lib/rag/retrieve.ts` · `score.ts` · `prompt.ts`。**纯函数，不进能力层。**

## 一、纯函数那一半（主战场，`pnpm test` 覆盖）

```ts
export type RetrieveQuery = {
  ageBand: AgeBand
  theme: string
  form: BookForm
  text: string // wish / reviseNote / 已有草稿拼出来的查询串
  owner: string // 检索发起人；② 只在这个 owner 的片里取
  polarity: 'example' | 'avoid'
  k: number
  minScore: number
}
export type RetrieveHit = { chunk: RagChunk; score: number; why: string }
export function retrieve(query: RetrieveQuery, index: RagIndex): RetrieveHit[]
```

四条不许违背：

1. **硬过滤在前，打分在后。** `ageBand` / `theme` / `form` 是过滤不是特征——
   `'*'` 通配，具体值必须相等。把约束做成打分特征，症状是「8 岁档的句子漏给 4 岁档」，
   而分数看起来还挺高。
2. **空结果是合法结果。** 过滤后为空、或全低于阈值 → 返回 `[]`。
   ★ **不许**兜底成「随便给几条」，也不许在调用方把空当成错误去重试
   （这个项目在「空值算不算错」那一节付过假拦的学费）。上游拿到 `[]` 就是「这次没有可参考的」，
   照常往下编故事。
3. **`owner` 是硬边界。** `polarity: 'avoid'` 只取 `owner === query.owner` 的 chunk；
   `'example'` 只取 `library` + 自己的。**跨 owner 取不到**要有单测。
4. **`why` 是可解释性**：一句话说清「为什么是它」（命中了哪些 bigram / 哪个约束）。
   它进事件与 provenance，是判据 6 的原料。

## 二、打分（`score.ts`）

- **中文按字符 bigram 建倒排，套 BM25**（k1=1.2, b=0.75）。这就是全部的打分。
  ★ 为什么不用分词器：中文没空格，而引一个分词器是给数百条语料上重装备；
  bigram 在零依赖下给出可解释的排序。理由写进文件头——
  **这就是「检索策略是否合理」的答案本身**。
- **没有融合那一步。** 只有一份排序，做 RRF 是自欺（它是为两份排序准备的）。
  这一条要写进文件头，免得下一个人照着"标准 RAG 架构"把 RRF 补回来。
- **它必须能在离线跑**：`engine-run --mode=stub` 不联网跑完一本书走的就是它。
  ★ 它今天**不是兜底档，是唯一档**——这个区别要写在文件头，别写成"降级路径"。

## 三、`prompt.ts`（检索结果 → 提示词那一段）

按 [spec §六](spec.md) 那个形状产出**正反两栏**，每条带出处标识。两条硬约束：

- 段首必须写**「只许参考节奏与用词，不许照抄句子」**。不写这一句，模型会把范例的句子
  直接搬进正文——那本书就成了别人的书，而产品第一句话是「以自己孩子为主角」。
- **空结果时整段不出现**（不是「没有检索到范例」这种话）。空段落在提示词里
  只会变成模型自由发挥的邀请。

## Comments

**2026-10-19 · 收工记录**

产出：`score.ts`（bigram + BM25 + `matchedTerms`）· `retrieve.ts`（`retrieve` / `retrieveBoth`）·
`prompt.ts`（提示词那一段）。测试 **63 条**（`score` / `retrieve` / `prompt` 三份 + 工单 02 那份）。
闸门：`format:check` / `lint` / `typecheck` / `pnpm test`（93 文件 · 1146 条）全绿，
`engine-run --mode=stub` exit 0。

三处**落地时才定准**的设计，都回填进了 spec §五：

1. ★ **`example` 收相邻一档年龄，`avoid` 反过来全不过滤。** 原稿只有一句
   「具体值必须相等」。落地时看数据发现那句会让这一栏**对四个年龄档里的三个是哑的**
   （库里 96 条全是 `4-6`，7 岁孩子的请求一条范例都取不到）。而 `avoid` 的语义是
   「他读过了」——那件事与档位无关（上个月是独读版 4-6、这次是共读版 6-8，落点重复一样要避）。
   于是两个极性走两套强度，表格写进 spec §五。
2. ★ **`retrieveBoth` 保证正反不重叠**，且**先算反例**。重叠会让提示词自相矛盾
   （"照着这个节奏写"与"不要重复这个"指向同一条），而模型面对打架的两段话行为不确定。
   先反后正的理由是：反例是硬边界，正例可替换。这个不变式住在模块里，调用方没机会做错。
3. **`form` 两侧都要求"同形态或通配"**：拿独读版的落点去避共读版的重复是错的。

三条踩到的坑：

- ★ **fixture 让两个过滤器互相遮蔽**——第一版用例想测"相邻档收不收"，
  而那几条 chunk 的主题同时也不匹配，于是它们**被主题挡掉**，用例是绿的却证了另一件事。
  这正是"测了个寂寞"的形状。改法：档位那四条 chunk **只有 `ageBand` 不同**
  （主题、形态全部对齐），一次只动一个过滤器。**写过滤器用例时，先问"这条路径上还有没有别的过滤器会先把它拦掉"。**
- **`bigramsOf` 里"标点被丢掉"与"空白是边界"是两回事**：`'云 🌙 在变'` 切三段，
  「云」单独成段就只剩它自己（单字段保留那个字），不是拼成 `'云在'`。用例原先写错了期望。
- **`matchedTerms` 的期望要注意标点**：`'天上有一朵云，正在变形状'` 抹掉逗号之后序列是
  「朵云正在」，所以 `'云变'` 这条 bigram **不存在**——想测"取交集"就得用真连着的写法。

另外一笔自我约束：`retrieve.ts` 最初自己又写了 `export const RAG_OWNER_LIBRARY = 'library'`，
与 `corpus.ts` 那份成了两处真值——改成从 `corpus.ts` 取（那条真值正是隐私边界那一侧的名字）。
