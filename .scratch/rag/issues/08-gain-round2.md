## 为什么要有这一张

评分表 #3 的三句话里，**① 架构**与**② 检索策略**已经做满（评审原话：「这一条答得罕见地好」），
**③ 生成质量是否因检索增强而显著提升**是**空的**——那一栏 62 分就是差在这一条上。
所以这一张只做一件事：**给 ③ 一个能被量出来的实验**。

第一轮的诊断（全部有实测支撑，写在 spec §九）：

1. **判据饱和**：v1 用的是 Schema 一次通过率 / 平均重试，而这个模型格式上本来就饱和
   （两轮 60 次调用只 1 次重试，而那一次还是**内容审核**拦的，不是格式）；
2. **n=10 时一本书 = 10 个百分点**，而阈值正是 10 个百分点 —— 判据与噪声同量级；
3. ★ **三分之一的样本剂量为零**：预检行显示两臂提示词的差是
   382、287、439、**0**、91、283、**0**、**0**、281、180 字 ——
   火箭、鲸鱼、城堡三个主题**一条范例都取不到**，那三本两臂提示词**逐字节相同**。

### 1. 裁决（预声明口径，见 spec §九）

| 端点                     | `off` | `lexical` | 差            | p    | 门槛           | 判       |
| ------------------------ | ----- | --------- | ------------- | ---- | -------------- | -------- |

### 2. 这一轮真正的产出：三件事各自量清了

1. **策略改动生效**（与判据无关，但读数很干脆）：预检行从
   `382 / 287 / 439 / 0 / 91 / 283 / 0 / 0 / 281 / 180` 变成**十个主题全非零**——
   **剂量为零的样本从 30% 降到 0**。取到范例的主题数 **6/10 → 10/10**。
2. **`③` 这条量具第一次活了**：v1 用它测手写旧书，两臂都是 0.0%（饱和）；
   这一轮 ②创作史由本流水线产出，`off` 臂基线 **3.3%**（个别主题 16.7%）。
   **量具修好了，treatment 的效果没被量出来**——这两件事必须分开说。
3. **"不显著"离"差一点"差一个数量级**：报告里附了**最小可检测效应**——
   `③` 4.9 个百分点、`②` 16.1 个百分点（α=0.05、功效 0.8、10 个主题、事后算）。
   观测到的差是 1 个百分点上下。要让这点差异变"显著"，样本量得抬高一到两个数量级。
   ★ 这一条把"没测出来"从一句话变成了一条**有功效分析的结论**，它才是这一轮最值钱的东西。

### 3. ★ 我们自己的一处口径错（记在这里，不悄悄改）

`③` 预声明的效应量门槛是 **≥5 个百分点**，而对照组基线只有 **3.3 个百分点**——
**重复度不可能低于 0，那道门槛在数学上就达不到**。门槛是**量出基线之前拍的**。
下一版（如果要测"不重样"）：**先量基线，再定门槛**。
`report.md` 里那一段也写着，`known-tradeoffs.md` 与 spec §九 各留了一份。

### 5. 过程中的两个发现（都不是本张的判据，但值钱）

1. ★ **`scripts/*.mts` 根本不在 `pnpm typecheck` 的范围内**：`tsconfig.json` 的 include 是
   `**/*.ts` / `**/*.tsx`，**不匹配 `.mts`**。这一张里就因此放过去一个真的运行期错误
   （Phase 0 的打印行引用了一个不存在的 `run`——它一路过 lint、过 typecheck，
   直到真跑起来才炸）。★ 量具自己只有一个闸门，这件事与"量出来的数"直接相关。
   建议（没在这一张里做，怕牵动别的脚本）：把 `scripts/**/*.mts` 写进
   `tsconfig.engine.json` 的 include，先看一遍有多少存量错误，再决定怎么收。
2. **量具与被量的配置必须同源**：`pairOf`（预检 / 分数分布 / 扫描表用的那个）一开始忘了传
   `narrowedMinScore`，于是预检行还在显示"4 个主题取不到范例"，而那时出厂配置已经不这么做了——
   差点把"剂量还是零"当成结论记下来。改成默认参数之后三张表才描述的是**出厂配置**。
3. 另外，`thresholdOf` 第一版把"收窄那一档"写成了**替换**：`minScore: 0`（"谁来都得留着"，
   脚本与测试常这么写）会被悄悄抬到 1。是 `load.test.ts` 那条合成用例当场抓到的
   （现象是"正例一条都取不到"，看着像检索坏了）。现在的语义是 **`Math.min`——收窄只放宽、不收严**，
   并补了两条用例钉着。
