与 spec 的「换档条件」。

★ **这一单自己也踩了一脚 W1 那个坑，记下来防第四次**：

第一版 sweep 汇总把「按错误码计数」当成结论，打印了一句
「26 个里没有一个能做嵌入」。紧接着第二遍跑，同一份目录回的全是 `RATE_LIMITED`
（17 个）——**网关在限流我们**（前面刚连打了几十次）。而 `RATE_LIMITED` 什么都没证明。

- 错在哪：把 **三种不同的话** 加成了一个数——「不会嵌入」（有结论的否定）、
  「没开通」（另一种结论）、「限流/网络错」（**没测成**）。加了之后再下全称否定，
  就是「把『没测成』记成『测出来』」换了个马甲。
- 修法（已进脚本）：**限流退避重试**（4s/12s/30s，只有限流才重试）＋
  每次间隔 `--delay`（默认 1.2s，实测 2s 就够）＋**有结论 / 没结论分开数**，
  只要有任何一个「没测成」，结论行就只许写「不完整，不下全称否定」。
- 修完的第三遍：**26/26 全部测成**，0 个 200——这才是可以写进文档的那个数。

另外两笔：用户当天换了新 key（旧的过期）；新 key 下结论**不变**（同样的模型级错误码），
说明第一轮结果与鉴权无关。★ 新 key 在对话里明文出现过一次，**测完去后台轮换**。
