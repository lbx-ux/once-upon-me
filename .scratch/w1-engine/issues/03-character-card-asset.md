# 03 · 角色卡资产化设计（#8 · 技术方案创新 8 分）

Status: done

## 一、这五个字到底在说什么（给范同学的解释）

**先说不资产化是什么样**：家长在 Step 1 填了"圆脸、爱笑、喜欢恐龙"，
系统把这些字拼成一句提示词发给模型，画完第 1 页。画第 2 页时**再拼一次**——
这次多了一句"他爬上云"，模型看着两句不太一样的话，画出了两个圆脸小孩。
第 3 页再拼一次。20 页 = 20 次各自为政的拼接。这就是市面上"能换名字、
换不了形象"的那一类，也是本项目 §一 里点名要解决的问题。

**资产化就是把"这孩子长什么样"从一次性的字符串，变成一个有身份证的东西**：

| 要求               | 大白话                                                           | 代码里的样子                                    |
| ------------------ | ---------------------------------------------------------------- | ----------------------------------------------- |
| **有 ID**          | 第 7 页的图不写"圆脸大眼"，它写"我出自 `xiaolu-r1` 这张卡"       | `Provenance.cardRevision`，每页都指回卡         |
| **改一次，处处变** | 家长说"头发再短一点"，改的是那张卡，不是 20 段提示词             | `promptFragmentOf(card)` 是角色段的**唯一来源** |
| **有版本**         | 微调之后旧版还在，因为旧书那 20 页是旧版画出来的，那是合法交付物 | `revision` 递增 + 文件名里带内容指纹            |
| **能失效**         | 卡改了，旧页要被认出来"这不是当前这张卡画的"                     | `cardDigest(card)` 语义指纹                     |
| **能核对**         | 一致性判定不问"像不像"，而是逐条问"骨相在不在、那撮翘发在不在"   | `checklistOf(card)`，**与生成同源**             |
| **能删除**         | 删孩子时连卡带参考图一起删，并报出删了几条                       | `CardStore.deleteChild()` 返回条数              |

一句话：**卡不是提示词，是被引用的对象。** 提示词是它的一个派生物，
核对清单是它的另一个派生物——两个派生物出自同一份数据，
"画的时候按它画、查的时候按它查"才成立，一致性分才有意义。

## 二、为什么这是"技术方案创新"而不是数据结构

评分表里 #8 的验收标准是"文档能讲出为什么非这样不可"。三条：

1. **跨书复用**：第二本书不用重做角色卡（Step 3 那句"下次做新书不用重来"）。
   没有 ID 与被引用，这句话只能靠家长重新描述一遍。
2. **一致性 Agent 有判据**：Agent 要能自主决定"重不重画"，
   判据必须是可核对的清单，不能是一个形容词。清单从卡派生。
3. **隐私承诺有落点**：原始照片"生成即删"，删掉之后系统里还得留下
   "这个孩子长什么样"——留下的那个东西就是角色卡。
   它是**派生资产**，不是原始素材，这条区分是合规论证的支点。

## 三、一条比所有代码都重要的不变式

> **卡里出现的每一项都必须跨页不变。**

姿势、表情、场景、光线属于页级 prompt，永远不进卡。
把"爱笑"写进锚点，下一页哭的那一页就会被判不合格；
把"常服"当硬判据，换衣服那页就是误杀。
所以锚点分**硬/软**两档（`ANCHOR_STRENGTH`）：骨相/眼睛/头发/头身比/肤色是硬的，
特征记号与常服是软的（可以合理变化）。这条分档是产品判断，写在数据里而不是散在校验代码里。

- 测试 **24 条**（`card.test.ts`）钉住：缺硬锚点拒绝出卡、同槽位后写覆盖先写、
  顺序稳定（横评可比性）、清单只列硬锚点、改锚点换指纹、改时间不换指纹、
  页级概念被拦下、revision 不改写原卡……
