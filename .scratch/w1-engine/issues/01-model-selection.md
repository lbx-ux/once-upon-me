# 01 · 模型选型对比实测（#1）

Status: **图像与文本两条判据 1 都已过线**（图像 ≥3 人盲读 go、文本 10/10 两家过 90%）。
剩：TTS 按用户口径推迟、判据 3/5/6 未测、语感盲评降为可选、`r_redraw` 待重测

★ **2026-10-13 口径变更（[ADR-0008](../../../docs/adr/0008-model-and-key-provided-by-user.md)）**：
**模型与密钥由用户自带**，"选型"这件事从产品里取消。本工单的性质随之从
**选型闸门**变成**默认推荐 + 兼容性证据**——下面所有实测数字一条没废，
但它们现在回答的是"默认填哪个、引擎在哪些模型上验过、它们各自会怎么坏"，
不再回答"产品只能用哪个"。**判据 2（语感盲评）因此降为可选**。
最值钱的产物其实是判据 1 那张表里的**失败分类**：它证明同一个引擎在 7 个模型上
会以四种不同方式坏——而按 ADR-0008，用户带来的任意模型都可能这么坏。

## 要做什么

照 `docs/tech-selection.md` §12 的协议跑，不另设计一次：

```bash
# 图像：候选 × 5 页
node scripts/w1-image-bakeoff.mts --models=wan2.7-image,qwen-image-2.0 --out=.out/bakeoff-image

# 文本：候选 × 10 本分镜，按 JSON 档分别测
node scripts/w1-text-bakeoff.mts --models=<候选1>,<候选2> --books=10 --jsonMode=object

# 真跑一本，拿 r_redraw 与端到端证据
node scripts/engine-run.mts --mode=live --form=solo --pages=5 --out=.out/live
```

★ 10/13 撤掉了 `--yes=1` 确认闸门与预算打印（口径见 `scripts/env.mts` 文件头）。
★ 报告排版改错了不要重跑：加 `--reportOnly=1`，从 json 重放，一个模型都不调用。

跑之前要先定的两件事：

1. **文本候选名单**。`GET /v1/models` 能列出当前供应商的对话模型（不含图像/视频）。
   按 §9.2 判据 1（结构化输出通过率）先粗筛，再进语感判读。**已做**：该接口实测报
   25 个型号，本轮测了其中 7 个（§9.1 表下有名单，没测的已标明"没测"）。
2. **视觉比对模型**（`VISION_MODEL`）。一致性 Agent 的手；没有可用的就得在
   10/20 明确写"判据 1 只有人工判读，没有机器分对照"。**已配**（`kimi-k2.6`），
   机器分作为对照记在案——但它不稳，见下面"卡住的两件事"。

## 已经出的结论

- **判据 1（结构化输出，一票否决，门槛 90%）过线的只有两家**：
  `qwen3.8-flash`（10/10，一次过 9/10）与 `deepseek-flash`（10/10，一次过 7/10）。
  这两家进判据 2 语感盲评。
- `kimi-k2.6` 报 7/7 **不算通过**：3 本根本没跑完（撞 180s 上限、`fetch failed`），
  分母只有 7；单本 100–320 秒，是 qwen3.8-flash 的 10–20 倍。出局理由是**延迟与稳定性**。
- `qwen3.8-max` / `mimo-v2.6-pro` / `seed-2.1-pro` 是真·判据 1 失败：**树形不合法**
  （"第 1 页给了父节点""父节点序号 ≥ 本页"），带反馈重试也救不回来。
- `glm-5.3-flash` 是**调用层**失败（`REASONING_REQUIRED`，不许关思考），不在判据 1 里。
- 思考模型会把 `max_tokens` 整条花在思考链上、正文一个字都不写 →
  引擎参数改动见 §9.1.1；`LLM_THINKING` 缺省 `off`（与平台默认相反）。

## 卡住的两件事（10/13 晚更新：第 1 条已解，换上一根更长的杆）

1. ~~**图像判据 1 要 ≥3 人独立看图。**~~ **已解**：≥3 人判读完，两组都认作同一个孩子
   → **go**。定稿取 `qwen-image-2.0`（判据 1 不区分两家，按出图快 2–3 倍破平），
   见 §7.5 / §7.6。
   ★ 但判读**只给了整体结论，没留逐页计数**，所以它答不了"谁更强、强多少"，
   也只覆盖了 `xiaoyu-r1`（男孩）那张卡。**下次判读要带打点表。**
2. **★ TTS 完全没动，而它是 W1 的产出物之一。** §8 那一整节还是 C 级（选型前的名单），
   五个候选没有一个跑过，`VoiceSynthesizer` 适配器是 `voice: null`，脚本一个都没有。
   而且它带着一条**硬约束**：候选必须支持「上传样本 → 返回 `voice_id` → 可解绑/删除」，
   否则直接和隐私设计的删除承诺冲突（§8.3）——**这条能一票否掉一个候选，
   而且查文档就能否掉，不用花钱**。
   它同样需要 ≥3 人盲听（产出物 2），**所以又是一根要排人时间的长杆，越晚开始越危险**。
3. **视觉比对模型不稳，`r_redraw` 量不准。** 8 页计划里 4 页比对没跑成
   （504 / `fetch failed`），拿到判决的只有 4 页。根因是载荷：两张 1440² 的图
   约 7 MB base64。**要先把图缩到 768 再送，而那要先有图像处理库——仓库现在没有。**
   这条同时卡住 §7.0 的资产体积决策（20 页 ≈ 50 MB/本，与 ADR-0003 冲突）。
   ★ 而且 §7.5 的人工判读已经说明**这个比对器的阈值本身也校准错了**，
   所以 `r_redraw` 不是"再跑一次就准"，是**要先重定阈值与锚点清单**（§9.1.4）。

## 已知缺口（别读成"已核实"）

- **`buildTree` 不校验页数**：两次独立复现（横评里 `mimo` 返回 7 页、
  真跑时请求 2 页给了 3 页），引擎都收了。判据 1 量"每页 4 字段"，页数不在其中。
- **锚点的可见性没有规则**：`肤色…膝盖有晒黑的印` 在多数构图里拍不到，
  于是必然判 fail、白烧重画——`r_redraw ≈ 0.75` 里有多少是这条锚点的错，现在分不开。
  见 §9.1.4。改锚点会改 `promptFragmentOf(card)` 的字节，要重跑整轮图像横评，
  所以等人工盲读做完再决定。
- 关思考对**语感（判据 2）**的影响未测。省 5–7 倍 token 是实测的，
  "思考让故事更好"是假设。
- 思考参数的 `auto` 档（平台原话"只支持开启、关闭或自动"）**字面量未验证**，没写进注册表。
