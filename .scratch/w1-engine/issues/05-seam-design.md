# 05 · 引擎与 UI 的模块边界与 seam（🧭 codebase-design，#11 验收的前提）

Status: done

## 结论：两处 seam，一个入口

```
┌──────────── UI（创作流 / 阅读器 / 面板，W2–W3）────────────┐
│  只 import src/lib/engine/index.ts                          │
│  只消费两样东西：runBook() 的返回（资产）+ 事件流（过程）    │
└───────────────┬─────────────────────────▲───────────────────┘
        请求（BookRequest）          EngineEvent[]
┌───────────────▼──────────────────────────┴──────────────────┐
│  engine：plan → illustrate(+check/retry) → assemble          │
└───────────────┬─────────────────────────▲───────────────────┘
        能力调用（4 个接口）          字节 / JSON
┌───────────────▼──────────────────────────┴──────────────────┐
│  providers：live（真供应商） ⇄ replay（录好的资产）           │
└──────────────────────────────────────────────────────────────┘
```

| seam      | 接口               | 两个适配器                                | 为什么是真的 seam                                                   |
| --------- | ------------------ | ----------------------------------------- | ------------------------------------------------------------------- |
| 引擎 ⇄ UI | `EngineEvent` 协议 | SSE 前端 / node 脚本                      | 同一串事件喂三个消费者（界面、MCP、日志）                           |
| 文本能力  | `TextGenerator`    | `openai-text` / `replay-text`             | 横评要换模型、演示要不联网                                          |
| 图像能力  | `ImageGenerator`   | `tokenrhythm-image` / `replay-image`      | 同上；且 URL 过期问题被关在适配器里                                 |
| 视觉比对  | `VisionComparator` | `openai-vision` / （未配置 → 未核对路径） | 只有一个真适配器，**所以它现在只有接口没有实现第二家**——见 Comments |
| 语音      | `VoiceSynthesizer` | （W4）                                    | **只有接口**。看板说 W4 落地，现在写实现就是死代码                  |
| 存储      | `AssetStore`       | 内存 / 磁盘                               | 测试不碰文件系统，且两实现行为一致（有测试钉）                      |

## 深度（depth）自查

- `runBook(request, deps)` 一个函数吃掉 ②–⑦ 全部阶段，调用方只需要知道
  入参、事件、返回值三件事 → 深。
- 四个能力接口各 1–3 个方法，参数是扁平对象 → 浅是应该的，
  **它们是适配器不是模块**：深度在引擎那一侧（重试、阈值、去重、事件都在里面）。
- 自写 Schema 校验器：一份定义同时出 JSON Schema 与运行时校验 →
  两处定义迟早会漂，漂了的症状是"通过率莫名偏低"。这是本轮第二深的模块。
