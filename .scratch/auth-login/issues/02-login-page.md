## 要做什么

`src/app/login/page.tsx`（**不放进 `(studio)` 组**，与 `/create` 同理：全屏页面，没有侧栏）

- `src/components/auth/LoginPage.tsx` + `src/components/auth/login.css`。

版式**照 `E:\match\login` 那份稿子**，用户 2026-10-16 的要求是
「和我提供给你的登录界面保持一样吧，你自己修改的不好看，背景就用提供的那个」。
所以：左栏一整幅水彩（`picnic-loop.mp4`），右栏**平涂 `--paper`** 上的表单。
★ **不铺 `StudioBackdrop`**——理由见 `login.css` 文件头第 1 条（那片天带一条 112vh 的天空带，
而十带表写着压在天上的字只允许 `--ink` 与 `--ink-on-sky`；这张表单从头到尾写着
`--ink-muted` 与 `--accent`，它们在 `--paper` 上才是量过的合法对）。

流程：

- 手机号 `/^1\d{10}$/`，只收数字、最长 11 位；输满 11 位当场验一次，没输满不报错。
- 「验证码登录 / 密码登录」二选一分段控件。
- 验证码：点「获取验证码」后 60s 倒计时，按钮显示 `60s` / 「重新获取」。
- 验证码通过后：新号 → **设置密码**（新密码 + 确认新密码，≥ 8 位，
  **边输边比对**，不一致就提示「两次输入的密码不一致」）；已有账号 → 直接完成登录。
- 每个错误都有 `aria-invalid` + `aria-live` 的提示。
- 成功 → `router.replace(safeNext(next) ?? '/home')`。

★ **一处刻意与稿子不同**：稿子最后有一个「登录成功」的中间态，要人再点一下「进入创作 →」。
这里登录成功即走人——那个中间态是给**静态稿**用的（双击 `index.html` 的人需要看到"成"了），
真页面不需要，他下一眼就在 `/home`。

★ **不进 `useEnterTimeline`**：`ENTER_STEPS` 是给 `/home` 定死的选择器清单，
为一个新页面再塞一套进去是给假想的将来搭架子。CSS 动画在禁 JS 时照样播，
`prefers-reduced-motion` 下 `animation: none` 就是静止终态。

**进场动画**：0.34s 从下面 8px 浮上来（`login-rise`）；两笔手绘装饰各自 7s / 9s
错开半拍地浮动（`login-float`，`-3.5s` 负延迟）。

### reduced-motion 的静止终态：从**活的 CSSOM** 里读的

不是读源码推的，是把 `document.styleSheets` 里所有提到 `.login__still` / `.login__video`
的规则连条件一起列出来：

| 条件                                      | 选择器          | `display` |
| ----------------------------------------- | --------------- | --------- |
| （无条件）                                | `.login__still` | `block`   |
| （无条件）                                | `.login__video` | `none`    |
| `(prefers-reduced-motion: no-preference)` | `.login__still` | `none`    |

所以 `reduce` 那一支拿到的是**那张画完的静止帧**，而 `no-preference` 那一支才放出视频。

### ★ 这一遍抓出来的真缺陷：登出再登入，昵称与「首次登录」都丢了

**症状**（浏览器里量到的，不是推想的）：设昵称「小满」→ 退出登录 → 用密码登回来 →
名字没了（侧栏退回打码手机号），而且 `createdAt` 被刷成了**刚才那一刻**。

```
登出前: createdAt 2026-10-16T04:48:52.347Z  nickname "小满"
登回来后: createdAt 2026-10-16T04:54:35.082Z  nickname ""
```

**根因**：`buildUser()` 只从**登录态**（`loadUser`）里读这两件东西，
而登出（`signOut` → `clearUser`）会清掉登录态。于是"登出 → 重新登录"这条路上
`previous` 是 `null`，两件东西一起变回初值。
而 `client.ts` 里那段注释当时写的是「`createdAt` 优先沿用本机已经记着的那一份：
不这么做的话，同一个人重新登录会把"首次登录时间"刷成现在——**一个写着"首次"的字段
每次登录都变，是坏的**」。也就是说：**注释写着要做对的事，代码只做了一半**——
它挡得住"重新登录"，挡不住"登出之后再登录"。

**修法**：给这两件东西单开一张**底账**（`state.ts` 的 `AuthProfile` +
`xiaozhujue.auth.profiles`），登出**不动它**。

- 这与那张在册号码表同一个道理：登出不该让一个号码忘掉自己设过密码，
  也不该让它忘掉自己叫什么、第一次是什么时候来的。
- `AuthUser`（登录态）与 `AuthProfile`（账号底账）是两件事：
  前者是"**此刻**是谁"，后者是"**这个账号**是什么"。混在一张表里的症状就是上面那两条。
- 写入点只有两个，都在那条缝里：`buildUser()`（第一次见到这个号码就记下来）与
  `updateNickname()`（改名要跟着改底账，否则登出再登入会读回旧名字）。
- 真后端那边这整张表会连同那段逻辑一起删掉——这两件东西存在服务端、跟着账号走。

**补的测试**（`client.test.ts` 的「★ 登出再登入：底账要留住（浏览器里踩到过）」一组）：

- 登出后走**密码**回来：`nickname` 与 `createdAt` 都在
- 登出后走**验证码**回来：一样都在（两条路都要覆盖）
- 底账里认不出来的条目一律丢掉、不抛，但**空串昵称必须留着**（"还没起过"是合法值）

**修完在浏览器里重跑的同一场景**：

```
password login -> /home
nickname                     "小满"
createdAt                    "2026-10-16T05:21:13.426Z"
createdAtMatchesFirstLogin   true
sidebar                      "小满"
```

★ 顺带说明为什么这条只在**真浏览器**里才被发现：`client.test.ts` 里原来的两个用例
分别是"从没登录过"与"同一个号码重新登录（**没有登出**）"，两条都过。
缺的那一格是"**登出之后**再登入"——它只有把 `AuthProvider.signOut()` 真的调一次才会出现，
而那是组件层的事。**测试全绿不等于这条路走通了**，这一条就是它的证据。

## 2026-10-16 补：图上那行字去掉底色 + 手机号不给默认值

用户看图之后提的两条，都照做了。

### 1. 字幕改成透明底（`.login__caption`）

原来它住在一颗不透明的 `--surface` 药丸里，我当时的理由是
「视频每一帧都不一样，`text-shadow` 在任何一帧上都成立不了、**也没有一帧可以量**」。

★ **那句"没有一帧可以量"是错的，而且错得不该**：抽帧就能量。
`ffmpeg -vf fps=2` 出 20 帧，把字幕框按 `object-fit: cover` 的换算
（缩放 900/768、水平各裁 10px）映射回 768×768 源图得 `x[29,336] y[713,747]`，
逐像素算相对亮度与对比度，共 **208,760** 个像素：

| 做法                      | 最坏        | < 4.5:1 的像素 |
| ------------------------- | ----------- | -------------- |
| 白字（稿子自己的取法）    | 1.04:1      | **99.55%**     |
| 墨字，无底无影            | 1.56:1      | 0.60%          |
| 墨字 + 纸色 halo @ α 0.55 | 9.88:1      | 0              |
| 墨字 + 纸色 halo @ α 1.00 | **16.69:1** | 0              |

**两条都推翻了直觉**：

- 稿子那版**白字在这张画上不可读**（画很亮，中位亮度 0.60）——它靠的是白字影，
  而白字影正是它自己没法验证的那部分。
- 墨字直接压上去"看着应该没问题"（99.4% 的像素都合格），
  但那 **0.2%** 压在蜡笔与深色描边上的正好是最坏情况，字会沉进去。

**取法**：`--ink` 字 + 8 个方向的**硬偏移** `--paper` halo（`blur = 0`）。
halo 只覆盖字的紧邻一圈，而那一圈正是"字被读出来所依赖的背景"，
所以上表第四行那个 **16.69:1** 就是要兑现的数——
与原来那颗药丸是**同一个对**（`--ink` 压 `--paper`），只是把底从"一整块"收成"沿着笔画的一圈"。
`blur` 取 0 是有理由的：带模糊的影在字边上的实际 α 更低，那几档这一轮没量，所以不写。

★ 记一笔**做反了的地方**：该量的量，不该用"没法量"当理由换成保守做法。
药丸先做了，用户说不好看之后才去量——量完发现两边都不是原来想的样子。

### 2. 手机号输入框不给默认号码

`placeholder="13800138000"` 删掉，**不换别的话术**。
那是演示账号（`DEMO_REGISTERED_PHONE`），拿它当占位符会让人以为
"这就是我的号"或者"系统已经填好了"。`+86` 前缀与上面那行「手机号」已经把该说的说完，
占位再写一遍是重复、写一个具体号码是误导。

这条在 `client.test.ts` 里有测试钉着。去掉的只是输入框里那个提示。
