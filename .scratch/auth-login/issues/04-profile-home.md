# 04 —— `/account` 个人主页

`Status:` **done**

## 要做什么

`src/app/(studio)/account/page.tsx`（**在 `(studio)` 组里**——这一屏是工作台的一屏，
侧栏要留着）+ `src/components/account/ProfileHome.tsx` + `profile-home.css`。

用户 2026-10-16 选的形状是**完整一屏**：头像 + 昵称 + 手机号（打码）+ 首次登录时间 + 退出登录，
再加一节「这台设备上做过的东西」。

内容（**服务端取数**，照 `/shelf` 那条"Why 放服务端"的理由：首屏就有内容）：

1. **身份纸**：头像占位圈 + 昵称（可改，写回本机）+ 打码手机号 + 首次登录时间 +
   一颗「退出登录」。
2. **这台设备上的作品**：`listCardItems()` 数角色卡、`listBooks(store, noCovers())` 数书，
   两条分别链到 `/character` 与 `/shelf`。
   ★ 标题写「**这台设备上**」不是「你的」——作品此刻还没跟账号关联，
   等后端把书挂到 userId 上再改那两个字。
3. **未登录进来**（人可以直接输 `/account`）给一张"还没登录"的纸 + 一颗去登录的按钮，
   而不是一个转圈、也不是一个 404。

## 三条判断

1. **头像是一个说得清的占位。** `AuthUser` 里根本没有这个字段——上传要后端
   （存 / 缩 / 过审），这一轮不做。与其画一张假头像，不如画一个**明确表示"这里空着"的圈**，
   并在 `pf__meta` 里直说「还没传过——要等接了后端才能上传」。
   这是 CLAUDE.md §不糊弄 里"图没到位就留一个语义上诚实的兜底"的同一件事。
2. **`!ready` 时框壳先在，不返回 `null`。** 那会让整页从"只有标题"跳到"有内容"，
   高度差一次就是一次可见的抖动。所以给一个与未登录那副面孔同一个框的空白壳
   （`min-height: 236px`）。
3. **`dt` 里的「头像」那一行会跟着占位圈一起消失**，等真上传做了之后。它是个临时的实话。

## 验收

- `/account` 首屏就有角色卡数与书的数（服务端渲染，不是挂载后填）。
- 改昵称 → 侧栏那一格跟着变；清空昵称 → 退回打码手机号。
- 退出登录 → 回到「这台设备上还没有人登录过」。

## Comments

- 颜色的选择有据：`.pf__avatar` 用 `--card-paper`（暖色，"物件"那一族）而不是 `--surface`，
  它上面的 `--ink-muted` 是量过的 **4.67:1**（写在 `profile-home.css` 里）。
- `.pf__sub` 用的是 `--ink-on-sky` 而不是 `--ink-muted`：这一屏的页头压在
  `(studio)` layout 给的天空带里，十带表（`studio-backdrop.css` 文件头）写着
  天上只允许 `--ink` 与 `--ink-on-sky`。
- 统计数字用 `--font-serif` + `font-variant-numeric: tabular-nums`，
  与全站"数字用衬线"一致，且换数时宽度不跳。
- `formatJoined` 把 `toLocaleString` 的字段表写死，不用默认值：默认跟着运行环境走，
  换个 node / 换个浏览器会突然多出个 "GMT+8"。

### ★ 补一句：昵称是**底账**，不是会话

改昵称这件事看着只影响"这一刻"，其实影响的是**这个账号**——
所以它落在 `xiaozhujue.auth.profiles`（那张登出不清的底账）里，而不是只在登录态里。

浏览器里量到过一次代价：`updateNickname()` 只改登录态那版，症状是
「改完当场对、**登出再登入变回旧名字**」——它不报错，名字只是悄悄回去了。
现在 `client.ts` 的 `updateNickname()` 会把底账一起改，
`buildUser()` 也会在读不到底账时用登录态补一次并写回。

★ 这两个写入点**都在那条缝里**，不在组件里：留在组件里的话，
接后端那天要记得在两个地方加 `fetch`，漏掉的那一处会安静地"改了但没存"。
