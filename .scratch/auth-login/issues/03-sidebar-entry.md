# 03 —— 侧栏底部那一格

`Status:` **done**

## 要做什么

改 `src/components/shell/AppShell.tsx` 的 `.shell__foot`，插在「模型与密钥」**上面**
（就是用户截图里红框那个位置）：**一格两副面孔**。

- **未登录**：门形图标 + 「请登录」，`<Link href={'/login?next=' + encodeURIComponent(pathname)}>`。
  图标是「箭头进门框」（`M15 4h3a1 1 0 0 1 1 1v14a1 1 0 0 1-1 1h-3M10 8l4 4-4 4M14 12H3`），
  **刻意不用人形**——人形是「角色卡」那一格的图标，两个"人"摆同一条侧栏上必然有人读错
  （这个仓库为同名不同物付过学费，见 `AppShell` 文件头「小主角 / 角色卡」那一段）。
- **已登录**：`<Link href="/account">`，标签显示**昵称**；昵称是空串（"还没起过"）
  就退回**打码手机号**。这不是"兜底一个默认名"，是"换一件真的能读的东西显示"——空着才是错的。
  图标是头像圈（`AVATAR_ICON`，与 `/account` 那颗**同一个图形**：两处指的是同一件事，
  长得不一样才是错的）。
- 收起侧栏时标签照旧被 `.shell__link-label` 那条规则藏掉。两格**复用既有类名与 `NavContent`**，
  于是 `useLinkStatus` 那颗 pending 转圈是白拿的。
- `app-shell.css` 只补一处：`.shell__link-label` 加 `text-overflow: ellipsis`——
  昵称最长 24 字，不收尾会把收起态那一格挤变形。

## 三条判断

1. **它排在「模型与密钥」上面**：先是谁在用，再是这个人在用什么。
2. **它不进 `NAV`**：那五格是"去做事"，这一格是"我是谁"，混在一排里会把导航读成六件并列的事。
3. **不做门禁**：未登录照样能创作、看书。没被要求，而"哪些页面要挡"是个产品决定。

## 验收

- 未登录进 `/home` → 侧栏底部是「请登录」→ 点它 → 落在 `/login?next=%2Fhome`。
- 登录后回到 `/home` → 那一格变成昵称（或打码手机号）→ 点进 `/account`。
- 「退出登录」→ 变回「请登录」。

## Comments

- `next` 用 `encodeURIComponent` 包一层是**必须的**：路径里可能带查询串，
  不编码就会把它接到 `?next=` 自己的参数里去。判据（挡 `//evil.com` 那类）不在这层，
  在 `lib/auth/state.ts` 的 `safeNext()`——这一层只管拼，不管判。
- 两副面孔走**同一个类名 + 同一个 `NavContent`**，而不是两段 JSX：
  两段的话，"未登录那格长什么样"和"已登录那格长什么样"会各自漂移。
