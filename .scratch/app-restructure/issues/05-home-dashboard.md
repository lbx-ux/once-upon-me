## 一、设计稿逐块落位（★ 这一节是本单的核心）

设计稿是一个通用儿童 App 的模板，里面**有几个数字在这个产品里没有出处**。
按项目美学，**没有出处的数字不许显示**——所以先逐块判"做 / 换个说法 / 不做"：

| 设计稿              | 真实数据源                                     | 判定                                                                                          |
| ------------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `已创作故事 12`     | 书库里的书数（磁盘上真有的）                   | ✅ **做**，数字实时数出来                                                                     |
| `阅读时长 8.5 小时` | **现在没有任何数据源**                         | ⚠️ 见 §二                                                                                     |
| `收藏角色 6`        | **现在没有"收藏"这个概念**                     | ⚠️ 见 §二                                                                                     |
| `连续天数 5`        | **现在没有任何数据源**                         | ⚠️ 见 §二                                                                                     |
| tab `最近`          | 书库按修改时间排                               | ✅ **做**                                                                                     |
| tab `收藏`          | 依赖上表那条                                   | ⚠️ 跟随                                                                                       |
| tab `推荐`          | **这个产品没有内容库**——书是生成的，不是挑选的 | ❌ **换**：改成**主题模板**（恐龙/太空/友谊…，即创作流第 2 步已有那批），点一下**预填创作流** |
| `为你推荐` 三张卡   | 同上                                           | ❌ **换**：同上，作为"今天可以写什么"的入口（真实、可点、有用）                               |
| `继续上次创作`      | 需要**每本书读到第几页**                       | ✅ **做**，但要求真记（见 §二）                                                               |
| `我的故事` 列表     | 书库                                           | ✅ **做**，每行：封面缩略 + 名字 + 页数 + 时间                                                |
| `新建故事` 卡       | 指向创作流                                     | ✅ **做**                                                                                     |
| `你好，小宇妈妈`    | 角色名有（小宇）；**"妈妈"没有出处**           | ⚠️ 见 §三                                                                                     |

## 二、三张统计卡：要么真记，要么不做

三个数都需要**产品现在不产生的数据**。两条路，**推荐第一条**：

**路 A（推荐）：实现一个诚实的本地记录。** 很小：

- 阅读器打开/翻页/关闭时写一条本地记录（书 id、页码、时长、日期）
- 由此派生：阅读时长（累加）、连续天数（日期序列）、继续上次创作（最后一本书的最后页码）
- ★ 必须**诚实地说明它的边界**：这些数**只在这台设备的这个浏览器里成立**——
  换台机器、清了浏览器数据就没了。界面上要有一句话说到这件事，
  因为它不是一个"账号级"的数字，装成账号级的就是撒谎
- 存储位置：**不能**用会误伤 key 纪律的地方——但这里存的**不是秘密**（书 id + 页码 + 时长），
  所以 `localStorage` 可以；要有一次审计确认写入的字段里没有 key（与 [04](04-settings-drawer.md) §三同一次检查）

**路 B：只做有真实出处的数。** 那 `已创作故事` 留着，另三张卡**不做**，
空出来的位置放真正有用的东西（比如"最近这本书读到第几页"）。

★ 两条路都不允许的做法：**显示设计稿里那个 12 / 8.5 小时 / 6 / 5**。
那是模板的假数据，搬进来就是给用户看的一个谎。

★ 若走路 A，"收藏角色"还需要**先有收藏这个动作**（角色卡上一个心形，本地记）。
它是一个真功能而不是一个数——**要做就连动作一起做，不做就把这张卡撤掉**。

## 三、问候语：`小宇妈妈` 里的 "妈妈" 没有出处

- 孩子名有出处（[03](03-character-profile.md) 的角色卡）
- **家长的称谓没有出处**：这个产品不知道来的是妈妈、爸爸、爷爷还是老师。
  直接写"妈妈"会把一半用户写错，而且是那种"第一句话就错了"的错
- 处理：**不改称谓**，写成 `你好，小宇的家长` 或 `你好，欢迎回来`；
  若要个性化，就在设置里让用户**自己选**（妈妈/爸爸/家长/其他），默认中性
- 没有角色时：`你好，欢迎来到小主角` + 一句"先挑一个示例角色，做第一本书"（**别**用"还没有故事哦～"）

## 四、路由与块序

`/home` 从上到下：问候+设置入口 → 统计卡（路 A 的四张 / 路 B 的一张）→
最近的书（"继续上次创作"）→ 主题模板（换掉"为你推荐"）→ 我的故事 + 新建故事卡。

- 顶栏的**齿轮 = [04](04-settings-drawer.md) 的抽屉入口**
- 「新建故事」→ `/create`（[06](06-wire-entries.md) 会把首页 CTA 也指过来）
- 每张书卡 → `/reader/[bookId]`
- 空态（新用户，一本书都没有）：这是**最重要的一屏**（Request 3(a) 说的"第一次进来就能看到效果"），
  必须直接给"用示例角色做一本书"的入口，**不许**留一个只有"新建"按钮的空页面

## 五、验收

- [ ] `/home` 存在，上述块序成立，两端（桌面/移动）都不塌
- [ ] 每张卡上的数字**逐个说得出来处**；说不出处的卡**不在页面上**

- [ ] 阅读时长/连续天数的**设备本地**性质有一句界面说明

- [ ] 问候语不出现"妈妈/爸爸"这类无出处称谓（`grep` 页面文案）
- [ ] 空态能一眼看懂"我该点哪"，且点下去真能到示例角色
