# 08 · 声音：两个默认音色 + 上传自己的声音做定制

Status: claimed（2026-10-14：五项探测已做完，§8.3 闭环实测通过；**听感没听**，实现未开始）
依赖：[01](01-model-selection.md)（TTS 供应商）、[04](04-settings-drawer.md)（key 与音色的采集处）、
[02](02-reference-image-pipeline.md) 的归一化经验（音频样本同样要归一）
对应 Request 6：系统提供两个默认音色；用户可以选择默认的，也可以上传自己的声音使用定制的。

## 一、★ 这一单推翻了一条既有口径，**先把那笔账结清**

W2 spec 口径 2 是"**TTS 推迟，阅读器里一个音频控件都没有**"，理由是
"一个只对四分之一能响的控件，证的是这一页想证的反面"（README §五「选择点」拆播放条那件事）。
本单把它翻过来，但**那条理由不失效，它变成了本单最重要的一条验收判据**：

> **要么整本书都能响，要么这一版还是不接线。**

具体就是：**不许**做成"第 1 页能听，其余页灰着"；**不许**做成"部分音色能听"。
理由与首页拆播放条完全同源——当时的失败不是"没声音"，是"控件在而能力不在"。

三条同时成立才允许把控件接出来：

1. 整本书（20 页）每一页都能合成
2. 合成失败时**整本的**行为是可理解的（不是某一页静默没声）
3. 演示书 `public/demo/books/xiaoyu-r1-4fe055c5723b/` 里**有真的音频文件**，
   断网也能听（ADR-0003 那条"断网也能走完一本"要连声音一起成立）

★ 这三条不成立时，正确做法是**继续不接线**，并在本单 Comments 里写清卡在哪一条。

## 二、§8.3 的硬约束：先淘汰，再比价

> TTS 候选必须同时满足：**上传样本 → 返回 voice_id → 支持解绑/删除该 voice_id**。
> 不满足这条的候选**直接淘汰，不进盲听**。

拆成两半看（[spec §1.2 / §1.2b](../spec.md) 的裂表）：

| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **两个默认音色**   | ★ **阿里 `qwen-audio-3.0-tts-flash`**（1 元/万字符，含**童声** `longjielidou_v3.6` 5 岁男童 / `longpaopao_v3.6` 5 岁女童）、Gemini TTS（$0.00225/10s 量级）、OpenAI（`gpt-4o-mini-tts` 音频 $12/1M token） | 都无 §8.3 问题；**价格都量到了，中文质量一个都没量**                                            |

★ **MiniMax 已被 §8.3 淘汰**（阿里文档原文："MiniMax **仅支持创建音色，不支持查询和删除**"）

所以本单开工第一件事不是写代码，是**把 §8.3 这一条量出来**：
对每家（有 key 的）真调一次"创建音色 → 拿到 voice_id → 删除该 voice_id"，

### 2.1 ★ 五项探测**已全部做完**（2026-10-14，脚本 `.out/tts-probe.mjs` + `.out/tts-probe2.mjs`）

五项里**四项拿到了确定结果，第五项（听感）机器判不了、等人耳**：

| #   | 待验                   | 结果                                                                                                                                                                                                     |
| --- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `WorkspaceId` 是否必需 | ✅ **不需要**。`POST https://dashscope.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer` 直接 **200**（1.3s）。→ [04 设置抽屉](04-settings-drawer.md) 语音组**字段与图像组一致**（无 workspace） |
| 2   | 合成一次真请求         | ✅ **200 · 0.7–1.5s/句**，`output.audio.url`（签名 OSS 地址，`expires_at` ≈ **24h**，是 `http://`）+ `usage.characters`。下载后 **mp3 · 101,851 字节**（24kHz 请求）                                     |
| 3   | **童声听感**           | ⏳ **没听**。三份样本已落盘：`longjielidou_v3.6`（5 岁男童）、`longpaopao_v3.6`（5 岁女童）、`longanxiaoxin`（"亲切活泼音"）。**听完之前本单不进实现**                                                   |
| 4   | 克隆闭环 + §8.3        | ✅ ★ **整条验过**：`create_voice` **200** → 用 cloned voice 合成 **200** → 跨模型 **400** → `delete_voice` **200** → 删后再合成 **400** → `list_voice` `total_count: 0`                                  |
| 5   | 音色与模型绑定         | ✅ 确认：`target_model=qwen-audio-3.0-tts-flash` 的音色打 `qwen-audio-3.1-tts-flash` → **400** `[cosyvoice]Engine error [411]`                                                                           |

**★ 一条意外的好消息（把 §1.2b 的隐私风险 ② 直接消解）**：
`create_voice` 的 `url` 字段**接受 `data:audio/mpeg;base64,…`**（实测 **200**）。
所以"样本必须先放到一个可访问的 URL 上"这个约束**不存在**——
样本只出现在请求体里，处理完即弃，**不需要签短时效链接、也不需要传 OSS**。
§8.3 的"样本拿到 voice_id 后立即删"因此是**可以真做到的**，不是一句口头承诺。

**顺手量到、会影响实现的数**：

| 数                  | 值                                                                                                                                                                 | 用到哪                                                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 计费字符 ≠ 文本字符 | ★ **规则推出来了**：`usage.characters` = **汉字 × 2 + 其他 × 1**。那句 20 字 = 17 汉字 + 3 标点 → 17×2+3 = **37**，与返回一致                                      | 报价：20 页约 800 汉字 → 计费约 1600 → **约 ¥0.16/本**（修正 spec §1.2b 早先的 ¥0.08）                                       |
| 音频参数            | 实测输出 **48kHz / 320kbps mp3**——请求里的 `sample_rate: 24000` **被忽略了**；那句 20 字 ≈ **2.5 秒 / 99KB**                                                       | 20 页 ≈ **50 秒 / 约 2MB**（按每页两句算）；320kbps 对语音是浪费但这是它给的；★ **2.5 秒念两句偏快**，语速合不合适要等人耳判 |
| 输出确定性          | 同音色同文本两次调用 mp3 **md5 一致**（`4f3332b4…`）                                                                                                               | 可按内容寻址缓存，与 ADR-0007 的资产模型同构                                                                                 |
| 音色列表形状        | `list_voice` → `{page_index, page_size, total_count, voice_list:[{voice_id, target_model, status, gmt_create, gmt_modified}]}`，新建的 `status` 是 **`DEPLOYING`** | 界面要能显示"音色还在部署中"这个真实状态，不能假装秒好                                                                       |
| voice_id 形状       | `qwen-audio-3.0-tts-flash-probe-<32 位 hex>`（带模型前缀）                                                                                                         | 可以肉眼看出它绑的哪个模型                                                                                                   |
| 音频 URL            | `expires_at` ≈ 24 小时、**`http://`**                                                                                                                              | 必须**立刻下载落盘**；从服务端取，避开混合内容                                                                               |

**没量到的（照实写）**：

- **听感**（第 3 项）——机器判不了。
- **实际计费**：文档两页互相矛盾（复刻模型页写 0.01 元/次，复刻指南 FAQ 写"创建音色免费"）。
  实测只拿到 `usage.count: 1`，**账单数字要等控制台**。本单不许引用任何一个当结论。
- 克隆音色**合成出来的到底像不像**那个样本：本次样本是**TTS 自己生成的音频**（不拿真人声音做探测），
  所以验的是**机制**，不是**克隆质量**。像不像要等 §8.4 那条路（团队成员自己的声音）再量。

## 四、落点

- **引擎侧**：`voice: null` 的 seam 在 W2 已经留好了（工单 w2-06 里有明确记载），

修法是精确匹配 `audio/mpeg → .mp3`（**不能**写成宽泛的 `includes('mpeg')`，
那会把 `video/mpeg` 也叫成 mp3），并先剥掉 `; charset=…` 参数。

★ 一个当时看着像 bug 的现象，记下来免得下次重查：第一次加载时
`audio.duration` 是 **`Infinity`**。原因是这条资产出口**不支持 Range**
（要支持得自己切 206 与 `Content-Range`）。加载完整后时长就是正常值（3.864），
`ended` 也照样触发——所以对我们的控件（从头播完、能停）没有影响，
**受影响的只有"拖动进度条"那种任意位置起播**，而这一屏没有进度条。
已在路由里把这件事写成注释。

★ 判据 ① 落成代码的方式是"**整本都有音才给控件**"（`fullyNarrated`），
不是"按页显示/隐藏"。所以一本 19/20 页有音的书**没有**朗读按钮，

**没有的东西直说没有**，而不是留一个大部分时候点不动的按钮。
