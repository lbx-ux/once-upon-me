# 04 · 设置抽屉：把"模型与密钥"从创作流里拿出来

Status: done（2026-10-14：抽屉、四组、三个真探测、key 不落盘都实测过；
唯一没做的是"主页右上角那个入口"——它跟 [05](05-home-dashboard.md) 一起做）
依赖：无（可与 [03](03-character-profile.md) 并行）；被 [08](08-voice.md) 依赖（TTS 也要一把 key）
对应 Request 3(b)：模型与密钥单独弄出来，"可以做成侧边栏这样的，或者你推荐什么"。

## 一、形态：**抽屉（drawer），不是侧边栏**

用户给了两个选项并问我推荐哪个。推荐**右侧抽屉**，理由三条：

1. **侧边栏要占横向空间，而这一屏的空间是给书的**。阅读器是单页书、创作流有表单，
   两者都在横向争位置；一个 240px 的常驻侧栏会一直压着它们，
   而设置是**一天改一次**的东西，不是每次都看的东西。
2. **抽屉是"临时的"，这与设置的性质一致**：它的存在感应该在打开的那一刻最大。
3. 抽屉在移动端天然退化成全屏（本来就没有侧栏的位置），**一套实现两端成立**；
   侧边栏要写两套。

沿用既有按钮式入口：主页右上角一个齿轮/「设置」，创作流里 key 没填好时**也**给一个
入口（不是"回到第 3 步"，见 §三）。

## 二、抽屉里放什么

分组按**作用面**分，不按供应商分——用户想的是"我要让哪个能力动起来"：

```
模型与密钥
  ├ 文字（写故事）      base URL · key · 模型 id
  ├ 图像（画插画）      base URL · key · 模型 id · [参考图能力探测]
  ├ 语音（朗读）★       base URL · key · 音色        ← 08 落地后出现
  └ 视觉（核锚点）      base URL · key · 模型 id
```

★ 语音那一组在 [08](08-voice.md) 之前**不出现**。理由与项目美学一致：
没有消费方的输入框就是假装。**四个组里不接线的那些不许摆成一个灰色占位组。**

每组要有**一条真实的自检**（不是 ping）：填完 key 点"试一试"，用**当前位置上的模型**打一次
最便宜的真实请求，把状态码与耗时显示出来。这是 [01](01-model-selection.md) 探测脚本的
界面侧复用——同一段逻辑，两个入口。

## 三、★ 一条硬约束：key 不落盘

ADR-0008 的纪律，重申（它最容易在"设置页"这种地方被破——因为设置页的**本能**是持久化）：

| 字段     | 能不能进 localStorage | 理由                                              |
| -------- | --------------------- | ------------------------------------------------- |
| base URL | ✅ 能                 | 它不是秘密，且用户不想每次重填                    |
| 模型 id  | ✅ 能                 | 同上                                              |
| 音色 id  | ✅ 能                 | 同上                                              |
| **key**  | ❌ **不能**           | 三条纪律：**不落盘、不进日志、不进录制 manifest** |

所以 key 的生存期是**这一次填写到这一轮生成结束**，刷新就没了。这会带来一个真实的
体验问题：**用户每次开机都要重填 key**。它有解，但要明说而不是偷偷绕过：

- 认下来，界面上一句话说明（"key 只活在这次会话里，刷新要重填——这是我们不存你密钥的代价"）
- 想更省事的用户，`.env.local` 那条路仍然存在（开发/演示用），**并且要说清它只在这台机器上**

★ 不许出现的实现：把 key 写进 `sessionStorage` 然后说"我们没落盘"。sessionStorage 也是盘。
★ 这一条要有**可执行的证据**，办法沿用 W2 那把密钥自查的做法：
一条 `grep`/测试扫 `localStorage` 的写入点，确认 key 不在其中。

## 四、从创作流里搬出来的具体动作

- `STEPS`（`src/lib/creation/state.ts:95`）删掉 `model` 这一步，五步变四步
- `stepProblems` 里的 `model` 分支**不删，要改语义**：从"这一步过不去"变成
  "生成前的一次全局检查"——生成那一步点下去时，若 env 不全，**打开设置抽屉**并指出缺哪个
- ★ `STEPS` 上面那段"模型与密钥排在角色卡之前"的注释要说清它为什么**现在失效了**：
  当时的理由是"先出形象再填 key，第一次点必然失败"。抽出去之后，key 的填写
  **发生在用之前**（主页那次设置），所以顺序问题从根上消失了。
  **注释要改，不能留一段解释一个不存在的问题的长注释**——那是下次读错代码的入口
  （同 `illustrate.ts` 那句"并发是 W2 的优化"）。
- `toCardBody` / `toBookBody` 的 `env` 参数**一个都不动**：per-request Env 是 ADR-0008 的
  实现，抽离的是**采集位置**，不是传递方式。这一条守住，引擎一行不改。
