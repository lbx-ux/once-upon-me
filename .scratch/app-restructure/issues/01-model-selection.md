## 一、为什么"离职一年的人"是这张工单的验收标准

§1.1 那条结论（`/v1/images/edits` 可用）之所以能推翻 W1，靠的是一次**碰巧**：
探针先试着往 `/images/generations` 塞了三种新形状，又顺手打了 `/images/edits`。
下一次要重复这个运气，得有人记得"聚合站的 `/v1/models` 不是能力清单"这件事。

所以本单的交付物不是一张表，是**一条命令**：

```bash
node scripts/probe-modalities.mts
```

它输出（不打印 key、不打印 base host 全名之外的东西）：

```
text    : ok    (2.1s)   25 个模型可见
image   : ok    (15.0s)  generations ok · edits ok（参考图 200）
speech  : 404   接口不存在
vision  : ?
```

判据：**每一行都得来自一次真实请求**，不许从 `/v1/models` 反推（§1.2 已经证明那个目录
漏报了图像能力）。脚本对每个模态打**两条**路由并记录状态码与错误体前 200 字，
这样下次聚合站换了形状，错误码会变（像 §1.1 那样从"字段不认识"变成"尺寸不对"），
而**错误码的变化本身**就是最早的信号。

## 二、验收

- [ ] `scripts/probe-modalities.mts` 存在，`node` 直跑，退出码 0/1 表示"能不能用"
- [ ] 六条路由各打一次：`/chat/completions`、`/images/generations`、
      `/images/edits`（带图）、`/audio/speech`、`/embeddings`、`/models`
- [ ] 输出里**只有状态码、耗时、模型名、错误体片段**——`grep` 一遍确认没有 key 前缀
      （沿用 [03](w2 的密钥自查脚本) 的做法）
- [ ] 结论回填进 [spec §一](../spec.md)：谁变了就改谁，改不动就在表里写"这轮没量"
- [ ] TTS 那几家**没量到价格的，本单不补**——补它们要控制台或第二把 key，
      是 [08](08-voice.md) 的第一个动作，不是本单的

## 三、候选清单的用法（★ 不要当推荐）

§1.2 / §1.3 两张表是**候选**，不是选型结论。本单只负责"我们有哪些选项、价格各是多少、
哪几个数字是量到的"。**"哪个更好"要等 [08](08-voice.md) 的中文 A/B**——
中文绘本的 TTS，页面上的语言支持列表说明不了任何事。

★ 表里 `价格没量到` 那几格**不许被下一轮的人当成"大概和谁差不多"来填**。
阿里/火山同为中文原生梯队，价格量不到就是量不到。
