# 10 · 缩略图这条通路：让生成出来的大图不拖垮页面

Status: done（2026-10-14：A + B 一起做完并实测。A = 演示静态图导出时预生成 `.webp`；
B = `/api/assets?w=` 现缩 + 落盘缓存。依赖新增 `sharp`，用户当场拍的板）
来源：不是原始八条需求里的一条，是 [03](03-character-profile.md) 做卡片墙时量出来的——
两张角色卡 5.6 MB、演示书三页 11.5 MB，而"看一本成品"是评委点开的第一屏。

## 一、为什么不是 `next/image`

README §五 把 `next/image` 列在「刻意未做」里（要改已交付的 `HeroOrbit.tsx`）。
而这一轮的诉求是**运行期生成的资产**：那些图不在 `public/` 下、文件名带内容指纹、
`next/image` 要另配 loader。所以走的是自己那条只读出口加一个查询参数，
`next/image` 那一行仍然留在原处（它独有的收益——自动 AVIF 协商、尺寸属性防 CLS——另说）。

## 二、做了什么

| 件                                      | 是什么                                                                                                       |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `src/lib/thumbs.ts`（新）               | 一张**封闭的档位表**（240 / 384 / 512 / 768 / 1024）、`?w=` 的解析与向上归档、缓存键、一次 sharp 缩放        |
| `src/app/api/assets/[...path]/route.ts` | 认 `?w=`：命中缓存直接发，没命中就现缩并写回资产根 `thumbs/<档>/<原路径>.webp`                               |
| `src/lib/asset-url.ts`                  | `assetUrlOf(path, width?)`——宽度是"想要多大"，不是档号，服务端负责归                                         |
| `src/lib/book-source.ts`                | 运行期的书：页图走 1024 档；演示书：优先用预生成的 `.webp` 兄弟文件（`demoAssetPathFor`，纯函数）            |
| `scripts/export-demo-book.mts`          | 导出时给每张 `.png` 生成 1024 档的 `.webp`；加 `--thumbs-only` 只补小图不重拷整本书                          |
| 消费者                                  | 角色卡墙 768、主页「小主角」胶囊头像 240（★ 因此头像终于敢放了）、创作流复用列表 240 / 预览 768、阅读器 1024 |

## 三、三条不是显然的判据

1. **`?w=` 不接受任意宽度。** 值向上归到最近一档；非法值（`0` / `abc` / 比最大档还大）
   **回原图**。理由写在 `thumbs.ts` 文件头：任意宽度 = 缓存键跟着 URL 无限增长 =
   自己给自己做一次磁盘 DoS，而且每次归不上的都要再跑一遍缩放（实测 60–600 ms）。
2. **静态的 `public/demo/` 走不到这条。** Next 直接发盘上的字节，查询字符串它看不懂，
   挂 `?w=` 会**静悄悄回原图**——一个骗人的优化比不优化更糟。所以那批用预生成的
   `.webp` 兄弟文件。★ 两条路出的字节数一模一样（同一组 sharp 参数），这是交叉验证。
3. **原图永远是记录。** 缩略图是派生物：不进清单、不进指纹、不参与一致性核对，
   删了能重算。缩放失败（图坏了、原生模块装不上）**回原图而不是 500**——
   一个性能优化不该变成一次故障。

## 四、实测

| 量什么                                 | 结果                                                                                                                           |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 角色卡墙（`/character`，两张卡）       | **5,590,702 → 156,342 字节**（35.8 倍），`content-type: image/webp`                                                            |
| 创作流第 3 步（预览 + 两张复用缩略图） | **约 8.4 MB → 95,096 字节**                                                                                                    |
| 演示书三页（`/reader/xiaoyu-r1-…`）    | **11,192 KB → 563 KB**（19.9 倍）。预生成三张分别是 162,564 / 178,918 / 234,604 字节                                           |
| 同一张图两条路的字节数                 | 现缩 `page-1?w=1024` = 162,564；预生成 `page-1-a1.webp` = **162,564** ✓ 完全相同                                               |
| 归档行为                               | `?w=480` → 512 档（30,082 字节 webp）；`?w=abc` / `?w=0` / `?w=999999` → 原图 2,818,478 字节 png，**不报错**                   |
| 缓存                                   | 第二次请求命中 `.out/web/thumbs/768/…webp`；三个档合计落盘 168 KB                                                              |
| 主页胶囊头像                           | `?w=240` → **9,780 字节**，胶囊显示 **小满**（名字来自 `kids.json`）而不是 `xiaoman-r1`                                        |
| 一次缩放耗时                           | 1440 PNG → 1024 WebP：190–580 ms（所以必须落盘缓存，不能每次现缩）                                                             |
| 密钥自查                               | `node scripts/check-secrets.mts`：`.out/web` + `public/demo` 13 个文本文件、8 条模式，**命中 0**                               |
| 闸门                                   | format / lint（0 error 0 warning）/ typecheck 全绿；`pnpm test` **272 通过 / 26 文件**（+13）；`engine-run --mode=stub` 5/5 页 |

## 五、欠着的

- **`/api/cards` 的 POST 响应仍回原图 URL**（家长刚点完"出一张形象"那一次会拉 2.7 MB）。
  要修得给 `CardForm` 加一个 path 字段，牵动 reducer；那一步刚花十几秒出完图，
  再等 2.7 MB 不算最疼，所以没在本单里顺手做。
- **`thumbs/` 没有清理策略**。它按"原路径 + 档"存，原图换指纹就换键，旧键不会自己消失。
  演示期无所谓；上线前要有一条"按最久未访问删"的，或干脆在导出脚本里清。
- **AVIF 没试**。同一张图 AVIF 通常比 WebP 再小两三成，但编码慢一个数量级，
  现缩那条路（60–600 ms 已经不算快）可能吃不消。要做得先量。
- `pnpm-lock.yaml` 与 `package.json` 因 `sharp` 变了，**提交时它们必须和代码在一起**，
  否则别人装完跑不起来（`/api/assets?w=` 会走"缩放失败 → 回原图"那条兜底，页面照常，
  只是慢——这条兜底顺带保证了"依赖没装对"不会变成白屏）。
