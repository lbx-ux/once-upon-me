## 一、两条选型结论（实测优先）

### 1.1 ★ 参考图：**不用换模型，现在这把 key 就能用**

用户的前提是"现在的生图模型不能根据参考图生成"。**这个前提是错的**，
W1 的结论也是错的。实测（2026-10-14，`IMAGE_MODEL=wan2.7-image`，
base `tokenrhythm.studio`）：

| 请求                                                          | 结果                                                                            |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `POST /v1/images/generations` + `image: [dataURL]`            | `400 请求包含未知字段`                                                          |
| `POST /v1/images/generations` + `prompt` 传数组               | `400 prompt 类型错误`                                                           |
| **`POST /v1/images/edits`** + `image: <dataURL>`（1×1 像素）  | `400 IMAGE_INPUT_DIMENSIONS_INVALID`：**"参考图宽高必须在 240～8000 像素之间"** |
| 同上，带 alpha 的 1440² PNG                                   | `400 IMAGE_INPUT_ALPHA_UNSUPPORTED`：**"不支持带透明通道的 PNG"**               |
| 同上，压平到白底（`sharp.flatten()`，1440²，3 通道，2.36 MB） | **`200`，15.0s，返回 2.27 MB PNG**                                              |

★ 三条错误码是**语义错误**（尺寸、alpha），不是"字段不认识"——
说明服务端**真的在解析这张图**。W1 只在 `/images/generations` 上试过 7 个字段名，
从没试 `/v1/images/edits` 这条路由，于是把"我们没找到入口"记成了"模型吃不了参考图"。

产物看图核对过：同一个孩子（短发、圆脸、大眼、红衣），新场景（草地、长椅、树、
午后暖光）与提示词一致；**衣服配色与参考图有偏差**（参考是红白条纹 + 蓝背带，
产物是红上衣 + 蓝背带）。所以"同一角色"成立、"同一套衣服像素级不变"不成立——
这一条要交给工单 [02](issues/02-reference-image-pipeline.md) 的比对器去量，
不许靠眼睛下结论。

**结论**：工单 [03](issues/03-character-profile.md) 要的"上传孩子照片 → 生成插画形象"
**不需要换供应商**，需要的是：① 引擎加一条 `edits` 通路；② 上传图做尺寸/alpha 归一
（≥240px、压平到白底、JPEG 或无 alpha PNG）；③ 用真实照片再量一次（见 §四 未决）。

### 二之补 · 未成年人图像：一句答辩话术要改写

`scripts/make-demo-cards.mts` 的文件头写得很清楚，而且是**刻意的**：
"演示与答辩现场不需要任何真孩子的照片，**#5「AI 安全可控」那一章就能干净地说
'我们从未处理过未成年人图片'**"。小宇与小满因此是**合成的**孩子。

Request 3(a) 要"上传自己孩子的照片"。这不是推翻它，是**在它旁边加第二条路**，
但代价是那句最好听的答辩话变弱了。所以本 spec 定的口径是：

1. **默认路径仍是合成角色**：第一次进来看到的两个孩子（小宇 / 小满）**已经存在**
   （见 §二·五），照片上传是一个**需要家长主动点、且必须先读同意说明**的动作。
2. **同意流程要有实体**：不是一句灰字小抄，是一次明确的勾选 + 一段写着
   "照片只用于生成这本书的插画、处理完即删、不用于训练"的说明。
   §8.4 对声音已经定了"录音前单独同意"，照片沿用同一套。
3. **删除要给凭据**：`character-card/store.ts` 的 `deleteChild` 已经返回删掉的条数，
   注释里写着这是"隐私设计 §九 要求删除凭据列出每个存储位置各删了多少条"。
   **照片这条路要走同一个出口**——上传的原图也必须被数进去。
4. **答辩口径改成两句话**（工单 [09](issues/09-docs-adr.md) 落纸）：
   "默认角色是合成的，我们不需要任何真孩子；家长要给自己孩子做书时，走单独授权的上传，
   有同意、有删除凭据、原图不留在我们的库里。"

## 四、未决（★ 别当成已成立）

1. **真实照片进参考图**能不能保住"是这个孩子"：§1.1 用的是**插画**参考。
   照片→插画是**跨域**，一致性可能明显掉。要量：拿一张真实儿童照片跑同一条 `/images/edits`，
   再用既有视觉比对器打分。**没有这张照片就量不了**——需要用户提供一张（或明确授权用哪张）。
2. **中文 TTS 质量**：三家都没听。见 §1.2 第 2 条。
3. **主页那四个数**：`阅读时长`、`连续天数` 现在**没有任何数据源**。
   要么实现一个诚实的本地记录（阅读器打开即记，只在**这台设备**成立），
   要么把这两张卡**不做**。工单 [05](issues/05-home-dashboard.md) 按"不做也不许显示假数"写。
4. **`r_redraw` 那个数仍然不能用**（一致性比对器阈值未重校准）——本轮所有"像不像"的判定
   都只报 pass/fail 与分数，**不引用重画率**。
5. **成本口径**：本 spec 里所有金额都是**供应商挂牌价**，不是我们这一轮的实际支出；
   项目自己的花费按既有约定不进汇报。
