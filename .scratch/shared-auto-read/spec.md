# 共读版的自动朗读（念到选择点停下来）· spec

Status: 已交付（2026-10-20）。用户原话与判据在下面，实测读数在文末 Comments。
相关：`.scratch/reader-prefs/`（独读版那条偏好，2026-10-17）、`.scratch/w3-shared-reading/`（共读版本身）。

## 一、要什么（用户原话）

> 现在的阅读偏好设置只有独读版，现在给共读版也加一个自动播放，有分支出现的时候就停下来，
> 并读一下分支的那个音频，然后用户选择完后再开始剩下的自动播放

拍板（2026-10-20，用户选定）：设置里**单独给共读版一节**（不沿用独读版那一条）。

## 二、现状（改之前）

`ReaderBook` 一台组件两种形态（ADR-0006），所以共读版**其实已经在读**那条偏好里的
「自动朗读」——但那条链在共读版上没有定义过终点：

- `use-narration.ts` 的 `onEnded` 念完一屏就 `goTo(opening + 1)`，**不看** `maxLeafOf`；
- 而共读版没选之前，`maxTarget` 恰好挡住封底那一片叶（`reader-model.ts:196`）。

于是按一次「自动朗读」：念到选择点那一屏、念完，**一路翻过选择点到「读完啦」**——
"选择点"三个字从头到尾没起作用，正是 `maxLeafOf` 那条注释要挡的坏法。
盘上有活的共读版书（`public/demo/books/xiaoyu-r1-6ca00a33b4d7`），所以这条能当场复现。

## 三、做什么

1. **两档各一条偏好**：新增 `xiaozhujue.reader.turn.shared`（`lib/reading-prefs.ts`），
   设置弹窗里多一节「共读版」（位置在「阅读偏好」之后、「手机横屏提示」之前）。
   老键 `xiaozhujue.reader.turn` 管独读版，**不改名**（改名 = 所有人的既有选择退回默认）。
2. **自动朗读在共读版上多一段路**（`use-narration.ts` 规则 4）：
   走到**还拦着路**的选择点那一屏 → 念完正文 → 接着念**提问 → 选项 A → 选项 B**
   （与那颗「🔊 念一遍」同一份音频、同一个顺序）→ **停在这儿等孩子选**；
   选了哪一支就从那一支的第一页接着念（`continueAfterPick()`）。
3. **选择点那三段的播放权搬进 `useNarration`**：自动朗读要念它，而这一屏的声音
   只能有一个出处（原先它们在 `ChoicePoint` 自己那份 `<audio>` 里）。
   `ChoicePoint` 只留按钮与那行小字，收三个 prop。
4. **顺手修掉那个活 bug**：`onEnded` 在 `stopAt` 那一屏不再 `goTo(opening + 1)`。

## 四、不做

- 不做"到选择点先停住、等人按念一遍"（用户要的是自动念）。
- 不做超时，也不自动替孩子选（"停住等选"是共读版从 W3 起就有的口径）。
- 不动独读版的行为（`stopAt` 在独读版恒为 `null`）、不动 `BooklistReader`（不传新参数）、
  不动 `flip.ts` 几何、不动 `maxLeafOf`、不给阅读器加第二颗开关。

## 五、算做完的判据

1. **设置里那两节互不干扰**：两个键、两组 radio（`name` 不同），改一节不动另一节。
2. **次序**：自动朗读在共读版上换源的次序恰好是
   `page-1 → page-2 → page-3 → ask → opt-a → opt-b`，六段**每段都真的响了**。
3. **停住**：走完那三段之后**停在第 3 页**（选择点那一屏），整趟**一次都没到封底**
   ——这条就是那个 bug 的反面。
4. **接着念**：按下某一支之后起来的是**那一支**的音频，而另一支的资产一次都没被请求。
5. **人翻页仍然一票否决**（独读版那条规矩没被推翻）。
6. 三条闸门 + `pnpm test` + `node scripts/chk-shared-reader.mjs`（判据 7b/7c）。

### 2026-10-20 · 实测（隔离 dev server + 无头 Chrome 直连 CDP）

用现成的 `scripts/chk-shared-reader.mjs`（真帧、真网络、真鼠标点击），新加判据 7b/7c，
**53/53 条通过**。这一趟记下来的次序与停车位置：

| 量                 | 读数                                                                                |
| ------------------ | ----------------------------------------------------------------------------------- |
| 换源的次序         | `page-1.mp3 → page-2.mp3 → page-3.mp3 → ask.mp3 → opt-a.mp3 → opt-b.mp3`            |
| 每一段是否真的响了 | 六段都取到了（`playing` 为真的帧都在）                                              |
| 底栏走过的读数     | 封面 → 第 1 页 → 第 2 页 → 第 3 页（**没有封底**）                                  |
| 停在哪儿           | 第 3 页，钮仍是「■ 停止」，小字是「自动朗读停在选择点上：选完一支，剩下的接着念。」 |
| 再等 3 秒          | 页与声音都没动                                                                      |
| 选 b 支之后        | 起来的是 `page-5.mp3`（b 支第一页）；这一趟 `page-4.*` 一次都没被请求               |
| 按 ›               | 声音停、这一趟结束（钮回到「▶ 自动朗读」），之后 2.5 秒不再自己念                   |

**探针自己先错过一次，记下来**：第一版的"停车"判据是
`src 是 opt-b && 没在播 && 钮是 ■ 停止`——而"刚换源、还没起播"那一瞬三条全中，
于是它在最后一段的**开头**就判定"停住了"（"停住"与"小字说清了为什么"两条都绿在一个
还没念完的时刻上）。改成 `audio.ended === true` 之后才量到真东西。
★ 同一条纪律下的另一半：把 `stopAt` 临时改成 `null` 复跑一遍，
**7 条新判据全红**（46/53），说明它们量的是这个功能，不是环境。
