## 一、五步（按产品定义，按 10/13 三问收敛）

产品定义是 5 步（`E:\compete\亲子绘本工坊.md` §二）。这一周实现其中四步 +
生成这一步交给 [05](05-generate-orchestration.md)，并且**两处刻意不做**：

| 步  | 产品定义原文        | W2 做到哪                                                                                                 |
| --- | ------------------- | --------------------------------------------------------------------------------------------------------- |
| 1   | 孩子是谁            | 名字（必填）+ **读音确认**（多音字）+ 年龄档 + 外貌/爱好标签（多选）                                      |
| 2   | 想讲什么            | 12 个主题（`lib/themes.ts` 的 THEME_KEYS，与首页那 12 张封面同源）+ 自由输入一句 + 想让他得到什么（可选） |
| 3   | 角色卡确认 ★ 高光点 | **锚点表单 + 出 1 张参考图**（见 §二）                                                                    |
| 4   | 形态与声音          | **只选形态**。声音那一格**不出现**（见 §三）                                                              |
| 5   | 生成                | 交给 [05](05-generate-orchestration.md)                                                                   |

### 照片上传不做（写在这里，也写在界面上）

产品定义第 1 步有"照片上传（可选）→ 用于生成角色卡参考图"。**这条路当前走不通**：
画像接口**不支持参考图**（7 个候选字段名全被 `HTTP 400 · 请求包含未知字段` 挡回，
`IMAGE_SUPPORTS_REFERENCE=0`，W1 实测）。所以照片传上去也没有消费方。

按项目的美学（CLAUDE.md「不糊弄」）：**没有的东西直说没有**。
界面上的处理：第 1 步不出现上传框；第 3 步给一行说明——
"这一版还不能用孩子的照片来生成形象：我们用的图像接口不支持参考图（实测）。
形象由下面这些外貌描述生成，改一条描述就换一版。"**留一个传上去没用的上传框就是假装。**

## 二、第 3 步：角色卡

1. **锚点表单**：7 个槽位（`ANCHOR_SLOTS`：骨相/眼睛/头发/身形/肤色/标记/衣着），
   每个槽位预填一条（标签与强度分档从 `ANCHOR_LABELS` / `ANCHOR_STRENGTH` 来，不另抄一份）。
2. **出 1 张参考图**：1 次图像调用（1440×1440），风格段取 `StyleLock.promptFragment`。
3. **确认或重出**：家长可以改任意锚点再出一张（重出＝按需的候选，不是一次给 3–4 张）。
4. **把同一份锚点的两种用法摆给家长看**：
   - `promptFragmentOf(card)` → "每页画的时候就按这段画"
   - `checklistOf(card)` → "画完就按这几条核对"

   ★ 这不是装饰。ADR-0007 的头号约束是"画的时候按 A 画、查的时候按 B 查，一致性分就失去意义"，
   所以这一层必须**同源于 `card.anchors`**。让家长看见这两段出自同一份锚点，
   是把那句内部约束变成产品上的可信感——也是"人机协同审卡"（#9 那条创新点）在 W2 的落点。

5. **校验**：`validateCard` 不通过时当场说清哪一条不行（页级词如"笑着"会被拦下，
   理由：页级的东西写进锚点，下一页哭的那页就会被判不合格）。

## 三、第 4 步：为什么"声音"那一格不出现

产品定义写"配音：默认童声音色 ｜ 克隆父母声音"。W1 口径是 TTS 推迟到 W4，
`voice: null`。所以这里有两个选择：**灰掉的控件**，或者**不出现**。

选后者。理由与首页拆掉播放条完全相同（README §五「选择点」）：
一个只对四分之一能响的控件，证的是这一页想证的反面。
更进一步：**一个灰掉的控件也在承诺**——它在说"这里将来会有声音"，
而 W5 的部署形态里那是真的会有。所以：
第 4 步只有形态；声音这件事在**生成过程面板**里由引擎那条非致命事件说一次
（"配音能力未接入（W4 落地），这本书暂时没有朗读"），**只说一次，说在真话所在的地方**。

### 共读版怎么摆

形态那一步只有独读版可选，共读版这一周**不摆**（不是灰的）：
"选择点"整套交互（图+语音按钮、树枝可视化）在 W3，摆一个进不去的入口等于把 W3 的活提前承诺。
界面上写一句："共读版（孩子做选择的那种）正在做，先把独读版走通。"

## 四、三态（#16 的验收面）

三态是**可测的**，不是形容词。每条都要能在预览里当场复现：

| 态   | 何时出现                                                    | 判据（怎么验）                                                      |
| ---- | ----------------------------------------------------------- | ------------------------------------------------------------------- |
| 空   | 首次进入 `/create`                                          | 清掉本地状态 → 首屏是完整的第 1 步表单，不是白页、不是 0 字段的骨架 |
| 空   | 书架/阅读器没有这本书                                       | 打一个不存在的 `bookId` → 一句人话 + 回创作流的入口，不是 404 白页  |
| 加载 | 提交后到首条事件到达之间                                    | 把网络拖慢或打桩 → 有明确的"正在……"，且**不阻塞**表单回退           |
| 加载 | 生成中（长任务）                                            | 见 [02](02-event-stream-transport.md)：过程面板持续有进展，不是转圈 |
| 错误 | 四种坏法 + key/model 错（见 [03](03-model-and-key.md) §三） | 每一条都能用"喂错值"当场复现，且文案可操作                          |

★ 四种坏法是 W1 实测出来的产品前提（不是边缘情况）：
树形不合法 / 思考链吃光 token 预算 / 平台不许关思考（`REASONING_REQUIRED`）/ 太慢。
ADR-0008 的原话是"把'任意模型会以各种方式坏'当成产品前提"。
所以**错误态不是兜底页，是常态页**，文案要能指导下一步做什么。

## 五、验收

- [ ] 五步能从第 1 步走到生成；每一步都能**退回上一步**且不丢已填内容
- [ ] 名字读音那一格有实际作用（它会进 `ChildProfile.nameReading`，配音时用于多音字）
- [ ] 第 3 步出图后能看到 `promptFragmentOf` 与 `checklistOf` 两段，且改一条锚点两段都变
- [ ] 页面上**没有**照片上传框、**没有**音频控件、**没有**灰掉的共读版入口；三处各有明写理由的一句话
- [ ] §四 那张表的每一行都能在预览里复现（`preview_*` 实测，不是嘴上说）
- [ ] `prefers-reduced-motion` 下每一步的过渡都有**静止终态**（不是"不播"——README §五 的硬要求）
- [ ] 移动端：单列、触控热区 ≥44px。★ 措辞照 `docs/tech-selection.md` §3.3：
      **44px 是我们的选择（4 岁孩子的手指），不是 WCAG 要求**（WCAG 的 Web 触控目标是 24px）
- [ ] 组件样式与组件同目录同名（`Foo.tsx` / `foo.css`），在 `globals.css` 里 `@import`；
      令牌只消费 `var(--x)`，**不在组件里新造颜色**

| ---- | ----------------------------------------------- | --------------------------------------------------------- |

**边界与摩擦，如实记**：

- **第 3 步要用第 4 步的 key** → 顺序重排（详见工单 [03](03-model-and-key.md) 的四、验收）。
- **第 4 步补了「用一张已有的卡」**（`GET /api/cards`）：只有"出一张形象"一条路时，
  每做一本书都要重新出一张脸，那正好把 ADR-0007 的"可复用"做没了。参考图走
  `/api/assets`（新开的只读出口，越界由 store 拒、按内容指纹给缓存头）。
- **客户端不许 import `engine/index.ts`**：`/create` 第一次编译直接
  `UnhandledSchemeError: Reading from "node:fs/promises"`，起因只是从 index 取了一个 `AGE_BANDS`。
  修法是改成从 `engine/domain.ts` 取，并且**加了 eslint 规则**（`CLIENT_LAYERS` 禁
  `engine/index`）——手动修一次只能修这一次。顺带把"引擎对 UI 的接口分两半"这件事写进了规则注释：
  跑一本的 API 在服务端走 index，事件协议与领域常量浏览器直接取叶子模块。
- **一处文案撒谎已修**：复用旧卡时写着"由你填的模型画出"，而那张卡是 W1 的脚本
  用 `wan2.7-image` 画的。现在如实显示「这张卡是 wan2.7-image 画的」。
- **两处裸色值已收进令牌**：新增 `--surface` / `--surface-soft` / `--danger` 三个
  （创作流第一次出现"面板、输入框、只读文本块、真错误"这四种东西，首页三屏一个都没有）。

**还没做的两条**（不藏）：

   但我**没有开模拟实测**（工单 [08](08-design-system-and-baseline.md) 的验收面里有这一条）。
