## 一、翻页几何：搬 `flip.ts`，不改它一行

### 为什么不是 gsap Flip（对看板 W2 那一行的校正）

看板写的是"🎬 用 `gsap`（Flip）做阅读器翻页动画"。**按此校正为：复用
[`components/book/flip.ts`](../../../src/components/book/flip.ts) 的几何 + CSS 3D。**

理由三条，都是可核对的：

1. `flip.ts` 的文件头就写着它为什么单独存在——"W2 的阅读器要重写接口时，
   几何能整块搬走，不用推第二遍"。那是 W2 之前留的伏笔，这一单正是它的兑现处。
2. GSAP 的 Flip 插件解决的是**布局变化后的过渡**（DOM 从 A 位置跑到 B 位置），
   不是"叶片绕书脊转角度"。拿它做翻书要自己写叶模型，等于把首页那套重写一遍。
3. README §二/§五 已经把 GSAP 的边界写死：**只在第三屏**，前两屏的滚动驱动不迁。
   阅读器不是第三屏；引入第二条 GSAP 用法会让那句边界从"设计决定"退化成"哪里都行"。

★ 若实现中发现几何真不够用（比如单页书需要一个新的叶模型）：
**改 `flip.ts` 要单独一次提交，并逐个变量对照首页第二屏的视觉效果**
（README §五 的纪律：搬动它可以，改行为不行，除非重新测过）。

### 叶模型：单页书，不是跨页书

出图尺寸是 `1440x1440`（**方形**，`DEFAULT_IMAGE_SIZE`），而首页第二屏那套是
"一张 3:2 跨页 = 两个 3:4 半页"。所以独读版按产品定义那句"全屏翻页，**一页一图一句**"
走**单页书**：第 k 叶的正面 = 第 2k 页，背面 = 第 2k+1 页，书脊在左侧，页从右翻到左。

- `flipState(q, leafCount)` 本身对叶数无假设（它是纯函数），要验的是**首页没假设 5 叶**
- 页数是入参（5–20），所以 `leafCount = ceil(pages/2) + 1`（封面与封底各占一面）
- ★ `flip.ts` 里那条"合着的书只有一页宽"的推论在单页书上更直白：
  书闭合时屏幕上只有一张方页，另一半是页面底色，**不是书的投影**

## 二、一页长什么样（版式，含一条可测的对比度判据）

一页 = 一张方图 + 一句正文。三种摆法里选**图在上、文字在下**（同一张"纸"上）：

| 摆法                 | 为什么不选                                                               |
| -------------------- | ------------------------------------------------------------------------ |
| 文字压在图上         | 水彩底 + 任意位置的文字，要稳过 4.5:1 对比度只能靠蒙一层黑纱，纸感就没了 |
| 文字与图各占左右半页 | 那是跨页书的版式，方形图铺进 3:4 的页面会拉伸或裁切                      |

正文用 `--font-serif`（衬线档，第三屏那句"书的封面上那句话"同一套），
一页一句、字号按年龄档微调（`AGE_BANDS`）。**正文是真 HTML 文字**，不画进图里
（首页第二屏的先例，`demoBook.ts` 的注释写着理由）。

## 三、声音：一个字都不提（口径 2）

阅读器里**没有**播放条、没有音量、没有"即将上线"的占位控件，也**不写一行静态说明**。

- 理由与首页拆掉播放条同源：一个只对四分之一能响的控件，证的是这一页想证的反面
- 那"没有声音"这件事在哪说？**生成过程面板里说一次**——引擎自己会发那条非致命事件
  （"配音能力未接入（W4 落地），这本书暂时没有朗读"）。
  **只说一次，说在真话所在的地方**：一条发生在生成那一刻的事实，就该在那一刻被说出来，
  而不是在阅读器里常驻一句免责声明

## 四、健全性：缺页、键盘、静止模式

| 事项     | 判据                                                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 缺页     | `Book.errors` 里的页显示成一张"这一页没做出来"的纸（文案 + 页码），**不留裂图、不留空框**                                                               |
| 键盘     | `←` `→` **只在这一层的容器上接**。★ 首页 `StorybookFlip` 那个已知 bug 就是 `window` 上无条件接键，书滚出屏幕照样翻页——**新页面不许复制那个 bug 的形状** |
| 静止模式 | `prefers-reduced-motion` 下换成**无动画的翻页**（直接切页），不是"不翻页"。终态必须静止                                                                 |
| 触屏     | 左右滑动翻页；热区 ≥44px（我们的选择，不是 WCAG 要求，措辞照 `docs/tech-selection.md` §3.3）                                                            |
| 进度     | 页码指示（"7 / 20"）与点击跳页；不要做 `BookSpine` 那种刻度（那是首页第二屏的东西，一屏一页用不上）                                                     |

## 五、预生成演示书的静态导出（ADR-0003 的演示路径）

W1 记过一条：**"离线演示路径从没通过"**——录制器把资产写进内存 store，
manifest 里记着路径而字节从没落盘，于是"断网也能出一本完整的书"这句话当时是假的。
所以这一条不是可选清理项，是**把 ADR-0003 从文档变成可测事实**。

- `scripts/export-demo-book.mts`：把 `ASSET_ROOT` 里一本书的
  `book.json` + 全部图 + `events.jsonl` 拷进 `public/demo/books/<bookId>/`
  （书号是卡 + 主题指纹、不含时间戳，所以导出可重复、覆盖同名）
- 这两样随仓库提交：**它们在演示当天必须不依赖网络、不依赖运行期目录**
- **一个解析函数、两个来源**：阅读器与重放接口都走同一个
  `resolveBook(bookId)` / `resolveAsset(path)`——先查运行期 store，再查 `public/demo/`。
  ★ 不许在页面里各写一遍查找顺序：两个来源两种顺序，就是两份会漂的真相
- 导出的是**图与文本**，不含任何密钥（工单 [03](03-model-and-key.md) 的检查要覆盖 `public/demo/`）

**2026-10-14 · 阅读器建成，九条里八条有实测**

最后一行的"20 页整本"**没做成**：盘上没有 20 页的书（现有产物都是 3 页），
它实际要等 [05](05-generate-orchestration.md) 那次 `pages=20` 的真实运行。**不勾**。

### 一、两个来源、一个解析函数（ADR-0003 从文档变事实）

用同一本书号 `xiaoyu-r1-4fe055c5723b` 前后各开一次，只改盘上的东西、不改代码：

| 运行期目录在 | `data-source` | 图地址                      | 页面上的话                 |
| ------------ | ------------- | --------------------------- | -------------------------- |
| 在           | `runtime`     | `/api/assets/books/…`       | 这一轮生成的               |
| 挪走（mv）   | `demo`        | `/demo/books/…`（静态文件） | 预生成演示书（不需要网络） |

网络面板里逐条核对：`demo` 那一次的会话**只有 `/demo/books/…` 三条**，
一条 `/api/…` 都没有；`runtime` 那一次取的是 `/api/assets/books/…`。
这就是"断网也能读"的可核对版本——**不是断网测的**（没有网络模拟开关），
是"这条路径一次都不碰 API"。

三张图各 `fetch` 一次：`200`，`image/png`，3.40 / 3.81 / 4.25 MB。
页面里**一个 `<img>` 都没有**（图走 `background-image`），所以除这三条之外没有别的图片请求。

### 二、键盘只在容器里生效（首页那个 bug 的形状没被复制）

用真键盘事件序列测两侧，中间**先等补间停稳**（连续两次快照一致才算停），免得把上一次翻页的余波读成本次的结果：

- 容器内：`qTarget` 前进（"下一页"按钮随即 `disabled`），连按后角度 `-124° → -152° → -180°`、进度 `0% → 23.05% → 66.67%`、页码 `封面 → 第 1–2 页 → 第 3 页`
- 容器外：`blur()` 后往 `window` / `document` / `document.body` 各派发一组 `keydown`+`keyup`，
  三处快照**逐字节相同**（`angles`、`progress`、`readout` 全等）——一次都没翻

★ 首页那一半不需要重测：`git status --porcelain src/components/book/` 为空，
`src/lib/useScrollDriver.ts` 与 HEAD 的内容差异也是空（它在 `status` 里显 M 是
之前记过的 CRLF 假故障，不是改动）。**没碰过的文件谈不上行为变化**。

### 三、静止模式：不是"我看了没动画"，是逐帧数出来的

做法：按帧采样进度条的**去重序列**，比较两种模式的"中间值个数"。

| 模式                            | `End` 一次的去重序列                                  | 中间值   |
| ------------------------------- | ----------------------------------------------------- | -------- |
| 动画                            | `36.4% → 77.1% → 84.8% → 94.5% → … → 100%`（15 个值） | 13 个    |
| 静止（`data-motion="reduced"`） | `0% → 100%`                                           | **0 个** |

静止模式是打桩 `matchMedia` 后**重新挂载**组件测的（组件里那次 `matchMedia` 只在挂载时读一次，
所以必须在挂载前打桩）。测完把原版还回原型链、重载页面复核：
`data-motion` 回到 `full`、系统设置 `prefers-reduced-motion: false`、动画序列重新出现。

**没做截图对比**：那时应用窗口被压在别的窗口下面，`preview_screenshot` 直接超时
（"the page did not finish rendering in time"）。逐帧采样比截图对比强——截图看不出中间帧，
而这里数的是中间帧的个数。**这一条是真的测了，只是换了量法。**

### 四、缺口与空态

- 缺页：一本 3 页全失败的书 → 5 个面里出现 3 处"这一页没做出来"（带页码），
  `reader__art` 元素 **0 个**——不裂图、不留空框
- 空态：`GET /reader/no-such-book-id` → **HTTP 200**（不是 404 白页），
  页面上是"找不到这本书" + 书号 + 回创作流的链接

### 五、声音：一个字都没提

`document.querySelectorAll` 数出来的：`audio` 0、`video` 0、`[controls]` 0，
按钮/链接文案里匹配 `播放|声音|朗读|配音|🔊|▶` 的 **0 个**。
口径 2 照办——那件事只在生成过程面板里由引擎自己说一次。

### 六、一处刻意的行为改动（唯一一处）

翻到最后一叶时全部叶都在**左边**，封底落在左半幅。原先 `--book-x` 沿首页那条
"`q ≥ 0.5 → 0%`"，于是末态是"开着的书 + 右半幅空白纸"。改成：

```
q < 0.5 → 25%    q > leafCount - 0.5 → -25%    其余 0%
```

即**末尾多一个合着态**，把封底挪回正中，与开头的封面左右对称。实测：
`--book-x: -25%` 时封底矩形与舞台中心重合（舞台 `x=100 w=943`，中心 `571.5`，
单页居中于 `335.75…807.25`），`25%` 时封面同样居中。
`flip.ts` 一行未动——动的是书脊平移，不是叶的几何。

### 七、顺手改掉的一处闸门噪音

`public/demo/books` 进了 `.prettierignore`，理由写在那个文件里：
它是**引擎自己写出来的字节**（`JSON.stringify(x, null, 2)` 与 Prettier 的排版不同：
短数组折行、末尾换行），让 Prettier 接管会使"仓库里那份"与"流水线刚吐出来的那份"
不再是同一个文件——而 ADR-0003 的演示路径正建立在"一本已生成的书是资产"上。

### 八、一次假警报，记下来免得下次重查

中途读到过 `progress: 109.2%`（`q` 越过最后一叶），一度当成补间的越界 bug。查完是**探针的问题**：

1. 那个值对应 `q = 1.0925`、`leafCount = 1`——是**另一个 `ReaderBook` 实例**（当时的
   客户端路由来回留下的一棵树，`pages` 为空 → `leafCount = 1`）的进度条被 `querySelector` 选中了
2. 补间的公式本身不可能越界：`next = qRef + (qTarget - qRef) × f`（`f ∈ [0,1]`）是
   `qRef` 与 `qTarget` 的凸组合，两者都在 `[0, leafCount]` 内，结果不可能出去

同一次还量到过"`Home` 停在 36.4% 不回 0%"，同一原因（读到的是另一棵树的元素）。
干净重载后 `Home`/`End` 逐页正确 —— 见第一节那张表。

另记一条环境事实，它误导过几次判断：**预览面板不可见时 `requestAnimationFrame` 一帧都不跑**
（实测 `visibilityState: "hidden"`、`rafTicksPerSecond: 0`），于是补间"看起来卡住了"。
这不是组件的问题——浏览器不给隐藏页排帧。要测动画必须先确认 `visibilityState`。
