## 一、令牌：延伸，不重挑

首页的令牌体系已经定稿在 [`app/globals.css`](../../../src/app/globals.css) 的 `:root`
（`--bg` / `--ink` / `--ink-muted` / `--accent` / `--card-radius` / `--card-shadow` /
两档字体栈），并通过 `@theme inline` 暴露给 Tailwind。

这一周的活是**把同一套令牌延伸到新页面**，不是重挑配色。四条硬约束照旧：

| 约束                                       | 本单的验收                                                    |
| ------------------------------------------ | ------------------------------------------------------------- |
| 令牌只在 `globals.css` 的 `:root` 定义一次 | 新组件里搜不到裸色值（`#hex` / `rgb(`），只有 `var()`         |
| 组件样式与组件同目录同名                   | `Foo.tsx` / `foo.css`，在 `globals.css` 里 `@import`          |
| 零 Web 字体                                | 不新增任何字体文件/网络字体请求（理由见 tech-selection §3.2） |
| 无深色模式                                 | 不写 `prefers-color-scheme`（README §五 已定：暂不做）        |

★ 可能真需要新增的令牌只有一个：**正文那一档字号**（首页没有"给 4–8 岁孩子读的长句"这个场景）。
新增就走 `:root` + `@theme inline` 两处，并按 `docs/tech-selection.md` §3.3
说明它是按年龄档定的**产品判断**，不冒充可访问性下限。

## 二、移动端基线

边界先说清：**首页三屏刻意只做桌面**（README §五 第一条，那条不推翻）。
这里的移动端基线指的是**创作流与阅读器**。

| 面     | 基线                                                                                                        |
| ------ | ----------------------------------------------------------------------------------------------------------- |
| 创作流 | 家长在手机上填的：单列、字段纵向排布、键盘弹起时当前字段可见、按钮不贴屏幕底缘                              |
| 阅读器 | 一屏一页；竖屏是常态（方图正好占满宽度），横屏不塌                                                          |
| 触控   | 热区 ≥44px。★ 报口径时写"**我们的选择**（4 岁孩子的手指）"，不报成 WCAG 要求（WCAG 的 Web 触控目标是 24px） |

## 三、三态视觉规范（与 [04](04-creation-flow.md) §四 的实现共用一份）

- 三态在**组件层**实现，不在页面层各写一遍（加载/空/错误各一个组件，页面组装它们）
- 错误态**不是兜底页，是常态页**：BYO 之后"任意模型会四种方式坏"是产品前提（ADR-0008）
- 每一条错误文案都要能回答"我现在该做什么"

## 四、Lighthouse 基线（#12，目标 ≥ 90）

跑**三处页面 × 两端**（移动端是基线，桌面端是参考）：

| 页面                  | 备注                                                  |
| --------------------- | ----------------------------------------------------- |
| 首页 `/`              | 已交付的三屏，这一周第一次量它                        |
| 创作流 `/create`      | 新页面                                                |
| 阅读器 `/reader/<id>` | 新页面，**图最多**（20 张方图），是最可能不达标的那个 |

数字记进 `docs/`（新开一节或写在 `tech-selection.md` 的性能节里），必须写清：

- 量的是哪个 URL、哪个浏览器、移动端还是桌面端（**说清哪一端是基线**）
- 哪一项没到 90、拖它的是哪条（不要只记一个总分——总分不能指导修复）
- 量法与时间戳（数字要能复现，README「不糊弄」那条）

★ 一个预判，别当结论：阅读器一屏一页、图是方形 1440²，
**首屏只加载当前页的图**（不要预加载全书 20 张）——这是 LCP 的关键，实现时就要按这个来。
真量出来如果不过，先看是不是这条没做到。

## 五、验收

- [ ] 三处页面 × 两端共 6 组数字进 `docs/`，含量法与时间戳
- [ ] 阅读器的图片加载是**按页**的（DevTools 网络面板核对：首次进入只请求当前页与封面）
- [ ] 新组件样式全部同目录同名且在 `globals.css` 里 `@import`
- [ ] 新组件里搜不到裸色值
- [ ] 移动端 375px 宽下三处页面都不横向滚动
- [ ] `prefers-reduced-motion` 三处页面各有静止终态
- [ ] 零 Web 字体：网络面板里没有字体文件请求
