# 07 · 规划期流式文本（#17 的地基，也是工单 01 缺的那三分之一）

Status: open
依赖：[02](02-event-stream-transport.md)（`event: delta` 那条通道）
给出去：[01](01-adr0004-threshold.md) 的量法要多一行"流式解析"的实测行数

## 一、两件事，别混在一起

### 1. 适配器侧的流式（真正的"流式解析"）

`TextGenerator` 现在只有 `complete()`。加一条流式方法：OpenAI 兼容的
`POST {base}/chat/completions` 带 `stream: true`，回的是 SSE 帧（`data: {...}` / `data: [DONE]`），
适配器边收边吐 delta。

★ 三件事必须当场说清，否则流式会悄悄改变行为：

1. **最终文本必须与 `complete()` 逐字段相等**。同一份录制响应，一次全量一次流式，
   跑出来的规划结果要**逐字段相等**——这条能测、且必须测。
   否则"流式"就是一个悄悄改输出的开关，而横评的数字（同一份 prompt 的通过率）
   就变成了两个口径。
2. **replay 适配器的"流式"是假的**。离线回放没有流可放：录下来的是一整段文本。
   所以 replay 的流式实现**一次把整段吐出来**，并且**标记它不是流**
   （`streamed: false`）。★ 不许用定时器把它模拟成打字机——那是在演示里造假，
   而 ADR-0003 的演示路径的全部价值就在于"屏幕上看到的是真的发生过的事"。
3. 流式的 `CallBudget.timeoutMs` 语义要重新想：全量调用的超时是"多久没回话就判失败"，
   流式的超时是"多久没有新 delta 就判失败"。**两个数不是一个数**，
   共用一份配置会在慢模型上把好结果判死。

### 2. 增量抽取（把 delta 变成家长看得懂的东西）

规划期的输出是一整张 JSON 故事表。**token 级的原始 JSON 打到屏幕上就是噪音**——
那是把内部状态当成产品。真正要看懂的是"故事正在被一页一页写出来"。

所以写一个**增量抽取器**：从累计文本里按到达顺序抽出**已经闭合**的
`"text"` 字段值（正文）与 `"title"`。它是个纯函数（进工单 [09](09-validation-tdd.md) 的 tdd 范围），
比"边解析不完整 JSON"简单得多：只看已经闭合的字符串字段，不试图给出半个对象。

★ 抽取器**只认已经闭合的东西**：半个字段不算数。否则会出现"第 7 页的正文先闪出半句再改掉"，
而屏幕上闪过的每一个字都必须是模型真的写完的字。

## 二、界面

- 规划期：一块"故事板"，已写出的页一条一条填进去，配一句"正在编故事（已写出 6 / 20 页）"
- 面板上的**持久**信息仍然只来自 durable 事件（[05](05-generate-orchestration.md) §二）：
  delta 是临时的，`plan-ready` 一到，故事板换成引擎给的那份正式标题与页数
- 规划一结束，delta 区**清干净**（不许留着一段"半成品"和正式结果并排）

## 三、取舍（写下来，免得以后被当成 bug）

**刷新后重放没有打字机效果**。重放的是 `events.jsonl`，里面只有 durable 事件
（[02](02-event-stream-transport.md) 的帧形状），delta 不在其中。
所以刷新之后看到的是"已经写好的故事板"，不是"正在打字"。

**这是对的**：日志的判据是"能重建同一串界面状态"，不是"能重建同一段动画"。
把 delta 也写进日志，代价是日志从几十行变成几十万行，换来的是一个纯粹装饰性的回放。
这一条要写进 [02](02-event-stream-transport.md) 的 Comments，两处口径必须一致。

## 四、验收

- [ ] 同一份录制响应的两条路径（全量 / 流式）产出的规划结果**逐字段相等**（测试钉住）
- [ ] replay 的流式实现标记 `streamed: false`，且界面上**不呈现成流**（不许定时器造假）
- [ ] 流式的空闲超时与全量超时是两个配置项，各有注释说清语义
- [ ] 故事板只用**已闭合**的字段；半个字段不显示
- [ ] `plan-ready` 到达后 delta 区清空，正式结果接管
- [ ] 原始 JSON 不出现在界面上的任何位置
- [ ] 键盘/读屏可达：故事板是 live region（`aria-live="polite"`），不要每来一个字就播报一次——
      **播报频率是可用性问题**，按页播报（每写出一页播一次）
- [ ] `prefers-reduced-motion` 下故事板静止呈现（无逐字动效）
- [ ] 量出流式解析的**代码行数**（非空非注释）并回填 [01](01-adr0004-threshold.md) §二 的表
