> **第 4 条的前提是一条实测结论，不是偏好**：图像接口**不支持参考图**
> （7 个候选字段名全被 `HTTP 400 · 请求包含未知字段` 挡回，`IMAGE_SUPPORTS_REFERENCE=0`）。
> 所以产品定义 Step 3 的「上传照片 → 生成形象」在这一条接口上**做不到**，
> 候选图只能由锚点文字生成。按项目的美学：**没有消费方的输入框就是假装**，
> 所以照片那一步 W2 不做，并在界面上写明为什么——而不是留一个传上去没用的上传框。

## 二、这一周的产出物（缺一不可）

1. **创作流 `/create`**：孩子是谁 → 想讲什么 → 角色卡（含 1 张参考图）→ 模型与密钥 → 生成（工单 [03](issues/03-model-and-key.md) [04](issues/04-creation-flow.md) [05](issues/05-generate-orchestration.md)）

## 五、闸门

```bash
pnpm format:check && pnpm lint && pnpm typecheck && pnpm test
```

外加两条本周新增的：

1. **`pnpm build` 必须过**。这是仓库第一次有 Route Handler 与客户端组件混在一个
   bundle 图里，Node-only 的 import 会在构建期就炸出来——比演示当天炸出来便宜得多。
2. **`node scripts/engine-run.mts --mode=stub` 仍要跑通**。它证明引擎没被界面污染，
   是"平台而非聚合"的证据本身（#11）。`lib/engine/` 不得 import React 这条硬约束
   这一周会第一次被真正试探（界面要消费 `describeEvent` / `isDisplayable`），
   试探的方向是**界面 import 引擎**，不是反过来。
