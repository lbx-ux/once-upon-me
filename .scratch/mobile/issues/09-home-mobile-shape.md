# 09 · 首页在手机上是另一副形态（第二轮）

Status: done

用户拿手机看首页报「适配效果不太好，可以改一下，不需要按 Web 端的界面来设计，
移动端可以修改一下」，并圈出首屏那句主张句的右端被切掉（2026-10-19）。

第一轮（04 / 07）做到的是"手机上不横向溢出"，五条判据全绿 —— 但那是**判据的边界**，
不是这一页的形态。这一轮为手机**重排**了三屏，桌面一个像素不动。

## 方向（用户定的四条，AskUserQuestion）

1. 保持三部分（首屏 / 一本书 / 五条亮点），**逐个换形态**；
2. 首屏主张句**保留打字机、允许折行**（补 `min-height` 让按钮不跳）；
3. 第三屏五条亮点改成**竖排五张全宽卡**（取消轮播与自动播）；
4. 第二屏那本书：**正文挪到书下方、整宽排**。

## 量到的三处坏（390×844）

| 面         | 改前                                                                                             | 后果                                                             |
| ---------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| 首屏主张句 | 行盒 **585px** 塞进 **350px** 的 `.hero__copy`，被 `.hero { overflow: clip }` 吃掉右边 **235px** | 第二句只看得见半句。★ 整页 `scrollWidth` 仍是 390，**判据 1 绿** |
| 第二屏正文 | `.book__face` 底左 **136px** 窄列（`max-width: 74%` 作用在半页 183px 上）                        | ≈ 9 字/行                                                        |
| 第三屏     | 轮播卡 **140px**（`min(560px, 36vw)`）、正文列 **94px**、13px 字、自动播                         | ≈ 7 字/行，读不成                                                |
| 整页       | **4784px ≈ 5.7 屏**                                                                              | 手机上滚得久                                                     |

## 改了什么

- 首屏（`hero-typewriter.css` / `hero-orbit.css` §6）：`≤640` 下
  `.hero__typing` 折行、占位 `.hero__typing-ghost` 隐藏、`min-height: 2.8em`
  （`≤340` 提到 `4.2em`）；`.hero-experience` 收到 **132dvh**，手机上 1.3 屏。
- 第二屏（`StorybookFlip.tsx` / `storybook-flip.css` §10）：新增 `.storybook__caption`
  （宽 `min(90%, 34em)`、15px / 1.75），`.book__text` 在手机上隐藏；
  **选择点那一页正文让到书上面**（`.storybook__stage[data-choice]` 换边）；
  页码条 `.storybook__pager` 在手机上显出来。整条只在
  `(max-width: 640px) and (prefers-reduced-motion: no-preference)` 里生效
  ——减少动效那一档仍走 `.storybook__static`（那条的正文本来就在页里）。
- 第三屏（`HighlightsReel.tsx` / `highlights-reel.css` §11）：窄屏早退（不挂 GSAP、
  不自动播、不挂拖拽），新增 `.hl__list`（`<ol>`，五张全宽卡，同一批内容与图）。

## Comments

- 2026-10-19 完工，**66/66**。前三屏的读数（390×844 / 360×640 / 412×915）：
  `.hero__typing` 350/320/372（行盒右端与文案盒右端相等）· `.hl__list` 列宽
  305/279/325 · 第二屏正文块 351/324/371 · 整页 `scrollWidth` 390/360/412。
- **判据 7a 的第一版是错的，而且看不出来**：计划写的是
  「`.hero__typing` 的 `scrollWidth ≤ clientWidth + 1`」。把旧样式注回页面（
  `Page.addScriptToEvaluateOnNewDocument`）再量，它**是绿的** —— 旧版那 585px 是
  `white-space: nowrap` 把盒子自己撑大的，`scrollWidth` 与 `clientWidth` 都是 585。
  改判"行的右端"之后旧版当场红（605 > 370）。教训：每条新判据都要先证明它**在改之前是红的**。
- **492 KB 那个说法是量的过程中被推翻的**：原计划写"手机上轮播 `display:none`，
  那 5 张（492 KB）不进首屏"；实测**改之前也是 0 次请求**（旧版那五张本来就在
  懒加载的余量外）。所以判据 7d 记成"不重复下载"的回归检查，不记成省带宽。
  连带的量法坑：内存缓存热了之后 `loading="lazy"` 会在元素建出来时立刻解析，
  同 tab 里量第二、三档会误报"加载期间就取了 5 张" —— 每次导航前
  `Network.clearBrowserCache`，三档量的是同一件事（冷缓存 = 第一次打开首页）。
- **首屏交接**（`132dvh` 之后那三个进度比是否还成立）：四个手机视口扫全程，
  **文案与书相交 0 帧**；文案最后一次还看得见时，书的上沿还在视口下方 0~32px。
  ★ 判据不能写成"书一进视口文案就得是 0"：桌面那一版也不满足（交接本来就是
  一边升一边淡），拿它当判据等于把设计判成 bug。
- **桌面基线逐项相等**（1440×900）：`.hero-experience` 1512 · `.storybook__book`
  810×540 · `.book__text` 300×182 · `.hl__card` 518×571 · `.hl__viewport` 1425×643 ·
  `.theme-strip` `display:none` · 新加的两套手机 DOM 在桌面都是 `display:none`。
  ★ 量 `.hl__card` 要取 `.hl__slot[data-current] .hl__card` 并**等过渡跑完**：
  量早了会读到 `scale .93` 的邻居卡（518 → 485），像是桌面被带歪了。
- **首屏上下留白**（计划「另外三条复量」的最后一条）：主张句折行、文案变高之后，
  卡带底 **330** → 文案顶 **477** = **148px**；文案底 **670** → 视口底 **844** = **174px**
  （390×844）。下侧比上侧多 26px，文案落在「卡带底—视口底」这一段的**偏上**处
  （视觉重心略高于几何中点），`top: 62%` 不动。
- **截图读字不能当读数**：同一张首屏截图，我第一眼读成「两句主张句同时画着」——
  去查 DOM 才定下来：`.hero__typing` 里只有 ghost（`display:none`）、live、`.sr-only`
  （1×1 的盒子 + 裁剪，`Range` 的矩形虽宽 856 但一个像素都不画）三块，**同时只画一句**；
  按 2x 把那一块单独裁出来才看清，被我读成「第二句」的两行其实是文案块**外面**的
  滚动提示与按钮上的小字。位置与字号的判据一律以 `getBoundingClientRect` /
  `Range.getClientRects` 为准，截图只用来"看一眼像不像"。
- `ready()` 的耐心从 12s 抬到 20s：工作台那几屏在 dev server 现场编译要十几秒，
  抬之前每次跑都有一屏报"一直没画好"、而每次报的是**不同的那一屏**（编译慢，不是页面坏）。
- 文档：`docs/known-tradeoffs.md` 新增「首页在手机上是**另一副形态**」一节
