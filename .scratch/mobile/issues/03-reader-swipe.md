# 03 · 阅读器：滑动从"阈值式"改成**跟手**

Status: done

## 现状

两台阅读器（`reader/ReaderBook.tsx`、`booklist/BooklistReader.tsx`）各有一份一模一样的
触摸处理：`onTouchStart` 记起点、`onTouchEnd` 比 `|dx| > 44 && |dx| > |dy| * 1.5` 才
`turn(±1)`。**拖动过程中画面一动不动**，松手才播一次补间。用户要的是"手动滑动屏幕"。

## 要做什么

- `onTouchStart` 记起点 → `onTouchMove` 把 `dx` 按**舞台宽**换算成叶数，**直接写
  `qRef`/`setQ`**（拖动期间绕过补间）→ `onTouchEnd` 用 `Math.round` 落定到最近的整数叶，
  交给既有补间收尾。
- 两端加**阻尼**（拖过 `0` 或 `maxTarget` 之后位移乘 0.35），松手弹回。
  这一屏是**有端头的**，与 `highlights-reel` 那条"环上没有端头、不需要橡皮筋"相反 ——
  两处注释要互相指出来。
- `prefers-reduced-motion` 下**拖动照旧**（那是用户自己的手势，`shelf.css` 对同一件事
  写过理由），松手**直接落定**、不播补间（与既有那条"不是不翻页，是不播动画"一致）。
- `touch-action`：竖屏 `pan-y`（页面还要能上下滚）、横屏 `none`（顺手挡掉下拉刷新）。
  ★ 用 `touch-action` 而**不是** `preventDefault()`：React 把 `touchmove` 挂在 root 上
  且是 passive 的，`preventDefault()` 不生效。这一条要写进注释 —— 否则下一个人会去加它
  然后发现没用。
- 共读版那条 `maxTarget`（没选之前封底不给）**照样是上界**，拖动不能绕过它。
- `takeOver()`（翻页就停朗读）在**拖动开始时**就调，不是松手时 —— 跟手就意味着人已经
  在翻页了。

## 判据

- `chk-mobile.mjs` 判据 4：派发真触摸事件，读出那一行的文字变了（"第 1–2 页" → "第 3–4 页"），
  并且拖动**中途** `q` 落在两叶之间（跟手 = 画面在动，不是先不动再跳）。

## Comments

- 2026-10-19 完成。两台阅读器共用一个 `use-swipe-turn.ts`（原来是各一份一模一样的阈值处理）。
- **实测（headless Chrome 派发真触摸，`chk-mobile.mjs` 判据 4）**：
  拖动**中途**采到 4 个各不相同的 `--leaf-angle`：`0 → −30.02 → −60.04 → −90.07`
  （等差 = 跟手）；松手后读出那一行从「封面 · 共 16 页」变成「第 1–2 页 · 共 16 页」。
- ★ 判据里**加了一条基线**：没碰屏幕时同一间隔采三次角度，必须一模一样
  （实测三次全是 `0deg`）。少了这一步，"中途在动"这句话可以被进场补间或一次 HMR 重载
  骗过去 —— 而那两种情形与手指毫无关系。判据取"四次采样各不相同"而不是"有两个不同"：
  一个"第一次 touchMove 就跳到终点、后面三次不动"的实现也能满足后者，而那正是要拦下的东西。
- `touch-action`：竖屏 `pan-y`、横屏 `none`（**不是** `preventDefault()`：React 把 `touchmove`
  挂在 root 上且是 passive 的，那里 `preventDefault()` 不生效）。两端加阻尼（0.35），
  与 `.hl__reel` 那条"环上没有端头、不需要橡皮筋"相反——这一屏**有端头**。
