# 08 · 书架在手机上"挤在一起"

Status: done

用户拿手机打开 `/shelf` 报「前端显示会挤在一起」（2026-10-19，附 390px 截图）。
截图上是四样东西：书名条里的角标竖成三行一根柱、书名一个字都不显示、
那一栏「正在编辑」逐字折行（「7」「页」「共读版」「编辑」各占一行）、
两颗按钮 30px 高。

## 判据

`chk-mobile.mjs` **判据 6**（新加）：登录态下每块书名条 `scrollHeight ≤ clientHeight`、
`.shelf__name` 盒高 ≥ 12px、`.shelf__meta` 的**每个直接子节点**只占一行。
五个手机视口 + 768×1024 + **1440×900（桌面对照）**；
架子上真是空的时**明说跳过，跳过不算过**。

## Comments

- 2026-10-19 完工。★ 先说清楚**为什么上一轮的判据 1 没拦住它**（两条叠加）：
  ①`scrollWidth ≤ clientWidth` 只问"整页有没有横着溢出去"，不问"里面挤没挤"——
  字在自己的盒子里折成三行、书名条被压成 0 高，一个像素都没溢出；
  ②那一屏**未登录时是一排空架子**（`shelf/page.tsx`：`if (!userId) return <ShelfDashboard books={[]} />`），
  而判据 1 那次跑没有带票，量的是一个"什么都没有"的页面。所以判据 6 自己签票
  （`--user=1`，读本机 `.env.local` 的 `APP_JWT_SECRET` 现签 `scope:'session'` 的 HS256，
  不起 Java 后端；密钥一个字都不打印）。
- **390×844 修前**：书名条 `104×48`、`scrollHeight 59`（内容被切掉）；
  `.shelf__name` 高 **0**；每枚角标 `31×48`、**3 行**；那一栏「正在编辑」的书名条只剩 146px、
  逐字折行；草稿缩略图 `44×0`；按钮 `30px` 高。
- **修后（判据 6 全绿，41/41）**：`--book-w` 152、`--label-h` 66、
  书名条 `152×66 scrollH 65`、`.shelf__name` 高 16、角标 `133×17` 整枚一行；
  那一栏折成两行（`260×44 制作为绘本` + `60×44 删除`）；桌面 `1440×900` 一个数没动。
- **老 bug（这一次才发现）**：`.shelf__cover--draft` 的 44×44 缩略图**在桌面和手机上都是 0 高**——
  同特异性、更靠后的 `.shelf__cover { height: var(--cover-h) }` 盖住了它，而 `--cover-h`
  在 `.shelf__rack` 之外没有定义 → `height: auto` → 0。桌面唯一的可见变化就是这颗缩略图
  真的画出来了（卡片 57 → 62 高）。
- **横屏那一档**：`844×390` 上宽度 > 640，`(max-width: 640px)` 不命中，编辑钮 42、
  两颗按钮 30 —— 判据 5 报了「制作为绘本 86×30 / 删除 50×30 / 编辑 69×42」。
  修法是把触控目标那几条写成**并列两支**媒体查询
  （`(max-width: 640px), (orientation: landscape) and (max-height: 560px)`），
  横屏那一支判**高度**。编辑模式的抓手 / ✕ 只有 26×26，外观不动、
  命中区用 `::after inset: -9px` 撑到 44；量具要把伪元素的 inset 加回去再量。
- **判据 1 顺手补的一个假故障**：`go()` 里 `ready()` 有可能在**上一份文档**上就返回 `ok`，
  于是紧接着的 `evaluate` 落在一份还在解析的新文档上 —— 症状是
  `Cannot read properties of null (reading 'getBoundingClientRect')`，看着像**页面坏了**。
  `ready(expect)` 现在要求 `location.pathname` 已经是这一趟那条路由。
