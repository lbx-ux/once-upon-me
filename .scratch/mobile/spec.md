# 移动端适配（mobile）

Status: **done** · 2026-10-19 完成

## 一句话

这个项目是桌面 Web 先做出来的。首页三屏里有两条 `min-width: 1280px` 的兜底，手机上
整页横着能拖；阅读器在 390px 竖屏上一跨页只有 179px 半页宽、正文约 11 字一行。
这一轮把它变成**手机上能用**，其中**看绘本**那一件事单独设计：竖屏提示转屏 →
横屏铺满 → 手指跟手翻页。

## 平台约束（决定了形态，不许用别的说法糊过去）

- `screen.orientation.lock()` 在 iOS Safari **不支持**；
- `Element.requestFullscreen()` 在 iOS Safari **只对 `<video>` 生效**。

所以做不成"锁死横屏"。能做的是：**提示 + 把横屏那一版铺满视口 + 手指跟手翻页**。

## 三个已定的决定（用户 2026-10-19 从选项里挑的）

| #   | 决定                                                                             | 被否掉的                                                                           |
| --- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 1   | 首屏那 12 张封面在手机上改成**横向滑动卡带**（原生 `scroll-snap`），不做移动版环 | 压扁的弧形轨道（要给 `HeroOrbit` 加一整套移动端几何）；竖排 2 列网格（首屏被拉长） |
| 2   | 竖屏进阅读器**弹一层"请横过来"的提示，可以关掉**（关掉后记成一份阅读偏好）       | 硬挡（不转屏就一行字都读不到）；只留一行小字（救不了 11 字一行的正文）             |
| 3   | 工作台侧栏在手机上改成**底部标签栏**                                             | 保留 72px 图标轨（吃掉 19% 宽度）；顶部汉堡抽屉（每换一屏多一次点击）              |

## 判据（怎么做算做完）

1. **不横向溢出**：五个手机视口 × 八条路由，`documentElement.scrollWidth <= clientWidth + 1`。
2. **横屏真的铺满**：844×390 下书的高 ≥ 0.80 × 视口高（竖屏那一档必然是 ~0.28，**这条有判别力**）。
3. **提示有判别力**：390×844 下可见、844×390 下不可见；判据取 `getComputedStyle` **加上矩形非零**。
4. **跟手滑动真的翻页**：派发真触摸事件，判据取**读出那一行的文字变了**，并量一次拖动中的中间态。
5. **触控目标 ≥ 44×44**：两台阅读器 + 底部标签栏里的每一个可点元素。
