## 一、为什么重做

现在的开书路径是两条腿：`/home` 写一句话、挑角色卡和声音 → 点「开始创作」→ `/create` 的四步
（孩子是谁 / 想讲什么 / 角色卡 / 生成）。用户 2026-10-16 的要求是把它换成一条**一屏到底**的流程：

1. 在输入框写下大致的故事内容，点「开始创作」；
2. 弹窗问「这一本做多少页 / 要不要配音」；
3. 确认后，**这个输入框沉到屏幕底部变成只读**，标题位置换成一条阶段轨；
4. 一页一页地出现（图 + 那一页的正文），**期间用户不能改任何东西**；
5. 全部图片与音频都完成之后，才对单页解锁「重画 / 重配」；
6. 整本都满意了点「确定生成」，这本书才成为一本成品。

参考实现：`E:\match\creation-flow-v2`（单文件原型，只看思路，不作为正式版本）。

## 二、★ 原型里三处是编的，不许照搬

| 原型                              | 事实                                                                         | 我们怎么做                                                          |
| --------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 节点「核对」                      | 引擎的核对**不是一段连续阶段**，是每页画完立刻比的（与 `illustrating` 交替） | 轨道上不放这一格；核对结论留在**那一页的格子**上（`Desk` 早已如此） |
| 节点 2 圆点里写「正在创作第几页」 | 那个数是原型自己造的                                                         | 用真数 `drawnCount(desk) / desk.total`，挂在「逐页画」那一格        |
| 「重画/重配」用定时器装           | 引擎一次跑完整本，没有单页入口                                               | 补一个真的单页入口（工单 [01](issues/01-single-page-rerun.md)）     |

★ 已核实：全仓库真的 emit 过的 stage 只有 `planning / illustrating / checking / retrying /
narrating / assembling`。`auditing` 与 `review` 类型存在但**从未发射**（`grep` 过），
所以轨道上不许出现「内容审核」这种永远不亮的节点。

## 三、三条决定（2026-10-16 与用户确认）

| 决定     | 选定                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------- |
| 流程落点 | 弹窗在 `/home`，运行视图在 `/create`（整幅宽），输入框以只读姿态停在 `/create` 底部续上         |
| 确定生成 | **草稿 / 成品两态**：跑完写 `status: 'draft'`，确定后翻 `published`；草稿在书架上带标记、不离场 |
| 旧四步   | **整条删掉**，入口统一到 `/home`；裸 `/create` 重定向 `/home`                                   |

## 四、几条横跨多张工单的约定

1. **音色只有一个家**：「这一本要不要朗读」是**这一本**的属性（进 `voiceId`），
   而「用哪个音色」永远只写 `settings.speech.voice`（与 `/home` 那颗药丸、`/voice` 同一字段）。
   弹窗里复制一份状态的那天起，同一个值就有了两个家。
2. **事件序号必须接续**。`createEventFactory` 每本书从 1 起，而单页重做是往**同一个**
   `events.jsonl` 追加。不接续的话日志里会出现两条 `seq: 1`，而 `seq` 正是
   「重放能重建同一串界面状态」的依据。
3. **失败的产物不许被覆盖**。页图按 `page-{n}-a{attempt}.png` 命名，上一次尝试的图是
   「上一版为什么不像」的证据（`illustrate.ts` 文件头第 3 条）。单页重做要从
   `原 attempt + 1` 起编号（`attemptBase`），不是从 1 重来。
4. **阶段轨是从事件推的纯函数**，放 `frames.ts`（有测试的那一层），不在组件里另算一遍。
5. **运行期间锁定，且故事正文始终不在这里改**。它进了书号指纹，改了就是另一本书——
   要改走「重做一本」，不做就地编辑假装「只是改一句」。

- ★ **做的时候撞出来的两件事，都不是计划里写下的**：

  1. **`deskOf` 一直把封面当成「第 0 页」算**（`pageNo: 0` 是封面的约定，
     `describeEvent` 写着它，`frames.ts` 没跟上）。真跑一本才看得见：
     画桌多一格写着「0」，计数写成 `4 / 3 页画好了`。修法在工单 05。
     → 教训与 §二 那三条同源：**"编出来的东西"最容易活下来的地方，
     是它在**没有真数据**的时候看着完全正常**。
  2. **四步流程里藏着全站唯一一处"给一个已经存在的孩子出形象"**。
     计划里写"指到 `/character/new`"是错的——那里建的是**另一个孩子**。
     删流程不能顺手删掉那个能力，见工单 06。这也是"整条删掉"这句话唯一一处
     需要打折的地方，不是偷懒，是能力搬家。
