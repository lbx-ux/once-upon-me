## 一、要什么

```
┌ ①编故事 ──── ②逐页画 ──── ③配音 ──── ④装订 ┐   ← 阶段轨（从事件推）
│              k / N 页画好了                  │
├──────────────────────────────────────────────┤
│ 《书名》                                     │
│ ┌────┐┌────┐┌────┐┌────┐                     │
│ │ 🖼 ││ 🖼 ││ ▨  ││ ▨  │                     │
│ │ 1  ││ 2  ││ 3  ││ 4  │                     │
│ └────┘└────┘└────┘└────┘                     │
├──────────────────────────────────────────────┤
│ 朵朵抱着月亮…（只读）        [ 创作中 ]        │
└──────────────────────────────────────────────┘
```

四件事：**阶段轨**、**画桌**（复用 `Desk`）、**底部只读输入框**、**右下那颗按状态变的主按钮**。

## 二、阶段轨是 4 格，不是 5 格

`编故事 → 逐页画 → 配音 → 装订`。

- ★ **没有「核对」这一格**。引擎的核对是每页画完**立刻**比的（`illustrating` 与 `checking`
  逐页交替），做成节点会 20 页闪 40 次，而那个闪烁**只说明我们在数事件**。
  核对是**某一页的事**，所以它留在那一格的 `note` 上（`dk__note` 本来就是干这个的）。
  这与 `frames.ts` 文件头那条"不声称第 N 页正在核对"是同一条纪律。
- `retrying` 折进「逐页画」。
- ★ 轨道上**不放**「内容审核」这类节点：`auditing` 与 `review` 在全仓库**从未 emit**
  （`grep` 过），摆一个永远不亮的节点是骗人（CLAUDE.md §不糊弄）。
- 「配音」这一格在关掉朗读时是 **`skipped` 态**，并写着「不配音」——不是灰着不说。

推导写成**纯函数**，放 `frames.ts`（`railOf(desk, voiceOn)`），不在组件里再算一遍：

```ts
export type RailNode = {
  key: 'planning' | 'illustrating' | 'narrating' | 'assembling'
  label: string
  state: 'todo' | 'now' | 'done' | 'skipped'
  /** 「逐页画」那一格上的 `k / N`。其余节点没有 */
  note?: string
}
```

判据来自 `desk.stage`（最新一条事件头部的 `stage`，`frames.ts` 已经在维护它——
它取的**不是** `kind === 'stage'` 那种事件，因为 `narrating` / `assembling` 两段真的
没有 stage 事件，只看 stage 事件的话画完之后这一行会一直停在"正在画"）。

## 三、「正在创作第几」用真数

`drawnCount(desk) / desk.total`，挂在「逐页画」那一格上。
★ 不另画一根百分比条：`20 格里画好了 7 格` 是**看得见的事实**，
一根 35% 的进度条是**编出来的数**（`Desk.tsx` 文件头第 1 条已经写过这条判断）。

## 四、底部那条输入框

- 显示这一轮那句话，**只读**。
- 三种状态的主按钮：

| 状态      | 输入框 | 主按钮                              |
| --------- | ------ | ----------------------------------- |
| `running` | 只读   | 「创作中」（禁用）+ 别关这个页面    |
| `ready`   | 只读   | 「确定生成」                        |
| `final`   | 只读   | 「翻开看看 →」（去 `/reader/<id>`） |

- ★ **故事正文始终不在这里改**：它进了书号指纹，改了就是**另一本书**。
  所以给一条明说的出口：「改故事＝重做一本」→ 说清这会丢掉这一本，然后回 `/home`。
  不做就地编辑假装"只是改一句"。

## 五、单页动作（只在 `ready` 之后解锁）

每一格右下角两颗：**重画** / **重配**（关掉朗读时只留重画）。

- `running` 期间**全部禁用**——用户原话就是"在此期间用户不能修改"。
- ★ 禁用要给理由，不是灰着不说（仓库既有习惯）：轨上那句「每一页都完成之后才能重做」
  就是理由所在的地方。
- 点了走 `POST /api/books/<id>/pages/<no>`（工单 [01](01-single-page-rerun.md)），
  帧格式与整本那条**完全一样**，所以客户端只有一个解码器、一个事件处理器。
- 重做期间那一格是 `busy`（`'drawing' | 'voicing'`），其余格子**不动**。

## 六、`?book=<id>` 恢复一份草稿

刷新 / 从书架点「继续做」进来时：既有的 `/api/books/<id>/events` 重放 →
`deskOf(events)` 重建每一格 → 有 `book.json` 就是 `ready`（可以重做、可以确定生成），
没有就是"这一轮没跑完"（如实说，`status` 帧的那三个字段就是为这件事存在的）。

★ 今天 `CreateFlow` 用的是 `sessionStorage` 里那个 `LAST_RUN_KEY` 指针。**保留它**，
但它不再是唯一一条路：「书架上那份草稿」才是（工单 [03](03-draft-and-published.md) §四）。

## 七、验收

- 端到端 5 页那一趟：空画框先摆出来 → 一页页填上 → 轨走到「装订」→
  主按钮变「确定生成」；**期间**每格的按钮都是禁用的
- 点「确定生成」→ `book.json` 的 `status` 变 `published`、书架那一本挪进成品那排
- 点第 3 页「重画」→ 只有那一格忙、目录里多一张 `page-3-a2.png`、`seq` 接续
- 刷新 → 过程与每格状态重建得出来，且仍然 `ready`

★ **CDP 抓出两个真问题，都修了**（都是"只有真跑一本才看得见"的那一类）：

1. **封面被当成「第 0 页」**。`deskOf` 每一处只判 `pageNo === undefined`，
   而封面的 `illustration` 带的是 `pageNo: 0`——`describeEvent` 早就把这条写成约定了
   （"0 是封面的约定，不是第 0 页"），`frames.ts` 没跟上。
   症状：画桌最前面多一格写着「0」，计数写着 `4 / 3 页画好了`。
   修法：`pageOf()` 把 `undefined` 与 `0` 一起挡在格子外；封面落到新的 `desk.coverPath`，
   而 `ready.coverPath` 优先用它（**退回第 1 页**那条留着，是给没有封面事件的旧日志）。
2. **`DeskState` 里那个 `spread` 位置错了**（把 `for (const event of events)` 吃掉了）——
   这是我自己改出来的语法错，typecheck 当场报的，记在这里只是说明它是怎么被抓住的。

★ 阶段轨**没有「核对」那一格**，理由不是"原型没有"，而是引擎的核对是每页画完立刻比的
（与 `illustrating` 逐页交替），做成节点会 20 页闪 40 次。核对结论留在那一格的 `note` 上。
`frames.test.ts` 里有一条用例专门钉这件事。
