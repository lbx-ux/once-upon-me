## 一、要什么

用户的原话（2026-10-16）：

> 画面放大一点，要是用户点击重画，就出现一个弹窗，上面显示原来的提示词，原来的提示词
> 不可以修改，然后还有一个补充的输入框，用户可以输入这一次画的纰漏是什么，
> 点击重配的话，就直接出现录音的音频是什么，用户直接在上面修改就行。

拆成两条：

1. **重画之前先说清"原来发的是什么、这次要改什么"**。原提示词**只读**摆在上面，
   下面一格写"这一次哪里不对"。两格是**接上去**的关系，不是两个 prompt 输入框。
2. **重配不要糊**：直接给出这一页现在的录音，能就地改它念的那段话、能重录。

## 二、怎么落

### 1. 弹窗要的那份内容，接口单独给

`GET /api/books/[bookId]/pages`（[route.ts](../../../src/app/api/books/[bookId]/pages/route.ts)）——
每页的 正文 / 提示词（`page.prompt`）/ 录音路径。理由：`events.jsonl` 里**没有**提示词
（`illustration` 事件只有 `assetPath` 与 `modelId`），所以它只能从 `book.json` 的 `tree.nodes` 取。

★ 这一条是**为什么不复用重放**：重放重建的是"界面状态"，而弹窗要的是"这一页的原料"，
两者不是同一份东西。

### 2. 点「重画」先开弹窗，不直接发请求

`openEditor(pageNo, kind)`（`GenerationRun.tsx`）——点下去只把弹窗叫出来，
**请求由弹窗的确认按钮发**。理由：重画是**花钱**的动作，中间要有一处让人看见"原来发的是什么"
的停顿；先发请求再让人确认等于钱已经花了。

### 3. `fixNote` 只进 prompt，不进任何记录

`pagePrompt({ …, fixNote })` 把它接在情绪那一行下面。它**不进 `provenance`**：
那个字段记的是模型、模板版本、卡版本，而这是人的一句话，进不了其中任何一个。
要追"这一版为什么长这样"，读的是 `events.jsonl` 那几页前后的事件。

★ 模板因此抬到 `image-page@v2`（`IMAGE_PROMPT_VERSION`，钉在 `image.test.ts`）。
不写 `fixNote` 的页逐字节与 v1 相同，但版本号说的是**模板**、不是某一次调用的参数——
而 `provenance.promptVersion` 正是"这批图的通过率能不能互相比较"的那个界。

### 4. 两个弹窗都挂在整个运行视图的最后

它们是**整屏**的模态，不属于任何一块内容——与 `/home` 那个"这一本要怎么做"同一处规矩。

## 三、第二轮：用户按着截图提的两处（2026-10-16）

> 图片有点偏上了，下面画圈的那句话不要。

1. **图片往下挪。** 修法是 `.rdg__grid` 的 `align-items: center`，不是改尺寸：
   两列的高度由"提示词那一块"决定（它有八行、还带自己的滚动条），而图是 3:2、比它矮，
   默认的顶对齐于是把图钉在最上面。
2. **删掉补充框下面那句说明**（"你写的这句会接在上面那段话的「情绪」后面……原来的提示词不会变。
   只改错字、错手这类「这一版画坏了」的事；要换整个画面，改的是故事里那几句话。"）。

   ★ **代价记在这里、不在这里争**：这个界面从此不说"接上去"这件事了，用户有理由以为
   那格会**替换**掉上面那段，于是写一遍完整的画面描述。
   要接回来的话接在**那一格下面**（那正是被划掉的位置），别另起一段。
   同一段代价也写在 `RedrawDialog.tsx` 判断 2 的注释里。

   `RevoiceDialog` 的说明句**没删**：用户划掉的只有重画这一处，
   而那两句里"图不会跟着重画"是一条真会发生误会的提醒。

## 四、验收

**端到端（CDP 打开真浏览器，对一本真跑出来的书）**

```bash
node scripts/chk-rerun-dialog.mjs "http://127.0.0.1:3321/create?book=<bookId>" .out/redraw.png
```

（这一条**在 `scripts/` 里**，不是 `.out/` 那种跑完就扔的临时脚本——`.out/` 被 `.gitignore`
整个忽略，写在里面的探针等于这份测量没有可复现的出处。第一次跑若报"等了 14 秒仍未出现 .dlg"，
是 dev 下那条 `/pages` 路由冷编译超窗口，再跑一次。）

```
点之前： {"动作总数":6,"重画可用":3,"重配可用":3,"主按钮":"确定生成","主按钮禁用":false}
重画弹窗： { "open": true, "title": "重画第 1 页", "grid": true, "alignItems": "center",
  "art": {"top":225,"bottom":385,"h":160,"w":240,"natural":"768x512"},
  "what": {"top":180,"bottom":429,"h":249}, "中点差": 0,
  "提示句还在": null, "textarea": true, "按钮": ["算了","重画这一页"] }
页面里的错误： 没有 ✓
```

判据选的是**中点差**（图与提示词那一块的水平中线之差）：顶对齐时它是一个正数，
居中之后才是 0——这个量只有真渲染出来才存在，静态读源码读不到。
`提示句还在: null` 是第二条改动的判据（不是"变短了"，是**没有这一句**）。

★ 用 CDP 而不是 app 预览面板：那边 rAF 与 transition 一起冻结，
量到的计算值会落在过渡起点上（那条记在 `preview-pane-hidden-freezes-raf-and-transitions`）。

★ 顺手核了一条**曾经担心过的**事，结论是不用改，记下来省得下一个人重查：

`bookIdOf()` 的指纹是 `cardId | revision | form | theme`——**不含 `wish`**。
而这一轮里"改故事＝重做一本"这句话（`GenerationRun` 底部那条出口）全靠书号跟着那句话变。
查下来：`toBookBody` 送的是 `theme: form.theme.theme.trim() || wish`，
而全仓库**没有任何一处**把 `form.theme.theme` 写成非空（`ChildDetail.tsx` 与 `state.ts`
的初始化都是 `{ theme: '', wish: '' }`，只有 `wish` 会被写）。
所以今天 `theme === wish` 恒成立，指纹是完整的；`wish` 那个字段在请求体里是**冗余**的。
★ 真正的风险边界说清楚：**哪一天有了一条路同时给出 `theme` 与不同的 `wish`**，
两个不同的故事就会算出同一个书号、后一本静默覆盖前一本（`runBook` 会用同一批文件名）。
到那时要么把 `wish` 并进指纹，要么别再单独送它。**今天够不着，所以不动。**
