# 07 · 输入框从 /home 中间"飞"到 /create 底部（可选）

Status: open
依赖：[04](04-setup-dialog.md) [05](05-run-view.md)
上游：spec §三（用户描述里的"这个输入框就移动到屏幕的下面"）

## 一、要什么

点「开始创作」之后，那张输入卡不是"消失、换一屏"，而是**从 /home 的中间落到底部**，
变成运行视图里那条只读的输入框——用户描述的连续性就是这个。

## 二、怎么落

**复用首页 12 张封面那套跨页接力**（`lib/theme-handoff.ts` 是现成范式，读它的文件头）：
出发页把每个元素的几何量好、写进一次性的交接载荷；到达页在第一次挂载时读它，
给那 N 个元素各设一条 `FLIP`（`from` 到刚量到的位置）。

★ 三条照抄 `theme-handoff.ts` 的判断，一条都不许改：

1. **只读不认领**（`peekThemes` 那种），认领交给一个 `useEffect`——
   批次初始化器在 StrictMode 下会跑两次，读一次就没的写法在 dev 下会读到空的。
2. **一次性**：`useEnterTimeline` 那个 ref 把"只在挂上这一屏时播一次"写死了。
   换个值重播整条进场时间线是错的（那是"页面刷新了"的感觉）。
3. **没有载荷就退回静态**：直接访问 `/create?book=…`、刷新、`prefers-reduced-motion`
   都必须落到**静止终态**，不是"不播动画所以位置不对"。

## 三、它是观感，不是功能

★ 这一单**不接也能用**：没有它，输入的连续性靠"同一句话、同一个形状、出现在底部"来承担。
所以它排在最后，做不完不许挡住 01–06 的交付。

## 四、验收

- 从 `/home` 进：输入卡落在底部同一条位置线上（量 `getBoundingClientRect()` 对齐）
- 直接开 `/create?book=…`：静止终态就是对的那一个，没有"从某个位置飞进来"
- `prefers-reduced-motion`：直接到位，元素都在
- ★ 动效判据**不能**在预览面板里验（面板隐藏时 rAF 与 transition 一起冻结，
  读到的会是过渡起点）。要真帧就走隔离 dev server + headless Chrome 直连 CDP 那条路。
