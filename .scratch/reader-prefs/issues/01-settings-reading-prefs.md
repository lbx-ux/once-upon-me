# 01 · 侧栏「设置」· 阅读偏好（自动朗读 / 自己翻）

Status: done（2026-10-17：三道闸门 + 896 条测试全绿；两个阅读器都在真浏览器里跑通了
"念完自动翻页并接着念"，实测记录见文末 Comments）
依赖：无

## 一、要做什么

用户原话：「在左下角的侧边栏弄一个设置，点开设置是阅读偏好，用户可以选择在阅读独读版
的时候，是系统自己播放音频，音频播放完自动分页还是用户手动分页」。

这一版之前，两个独读版阅读器（`/reader/<bookId>` 与灵感书单那本样书）的朗读只有一种用法：
点一下念**当前这一页**，念完就停，页永远由人翻。缺的是一条**自动朗读**。

## 二、开工前拍板的四条（用户选定，全部取推荐项）

| 决定     | 取值                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 怎么开始 | **按一下才开始**。浏览器不许页面在没人点过时出声，一进来就自动播多半被拦 |
| 手动翻页 | **人接管**，自动朗读那一趟就此结束（保住现有那条"翻页就停"）             |
| 生效范围 | **两个阅读器都算**（`/reader/<bookId>` 与灵感书单那本样书）              |
| 存在哪   | **本机浏览器**（`localStorage`），与侧栏折叠、阅读记录同一做法           |
| 默认值   | **我自己翻**（= 现状，不改任何人的既有体验）                             |

## 四、三条判据

1. **不设偏好时，行为一个字都没变**：手动模式下那颗钮仍然是「封面与封底没有朗读」且禁用，
   念完就停、页等人翻。
2. **自动朗读真的接得上**：一段念完 → 自动翻页 → 下一页的声音**自己**起来。
   判据取 `preview_network` / `audio.currentSrc` 上"下一页那段 mp3 被换成当前源并真的在播"，
   不取"按钮变成 ■ 停止"（那只说明按下了）。
3. **人翻页说得一不二**：自动朗读念着时按 ›，声音停、这一趟结束，且**不许自己再念下去**。

### 2026-10-17 · 实测（隔离 dev server + 浏览器面板）

**探针送出的是什么值**：`element.click()` 之于那颗钮（`.reader__audio`）——
先在**同一轮 JS** 里查 `__reactProps$`、再 `elementsFromPoint` 量命中
（按钮中心 (770,746) 的最上层就是它本身，没有被谁盖住），然后点。

- **`preview_click` 那一次没打到。** 面板隐藏时它报 `Successfully clicked` 但
  React 的 `onClick` 没跑（`qTarget` 没动、`pendingShimRafs` 是 0）。
  所以下面这些读数全部来自 `element.click()`，**不是** CDP 真鼠标事件——
  "按钮可点"这一条的闸门是 `elementsFromPoint`，不是那一次点击。
- **面板隐藏时 rAF 冻住**（这一条在仓库的记忆里），补间永远落不到位、
  自动朗读那条链会卡在"念完了但翻不过去"。所以探针里把 `requestAnimationFrame`
  换成 16ms 的 `setTimeout` 垫片——**垫的是帧调度，不是行为**：验的是
  "念完 → 翻页 → 接着念"这条链，`ended`、`play()`、`src` 全是真事件真请求。

**`/reader/xiaoyu-r1-4fe055c5723b`（3 页，三页都有配音）· 自动模式**，从封底按 ▶
（顺带验了"从头念一遍"）：逐次采样（每 150ms）只记变化，得到

| 秒   | 页面    | 音频           | 在播   | 钮         |
| ---- | ------- | -------------- | ------ | ---------- |
| 0.2  | 第 1 页 | （还在上一段） | 否     | ■ 停止     |
| 0.5  | 第 1 页 | page-1-a1.mp3  | **是** | ■ 停止     |
| 6.6  | 第 2 页 | page-1-a1.mp3  | 否     | ■ 停止     |
| 6.9  | 第 2 页 | page-2-a1.mp3  | **是** | ■ 停止     |
| 11.0 | 第 3 页 | page-2-a1.mp3  | 否     | ■ 停止     |
| 11.3 | 第 3 页 | page-3-a1.mp3  | **是** | ■ 停止     |
| 17.0 | 封底    | page-3-a1.mp3  | 否     | ■ 停止     |
| 17.3 | 封底    | page-3-a1.mp3  | 否     | ▶ 自动朗读 |

三段音频的自然时长约 5.6 / 4.1 / 5.7 秒（`playbackRate` 读回来是 1，**没有加速**），
每一次换源都发生在上一段 `ended` 之后。**判据 2 成立。**

**人接管（判据 3）**：第 1 页念着时按 › → `playing: false`、页面到第 2 页、
钮回到「▶ 自动朗读」且 `aria-label` 变成「从这一页开始自动朗读」（这一屏上有得念了）；
再等 3 秒，**仍然是停着的**，没有自己接着念。**判据 3 成立。**

**手动模式（判据 1）**：钮「▶ 朗读」、封面/封底上禁用且 `aria-label` 是
「封面与封底没有朗读」、正文下**没有**那行「自动朗读开着」的小字；
在第 2 页点 ▶ → 播 `page-2-a1.mp3`；念完 → **还停在第 2 页**、钮回到「▶ 朗读」。
**判据 1 成立。**

**灵感书单那本样书（`/booklist/balloon`）**：同一套文案、同一条链。封面按 ▶ →
翻到第 1 个跨页 → `p1.mp3` 播 13.3 秒 → 翻到第 3–4 页 → **`p2.mp3` 自己起来**。

### 2026-10-17 · 顺手清掉的两处

- 「帮助」那颗钮上的 `shell__link--btn`：全仓库没有一条 CSS 规则选中过它，是个死钩子。
- `BooklistReader` 里 `readout` 那个 `spread: 0` 字段：加了 `opening` 之后它没人读了，

  （`reader-model.ts` 的 `readoutOf` 为同一类坑记过一次账）。

### 2026-10-17 · 用户圈掉了弹窗里那两句注解

用户看着截图原话：「下面画圈的这句话不要了」——红框圈住的是选项下面**整块**
（两句都在框里），所以两句一起删了，`.prefs__caveat` 那几条 CSS 跟着删（不留死规则）。

删掉之后各自的下场，写下来免得下一个人以为是漏了：

- **「只有整本书每一页都录了朗读时才生效」** —— 它没有变成假的，只是**换了说话的地方**：
  阅读器碰到半本有录音的书本来就会在正文下面写"这本书只有 N/M 页有朗读，所以没有给
  朗读控件"。也就是说它现在出现在**真会撞上它的那一刻**，而不是一个大部分人用不到的
  设置页里（与「帮助」那段"常驻的说明会被读成背景噪音"同一条判断）。
- **「这个选择只存在这台设备的这个浏览器里」** —— 这一条**界面上再没有任何地方说了**。
  行为没变（仍是 `localStorage`，换设备要重选），但用户看不见了。留在 README §五
  与 `lib/reading-prefs.ts` 的文件头里，那是给接手的人看的。
