## 用户划掉的三处（按他划的删，不留半截）

## 右上角那颗钮

照 `.cw__new` 的长相（`/character` 那一屏的「＋新建角色」）：填强调色的胶囊，点了开面板。
面板沿用设置抽屉那套（遮罩 + Esc + 点外面关）：

```
① 同意：一段话说清 只录本人 / 产出是合成语音 / 这段录音不保留 → 一个勾
② 采集：「开始录音」（计时中显示秒数）或「选一个音频文件」
③ 试听：听你刚录的那段 + 时长；重录 / 生成音色（+ 名字，默认「我的声音」）
④ 生成中 → 成功（卡片出现在墙上）/ 失败（照原文说失败）
```

## 我录的卡

- 与预设卡同一个长相，多一枚「我录的」标签（照角色墙 `.cw__demo` 那条做法：
  标在**来源**上，不是档案里的一个字段）。
- 卡脚（预设卡已经没有这一行了）**只有我录的卡**写两件真事实：
  **录的那天**与**建它时的模型**——后者在"当前模型与它对不上"时是**说清为什么不能选**
  的唯一凭据，那不是装饰。
- 「听一句真的」同上：创建成功后**立刻真合成一次**，通了才说"能用了"，
  不通就说"还在部署中"（`DEPLOYING` 是实测见过的真实状态）。
- 「删掉它」→ 两步确认（列出将要失去什么）→ 报数凭据（删了哪一条、厂商侧是否已解绑）。

## 判据

- 同意没勾 → 录音钮不可点（`disabled`，不是点了才报错）。
- 麦克风被拒 / 没有麦克风 → 如实说，并**保留 "选一个音频文件" 那条路**。
- 生成失败 → 面板里说失败，卡片不出现，本地记录不写。
- 删掉后卡片消失、本地记录同步消失、`settings.speech.voice` 若正指着它则清空并说明。

| 容器 1110.5px，而 3×352 + 2×28 = **1112**                                                                                                                | 三张卡排成一排**差 1.5px**，于是掉成 2+1，第三张孤零零留在左列、右边空一格 |

**改法**（都在 `voice-picker.css` / `VoicePicker.tsx`，配色一个令牌都没动）：

1. 墙：`repeat(auto-fit, minmax(288px, 352px))` → **`repeat(auto-fill, minmax(min(276px, 100%), 1fr))`**，
   并去掉 `justify-content: center`。★ 症结在 `auto-fit`/`auto-fill` 的**列数在 max 是定值时按 max 算**
   （CSS Grid §7.2.3.1）：定值 352 决定了列数，`1fr` 是不定值、于是改用 min（276）算 —— 三列从此放得下。
   墙铺满容器之后，页头的左右缘**就是**墙的左右缘（实测 288 / 1386 两头都对齐）。
2. 卡改**两段式**：卡身 `padding: 0`，上下两段各自带 18px 内边距 →
   名字与语料**共用一条左缘**（实测 306.5 与 307，差 0.5px 是字形侧边距）。
3. 下半截从"卡里嵌一个四边描边的框"改成**贴着卡底铺满整宽**的一条（左、右、下三边就是卡的边）——
   "洞"这个读法从几何上被取消了。描边只剩顶上那条分界线。
   ★ 底色**不敢再深**：试过 #dcebee 一类，`--ink-muted` 会掉到 4.40:1，而那颗不可点的试听钮写的正是它。
4. 删除那颗从卡底的独立一行挪进试听那一行（`margin-left: auto` 靠右）——
   三张卡的下半截结构因此完全一样。确认态与试听块**二选一**（不是叠加）：
   叠着的话底下会留下一颗看不见却 Tab 得到的试听钮。

★ **验证时又量出一个**：`auto-fit` 在只有两个音色时会把空轨道折掉，两张卡各长到 **535px**，
而三个音色时是 347px —— 卡宽随音色数量变，加一条声音会把另外两张挤窄。换成 `auto-fill`
（留着那一格空位）之后，两三个音色都是 347px，墙仍然铺满容器。

★ **这一轮真在浏览器里看了**（本会话自己的隔离 dev server，`session-isolated` 起在 3317）：
三张卡一排、卡宽 347.3、三张的**下半截顶边都落在 y=258.3**（我录的那张没有调性那一行、
上半截矮 25.5px，靠 `margin-top: auto` 补齐）。★ 面板里的入场动画 `vc-pin` 会冻在起点
（`opacity: 0`、`translateY(-14)`），量出来的是"起手式"而不是终态 —— 用
`document.getAnimations().forEach(a => a.finish())` 落到终态再量、再截。
★ 一个已知代价：确认态展开时那一排会长高 **82px**（207.9 → 289.7），另外两张跟着拉伸。
选"替掉下半截"而不是"叠在上面"，就是把这个跳幅从 145px 压到 82px 换来的。

**2026-10-16 · 第十轮：用户点「听一句真的」，什么都没响 ——「现在这个听一句真的是假的，根本听不了」**

**先证明不是代码坏了**：`.out/preview-route-check.mjs --port=3312` 拿真 key 打我们自己的路由，
`HTTP 200 · audio/mpeg · 41,371 字节 · 2,363ms · 头 4 字节 49 44 33`（ID3）—— 引擎、路由、key 都是通的。

**坏的是这一屏在最常见那种状态下的可信度**。ADR-0008 定的 BYO key **只在内存里活一次请求**，
刷新就没了（`STORABLE_FIELDS` 只有 baseUrl / model / voice），于是没配 key 的浏览器里
三颗钮全是 `disabled`。而它**看上去几乎是活的**，实测：

| 属性         | 旧版"死"钮            | 能点的钮        |
| ------------ | --------------------- | --------------- |
| `color`      | `rgb(107,106,116)`    | `rgb(23,23,29)` |
| `border`     | `rgba(47,134,207,.3)` | 同一支蓝        |
| `background` | `rgb(255,255,255)`    | 同一块白        |
| `opacity`    | `1`                   | `1`             |

四个信号里只有"字浅一档"变了，而**唯一的解释挂在一个 `title` 上**（要 hover 才看得见）。
一个看起来能点、点下去什么都不发生的钮，就是用户说的"假的"。

**两处一起改**：

1. **预置音色的试听不再需要 key。** 那句语料是固定的、音色是厂商预置的，所以"它念这句什么样"
   是一个**常量**：一次生成、跟着仓库走 —— `public/voice-samples/{longjielidou_v3.6,longanlingxi}.mp3`
   （41,371 / 50,971 字节，都是 ID3 开头），表在 `src/lib/voices/samples.ts`，
   生成脚本 `.out/make-voice-samples.mjs`（走我们自己的路由，所以样本与现场合成**同源**）。
   这是 ADR-0003「预生成资产让演示与 API 解耦」在语音上的同一条做法。
   ★ **它与"试听是一次性的：不缓存、不进资产根"不矛盾**：那条管的是**现场合成**的结果不许缓存；
   这里进的是一份**出厂就带着**的样本，不是任何一次运行时调用的产物。
   ★ **克隆的那条没有样本，也不可能有**（它只存在于用户自己的厂商账号里），只能现场合成。
2. **放不出来的那些不再假装能放。** 两个态分开：
   - 要 key 的（克隆的那条）：钮上写「**先配密钥**」、**不挂播放图标**（钮上写配密钥却画喇叭，
     就是"控制与它做的事对不上"）、按下去直接开「模型与密钥」抽屉；
   - 真死的（音色用不了）：把"能点"的三个信号一起收掉 —— 边退回中性 `--hairline`、
     底落到 `--surface-soft`、cursor 回 `default`，不再只是字浅一档。
     ★ 判据带上 `voice.usable`：音色用不了时钮是死的、理由由卡上的 `.vc__why` 说
     （那一种是"模型对不上"，说"先配密钥"会把病因指错）。

**实机验的三个态**（隔离 dev server 3312，每个态都读了计算样式与真实行为）：

| 状态                                   | 实测                                                                                                                                                                                                  |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 预置 + **完全没配**（localStorage 空） | `听一句真的`、`disabled: false`、白底蓝边、有图标；点下去 `src=/voice-samples/longanlingxi.mp3`、`正在听…` 亮 2.54s 后归位，**那一段窗口里唯一的网络请求就是那个 mp3**（没有打 `/api/voice/preview`） |
| 克隆 + 没配 key                        | `先配密钥`、无图标、边 `rgba(28,28,36,.18)`、点下去抽屉真的开了（`.sd` 出现）                                                                                                                         |
| 克隆 + 模型对不上（`用不了`）          | `disabled: true`、底 `rgba(28,28,36,.05)`、边 `rgba(28,28,36,.1)`、cursor `default`，卡上有 why 说清是哪两个模型不同                                                                                  |

★ 顺带修掉一个**只有测试数据里才会出现**的空子，但判据值得留在代码里：样本要按
`voice.source === 'preset'` 取，不能只按 id 取 —— 否则一个 id 恰好撞上预置音色的克隆卡
会把**别人的录音**当成用户自己的声音播出来。

★ 新测试 `src/lib/voices/samples.test.ts`（4 条）钉住表与文件：文件在不在、字节数与表里写的
是不是**完全一致**、开头是不是 `ID3`、样本的 voiceId 是不是都在 `DEFAULT_VOICES` 里、
样本念的是不是 `PREVIEW_LINE`。漂移的后果不是报错，是页面上悄悄换了一个声音。

**2026-10-16 · 第十一轮：确认框里那两行说明划掉，只留两个钮**

用户的话：「把画圈的地方去掉，直接写底下的确认删除、取消」。圈住的是
「删掉「我的声音」会失去：」加下面那两条（录音没留、删了要重录 / 以后的书不能再选它）。

改法不是简单地删两行——**顺带把确认块从"整块替掉下半截"缩成了"只换掉那行钮"**：

|                | 旧                                 | 新                                                   |
| -------------- | ---------------------------------- | ---------------------------------------------------- |
| 确认时看到的   | 整块换成标题 + 两条说明 + 两个钮   | 下半截照旧（那句语料还在），只有那行钮换成两个钮     |
| 那一排卡的高度 | 207.9 → 289.7（**整排长高 82px**） | **203.7 → 203.7，一动不动**（实测）                  |
| 那句说明去哪了 | 印在卡上                           | 「确认删掉」的 `title` + `role="alertdialog"` 的名字 |

★ 实测（隔离 dev server，点垃圾桶前后各量一次）：预置那两张卡 `203.7 → 203.7`，
我录的那张 `178.2 → 173.4`（它本来就比一排里最矮的还矮，所以**排的高度由预置那两张定**，
确认态一点都不跳）。旧版整块替换时那一排要动 80px 上下——这次顺带治了。

★ 被划掉的那两句话**没有消失**，只是换了载体：`title="录它时的那段录音我们没有留，删了只能重录"`
与 `aria-label="删掉「我的声音」：…已经做好的书照旧有声"`。看得见的仍然是"确认删掉"三个字，
读屏与鼠标停一下都拿得到原因。★ 这是**产品决定**（用户划的），不是漏了：
CLAUDE.md「没有的东西直说没有」要求的是别假装，不是"每件事都得占一行正文"。

★ 同一次改掉的还有两处**过期注释**（它们按旧结构写的，留着就是注释在撒谎）：
`.vc__card` 的 `position: relative` 现在**没有承重的东西**了（胶带是最后一个绝对定位的孩子），
这一条写在 CSS 里说明"保留是有意的"，免得下一个人以为它在撑什么；
`.vc__delete` 那段里"将要失去什么那两条就在那张卡上"改成"动手的地方就是将要变的那张卡"。
★ 钮上的字仍是「确认删掉 / 算了」（用户写的是"确认删除 / 取消"）——按现有措辞保留，
要改是一处 `label` 的事。

**紧接着的第二句：「点击删除之后，就不要出现哗啦啦，大雨落下来这句话了」**

两次划的是同一件事的两半 —— 这一格在确认态里**只剩那两个钮**。所以那句 `PREVIEW_LINE`

**2026-10-18 · 第十二轮：新建声音面板的「正在生成…」太单调，要「创作」那优化钮同款的呼吸灯**

用户原话：「正在生成音频这太单调了，好歹加一个"创作"那优化提示词那样的呼吸灯样式啊」。

**先量清楚它现在是什么样**：`.nv__go` 忙起来时落到 `:disabled`（`disabled={blocked || step === 'creating'}` 那一支），
而那条规则把底色换成 `background: var(--dot)` —— 一层 **18% 的墨**压在面板的白底上，再压**白字**：

|                | 实得                                     |
| -------------- | ---------------------------------------- |
| 底色（合成后） | 约 rgb(210,210,212)                      |
| 文字           | `--surface`（白）                        |
| 对比度         | 约 **1.5:1** —— 那四个字几乎是读不出来的 |

也就是说它与 `.cl__optimize` **在 2026-10-18 修掉的那一处是同一个病**：`disabled` 把忙态一起吃进去，
**忙被画成了"坏"**，而且比"能用"还难认。

**改法：抄 `create-landing.css` 那一整套，不另发明**（用户点名要同款）：

1. `data-busy={step === 'creating' ? 'true' : 'false'}` + `aria-busy`（字面上"正在生成…"会说，
   但读屏的语义要靠它）；
2. `:disabled:not([data-busy='true'])` —— 灰底那条从此只管"真的不能用"（名字空着）；
3. `[data-busy='true']`：**实心橙**（接着悬停那一片，一个颜色都不跳）+ `cursor: progress`
   - `nv-think-ring` 1.5s `ease-out` 从边缘荡出去的一圈光（**只荡一圈不是转圈** ——
     "新建一条音色"的进度我们并不知道，转圈会让人以为可测，理由同 `.cl__optimize`）；
4. `prefers-reduced-motion` 下：动画关掉，**留一圈固定的光晕**（`0 0 0 5px rgba(--accent-rgb,.16)`，
   与优化钮同一个值）—— 关掉的只是那点动，不是那条信息。

★ **字不跟着呼吸**（这一颗与优化钮不同的地方）：那颗的图标可以淡到 0.55，而 13.5px 的白字
在橙底上淡到 0.8 就只剩约 **2.9:1**。节奏全部交给那圈光，四个字始终读得清。

**实机验的**（隔离 dev server 3312；走的**是真的那条路**：面板 → 勾同意 → 塞一段合成出来的
4 秒 WAV 进 file input → 到试听步 → 把 `/api/voice/clone` 的 fetch 挂住，于是停在真的忙态里，
**没有在厂商那边建任何音色**）：

| 读到的东西                | 值                                                                                                       |
| ------------------------- | -------------------------------------------------------------------------------------------------------- |
| `data-busy` / `aria-busy` | `true` / `true`                                                                                          |
| 底色 / 字色               | `rgb(194,65,12)`（`--accent`）/ `rgb(255,255,255)`（5.18:1 ✓，不再是那 1.5:1）                           |
| `cursor`                  | `progress`                                                                                               |
| 动画                      | `nv-think-ring` / running / 1500ms                                                                       |
| 光晕 @600ms / @750ms      | `0 0 0 6.28px rgba(194,65,12,.18)` / `0 0 0 7.53px rgba(194,65,12,.133)`                                 |
| 静止模式那条规则          | 在**服务端发过来的 CSS 里**读到了：`animation: none; box-shadow: 0 0 0 5px rgba(var(--accent-rgb), .16)` |

★ 两处手法值得记：面板里 rAF 是冻的，所以光晕那一帧是**手动把 `getAnimations()` 的 `currentTime`
推到 600/750ms** 再读的（不是靠等）；顺带发现读 `getComputedStyle` 返回的是活对象——
先读"t=0 的影子"、再推时间、再读，两次会**都是同一个数**，要分开取。
★ 那条 4 秒样本面板自己报了「只有 4.0 秒，偏短。10–20 秒最像你」——顺带证明那条诚实提示还活着。
