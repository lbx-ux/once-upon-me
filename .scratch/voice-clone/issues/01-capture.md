# 01 · 采集与转码：录音/选文件 → 16kHz 单声道 WAV

Status: **done**（2026-10-16）

## 为什么不能直接用 `MediaRecorder` 的产物

Chrome 上 `MediaRecorder` 给的是 `audio/webm;codecs=opus`，而厂商只收
**WAV(16bit) / MP3 / M4A**（`qwen-speech.ts` 的 `SAMPLE_MIMES`，实测文档原文）。
所以要过一次真解码：`AudioContext.decodeAudioData` → 重采样 → 自己写 WAV 头。

顺带三件只有解码之后才拿得到的事：

- **时长**（判"10–20 秒为宜、≤60 秒"——这条约束本来就落在采集这一层，
  适配器的注释里写着"这里只保证不把明显不合规的字节发出去"）
- **单声道/16kHz**（文档要求 ≥16kHz；单声道把体积压到 1/2，20 秒约 640KB）
- **能试听**（听的是记录下来的那段，不是合成结果）

## 做

| 文件                        | 是什么                                                                                                                                                          |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/lib/audio/wav.ts`      | `encodeWav(samples, sampleRate)`：写 44 字节头 + PCM16。纯函数                                                                                                  |
| `src/lib/audio/capture.ts`  | `toSample(blob)`：decode → OfflineAudioContext 重采样到 16kHz 单声道 → `encodeWav`；返回 `{bytes, mime, durationMs}`。带一条 `PROBLEMS` 判据（`sampleProblem`） |
| `src/lib/audio/wav.test.ts` | 头 44 字节逐字段断言（RIFF/WAVE/fmt/16bit/mono/采样率/数据长度）、越界样本钳制、空输入                                                                          |

## 判据

- 录/选进来的一段 3 秒音频 → 转出来的 WAV：`byteLength === 44 + 16000*3*2`，头里写的是
  `16000`、`1` 声道、`16` 位。
- 时长判据：<3 秒 → 提示太短（生成出来不像）；>60 秒 → 提示太长（厂商上限）；
  10–20 秒之外但没越界 → **放行但说一句**（"偏短/偏长"），不拦。
