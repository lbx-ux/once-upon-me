## Comments

**一、★ 这一档的第一版是错的，而发现它错的是量具，不是直觉**

第一版完全照计划做：把 `LEXICON_CLAUSES` 那六条的**条款原文**当画面判据送进去
（六条看着都能落在画面上，而且这样最省事——`PICTURE_CLAUSES` 就是 `.map(c => c.text)`）。
然后拿盘上真出过的 87 张图跑 `scripts/picture-review-cases.mts`：

```
node scripts/picture-review-cases.mts --only=neg

反例（真出过的图）：测成 87/87，其中误报 32
  误报率 36.8%
```

32 张的成因**一种一个样、全都不是随机噪声**：R-06 报了 17 次（"独自在水塘边，无成年人看护"
"独自坐在公园长椅上"）、R-03 报了 11 次（"神情悲伤落寞""肃穆沉静的整体氛围"
"影子呈平躺人形"）、R-01 报了 7 次（"黑色人影剪影""右下角伸出的影子手"）。
而 R-02 / R-04 / R-05 **一次都没报**——那三条的原文本来就写成"画面上有没有某个东西"。

结论只有一句：**那三条条款的原文是给"字"写的，不是给"图"写的。**
`R-06` 原文里有「无成年人看护的**独处险境**」，而童书插画里到处都是一个人待着的孩子；
`R-03` 写「死亡、丧亲的**情节或字眼**」，而"神情悲伤""低饱和色调"在绘本里是**安静**；
`R-01` 的「黑暗恐惧」落到画面上就是**暗部的影子**，那正是童书的常用笔法。

**修法：换尺子，不是调松阈值。** `PICTURE_CLAUSES` 重写成六条画面专用判据，
每条带一句「**不算**」，而"不算"举的例子**全部来自上面那 32 张**。
三条共同的写法：① 判据是"画面上明确画出来的东西"不是氛围（提示词里要求 `where`
必须写**一样具体的东西**，指不出来不许报）；② 「正在发生」与「静止地待着」分开；
③ 条款 id 保留，翻回 `REVIEW_CLAUSES` 仍查得到原始条款。

**二、改完的读数：87/87 测成、误报 0 —— 但这不是独立验证**

```
node scripts/picture-review-cases.mts --pause=1200      # 2026-10-20

反例（真出过的图）：测成 87/87，其中误报 0
  误报率 0.0%
正例：测成 4/4，其中报出来 3/4
没测成：0 张
```

这一轮 91 次调用**全部测成**（限流 0；有一次 `UND_ERR_SOCKET`，退避后第 3 次过），
所以"没测成"那一栏是 0 —— **这一轮才有资格下结论**（量法纪律第 4 条：只要还剩一格
没测成就不许下全称否定）。

★★ 但必须连着说：**这 87 张就是第一轮量出误报、并据此改写条款的那 87 张。**
所以 0% 的含义是"改成这样之后那批图不再误报"，**不是**"这套判据在没见过的图上也不误报"。
把 36.8% → 0% 写成"修好了"是**过拟合的写法**。新量要拿新书的图重跑。
★★ 而且那 87 张**每张只跑了 1 次**——下一节证明了这一点要紧（读数会翻边）。
所以严格说 `0/87` 是"某个半小时窗口里 87 次采样误报 0 次"，还不是"误报率"。

**三、★ 正例那一栏是这一档自己的反例——而且它**在两次运行之间翻边****

误报率归零可以靠"什么都不报"做到，所以同一轮必须跑正例。正例里有**两种东西**。
**第一轮**：

```
★ 正例（示意图）pos-monster     → R-01「三只眼睛与嘴里的白色尖牙」
★ 正例（示意图）pos-match       → R-06「那只手正握着的、顶端带火焰的火柴」
★ 正例（示意图）pos-club        → R-04「头部的黑色弧形绳套与横向长条（横梁）」（**报错了条款**）
· 正例（真插画）pos-real-fight  → 没报（「未发现违反条款清单的内容」）
```

**然后同一份输入再跑一遍（`--only=pos`）**：

```
· 正例（示意图）pos-club        → 没报
★ 正例（真插画）pos-real-fight  → R-02「穿橙色T恤的男孩正用双手抓着坐在地上的
                                   穿蓝色连帽衫男孩的手臂和肩膀，蓝色衣服男孩已倒地且面带泪痕」
```

**同一张图、同一个提示词、`temperature: 0`，两张的结论都反了过来。**
这一条改掉了整节的结论：

- **不是"漏了一张真插画"，是"读数不稳"。** 我第一轮把这一节写成
  "它没报 → 抓不住柔化的那一类"，第二轮就把它推翻了。
  **把一次采样写成性质，与把噪声写成信号是同一个错。**
- **`pos-club` 那一次"报了"也是噪声**：报的是 R-04（自伤），理由是把举起的棍子与握把
  读成了"绳套与横梁"。**撞上的，不是认出的。** 所以第一轮那个 3/4
  **两个方向都虚**：一张靠撞、一张靠运气没报。
- 根因不是温度：`temperature: 0` 在这家网关上不等于确定性
  （同族的账在 `docs/known-tradeoffs.md` 的"配音的语气"那一节付过一次学费）。

★ 因此量具补了 **`--repeat=N`**，判词也跟着变严：正例要 **N 次全报**才算抓住、
反例只要**任何一次报了就算误报**，并且单独报一个**翻边**的计数；
`--repeat=1` 时脚本**拒绝给通过判词**（一轮读数分不出"抓得住"和"这次恰好抓住了"）。

`pos-real-fight` 仍然是这一栏最要紧的一张——**真插画**，
`scripts/make-picture-review-real-positive.mts` 用**生产同一个出图 provider** 画的
（两个男孩抢玩具、一个把另一个推倒在地、被推倒的坐在积木堆里、水彩彩铅风）。
手画的示意图只能证明"条款能被读懂并触发"，**证不了**产品真正关心的那件事。
它现在证明的不是"漏了"，而是「**这一档必须跑 N 次**」。

★ 这一档能给的最强说法仍然是「**抓得住显式的（怪物、点燃的火柴），
抓不住柔化的（没有武器、没有血、只是把孩子推倒的争执）**」，
再加一个限定：**这句话本身也得跑 N 次才敢说**。
`review-corpus.ts` 文件头那句"不许说它覆盖了画面红线"，现在有了一行**自己的数据**作证。

**四、封面拦下来 = 整本书失败，所以封面那条路要写重试循环**

页面被拦下来的处置是"图留着 + `needsHumanReview`"（降级 B）。封面**不能**这样：
一本书的 `cover.png` 只有一张，而 `/illustrate` 在 `book.json` 已存在时回 409——
**已完成的封面修不了**。所以 `illustrateCover` 自己带循环（`cover-a{attempt}{ext}` 命名、
每次尝试后发一次 `review`、要重画时发 `stage: 'auditing'` 的 `retry`），
重画用尽仍为 `flag` 时抛 `review-blocked`。失败的图照旧落盘（那条纪律不变）。

★ 顺带两条省钱的与一条判别的：

- **一致性判 fail 且还要重画的那一张不审画面**（下一张会覆盖它），按页省一次 ≈20 s 的调用；
  但**判不了**（`unavailable`）的那一张照样审——省钱的判据是"这张会被丢弃"，
  不是"这张没结论"。
- 单张实测 ≈**20 s**（2026-10-20 计时：21.9 s，含 node 启动），而出一张图 ≈154 s，
  所以这一档把每页的墙上时间加约 **13%**。
- **`stage` 是 retry 事件的判别字段**：`planning` = 重写故事、`retrying` = 一致性重画、
  `auditing` = 画面重画。三个不同动作共用一个 `kind: 'retry'`，靠它分开。

**五、为什么是两次调用，不是"顺带问一句"**

计划表写的是「出图那次调用之后顺带问视觉模型第二个问题」，那句话可以读成
"并进 `compare` 那一次 HTTP 调用"。落成两次，三条理由：

1. **载荷不一样**：比对要送**两张** 1440²（参考图 + 待审页，约 7 MB base64），
   而画面审核只需要待审页**一张**。并起来等于让安全那一问替参考图付流量。
2. **封面没有比对**。封面是一次单独出图，不走一致性那条路
   （`illustrateCover` 文件头判断 1）——所以独立方法**反正要写**，写了就用它。
3. **比对有撞线的历史**。`DEFAULT_COMPARE_MAX_TOKENS` 那段记着：预算 400 时
   8/8 页都判成 `unavailable`。并成一次调用的话，比对一撞线，**安全那一问跟着一起丢**。

**六、一处对计划的偏离：正例的生成脚本进了仓库**

计划里只说"判据：拿盘上真出过的图跑误报率"，没提正例。落地时正例成了两族，
而**两族的生成都写成了仓库里的脚本**（`scripts/make-picture-review-positives.py`
画示意图、`scripts/make-picture-review-real-positive.mts` 出那张真插画），
图本身落 `.out/`（不进仓库）。理由：**正例不复现的话，"3/4"这个数就没人能复核**，
而这一档偏偏是那个"读数不可复现"的兜底——它自己的判据更不能建在一次性的手工操作上。

**七、`--repeat=3` 的补测：判词是"没过"，而这次是有资格下的**

拿第一版误报过的那 32 张（`--from=.out/v1-false-positives.txt`）加 4 张正例，
每张连打 3 次。108 次调用测成 107（1 次网络失败，记"没测成"、不并进两栏）：

```
反例（真出过的图）：32 张，其中误报 2（★ 有没测成的：测成 95/96 次调用）
  误报率 6.3%（按张）· 误报次数 2/95（按次）
正例：抓住 2/4（要求 3 次全报），一次都没报 0
★ 噪声底（翻边）：4/36 张在同一份输入上 N 次结论不一致
```

- 两次误报都是 **3 次里报 1 次**，而且都是 **R-06 的边界画面**（「站在水里、水位已达腰部」
  「在楼梯台阶上双脚离地跳跃」）——R-06 原文里「身体已经在水里」**算**、
  「静止地待着」**不算**，这两张恰好骑在界线上。**翻边不是均匀噪声，
  它长在判据自己的边界上**（显式那两张正例 3×3 全满票，一次没翻过）。
- 正例反而变实了：显式两张 **3/3 满票**；柔化那张真插画 **3 里 1 次**
  （报的那次条款对、描述准）；`pos-club` 报的那次条款**也对了**（R-02）——
  第三节记的"报错条款 R-04"原来同样是一次采样噪声。
- 结论与第三节同向、更硬：这一档**当判据不合格、当兜底合格**——
  兜底的处置（图留着 + `needsHumanReview`；封面重画）不销毁任何东西，
  2% 量级的按次误报在这个处置下是可安放的。
