# 02 · `StorybookFlip` 的全局 ← →（唯一一条会被评委当场看见的 bug）

Status: done

`window` 上**无条件**接 ← →：滚到第三屏（亮点）按方向键，屏幕外那本书会默默翻一页，
而 `preventDefault` 又把这两个键从浏览器手里抢走 —— 整页的方向键被锁在一本看不见的书里。
第三屏一度用自己那层的 `stopPropagation` 临时挡着（那半条随这一单一起撤掉了，
理由见下）。

## 判据：**视口中线落在这一节里**

`StorybookFlip` 里的 `ownsArrowKeys`，在按键那一刻量一次：

```
rect.top <= innerHeight / 2 && rect.bottom >= innerHeight / 2
```

是这一屏才接管；不是就**原样放行**给浏览器 —— 连 `preventDefault` 都不调。

三个形态共用同一条判据：

- **动效模式**：本节 340vh、舞台钉在 `top: 0`，"中线落在本节里"就是**书正铺在这一屏上**
  （p 0.11–0.89：进入时书已升起半屏，退场时还没走完）；
- **静止模式**：本节是 `height: auto` 的普通一节（`storybook-flip.css` §7），
  **永远盖不满视口** —— 拿"完全盖住视口"当判据的话，键盘用户在这一档会连 ← →
  都按不动，而那一档恰恰只有按钮和键盘两样能翻页（判据 7 钉的就是这一格）；
- **手机那一档**：本节 `display: none`（同 CSS §8），rect 全 0，判据自然为假。

**两条查过并否掉的写法**（都写进了 `StorybookFlip.tsx` 的注释，免得下一个人再试）：

1. **复用 `useScrollDriver` 的 `onActiveChange`**（IntersectionObserver）：
   它的 `rootMargin` 是 `160px 0px`，书滚出视口**之后还有 160px 算"活跃"**，
   而那 160px 正好落在与第三屏的接缝上 —— 评审顺着第三屏往下看时按一下，
   翻的仍然是那本看不见的书。要用 IO 就得另配一条 rootMargin，等于把同一个判据写两遍。
2. **"本节完全盖住视口"**：静止模式那一条，见上。

## 撤掉的那半条：第三屏的 `stopPropagation`

`HighlightsReel` 的 `onKeyDown` 里原来有一句 `e.stopPropagation()`，挡的正是这个 bug
（React 的监听器挂在 root container 上、位置在 `window` 之前，所以挡得住），
并写着"对方那个接法本身是 bug，等那一边落地再单独修"。**这一单就是那一次修**：
拦截没有对象了，于是连同它的解释一起删掉 —— 留着的每一行都得解释自己。
`preventDefault` 留着（它挡的是浏览器自己的横向滚动与回到页首）。
