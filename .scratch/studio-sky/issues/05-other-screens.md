## 一、审计是机械跑的，不是眼看的

在浏览器里遍历每个元素：取计算色 ∈ {`--ink-muted`, `--accent`}、有文字、
文档位置落在天空带内的，再往上走祖先链看有没有一层不透明的纸。报出来的就是
"直接压在天上、且颜色不允许"的那些。四屏结果：

| 屏           | 落点                             | 段  | 灰字在那一段 | 判定 |
| ------------ | -------------------------------- | --- | ------------ | ---- |
| `/home`      | `.cl__sub`（见 03）              | 3   | 4.14 ✗       | 已改 |
| `/shelf`     | `.shelf__sub`                    | 1   | 3.96 ✗       | 已改 |
| `/shelf`     | `.shelf__local-note`（含 `<b>`） | 3   | 4.14 ✗       | 已改 |
| `/shelf`     | `.shelf__tab`（未选中态）        | 3   | 4.14 ✗       | 已改 |
| `/character` | `.cw__sub`                       | 2   | 3.98 ✗       | 已改 |
| `/voice`     | `.vc__sub`                       | 1   | 3.96 ✗       | 已改 |

全部改成 `--ink-on-sky`（十段 6.60…8.18）。★ 注意第 1 段（y 0–10%）
**没有任何一段横向区间是安全的**（那一段最暗的 1% 是云的暗部），所以 `.vc__sub`
压在第 1 段不是"往纸里挪一行"能解决的——那一屏的页头整个落在天空带里。

卡片里的灰字（`.shelf__stat-*` / `.shelf__book-*` / `.cl__hint` / `.cl__theme-tag`）
**一个都没改**：它们各自在 `--surface` 上，是合规的。

`.shelf__tab` 改完之后选中/未选中的区分没丢：选中是 `--ink` + 一条陶土下划线，
未选中是 `--ink-on-sky`，两档之间还有一倍差距。

## 二、书架那四张统计卡合成一条纸

四个各带边框的白浮块读起来像四张并排的便利贴，谁也不是谁的一部分；
而它们本来就是同一件事的四个面（这一屏"读了多久"）。
改成**一条纸上的四格**，格间三道竖向发丝线（`.shelf__stat + .shelf__stat { border-left }`），
`gap` 归零、边框/底色/影子收到容器上。

边线从 `--dot` 换成 `--hairline`：`--dot` 是点阵纹理的墨色（α .18），拿它当卡片边框
是巧合不是设计——globals.css 那条写的就是这件事。屏幕上少三个浮层。

衬线大数字保留——`shelf.css` 文件头那条"数字本身就是这一屏的视觉主体"仍然成立
（这一屏没有插画可依靠）。

## Comments

- 审计脚本走过一次弯路：**Chrome 在样式规则上也暴露 `cssRules`**（CSS 嵌套），
  递归时先判 `r.cssRules` 会把每一条普通规则都当成容器跳过去，于是报"零条匹配"。
  要先判 `r.selectorText`。记下来，免得下次又对着一个"什么都没有"的结果排查半天。
- 另一条弯路更值得记：把 `transition: border-color` 的**未推进**读成了"焦点样式失效"。
  面板隐藏时 CSS transition 与 rAF 一起停（见 06），把 `transition` 临时设成 `none`
  之后边框立刻变成 `rgba(194, 65, 12, 0.5)`——规则本来就在。
- 审计脚本有一个结构性盲区，写清楚：它只走**祖先链**，而背景层 `.sb` 是内容区的
  **兄弟**。所以报 "ON BACKDROP" 时，意思正是我要的"它直接坐在天上"；
  但反过来，元素自带 `background: var(--surface)`（比如 `.cl__pill`）时第一次没认出来
  （走的也是父链）。第二次跑把元素自己也纳入了检查。
