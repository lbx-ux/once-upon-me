# 02 · 侧栏

Status: done（2026-10-15）
依赖：01

## 改了什么

1. `.shell` 的 `background: var(--paper)` **删掉**，背景层接管；`.shell` 加
   `position: relative`（它必须是 `.sb` 的包含块，因为 `.sb` 是 `absolute`——
   而 `.sb` 刻意不加 `isolation` / `z-index`，`.sb` 的 `z-index: 0` 与 DOM 顺序已经够定层序）。
   ★ **上面这句当时的后半句是错的**，2026-10-15 第二轮订正：
   "DOM 顺序已经够定层序"只在**两个都是定位元素**时成立。`.sb` 是 `absolute`，
   而 `.shell__side` 当时是 `static` —— `static` 的 flex 项按绘制顺序排在定位元素**之前**，
   于是整条侧栏被那片天盖住。用户在自己浏览器里实测到的就是这个：整条侧栏不见，
   只剩「创作」露出来，而它是侧栏里唯一带 `position: relative` 的那个（当前项的书签样式）。
   修法见下面第 2 条。
2. `.shell__side` 加 `position: sticky; top: 0; align-self: flex-start; height: 100vh;
overflow-y: auto`。一条同时解决两件事：
   - **层序**：定位元素之间才轮到按 DOM 顺序比，所以侧栏从此画在 `.sb` 上面（同第 1 条那条订正）。
   - **可达性**：原来侧栏被 flex 拉伸到**整个文档高**，`.shell__foot` 的 `margin-top: auto`
     于是把「模型与密钥」「收起侧栏」钉在**文档底部**而不是视口底部——
     实测 `/home` 文档高 1224 时它在 y=1119，而视口只有 900（`/character` 更高，1627）。
     钉成一屏高的常驻列之后它回到视口底部，内容区照常滚。
     ★ `align-self: flex-start` 不是装饰：默认的 `align-items: stretch` 会把项拉满容器高，
     拉满就没有可粘的余量，`sticky` 等于没写。
     侧栏一层**实底半透明纸** `rgba(var(--paper-rgb), 0.78)`，右边缘一条 `--hairline`
   - 一层往内容区拖出去的柔影（这条"边"是**纸的厚度**，不是一条描边）。
     ★ **刻意不是毛玻璃**：`backdrop-filter` 挂在固定元素上 = 背景每变一次就要重新采样
     并重绘它背后那块屏幕，而它背后正是一张满屏大图。首页为同一件事拆过 `.to-top` 与
     `.btn--ghost`（README §五）。
     ★ α 是 **0.90 → 0.78**（2026-10-15 第二轮）：0.90 那一档是为了在**暖**纸上压住天；
     而工作台的纸本身翻成冷白之后（理由见 README §五「冷的是光，暖的是物件」），
     侧栏与页面同族，压住不需要那么厚——"侧栏太重、和右侧割裂"就是那 12% 的差别。
     两档都是量的，读数见 01。
3. **当前项不再是实心橙块**，改成一张**从纸上抽出来的卡**：`--surface` + `--sheet-shadow` +
   陶土橙的文字与图标 + 左边一条 3px 橙书签。判据没变（四项要一眼看出在哪），
   变的是"用纸不用色块"——与整个产品的纸语言一致。`--accent` 在 `--surface` 上是 4.77:1。
   原来整块填 `--accent`、白字，那是通用 SaaS 的读法：这一屏里所有别的东西都是纸，
   只有它是塑料。
4. `«` / `»` → 内联 SVG chevron（折叠后 `rotate(180deg)`）。文字字符的形状、字重、基线
   全跟着系统字体走，换一台机器就换一笔——与首页那条"emoji 是扁平 clip-art、
   与水彩是两套画法"同一个判断。
5. 焦点环合并成一条 `.shell :focus-visible`。组件里那几份**保留不删**：
   删是另一件事的迁移，按"迁移是单独一个提交"那条纪律不混进这次。
   实测：导航项与主题卡都拿到 `rgb(194, 65, 12) solid 2px`，且 `:focus-visible` 为真。
6. `.shell__main::before` 那条点阵**删掉**：它要解决的问题已经不存在——点阵是给一块平涂
   加层次的，而这块地方现在上面是天、下面是纸，自带层次；再叠一层深色网点只会在云最亮
   的地方读出脏。要纹理，首页那两屏仍然有。

## Comments

- **一轮实测抓出来的真 bug（2026-10-15 第二轮订正，加在上面第 1、2 条里）**：
  这一单交付时"侧栏被天空盖住"与"底部两项钉在文档底部"两件事都**没被发现**，
  是用户在自己浏览器里看见并截图指出来的。两个原因合起来骗过了当时所有的检查：
  预览面板是隐藏的（rAF 与 transition 都不推进，很多现象看不见），
  而且**这个面板里层序类 bug 本来就不复现**。教训写进 `.shell__side` 的注释里了：
  凡是"谁是定位元素"这种问题，DOM 顺序一句话是不够的。
- 窄屏那条媒体查询原来写死 `flex-basis: 72px`，现在改 `--side-w`。
  原来之所以有两个地方描述同一件事，是因为背景那团阅读光也读它——光删掉之后，
  这条单源约定留着是对的（"侧栏宽度只有一个数"）。
- `.shell__brand` 折叠时左右 padding 归零那条注释留着：实测折叠后渲染出来是 75px
  而不是 72px，是 34px 标记 + 左右各 6px padding 的 min-content 撑的
  （flex 项默认 `min-width: auto`，收缩不到内容以下）。这是一次真实测量，不是推测。
