## ★ 只有一个动词了：预演整个撤掉

第一版照着 `/api/children/[childId]` 做了两步：`GET` 一张"将要失去什么"的凭据
（一个字节都不动）→ 界面上逐行列出来 → 确认 → `DELETE`。用户看着那份逐行清单说
**「也不要写这么多，就一个确认是否删除，还是算了」**。

于是撤掉的是三样，不是三行字：

| 撤掉的             | 为什么不是"留着不用"                                             |
| ------------------ | ---------------------------------------------------------------- |
| 那条 `GET`         | 一个没有调用方的动词，是下一个人会接上去的线头                   |
| `planBookDeletion` | 同理；而且"预演"这条路上最容易出的错正是"预演说能删、真删说没有" |
| 凭据上的 `stage`   | 那一个字段的全部作用就是分"预演那张"与"真删那张"，只剩一张了     |

**代价说清楚：点确认之前不再知道"要失去多少张图"。** 用户接受的正是这个代价
（他要的是"问一句"）。真删那张凭据还在，`complete: false` 时**跟着 500 一起回**，
界面那时才把逐行的位置清单渲染出来——那不是"留下的记录"，是必须说的话。

## 拒绝的两种情形话不一样

- 盘上没有这一本 → **404**。这不只是客气话：用户看到的书架是服务端渲染的，
  另一个标签页刚删掉它时，"再删一次"就会走到这里。
- 删到一半失败 → **500 + 带上那张不完整的凭据**（哪些删了、哪些没有）。
  只说"删除失败"会让人以为一样都没删，而"确实删了一半"与"什么都没删"要让用户做
  两件不同的事：前者不用重试（再删一次也不会更干净），后者可以重试
  （`deletePrefix` 对不存在的路径回 0）。

## 凭据里的三个位置与它们各自的数字

| 行         | `deleteBookEverywhere` 报的     |
| ---------- | ------------------------------- |
| 这本书     | `deletePrefix` **真删掉的条数** |
| 缩略图缓存 | 五个档位各删一次、加在一起      |
| 顺序记录   | 划掉就是 1，本来不在就是 0      |

★ 顺序那一行**不走 `deletePrefix`**：要的是"把书名划掉、别的项留着"，`saveOrder`
正好干这件事（剪枝也是它自己的事）。

★ 那个数与删之前枚举出来的数**不共用**：`bookTargets` 那一次枚举只负责拼出凭据上那句
人话（「2 张图 + 1 段朗读 + 1 份过程日志 + 1 份清单」）。共用的话，"给出一张能证明真的
删了这么多的凭据"就变成同一个数读了两遍——两者在"正常情况"下相等，而"正常情况"
正是不该被假定的东西。用例钉着这条（枚举完再偷偷塞一个文件进去，凭据要报 11 不报 10）。
