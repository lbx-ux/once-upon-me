## 三条实现上的讲究

1. **指针捕获挂在 `<ul>` 上，不挂在被拖的那一本上**；被拖的那本拿 `pointer-events: none`
   并转 `position: fixed`。理由见 spec §二（`elementFromPoint` 才能看见下面的邻居；
   留在流里"跟手"会变成抖）。拖动开始量一次 `rect0`，页面滚动按 `scrollY` 差值补偿。
2. **`touch-action: none` 只给抓手那颗按钮**，不给整本书。手机上"按封面拖 = 翻页、
   按抓手拖 = 换位"就是这一行定的——`touch-action` 从命中元素往上求**交**，`auto` 的祖先
   不会把它抵消掉；反过来写在整本书上，编辑模式在手机上就再也滚不动了（书多了要往下翻）。
   浏览器打断时长发 `pointercancel`，这一层**撤销、不写盘**。
3. **写盘失败回滚**：拖完立刻 PUT，失败就退回**上一次服务端确认过的那一份**，页头底下
   说一句「顺序没存上」。不许让界面留着一个没存上的次序。

★ **删完页面上什么也不留**（用户原话："书架底下什么也不要留"）：凭据只活在确认框里，
成功了就随确认框一起消失；不做"最近删除"、不做回执行。
**删到一半失败是例外**——那不是"留下的记录"，是必须说的话，所以面板留着并标出失败的行。

★ 编辑模式下那本虚线「新建故事」**不渲染**：它是入口，不是可摆的一本书。
编辑模式下点一本书**不跳走**（书不是链接了）——这条有判据钉着，否则编辑模式下
"想删这一本，结果打开了阅读器"。

## 探针：⑩–⑬ 四节，外加两道守卫

```
node scripts/make-probe-library.mts --out=.out/shelf-probe          # ① 造隔离资产根（9 本 probe-01…09）
ASSET_ROOT=.out/shelf-probe node scripts/dev-preview.mjs --dist=.next-shelfprobe --port=3333
node scripts/probe-shelf.mts                                        # ② 探
```

★★ **守卫一（脚本层）**：`make-probe-library.mts` 会先 `rm -rf` 那个 `--out`，
所以它拒绝两个路径——缺省资产根 `.out/web`（那是用户自己的书架）与 `public/` 里面
（那是随仓库提交的内容）。这不是"防御性编程"：这个脚本的用法就是"传一个目录给我删干净"，
而手滑把 `.out/web` 敲进去的代价是用户自己做的那本书没了。

★★ **守卫二（探针层）**：拖动 / 键盘 / 删除三节只在"架子上真有 `probe-` 开头的书"时才跑。
指向 `.out/web` 时**跳过并打一行说明**。一次"验收"把用户唯一那本书删掉，
是这个脚本最坏的失败方式，比漏测严重得多。

### 实测（2026-10-16，1440×1000 与 375×812）

| 量                           | 读数                                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------- |
| `h1` 文字 / 可见高度         | 「书架」 / **54px**（挂在 `sr-only` 上的那一版是 0）                                   |
| 标题位置                     | y 50 < `--sky-h` 128；x 288 ≤ 第一本书的 288                                           |
| 「编辑」那颗                 | `<button>`，右边缘 **1384 = 书架右缘 1384**（Δ 0）                                     |
| 点它 →                       | `data-editing=true`，字变成「完成」；9 本各有一颗 ✕ 与抓手                             |
| 虚线那本                     | 编辑模式下不在；编辑模式下点书**不跳走**（还在 `/shelf`）                              |
| 原地按一下（按下与抬起同处） | 次序不动 → **不写盘**                                                                  |
| 拖过一格                     | `01 02 03…` → `02 01 03…`                                                              |
| **重载之后**                 | 还是 `02 01 03…` ← "写进盘里了"的证据                                                  |
| 键盘 `→`                     | `02 01 03…` → `01 02 03…`；读屏念「《探针样书 02》移到了第 2 位，共 9 本」             |
| 确认框                       | 3 行；第一行「4 条 · 1 张图 + 1 段朗读 + 1 份过程日志 + 1 份清单」；缩略图那行「1 条」 |
| 确认后                       | 9 本 → 8 本；接口里也没有了；**页面上找不到任何回执行**                                |
| 375 下                       | 横向溢出 0；书的底边 − 板顶 187 vs 187                                                 |
| 控制台                       | 0 error / 0 异常                                                                       |

★ **"重载之后还在"这一条才是次序的判据。** DOM 顺序变了只证明本地状态改了；
`Page.navigate` 重载之后新次序还在，才证明它进了 `shelf/order.json`。

★ 拖动的按键由 CDP `Input.dispatchMouseEvent` 发（`buttons:1`），**分步横移**：
一步跳过去只会有一次 `move`，测的是"起点→终点"而不是"经过谁"。

## Comments

- 2026-10-16 用户两次选项确认：**拖拽换位**（不是左右箭头）、**真删磁盘且删完不留回执**。
- 2026-10-16 ★ 这一屏从纯服务端组件变回客户端组件了，但"首屏就有内容"没退：
  App Router 里客户端组件**在服务端也会渲染出 HTML**，而这里的状态是从 `props` 接过来的
  （次序由 `shelf/page.tsx` 排好）——没有 `useEffect` 取数、没有"挂载前后两副面孔"。
  上次撤 `'use client'` 撤的是那两样，不是这三行指令。
- 2026-10-16 `prefers-reduced-motion`：拖动中的抬起（影 + 1.03 倍）与落位动画去掉，
  **拖动本身照旧**——那是用户自己的手势，不是播给谁看的动效。静止终态因此是默认态。
  （同一段媒体查询里还捎着 `(hover: none)`：窄屏上"悬停抬起来"本来也没有意义。）
- 2026-10-16 确认框的底是 `--surface` 而**不是** `--card-paper`：这一屏刚刚因为
  "暖色硬边压在天空背景上太硬"撤掉过一整块暖纸，再摆一块回来是同一件事。
  危险感由那圈 `--danger` 细边与实心按钮承担，不靠底色。
- 2026-10-16 没做的（说清没有，不是含糊过去）：**没有撤销**、**没有拖拽的 FLIP 落位动画**
  （松手即归位；做 FLIP 要一套会和滚动打架的测量，收益只有一次 150ms 的位移）、
  **没有"最近删除"**（用户明确不要）。
