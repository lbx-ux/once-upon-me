# Spec · 书架：一个可见的标题 + 右上角的「编辑」

创建：2026-10-16 · 用户口述 + 一张截图（红笔圈了搁板右边空着的那一段）

## Problem Statement

第二轮（`.scratch/shelf-on-sky/`）撤掉暖色柜身之后，这一屏剩下一排书、一块通长的板，
和末位那本虚线的新书。用户在同一张截图上**红笔圈了搁板右半边那段空的地方**，
写了两件事：

> 「这个页面的左上角写上"书架"这两个字，和其他保持一致，然后右上角有一个编辑功能，
> 可以移动多个书籍之前的顺序和删除书籍的功能」

拆开来是三条：

1. **这一屏没有页头。** 一级标题是 `h1.sr-only`「我的书架」——给读屏用的落点，
   眼睛看不见。而 `/character`（`.cw__head` / `.cw__title`）与 `/booklist`
   （`.blw__head` / `.blw__title`）都有可见的标题块。用户要的「和其他保持一致」
   指的是**同一个版式**，不是随便写两个字。
2. **顺序不能改。** 摆法只有一条规则：`listBooks` 的 `createdAt` 降序（新的在前）。
3. **书不能删。** 盘上的书只能靠手删目录。

★ 圈的是右半边那块空的，但**这一轮不动它**：板的通长是第二轮明确选过的那一头
（spec §一那张「色 / 空」对照表，"空"那一栏写着"板仍然通长"）。用户这次圈它是在说
**"这块地方应该放点什么"**——放的就是右上角那颗「编辑」。板本身不动。

## Solution

页头照 `.cw__head` 原样搬：`h1` 左、「编辑」右。编辑模式下这一屏多两件事能做：

| 能做   | 怎么做                                                              |
| ------ | ------------------------------------------------------------------- |
| 挪次序 | 拖（鼠标按住书拖；触摸按住左上角那枚抓手拖）+ 键盘 `←` `→` 挪一格   |
| 删一本 | 封面右上角一枚 ✕ → 确认框问一句「删掉《X》？」→ 确认 → **真删磁盘** |

两个交互选择都是**用户选项确认过的**，不是这里替他定的：

- **拖拽换位**，不是每本书两颗箭头（箭头在 9 本书上就是 18 颗按钮）。
- **删除是真删磁盘**，而且**删完书架底下什么也不留**——不要"已删掉《X》"那种回执行。

★ 确认框最终只剩**一句话**（用户第二句话，2026-10-16）：「也不要写这么多，就一个确认
是否删除，还是算了」。下面 §一 删除那一节记的"预演 → 确认 → 真删"两步里，
**预演这一步撤掉了**（连同它的 `GET`），留下的只有真删那张凭据——而它只在删到一半
失败时被人看见。

## 一、两处会写盘的东西

### 顺序落在资产根，不落 `localStorage`

```jsonc
// .out/web/shelf/order.json
{ "order": ["probe-03", "probe-01", "probe-02"], "at": 1792076443362 }
```

书架那一屏是**服务端渲染**的。顺序只存在浏览器里的话，首屏只能按默认序渲染、
挂载之后再跳一次——那正是 `ShelfDashboard.tsx` 文件头写过的"挂载前后两副面孔"。
落盘顺带让"换一台设备打开，排好的顺序还在"自然成立。

与 `library.ts` 的分工（`listBooks` 一行没改）：

```
listBooks(store, coverUrlOf)   ← 默认序：新的在前（这条规则仍然是真的）
        ↓
applyOrder(books, loadOrder(store))   ← 手排是它的**覆盖**
```

★ **清单没见过的那几本排在最前面**是刻意选的。默认规则只有"新的在前"，手排是它的
覆盖，而覆盖只对它写下的那几本负责。刚做完一本书回到书架、发现它在最右边
（甚至要翻一屏才看见），比"排列被顶掉一格"糟得多——后者是用户自己刚做的动作，
前者读起来像"我的书是不是没存上"。这条有专门的用例钉着。

★ 文件**不因为空了就删**：删文件与写空清单在这一层是同一件事，多一个"文件在不在"
的状态就多一处要判断。死 id 一律忽略，写盘时顺手剪掉。

### 删除：这本书自己的东西，三类

| 位置                          | 里面是什么                                  | 为什么必须在清单里                                                           |
| ----------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------- |
| `books/<bookId>/`             | 页图、封面、朗读 mp3、过程日志、`book.json` | 册子本体                                                                     |
| `thumbs/<档>/books/<bookId>/` | 那些图的缩略缓存（5 档各一个目录）          | **派生内容也是这本书**；`child-deletion.ts` 记的那个真实的漏在这里是同一件事 |
| `shelf/order.json`            | 那本书在次序清单里的一格                    | 不划掉的话，文件会一直记着一个不存在的书号                                   |

纪律逐字照 `child-deletion.ts`（那一层的文件头写了为什么"删掉了"这三个字必须能
对着清单被检查）：前缀一律带尾斜杠、凭据上那些数出自 `deletePrefix` **真删掉的条数**
而**不共用**删之前那一次枚举（那一次只负责拼出那句人话的解释）、每个位置各自
try/catch（失败记进 `failed` → `complete: false`，界面**不许**说"删掉了"）、不报字节。

★ **不报字节**不是省事：`AssetStore` 没有 `stat`，要算字节得把几十张页图读一遍，
而家长要问的是"删干净了吗"，不是"删了多少 MB"。

★ **这一层不抛"删到一半"的异常**，也**不复制 `DeletionPartialError`**：
`child-deletion.ts` 那边导出了那个类，但它的 `deleteChildEverywhere` 从头到尾不抛它
（那个 `instanceof` 分支够不着）。多一个永远走不到的分支，就多一处会骗人的代码。
这一层的做法是把 `complete: false` 与每个位置的原话写进凭据，路由照着凭据回码。

★ **盘上一条文件都没有时不抛**：这一层不判断 HTTP 状态，它给一张数字全是 0 的凭据
（每行带一句"为什么是 0"），路由用 `bookOnDisk` 看见没东西就回 404。
"回什么码"只有一个地方决定，"盘上到底有什么"也只有一个地方数。

## 二、界面上的三条讲究

### 1. 指针捕获挂在 `<ul>` 上，不挂在被拖的那一本上

被拖的那一本要拿 `pointer-events: none`——否则 `elementFromPoint` 只会永远返回它自己，
"指针现在压在哪一本上面"就永远问不出答案。捕获挂在不会动的容器上，这条路才走得通。
同一个理由决定了它必须 `position: fixed`：留在流里的话，次序一变它自己在格子里的
位置就跟着变，"跟手"会变成抖。

### 2. 手机上：按封面拖 = 翻页，按抓手拖 = 换位

`touch-action: none` 只给左上角那枚抓手。整本书都给的话，编辑模式在手机上就再也
滚不动了（书多了要往下翻）。手指按在封面上拖时浏览器发 `pointercancel`，这一层
照单全收——**撤销**，不写盘。

★ 抓手与 ✕ 都落在**封面上**，不落在书名条上：书名条那一行在窄屏（`--book-w` 104px）
只剩六十来个像素放"3 页 有朗读"，再挤一颗按钮进去就要压字了。

### 3. 写盘失败要回滚

拖完立刻 PUT。失败就把次序退回**上一次服务端确认过的那一份**，并在页头底下说一句
「顺序没存上」。让界面留着一个没存上的次序比当场退回去糟得多：用户以为存上了，
下次打开发现书跳回原位，而中间什么都没提示。

## 三、判据

`scripts/probe-shelf.mts` 加六组（详见 `issues/03-edit-mode-ui.md`）。三条硬要求：

★★ **探针会写盘、还会删文件。** 所以它跑在 `scripts/make-probe-library.mts` 造出来的
**隔离资产根**上，且**双重守卫**：拖动 / 键盘 / 删除三节只在"架子上真有 `probe-` 开头的
书"时才跑，指向 `.out/web`（用户自己的书架）时**跳过并打一行说明**。
一次"验收"把用户唯一那本书删掉，是这个脚本最坏的失败方式，比漏测严重得多。

★★ **"次序变了"要重载一次才算数。** DOM 顺序变了只证明本地状态改了；
`Page.navigate` 重载之后新次序**还在**，才证明它写进了 `shelf/order.json`。

★★ **删那一节的判据是"确认框有多短"，不是"它写了什么"**（用户第二句话之后改的）。
所以判据是：里面不许出现"11 条"那种数、不许出现旧版那三行位置名、两颗按钮正好是
「算了」与「确认删掉」；并且**先点一次「算了」**——那一本还在架上、还在 `GET /api/books`
里（"能反悔"才是这句话的全部意义），再点 ✕ 重新问一遍才真删。

## 四、明确不做

- **不做撤销**（用户选的是真删；"删了就找不回来"写在确认框里）。
- **不做拖拽的 FLIP 落位动画**：松手即归位，够清楚，且省掉一套会和滚动打架的测量。
- **不改搁板几何**：这一单不碰那七个咬合变量，也不动右半边那块空的。
- **不动** `.scratch/shelf-bookcase/`（已冻结）与 `.scratch/shelf-on-sky/`——新开一册。
