# Spec · 书架那一屏改成「真的书架」

创建：2026-10-16 · 用户口述 + 一张参考图（一格木头书架，书立着、封面朝外，书名在每本下面）

## Problem Statement

`/shelf` 这一屏当时是一个**仪表盘**：顶部问候语「你好，欢迎回来」、四格统计
（已创作故事 / 阅读时长 / 我的角色 / 连续天数）、一句「只记在这台设备上」、
一张「继续上次创作」卡、最近 / 主题模板两个 tab，最后才是「我的故事」列表。

两个问题：

1. **它叫书架，但看起来像一张后台报表。** 侧栏那一格写着「书架」，点进来是一排数字
   和一行行文字。用户的原话是「书架就应该像一个真正的书架一样」，并给了一张参考图：
   书立着、封面朝外、书名写在每本下面。
2. **顶部那一整块是用户圈掉的。** 用户在同一张截图上用红笔圈了「我的故事」以上的全部
   内容，并在四格统计上打了一个 ×，说明「画圈的地方的文字都不要了」。

## Solution

这一屏只剩**两样东西**：一排立着的书（封面朝外、下面一块写了书名的牌子）+
末位一本虚线的新书（新建故事）。顶部那一整块连同它的数据来源一起撤掉。

搁板用**容器上的一张平铺背景**画（每 `--row-h` 一格画一条板），不是每格各画一条——
见下 §二。

## 一、圈里那些块：删掉，并且说清它们去哪了

用户在追问下做了两个选择：**「整块删掉，只留书架」**、**「（继续上次创作）彻底不要」**。
逐块的下场：

| 删掉的               | 它现在在哪                                                                  |
| -------------------- | --------------------------------------------------------------------------- |
| 四格统计             | 没了。台账仍在本机、仍在被写（阅读器 `useReadingLog` 照记），只是不摆出来   |
| 「只记在这台设备上」 | 跟着统计一起删——那句话是**为那几个数**写的，数没了它就没有主语              |
| 继续上次创作         | 用户明确选了「彻底不要」：不搬走、不改书签、不改成"最近这本"                |
| 最近 / 主题模板 tab  | 没了。「主题模板」本来是从 tab「推荐」换过来的，那条路现在由 `/booklist` 走 |
| 问候语               | 没了。工单 05 §三 讨论过"不写'小宇妈妈'"，这一轮连问候一起去掉              |
| 「我的故事」小标题   | 没了。一屏只有一样东西时，它不需要再说一遍自己是书架                        |

★ 这不是"没做出来"，是**做过、量过、然后判断它不该在这一屏**。所以这一屏顺手
从客户端组件变成了**纯服务端组件**：删掉的那块里唯一只在浏览器里存在的东西就是
阅读记录，它走了以后，`'use client'`、`useEffect`、还有"挂载前后两副面孔"一起撤了。

★ 那句"今天要在客户端算"的理由（跨时区差一天，`reading-log.ts` 规则 4）跟着失效。
它**不是被推翻**，是那个读者不存在了——所以这段推理写在 `shelf/page.tsx` 的文件头里，
而不是删掉。

## 二、书架是怎么摆出来的（★ 本单的核心）

**搁板是 `--row-h` 为一格的平铺背景，不是每个格子各画一条。**

一条一格的板，在**末行摆不满**时会缩到最后一本书下面，看着像半截货架；
而"通长的板"正是"这是个架子"的全部信息。所以板画在容器上：
`background-size: 100% var(--row-h); background-repeat: repeat-y`。

平铺要成立，前提是**每一行一样高**。于是整个架子只有一个输入 —— `--book-w`：

```
--book-w   = clamp(104px, 13vw, 156px)      /* 唯一输入 */
--cover-h  = --book-w × 4/3                 /* 竖版封面 3:4，与 make-webp.py 的 book-cover 预设同比例 */
--label-h  = 54px                            /* 书名条：写死才可能行高一致 */
--board-h  = 12px
--row-gap  = clamp(26px, 3.4vw, 40px)
--row-h    = --cover-h + --label-h + --board-h + --row-gap
--board-top= --cover-h + --label-h           /* 书的底边正好落在板的顶面上 */
```

`--book-w` 两端都有出处：104px 是 375 视口下两本能并排的下限
（375 − 侧栏 72 − 左右 40 = 263，两本 104 + 缝 14 = 222）；156px 是上限
（显示宽 ×2 倍屏 = 312，正好落在缩略图 384 那一档）。

板本身是**两层**背景：② 书压下去的那道影（落在板顶面上）+ ① 板（顶面亮边 → 板身 →
前沿压深）。顺序不能反。

★ **这里没有 `color-mix`**：搁板的两个颜色是 `globals.css` `:root` 里的
`--shelf-wood` / `--shelf-wood-edge`（同一支色相 34° 附近压明度）。设计令牌只在
`:root` 定义一次是本仓库的硬约束，改配色只动那一块。

## 三、封面：三条不许破的规矩

1. **不许拿第一页冒充封面**（`ResolvedBook.coverUrl` 那条同一条）。运行期的书真的带
   `cover` 字段，所以这一屏显示的是**真的封面**。
2. **封面不在时不做空框、不留裂图**：一张 `--card-paper` 的相纸 + 一枚 📖。
   ★ 用中性的 📖 而**不是** `THEMES[].emoji`：书里没有主题字段（`Book` 上没有，
   书号里的指纹也推不回来），拿一个**猜的**主题图标比拿一个通用图标更糟——
   它会*看起来*像知道这是哪一本。
3. **走 384 档**（`SHELF_COVER_WIDTH`），不是阅读器的 1024：这一屏的书只有 104–156px 宽，
   一屏按 1024 拉就是几张 159 KB（384 档实测 ~13 KB）。

## 四、完成判据

`scripts/probe-shelf.mts`（真浏览器 + 真 HTTP），判据选的是"只有真做对了才会不同的量"：

- 书的底边 y 与 `--board-top` 差 ≤ 1px（**这条最先红**：改 `--book-w` 漏改 `--row-h` 时）
- 板按行高平铺（`background-size` 周期 == `--row-h`），且是 2 层
- 封面走的是 `?w=384` 且 200（截真请求）
- 375 视口没有横向溢出
- 控制台没有 error
