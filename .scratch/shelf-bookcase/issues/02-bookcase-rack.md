## 两条 CSS 上的讲究

1. **末位那本"虚线书"是一本空书，不是一颗按钮。** 它摆在同一排里，自己说明"这里还差一本"；
   它复用 `.shelf__book`（样式共用），但**没有书脊、没有影子**（`::after { content: none }`）
   ——它不是一本书，是一个空位。
2. **书脊那道明暗走 `::after`，不是给 `background-image` 再加一层。**
   封面图是**内联样式**打进来的（服务端就知道地址），内联的 `background-image`
   会把 CSS 里那一层冲掉。

  与 `--board-top` 各自四舍五入）。判据给的容差就是 1px；容差写 0 会让这条在窄屏上
  假红，而假红的闸门最后一定会被无视。

- 2026-10-16 闸门：`pnpm typecheck` / `pnpm test`（46 文件 548 用例）/

- ★ **判据为什么值得单独留一个脚本**（`scripts/probe-shelf.mts`，跟着仓库提交）：
  那七个变量是咬合的，改 `--book-w` 而漏改 `--row-h` 的后果是"书浮在板上面一点点"——
  肉眼看不出，但看一眼就知道整屏不对劲。这条不变量不该靠人眼守。
  脚本需要**一个 Chromium 内核浏览器 + 一个 dev server**（两者都不是包依赖），
  文件头写明了这两条前提与启动命令。

- ★ 为什么不用 app 内置预览量这些数：面板隐藏时 rAF 与 transition 一起冻结，
  `getBoundingClientRect` 读到的是**过渡起点**——量出来的几何是错的数，
  看着像样式没生效。所以几何判据一律打真浏览器。

- 没做的（说清没有，不是含糊过去）：**板与板的层数、书与书之间那种"挤一挤"的错落感**
  不做——参考图里是一格一格等宽的架子，书是一本本立着；真做错落就得有"每本书厚度不同"
  这个数据，而书是生成的，没有厚度这回事。
