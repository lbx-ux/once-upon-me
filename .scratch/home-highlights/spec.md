# Spec · 首页第三屏「项目亮点」

Status: ready-for-agent
Labels: home, highlights, gsap, vitest
创建：2026-10-12

## Problem Statement

首页现在有两屏：首屏用 12 个不同的孩子回答「能做什么」，第二屏用一本翻开的书回答
「每一页都是同一个他」。看完这两屏，评委与家长会**相信这个产品存在**，
但还不知道**它凭什么做得出来**——角色一致性怎么保证、声音从哪来、
为什么叫引擎而不是叫一堆工具的串联。

这三件事现在只写在 `README.md` 里。README 是给 clone 仓库的人看的，
**首页上没有一条路径能到达它**。参赛作品的第一印象只有网页。

## Solution

加第三屏：**五条亮点的横向卡片轮播**，每条说清一个机制，
并且诚实标出它是「已经能在上面两屏看到」还是「排在第几周」。

视觉上它是首屏那个环的**压平版**——同样的近大远小、同样的后排糊、同样的陶土色强调，
所以整页读起来是一套系统而不是三个拼来的段落。

交互上唯一的记忆点是**卡片是一张被一角托起的纸**：鼠标在卡面上移动，
卡片朝光标方向做 3D 倾斜，插画在框内反向滑动，一层暖光高光跟着光标走。

## User Stories

1. 作为评委，我想在首页就看到「凭什么别人做不到」，以便不用翻 README 就能打分。
2. 作为评委，我想看到每条亮点背后的**机制**而不是形容词，以便判断技术深度。
3. 作为家长，我想知道换名字容易但换脸难，以便理解这跟淘宝定制童书的区别。
4. 作为家长，我想知道要录多久的声音，以便判断上手成本（30 秒）。
5. 作为家长，我想区分睡前和白天两种用法，以便知道这不是一个「给孩子玩的 App」。
6. 作为关注社会价值的评委，我想看到留守儿童那条场景，但**不要卖惨**，以便相信我们是认真的。
7. 作为接手代码的同学，我想知道哪些亮点已经落地、哪些还在周计划里，以便不重复造。
8. 作为用键盘的人，我想用 ← → 切换卡片，以便不用鼠标也能看完五条。
9. 作为用读屏的人，我想只听到当前那张卡，以便不被四张隐藏的卡片干扰。
10. 作为开了「减少动态效果」的人，我想看到静止的终态卡片，以便正常读完。
11. 作为往下滚的人，我不希望在这一屏被滚轮劫持，以便按预期离开这一节。
12. 作为维护者，我想让倾斜的角度映射是纯函数，以便不用开浏览器就能验证符号没反。
13. 作为维护者，我想让轮播的可见性/焦点状态由一处算出，以便 aria 与 tabindex 不会各说各话。
14. 作为读提示词文档的人，我想知道这五张图的出图约束与落盘预设，以便重出一批。

## Implementation Decisions

### 内容：五条，全部来自 README 已定稿的设计与周计划

| #   | 分类             | 主张                             | 状态标注         |
| --- | ---------------- | -------------------------------- | ---------------- |
| 01  | 角色一致性       | 一张角色卡，锁住二十页的脸       | 第二屏已经演示过 |
| 02  | 声音             | 录三十秒，让孩子听你的声音讲完   | W4               |
| 03  | 一个引擎两种形态 | 同一本故事，睡前线性，白天分支   | 第二屏已经演示过 |
| 04  | Agent 流水线     | 规划、生成、三个校验，全程摊开   | W2 / W4          |
| 05  | 无头引擎         | 引擎不碰 React，脚本能跑完整本书 | W1 架构          |

**不写「查看详情」**——没有详情页可去。这一屏的每条亮点要么给一个回第二屏的锚点
（01、03 的论点就是上面那本书），要么给周次与日期。**指向不存在的东西比不指更难堪**，
与「演示仅第 1 页配音」是同一条规矩。

### 视觉：首屏那个环的压平版

- 深度线索复用首屏那套：非当前卡 `scale` 缩小 + `blur` + 降不透明度，与
  `hero-orbit.css` 的卡片处理同源。**刻意不做第二套阴影语言**。
- 底色、点阵、暖光延续第二屏 §1.5 的做法：纹理挂在满屏元素上而不是这一节的框上。
- 强调色只用陶土橙一处（当前卡的编号与进度点），与全站「每张图只用一个暖色重音」一致。
- 卡片圆角走 `--card-radius`，插画区**比卡片外角更小的圆角**，读起来是「贴在卡上的照片」
  而不是「一个圆角矩形里套一个圆角矩形」。

### 交互：纸卡倾斜 + 内层视差（用户选定）

- 归一化指针位置 → `{rotateX, rotateY, artX, artY, glowX, glowY}` 的映射是
  **纯函数**（`lib/tilt.ts`），GSAP 只负责把它平滑地写到元素上。
- 上限 ±6°。超过 8° 会读成「玩具」而不是「纸」，且容易掉帧感。
- 指针离开必须**同一组属性反向补回**（quickTo 的目标值归零），
  快速甩出去不能卡在倾斜态。
- **不在卡面上做 `preserve-3d`**：非当前卡带 `opacity < 1`，一旦父层 preserve-3d
  就会压平子层——这是首屏已经踩过的坑（README §五 交接段那条）。
  透视挂在轨道容器上，卡片自己是叶子，内层视差用二维位移。
- 不做滚轮劫持。理由：上一屏整屏都在用滚轮翻页，到这一屏偷偷改滚轮语义是最恶劣的一种坏。
- ~~不做自动轮播~~ → **2026-10-12 被产品决定推翻**，见工单 05。
  本提案的这条理由（会把正在读第三条的人扔走）依然成立，所以实现带着四个中断条件
  与一个 WCAG 2.2.2 的暂停按钮，而不是裸的定时器。
- ★ 提案里另外两句**实现时改了**，留在这里划掉而不是删掉：
  - 「透视挂在轨道容器上」→ 实际挂在**每个 slot 自己身上**。slot 带 `opacity < 1` 与
    `blur()`，这两样都会压平 3D 子元素，挂在容器上会得到"邻居卡不倾斜"。
  - 「`rendered` 决定该不该进 DOM」→ **删了**。它让 5 条亮点在预渲染 HTML 里只剩 3 条。

### GSAP 引入边界

- **只用于第三屏。** 前两屏的滚动驱动仍是 `useScrollDriver`，**不重写**。
  那两屏的每个数字都是实测出来的，重写等于把已交付的东西重新变成未验证的。
- 用 `gsap.context()` + `ctx.revert()` 做卸载：App Router 默认开 StrictMode，
  effect 跑两遍，不 revert 会留下双份 ScrollTrigger。
- `gsap.matchMedia()` 承载 `prefers-reduced-motion`：该分支里**只设终态**，不建 tween。
- 不引 `@gsap/react`——`gsap.context` 在核心里，为一个 hook 多加一个运行时依赖不值。

### 测试缝（用户已确认：S1+S2+S3 纯逻辑）

- 运行器 `vitest`，`environment: 'node'`，**不引 jsdom / testing-library / Playwright**。
- 版本钉 `^4`：vitest 5 的 `@types/node` peer 要 `^22 || >=24`，
  与本项目 `@types/node ^20`（README 写明 Node ≥ 20）冲突。
  为了装新版而抬 `@types/node` 是拿错配换兼容——引擎层要能在 Node 20 跑，
  类型却按 22 给，等于允许写出跑不起来的代码。
- 好测试的判据：只观察导出函数的输入输出，不碰实现细节；期望值来自手算的
  独立来源（规格里的数），不用被测代码自己算一遍再对比（那是同义反复）。

## Testing Decisions

- **测什么**：`reelState` 的可见性/焦点一致性（越界、单卡、count=0）、
  `tiltFromPointer` 的符号与上限（右上→正角度、出界→回零、中心→零）、
  `smoothstep` 的退化区间（`edge0 === edge1` 不能出 NaN）。
- **不测什么**：GSAP 是否真的写了 transform、ScrollTrigger 的触发时机、
  轮播的视觉位置——这些是浏览器事实，用 preview 实测并截图，
  用 jsdom 测它们只会测到 GSAP 的内部行为。
- **prior art**：本仓库此前**没有测试**。这三个文件是第一批，
  所以 `pnpm test` 脚本、`vitest.config.ts` 也在这个批次里落地。
- **红先于绿**：每个纯函数先跑一条真失败的测试，看到红色再写实现；
  不批量先写完测试再批量实现（横向切片）。

## Out of Scope

- 移动端（沿用首页桌面 `min-width: 1280px` 兜底那条决定）
- 深色模式（全站只有浅色一套令牌）
- 亮点详情页 / 路由（没有内容可放，链接因此不写）
- 把 `HeroOrbit` / `useScrollDriver` 迁到 `lib/math.ts` 与 `useScrollDriver`
  （单独提交，行为必须一字不变）
- 引入 `@gsap/react`、`next/image` 迁移、shadcn/ui（README 未做清单里各自有条件）
- 五张成图本身（本批只交付提示词与槽位）

## Further Notes

- 第二屏底边与本节的衔接**不做负 margin 叠入**：第二屏是 340vh 的 sticky 长节，
  它的收尾 CTA 已经在 `bottom: 5.5vh`；本节用正常文档流接上，
  靠同一套点阵与同一张纸色延续，不靠重叠。首屏→二屏那条 -62vh 是有三个数咬着的特例，
  不要当成通用手法复制。
