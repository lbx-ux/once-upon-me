# 05 · 自动轮播（推翻 spec 里那条「不做」）

Status: done
Spec: ../spec.md
创建：2026-10-12（用户后补需求）

## What

第三屏的轮播**自己一直走**：每 6.5 秒翻到下一条，走完第 5 条绕回第 1 条。

## 与 spec 的冲突

spec 与工单 04 都写过「不做自动轮播」，理由是"它会把正在读第三条的人扔走"。
这条理由成立，但决定权在产品 —— 所以不是把理由删掉，而是**把它变成中断条件**。

## 要做的事

- `wrapActive()`：环形步进。**只有自动播用它**；手动那套（`stepActive`）继续夹在两端、
  到头 disable 按钮 —— "到头了"是说给人听的信息，两条路径不该共用一个函数。
- 四个中断条件，任一成立就停：指针在本节内 / 焦点在本节内 / 标签页在后台 / 用户按了暂停。
  前三个离开后自动恢复，第四个不恢复（用户明确表达过意图）。
- **暂停按钮**：WCAG 2.2.2 —— 持续超过 5 秒的自动更新必须给暂停/停止/隐藏的手段。
  hover 中断**不算**这个手段：键盘用户与触屏用户碰不到 hover。
- 手动翻一次要把 6.5 秒从头计（`timerSeed`），否则刚点到第 3 条就被自动播扔走。
- `prefers-reduced-motion` 下**一次都不启动**，不是"启动后再停"。
- 自动播期间 `aria-live` 转 `off`：不然每 6.5 秒对读屏念一遍"第 N 条"。
  这个开关是安全的，因为**任何手动翻页都必然先经过 hover 或 focus**，
  而那两者都会把 `playing` 打成 false → 播报自动恢复。

## 已知代价（写进注释，不藏）

6.5s **短于**读完最长那条所需：第 3 条约 110 个汉字、三到四行，
中文默读按 8–10 字/秒算是 11–14 秒。所以间隔必须配"碰到就停"才成立。

### 我在这张单上又犯了一次工单 04 里刚写过的错

先勾了「后台不推进」和「`playing` 可观测」两条，然后才发现**它们都不成立**：

- 我拿 `aria-live === 'off'` 当 `playing === true` 的证据。可 `document.hidden` 那时是 `true`，
  两者矛盾 —— 说明 `aria-live` 那个值**是过期的**。
- 于是做了个对照实验：点暂停键，看 `aria-pressed` 会不会翻。**不翻。**
  说明在这个后台文档里 **React 根本没提交重渲染**（React 的调度器在隐藏标签页里
  退到被节流的 timer 上）。那么 `aria-live` 读到的永远是挂载时那一次的值，
  它既不能证明 `playing`，也不能证明 `behindTab`。
- 而「`current` 恒为 0」这件事，同时被 Chrome 的定时器节流和 React 不提交解释得通 ——
  **一个能被三种原因解释的现象，一种都不能证明。**

所以这四条全部退回未测。能算数的证据只有：`wrapActive` 的 6 条单测
（含 `(-1) % 5 === -1` 那个坑），以及 `playing`/`behindTab` 是**普通 React 状态**、
接线方式与已经实测过的 `active`（前台时点圆点会翻）完全相同。

教训和工单 04 是同一条，只是这次我隔了一小时又踩了一遍：**测量环境不配合时，
"没测出问题"和"测出没问题"是两件完全不同的事。**

（与工单 04 里"一次测错的账"是同族问题：后台文档既冻结 rAF 又节流 timer，

### 复测 · 2026-10-12 21:0x（另一条会话）

面板这次给了一个 rAF 真的在跑的窗口，四格里补掉三格。**关键不是运气，是换了个量法。**

#### 上一轮为什么什么也证明不了，这一轮怎么绕开的

上一轮的困境是"定时器节流"和"`behindTab` 让它停"两件事叠在一起，
两者都解释得通"没推进"，于是哪种都不算证。

绕开的办法是**把 `document.hidden` 打桩**：用一个可控 getter 冒充它、再派发
`visibilitychange`，于是"后台停"这件事由**被测代码**负责，不由 Chrome 的
定时器节流负责。这样每个断言只剩一个解释。

另外，判据也换了：不再读 `document.visibilityState`。
**它是会骗人的**——实测到 `visibilityState === 'visible'` 而 rAF 在 1.2 秒里 0 次 tick
（窗口被遮挡时 Chrome 停 rAF，可见性却照报）。现在的判据是直接数 rAF。
**推论：等条件别 `await` rAF**，冻结文档里那会把脚本挂死（这次真超时了一次）。

#### 补上的三条，数字

| 项            | 量法                                           | 结果                                                                       |
| ------------- | ---------------------------------------------- | -------------------------------------------------------------------------- |
| 每 N 秒翻一条 | MutationObserver 数 `aria-live` 段落的文本变化 | 间隔 **3198 ms / 3191 ms**（`AUTOPLAY_MS = 3200`），并看到 5 → 1 环形绕回  |
| 后台真的停    | 桩成 `hidden` → 数 9 秒内的推进                | 310ms 内 `aria-live` 转 `polite`；**9 秒 0 次推进**；撤桩后 300ms 恢复推进 |
| hover 进节停  | 可信指针进本节 → 数 9 秒内的推进               | **0 次推进**，`aria-live` 转 `polite`；指针移出后 **6484 ms** 推进一次     |

第一行的数字顺带排除了"定时器被节流"这个解释：节流会把间隔拉成不规则的 ≥1s 量级，
而两次都**落在常量上**（误差 2ms / 9ms）。

**但要看清楚 hover 那一行是在哪一版上测的**：`HighlightsReel.tsx` 在 20:57
被另一条会话改过（`AUTOPLAY_MS` 6500 → 3200、整排控件删除、
`.hl__viewport` 加 `tabIndex={0}`、`playing` 的输入从四个减到三个）。
上表第一、二行是**改后**（当前版本）测的，第三行是**改前**测的 ——
在当前版本上重测时面板不再产出可信指针事件（`card.dataset.hover` 五张全 `null`），
所以 hover 这条**当前版本没有复测**。

#### 作废的那一条：暂停键

那颗键连同圆点、箭头整排控件已在 20:57 的改动里删除（理由与代价写在
`HighlightsReel.tsx` 文件头与 README §五）。所以"按下暂停键不再推进"这条
**不是没测出来，是已经没有这个东西可测**——按 `dropped` 处理，不按未完成处理。
真正要留意的变成：WCAG 2.2.2 要的"看得见、点得到的暂停手段"现在只剩
"Tab 进本节"这一条间接路径，而它**没有被实测过**（下一段）。

#### 仍然没测的一条：焦点

这条是 20:57 之后才加的键盘路径，而它恰好是这一版留给"停一下"的唯一手段，
所以不能含糊。实测撞到的阻碍是**窗口没有系统焦点时 Chrome 不派发 `focusin`**：
`vp.focus()` 之后 `document.activeElement` 确实进了本节（`focusInSection: true`），
但 `focused` 没有变真 —— React 的 `onFocusCapture` 正是靠 `focusin` 接的。
预览工具也没有按键注入，没法造一次真的 Tab。

**要关掉它只需要一次真的键盘操作**（面板点到前台、Tab 一次、看 `aria-live`
是否转 `polite`、再 Tab 出去看是否恢复），不需要改任何代码。
