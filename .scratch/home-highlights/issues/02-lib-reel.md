# 02 · 轮播状态 `lib/reel.ts`

Status: done
Spec: ../spec.md

## What

纯函数 `reelState(active, count)` → 每张卡的
`{ offset, isCurrent, visibility, tabIndex, ariaHidden }`。

## 抓什么

**可见性、焦点、辅助技术三者必须一致**，这是这一屏最容易改坏又最难用眼睛查的地方：

- 视觉上被推到边缘、只露一条边的卡，不能还在 tab 序列里
- 读屏不该念到非当前卡
- `active` 越界要夹住，不能算出负 offset

## 接口约定

- `count === 0` 时返回空数组，不抛
- offset 单位是「卡位」，不是像素——像素换算留给 CSS 与组件

## 验收

- `pnpm test` 绿；`reelState(0, 1)` 不抛

## Comments

**2026-10-12 完成，但接口与提案有两处不同，都是被实测改掉的。**

1. **`rendered` 被删了。** 提案里它是"该不该在 DOM 里"。`pnpm build` 后数
   `.next/server/app/index.html` 里的 `.hl__card`，得到 **3** 而不是 5：
   静态预渲染时 `active=0`，左边没有卡位，`|offset|<=2` 就只放过三张 ——
   **另外两条亮点对爬虫与禁用 JS 的人根本不存在**，而页面上完全看不出来。
   五条绝对定位的卡片不是性能问题，内容缺失才是。现在 `reelDepth()` 只钉外观档位，
   超出舞台的卡由 `.hl` 的 `overflow: hidden` 裁掉，DOM 里始终全在。
   验收判据就是那个计数：改完是 **5**。
2. **`reelShift`（两端整排平移）加了又删。** 加它是因为当前卡走到两端时一侧会空掉大半屏；
   但那个"平衡"换来的是当前卡不居中，用户要的是轮播图 —— 轮播图的规矩就是当前卡居中、
   邻居被视口切掉。删掉后实测几何：偏移 `[-971,-525,0,+525,+971]`、
   缩放 `[0.86,0.93,1,0.93,0.86]`，左右严格对称。

`advanceOnClick` 在浏览器里也验过：点 offset=1 的邻居会翻，点 offset=3 的不会（只露一条缝）。
