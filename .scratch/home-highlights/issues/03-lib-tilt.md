# 03 · 指针→倾斜映射 `lib/tilt.ts`

Status: done
Spec: ../spec.md

## What

纯函数 `tiltFromPointer(nx, ny, config)` →
`{ rotateX, rotateY, artX, artY, glowX, glowY }`，
输入是归一化到 `[-1, 1]` 的指针位置（卡片中心为原点）。

GSAP 只负责把输出平滑地写上去，**映射本身不碰 DOM**——
所以符号反了、上限漏了这类错误能在 node 里查到，不用开浏览器。

## 抓什么

- **符号**：指针在右上 → 卡片右上角**抬起**（远离观察者）。这个方向写反，
  观感是「卡片往后仰」，一眼假，但只有对着具体数字才查得出来。
- **上限**：±6°。超过 8° 读成玩具而不是纸。
- **中心归零**：指针在正中心时六个输出全为 0。
- **出界**：输入超出 `[-1,1]` 要夹住，不能线性外推到 12°。

## 配置

`TILT_CONFIG` 集中放角度上限、插画位移、光斑半径，注释写明每个数字的观感依据。

## Comments

**2026-10-12 完成。** 符号表按提案贴在测试顶部，四角与中心各一条。

接口改了一次：`glowX/glowY`（像素）→ **`glowU/glowV`（0–1 比例）**。
原因是 GSAP 把自定义属性按**裸数字**序列化，px 值会写出
`radial-gradient(at 280 140 …)` 这种无效 CSS。比例配 CSS 的 `calc(var(--hl-gx) * 100%)`
没有单位问题，而且窗口变窄、卡片跟着变窄时光斑仍落在同一个相对位置。
连带 `tiltFromPointer` 不再需要 `size` 参数（只有 `normalizePointer` 需要）。

浏览器实测（1440 视口，指针在右上角）：
`rotateX(-5.89deg)`、`rotateY(-5.76deg)`、`--hl-gx: 0.98`、`--hl-gy: 0.009`、
插画 `x=-9.6px / y=+9.8px`（往反方向滑）。两个角度都在 ±6° 之内，符号与表一致。
