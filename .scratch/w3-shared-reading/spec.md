## 零、最大的一个判断：共读版做多大（放在最前面，因为它是你提的问题的答案）

**你问过："一个绘本就最多 20 页，能出现什么选项呢？"** 这条 spec 的回答是：

选项的价钱不是页数给的，是**层数**给的——因为两条支不能汇合（`tree.ts` 的
"单父 + 选择点恰好两子"决定了这一点，见 §二），一条支就必须自带到结尾的全部页。
**每加一层，要多付一整条尾巴：**

| 形状                        | 每条路读到 | 全书要画 | 那个孩子**看不见**的比例 |
| --------------------------- | ---------- | -------- | ------------------------ |
| 独读版（0 层）              | 8          | 8        | 0%                       |
| **1 层**（选择点在 65% 处） | 8          | **≈11**  | 27%                      |
| 2 层（60% / 80%）           | 8          | ≈14      | 43%                      |
| 3 层（50/70/85）            | 8          | ≈22      | **64%**                  |

而选择的上界也不是页数给的，是年龄给的——`domain.ts:347` 原话：
「两个选项（**孩子不识字**，两个已经够）」。多做几层不等于多做几次选择，
等于把同一个选择摊到更多页上去付费；五分之三的书对那一个孩子永远不存在。

**所以本 spec 的形状定死：一棵树上恰好一个选择点，两支各自收出自己的结尾。**

这就是首页第二屏那本《小宇的云》已经对用户演示过的形状（第 3 个跨页停下来选，
第 4 个跨页由选择决定、选完就读完），也是 `demo-plan.json` 里那份剧本的形状
（5 个节点、choice 在第 3 页、两支就是第 4、5 页）。共读版落地时**不发明新形状**，
把这一形状接到真的生成流水线上。

**代价（必须写进 README，不许藏）：** 两支各自的结尾要多画约一倍的尾巴图，
而孩子只会读到其中一支。这是 GLOSSARY「预生成」这个词本身的价钱——但共读版是
第一次让它变成真账，所以要**在花钱之前告诉家长**（见 §五·三）。

## 二、树的形状：恰好一个选择点，两支各自收尾

### 一、为什么不能"两支走回同一页"

`tree.ts` 的三条硬规则：每节点**最多一个父**；选择点**恰好两子**（via=a/b）；
非选择点**不得有第二个孩子**。推论：**汇合无法被表达**——汇合节点需要两个父
（撞规则一），或者挂回选择点（撞规则二）。这不是没实现，是无法表达。

所以 `FORM_RULES.shared` 现在那句话是**口径漂移**，读起来像结构约束，实际做不到。
本次改为如实的话：**两支各自收出一个结尾，而两个结尾要落在同一个落点与同一种情绪上**
（同一个场景回环、同一句主题），否则孩子选完会觉得"故事没讲完"——
这是提示词的活，不是校验能管的（校验能管的在下面）。

### 二、新判据（进 `buildTree`，会 red 的那种）

只写在提示词里就等于没有。共读版专属、机械可查：

| 判据                                       | 为什么                                                             |
| ------------------------------------------ | ------------------------------------------------------------------ |
| **恰好一个**选择点                         | 产品定义的"2–3 层"按 §零那张账收窄成一档；嵌套出现时重试提示会点名 |
| 选择点**不得是最后一页**                   | 选完一个字都没有，那不叫选择点                                     |
| 两支**深度差 ≤ 1**                         | 一支 1 页、一支 5 页时一半孩子读到的明显更少，而界面不提示         |
| 每支至少 1 页（选择点有 via=a/b 两个孩子） | 已由现有校验保证，不重复加                                         |

### 三、schema 余量核实过，**不用动**

`planDraftCodec` 的 `nodes` 与 `from` 上界都是 40。按"一个选择点"算：
20 页的路、选择点最早落在第 2 页 → 节点 = 2 + 2×18 = **38 < 40**。
（2 层以上才会撞墙——那正是不做 2 层的又一条理由。）在测试里钉一条
"20 页 + 选择点在第 2 页"的用例，余量就有人看着了。

### 四、ADR-0006 与文档口径

- ADR-0006 **仍然成立**（一棵树、形态是入参、`buildTree` 双向拒），只在文末 Comments
  补一段：为什么不扩展 `from` 支持汇合（本 spec §二·一那三条规则 + §零那张账）。
- **README §一 与 GLOSSARY 里"2–3 层分支"要改成"一个选择点"**——文档跟着交付走，
  交付了 1 层就写 1 层；写了 2–3 层而做的是 1 层，是本次要修的第二处口径漂移。

## 三、阅读器：`/reader/[bookId]` 同一台的第二个形态

### 一、判断：路由不分裂、组件不分裂

ADR-0006 原话："`form` 是入参不是两个入口函数，UI 不许出现 `runSoloBook()` /
`runSharedBook()` 这种分裂"。阅读侧同一条；`use-narration.ts` 的文件头也早已为
"两份抄件迟早漂成两个脾气"付过学费。**`/reader/<id>` 一个地址，`resolveBook`
之后形态由 `book.form` 说。**

### 二、页模型：阅读顺序 = 路径，`pageNo` 只是资产号

| 概念      | 独读版         | 共读版                                               |
| --------- | -------------- | ---------------------------------------------------- |
| `pageNo`  | 第几页         | **资产编号**（`page-7-a1.webp`、进度事件用的也是它） |
| 阅读顺序  | `linearOrder`  | **从根走到叶的那条路**                               |
| "共 N 页" | `nodes.length` | **路长**（`nodes.length` 含走不到的那一支）          |

★ 最容易做错的一处：`readerPages()`（`book-source.ts:230`）是 `linearOrder` 平铺。
今天盘上没有共读版书所以不是活的 bug；第一本落盘后 `/reader/<id>` 会把两支
当连续两页读出来，**三道闸门一条不响**。处置：

- `book-source.ts` 新增 `readerStory(book, urlOf)`：节点表 + 选择点 + 每节点图/音/正文
  （两个来源、一个解析函数那条纪律不变）；
- `ReaderBook` 收 `story`（独读版 = 退化成一条链，同一个函数产出，不分两条真相）；
- **一条测试钉死**：给带分支的树，平铺顺序 ≠ 任何一条路径；`form === 'shared'`
  的书不许走 `readerPages` 渲染。

### 三、选择点那一屏（产品定义："读到选择点画面停下，出现两个大按钮"）

1. **停住等选**。共读是白天陪玩、家长在旁的场景；不等就选，等于把"聊故事"删掉。
2. **往回翻永远可以**；选过之后回到选择点，**按下态还在、可改选**
   （`StorybookFlip` 已有同款行为，照它）。
3. **不做「先跳过」**。"不选也能往下翻"会让分支变成可有可无——那共读版就只是
   独读版加两页装饰。★ 与首页**刻意相反**：首页那本是滚动演示，必须不阻塞
   （评审滚到底才看得完）。两处场景不同，所以做法不同，这是判断不是不一致。
4. **双通道**：图标 + `label` 给眼睛，`spoken` 给耳朵；`choice.prompt` 是
   **给家长念的引导提问**，排在两个按钮上方、字号让家长照念。
5. **没有朗读的书也要能玩**：选项的图与字仍成立，家长自己念——但**有一行小字
   说清"这本书没有朗读"**（首页那条"只对四分之一能响的控件证的是反面"的同源处置：
   把为什么说出来，不是把控件藏起来）。判据沿用"整本都能响才给朗读控件"，
   **选择点的三段音频也算进"整本"**（见 §四）。
6. **静止模式（`prefers-reduced-motion`）有终态**：不播动画，选择点直接在场、
   两颗按钮有静止态——README 硬约束：每一处动效都要有静止终态，不是简单地不播。
7. **键盘**：只在容器上接（不许复制 `StorybookFlip` 在 `window` 上接键那个已知 bug
   的形状）；选择点用 `←` `→` 在两选项间移动、`Enter` 选定。
8. 控件挂在 **opening 层**不进 3D 叶（半翻时会跟着转、点不准——`ReaderBook`
   把朗读按钮放底栏是同一条理由）；首版**不做进场动画**，"在场 + 静止态成立"即可
   （动效在预览面板验不了，值得单独一次）。

### 四、朗读：三个新片段

| 片段     | 念什么                                      | 键（去重） |
| -------- | ------------------------------------------- | ---------- |
| 页正文   | `node.body.join('')`                        | 已有       |
| 引导提问 | `choice.prompt`                             | 新         |
| 两个选项 | `options[i].spoken`（口语句，不是 `label`） | 新         |

- `Narration` 加**可选**的片段字段（缺省 = 正文；盘上已有的书一本不受影响——
  与 `Book.status` "缺省 = 成品"同一类迁移决定）；落盘名
  `page-3-prompt-a1.mp3` / `page-3-opt-a1.mp3` / `page-3-opt-b-a1.mp3`；
- 去重键一个字不改（`(voiceId, textHash)`）；成本：每个选择点 +3 次 TTS，噪声级；
- ★ 明确不做：浏览器 `speechSynthesis` 念选择点。它免费离线，但**声音不是父母的**——
  这个产品全部的主张是"用你的声音讲出来"，一本书两个讲述者不可接受。

### 五、进度与记录

- 底栏报 **「第 k 页 · 这条路共 n 页」**（k = 路径序号）。报全树节点数是假的。
- 不做刻度盘（工单 06 §四 已定，`BookSpine` 是首页的东西）。
- 阅读记录仍记 `pageNo`（走不到的那支不会被记成读过——它压根不进阅读顺序）。

## 四、选择点图标：`iconKey` 从自由字符串变成封闭词表

`choiceCodec` 的 `iconKey` 现在是 `string({ max: 24 })` 缺省 `'generic'`，
没有任何图。三个选项里选**封闭词表 + 手工出一批**：

| 选项                        | 代价                                                           |
| --------------------------- | -------------------------------------------------------------- |
| ① 引擎现出（每选择点 2 张） | 小图标出图质量不可控，且**不在一致性核对覆盖里**，坏了没人知道 |
| ② **封闭词表 + 手工出**     | 一次性出 16–24 枚；模型只能从词表挑，挑不中露 emoji 兜底       |
| ③ 纯 emoji                  | README 已有判据：emoji 是扁平 clip-art，与水彩**两套画法**     |

- `CHOICE_ICONS` 与 `LOOK_TAGS` / `MOODS` 同一处（`engine/domain.ts`），
  schema 用 `enumOf(CHOICE_ICONS)`——**判据只有一处**，提示词与校验都从它取；
- 词表按"孩子会想看的东西"拼（恐龙 / 船 / 火箭 / 小鸟 / 猫 / 鱼 / 月亮 / 星星 /
  树 / 房子 / 云 / 门 / 桥 / 灯 / 花 / 车…），**每枚都能当任一侧的选项**
  （不要"上/下""左/右"这类方向词）；
- 出图走现成档位 `make-webp.py --preset book-icon`（192×192 / ≤15KB，
  首页那两枚云图就是这一档）；提示词与逐张验收记录进
  `docs/choice-icon-prompts.md`（与封面、立绘那两份文档同构）；
- 图没到位时露 emoji 兜底（`alt=""` 的 `<img>` 404 时什么都不画）——
  与选择点云图、第三屏插画**同一个机制**：兜底是退路，不是死代码。

## 九、验收判据（挑有判别力的）

1. **不是平铺**：选 b 之后屏幕出现的是 b 支正文，而 **a 支的图与音频一次都没被请求**
   （`preview_network` 逐条）。★ 只看"页面上有没有字"分不出 `readerStory` 与
   平铺实现，网络里的字节才分得出。
2. **预生成是真的**：选完之后**零出图 / 零 TTS 调用**——两条支的钱在生成那一刻
   就花完了。GLOSSARY「预生成」的可核对版本。
3. **构造性判据**：回翻到选择点 → 按下态还在 → 改选 → 走的是另一支（判据 1 反向再跑）。
4. **持久化含真销毁**：换标签页 / 重挂之后 via 还在；只改内存的实现过不了这条。
5. **形状判据全红**：2 个选择点、支深差 2、选择点在最后一页——每条反例都要红；
   `--mode=stub`（默认 shared）那本要绿。
6. **闸门与产物一致**：闸门上把某个 `spoken` 改一个字 → 重配 → `textHash` 变了、
   阅读器里念的是新那句。只验"保存成功"证的是别的。
7. **静止终态**：`prefers-reduced-motion` 下选择点在场、有静止态。
8. 三条闸门 + `NEXT_DIST_DIR=.next-build pnpm build` + `node scripts/engine-run.mts --mode=stub`。
9. **口径审计**：grep "2–3 层" 零命中；README/GLOSSARY 写的就是交付的那一档。

## 十一、需要你拍板的四件事

1. **默认规模**：共读版默认**路长 8 页**（与 `DEFAULT_PAGES` 对齐；选择点约在
   第 5–6 页，两支各 2–3 页）？20 页那档留给想认真做的人。
2. **停住等选**：我建议停住（可回翻、可改选、不做跳过）；与首页那本滚动演示书
   **刻意相反**（场景不同）。
3. **图标**：封闭词表 + 手工出一批（16–24 枚，`book-icon` 档）？还是先用纯 emoji
   起步、词表后补？（词表的好处是"判据只有一处"，emoji 兜底本来就留着。）
4. **演示那本**：`public/demo/books/` 里放一本**真跑**的共读版（≈11 张图 + 数段音，
   机器 30–40 分钟、要花钱），还是用 `--mode=stub` 造（零成本，但图与配音不是它自己的，
   必须如实标注"形状示范"）？——★ 断网演示共读版这条路（ADR-0003）只有这一条。
