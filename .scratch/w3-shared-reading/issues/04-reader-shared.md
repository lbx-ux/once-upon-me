# 04 · 阅读器：`/reader/[bookId]` 的共读形态

Status: **done**（2026-10-18）
依赖：[01](01-shape-and-prompt.md)、[03](03-choice-narration.md)
——本单最大，也是唯一**必须在真窗口里看**才能收的（预览面板冻结 rAF）。

## 一、页模型：阅读顺序 = 路径

| 概念      | 独读版         | 共读版                                      |
| --------- | -------------- | ------------------------------------------- |
| `pageNo`  | 第几页         | **资产编号**（`page-7-a1.webp`）            |
| 阅读顺序  | `linearOrder`  | **从根走到叶的那条路**                      |
| "共 N 页" | `nodes.length` | **路长**（`nodes.length` 含走不到的那一支） |

- `book-source.ts` 新增 `readerStory(book, urlOf)`：节点表 + 选择点 + 每节点的图/音/正文。
  **两个来源、一个解析函数**那条纪律不变。
- `ReaderBook` 收 `story`（独读版 = 退化成一条链，同一个函数产出，不分两条真相）。
- ★ **一条测试钉死**：给带分支的树，平铺顺序 ≠ 任何一条路径；`form === 'shared'`
  的书不许走 `readerPages` 渲染。今天盘上没有共读版书所以不是活的 bug，
  第一本落盘后 `/reader/<id>` 会把两支读成连续两页，**而三道闸门一条不响**。

## 二、选择点那一屏

1. **停住等选**：产品定义是"画面停下"；共读是白天陪玩、家长在旁的场景。
2. **往回翻永远可以**；选过后回到选择点**按下态还在、可改选**（照首页那本）。
3. **不做「先跳过」**：那会让分支变成可有可无。★ 与首页**刻意相反**——首页是滚动
   演示，必须不阻塞（评审滚到底才看得完）。场景不同，做法不同。
4. **双通道**：图标 + `label` 给眼睛，`spoken` 给耳朵（03 出音频）；
   `choice.prompt` 排在两个按钮**上方**，字号让家长能照念。
5. **没有朗读也要能玩**：图与字仍成立，家长自己念；但有一行小字说清"这本书没有朗读"，
   判据沿用"整本都能响才给朗读控件"（**选择点那三段也算进整本**）。
6. **静止模式（`prefers-reduced-motion`）有终态**：不播动画、选择点直接在场、
   两颗按钮有静止态——README 硬约束：每一处动效都要有静止终态。
7. **键盘只在容器上接**（不许复制 `StorybookFlip` 在 `window` 上接键那个已知 bug）；
   `←` `→` 在两选项间移动、`Enter` 选定。
8. 控件挂在 **opening 层**、不进 3D 叶（半翻时会跟着转、点不准——朗读按钮放底栏是同一条）。

## 三、进度

底栏报 **「第 k 页 · 这条路共 n 页」**（k = 路径序号）。报全树节点数是假的。
不做刻度盘。阅读记录仍记 `pageNo`。

## 验收

每一条都用 `scripts/chk-shared-reader.mjs` 在**真帧**里量出来（无头 Chrome + CDP，
见下面的「怎么验的」）。最后一遍：**39/39**。

- [x] 选 b 之后屏幕是 b 支正文，**a 支的图与音频一次都没被请求**（网络面板逐条）
      → `屏幕上是 b 支的正文（不是 a 支的）`、`★★ a 支的图与音频一次都没被请求`
- [x] 选完**零出图 / 零 TTS 调用**（预生成的可核对版本）
      → `★★ 阅读器全程只做 GET：建书 / 出图 / 改故事 / 发布那些写接口一次都没被碰`
      （整趟的 `/api/` 请求逐条收下来：3 条，全是 GET）
- [x] 回翻 → 按下态还在 → 改选 → 走另一支（上面两条反向再跑一遍）
      → `★ 按下态还在`、`★ 改选 a 支：屏幕上换成 a 支的正文`、`a 支这条路共 4 页`、`改选之后 a 支的图也取到了`
- [x] 静止模式下选择点在场、有静止态
      → 那四条 `静止模式：…`（在场 / `visibility: visible` / 仍在书上且居中 / `transition: 0s`）
- [x] 键盘：容器内换项/选定生效；容器外（切走焦点）按 ← → **一次都不翻**
      → 那四条 `焦点在…`（含 `★ 焦点在按钮上时 ← → 一次都不翻页`）
- [x] 缺图那一页仍走兜底纸（`Book.errors` 那条路不受影响）
      → 判据 9 那五条（兜底纸在场 / 同一屏两个号不同 / 正文照旧读得到 /
      **那张死图一次都没被请求** / 缺图 ≠ 缺音）

## 做完的样子（与上面这份设计的偏差，一条一条写清）

1. **卡片要抬起来**（`reader-book.css`）。设计里只说"浮在书上"；实测按首页那套
   `clamp(16px, 5.5vh, 68px)` 落位时，卡片左下角**切到正文最后一行的行头 25×7px**
   （用 `Range` 逐行矩形量出来的，不是看出来的）。改成 `bottom: clamp(20px, 12%, 96px)`
   —— 基准是**书的高**（定位盒就是舞台），因为正文那块的高度也跟着书走。
   这条有个前提：正文是短的（出图那条构图约束与提示词都按"一两句"给的）。
2. **`pressedOf` 删掉了**（`reader-model.ts`）。它从写下来就没有消费者，而且**恒等于
   `pick`**——留着就是给下一个人一个"也许该用它"的假线索。原地留了一段注释说明这件事。
3. **舞台键盘处理器里那条"焦点在按钮上就让路"的守卫删掉了**（`ReaderBook.tsx`）。
   它是**死代码**：控件根本不在 `.reader__stage` 子树里，事件到不了那儿。真正的机制是
   **结构**（控件挂在 `opening` 层），不是判断——把机制写成判断，下一个人会以为
   "哪天控件挪进去了也照样安全"。
4. **多了一层 `.reader__stagewrap`**（只有一个职责：给选择点一个"书有多高"的定位盒子）。
   它不能进 `.reader__stage`（滑动手势与键盘翻页的容器）也不能进 `.reader__book`（3D 旋转的叶）。

## 怎么验的（方法本身要写下来，不然下一个人会走一遍弯路）

- **预览面板验不了这一屏**：它把 rAF 冻住（`preview-pane-hidden-freezes-raf-and-transitions`
  那条记过），补间一步都不走、`settled` 永远为假、选择点永远不浮出来——而这一单要验的
  恰好是"翻到选择点那一屏"。所以走**无头 Chrome + CDP**（`Input.dispatchMouseEvent` /
  `dispatchKeyEvent` / `Network.*` / `Emulation.setEmulatedMedia`）。
- **共享工作区里别的会话一存盘就整页重载**，多步流程会被打断（脚本会把 HMR 次数印出来，
  看见就先按这条排除）。所以验的是**一份冻结的副本**（`.out/rd`，自己的 distDir 与 :3309），
  跑完删掉。
- **夹具两本，都要造、都要拆**：

  ```bash
  node scripts/mk-shared-fixture.mjs            # 《两条路》：验阅读顺序
  node scripts/mk-shared-fixture.mjs --missing  # 第 5 页图没出成：验兜底纸
  node scripts/mk-shared-fixture.mjs --clean    # 跑完拆掉（产物在 .gitignore 里）
  ```

  一本手工拼出来的书不能躺在 `public/demo/books/` 里随部署上线，所以两件事都做了：
  `.gitignore` 按名字忽略，脚本给 `--clean`。

## 边界

- `flip.ts` **一行不动**（页模型是对的，要加的只是"选择点"这一层）。
- 不做选择点的进场动画（首版只要"在场 + 静止态成立"）。
- `booklist` 那台阅读器一行不动。
- **选择点的图标仍是 emoji 兜底**（词表之外的 key）——真图标是 [02](02-choice-icons.md) 的事，
  这一单只保证"词表里有图的画图、没有的露 emoji、绝不出现 404 的碎图标"。
