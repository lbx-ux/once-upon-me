# 07 · 路径落盘：选了哪一支要记得住

Status: **done**（2026-10-18）
依赖：[04](04-reader-shared.md)

## 做了什么

同一本书第二天再翻开，**上一次选的那一支要还在**（按下态还在、往下翻走的是那一支）。
`StoryNode.pathFromRoot` 是静态的那一半，**孩子这一次选了哪一支是运行时状态**。

- 落点：[`lib/reading-path.ts`](../../../src/lib/reading-path.ts)（新），`localStorage`，
  一本书一个键；`parsePick` 是纯函数、`load/save` 是那层薄的存取——
  与 `reading-log.ts` / `reading-prefs.ts` 同一套分法、同一套"认不出来的值退回默认"。
- ★ **键名与工单里写的不同**：工单说 `xzj:path:<bookId>`，落地写成
  **`xiaozhujue.reader.path.<bookId>`**。理由是这一族的名字空间：`xiaozhujue.reading.v1`、
  `xiaozhujue.reader.turn`、`xiaozhujue.reader.paper`、`xiaozhujue.shell.collapsed`
  ——`xzj:` 是一个**不存在**的第三族，而工单自己那句要求是"与阅读记录、阅读偏好同一族"。
  跟名字空间走才是那句要求的兑现，所以按族里的拼法写。
- ★ **不进 `book.json`**：产物是引擎写的，被阅读的行为改写会让清单漂
  （`AssetRef.digest` 与"这本书是什么"的判据都建立在它不变之上）。
- 只存"选了哪一支"（`'a'` / `'b'`，`''` 与"键不在"都读成没选过），
  **不存整条路径**——路径由树推得出来，存两份就是两个真相。
- 接线只有两处（`ReaderBook.tsx`）：挂载后读一次（`loadPick(bookId)`，**初值一律 null**
  ——服务端渲染那一趟读不到 `localStorage`，初值写成"读得到就读"会和首屏 HTML 打架），
  以及 `pickVia` 里写一次（**唯一的写盘处**，改选也是覆盖）。

## 验收

每一条都用 `scripts/chk-path-memory.mjs`（无头 Chrome + CDP）量出来，最后一遍 **18/18**。

- [x] ★ **含一次真销毁**：选 b → **关掉这个标签页、另开一个** → 回来，按下态还在、
      继续往下读走的是 b 支
      → `★★ 真销毁之后回来：一根手指都没碰过，b 已经按着`（`["false","true"]`）、
      `★★ 走的是 b 支：取了 page-5 / page-6 的图，而 a 支那一页（page-4）一次都没被请求`
      ★ 销毁的做法是 `Target.closeTarget` + `Target.createTarget`（真关真开），
      不是刷新——只改内存 state 的实现也能"刷新前一致"，过不了这一条。
- [x] 清掉 `localStorage` 后照旧能读：没有记录 = 没选过，不是"走到第一支"
      → `两颗都没按，也没有「共 N 页」` + `正文照旧读得到（25 个字），而 › 按不动`
- [x] 坏值（手改成 `'c'`、半截 JSON）退回"没选过"，不抛、不锁死
      → 两档同上，另加一条 `别的书选了 b（键带书号，不该串过来）`：也是"没选过"；
      趟 3–4 全程 `一次异常都没有`

## 怎么验的（方法本身要写下来）

- **`chk-path-memory.mjs`**：四趟（真的按一次 b / 真销毁后回来看 / 清掉 / 坏值），
  前置是 04 的夹具 `node scripts/mk-shared-fixture.mjs`，跑完 `--clean`。
- ★★ **被绊倒过一次，值得记**：第一版判据写的是"按完 b 之后底栏变成「第 5 页」"，
  结果两条支**都**翻到「第 4 页」——因为底栏那个数是**这条路上的第几屏**
  （04 §三：k = 路径序号），两条支的下一屏位置上算同一格，它**分不出走了哪一支**。
  改判据为**网络里的字节**（取了 page-5、没取 page-4），那才是唯一有判别力的量。
  这条与 04 的判据 1 是同一个道理，只是换了一层皮：**"走了哪条路"是资产的事，不是标号的事**。
- ★ **键名不写死在脚本里**：第 1 趟从 `localStorage` 里**找**出那个值是单个字母的键，
  后面几趟拿它做坏值实验。写死键名的话，改键名的那天脚本会从"验它"变成"验别的"，
  而它照样全绿。
- ★ 顺带**修了 04 那个脚本的一处脆**：它的 Chrome profile 是复用的，
  而这一单之后"上次选了哪一支"会跨趟留在里面——第二次跑时它一开始就"已经选过"，
  那些"第一次站上岔口"的判据验的就不是原来那件事了（**而它照样全绿**）。
  加了一行：跑之前先把这个 profile 删掉。改完重跑 04：**39/39**。
- ★ 另一处顺手补的：`.gitignore` 只忽略了 `xzj-shared-verify/`，
  `--missing` 造的那一本**没被忽略**——它会以"未跟踪"的样子挂在 `git status` 上
  等着被谁 `git add .` 进去。两本都列上了。

## 边界

- 不做"走过的路"可视化（那是下一步功能的开场，见 spec §七）。这一单只是**记得住**。
- 不做跨设备同步（与阅读记录同性质：只在这台设备的这个浏览器里）。
- 不做"忘掉这次选择"这个动作：界面上没有它，而多一个没人调的 `clearPick` 就是
  给下一个人一个"也许该用它"的假线索（`pressedOf` 那条是同一个教训）。
- 不给"上次你走的是这条路"加一句提示语：按下态本身就是那句话
  （`.book-choice__btn[aria-pressed]`），再加一行字是同一件事说两遍。
