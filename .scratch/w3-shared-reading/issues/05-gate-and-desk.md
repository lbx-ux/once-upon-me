# 05 · 闸门那一屏能改选择点 + 画桌标出岔路 + 钱说在花钱那一刻

Status: **done**（2026-10-18）
依赖：[01](01-shape-and-prompt.md)

★ 2026-10-18：这一单的紧迫性在 06 一 落地当天就变了——`/home` 的弹窗里已经能选共读版，
于是这一屏的缺口从"以后要补"变成"用户点两下就撞上"（实测：一本共读版进闸门，它按
`pageNo` 平铺出**全树 9 个节点**、看不出哪一页是选择点、那三格也改不了，也没有

## 一、`StorySheet` 补选择点那一组框（已做）

那一页多出一组「选择点（这一页分成两条路）」：**提问** + 两个选项各自的
**图标（emoji 兜底 + 词表名两个值）/ 按钮上的字 / 念出来的**。

- ★ **摊开的判据是两件已有判断的并集**，不新造第三条：`isChoicePage()`（引擎那一份，
  2026-10-18 从 `toChoice` 里提出来，两边共用）**或**这一页有 `field === 'choice'` 的问题。
  并集的两半各自在挡一种真实的坏法：写了一半的那一页**树建不起来**——只用"树建成了"
  当判据的话，正是那一页摊不开、改不了；而家长把某一格改空之后 `isChoicePage()` 认不出
  那种残留，由"问题清单那一半"兜住。
- 图标那一格是 **emoji + 词表名两个值**：`iconKey` 决定"有图时画什么"，`emoji` 是缺图时的
  兜底（`lib/choice-icons.ts`）。今天词表里只有 `dino` / `ship` 两枚有图（工单 02 出其余
  那批），所以多数书上按钮露的就是那个 emoji——两个都摆出来，别让人以为选了名就一定有图。
  词表之外的旧值**照实显示**（选项里标一句"不在词表里"），不静默改成别的 key。
- ★ **`TreeProblem` 多了 `field`**（`tree.ts` → `story-problems.ts`）：选择点那一族问题
  （两条分支 / 写了一半 / 多出来的孩子 / 整本一个都没有）原来一律报成那一页的**情节**，
  于是「缺 labelA / spokenA（A 那颗按钮）」出现在一个与它无关的框下面，而那一组框什么都
  没说。现在它们落进那一组；整本的那一条也终于说成「选择点：…」而不是「页数：…」。
- ★ 顺带修掉一个真坏过的形状：`dedupe` 的键里加了 `cell`。原来同一页上 `labelA` 与
  `spokenA` 都太短时，后一条会被当成重复的丢掉——家长改完一处、另一处还红着，
  而清单里从没提过它。

## 二、钱要说在花钱那一刻（已做）

- 弹窗里那一行（"共读版会多画走不到的那一支（图约多一倍）"）**写过又被用户划掉**
  （2026-10-18，理由与代价见 `GenerationSetupDialog` 判断 1）——所以那一屏不再解释口径，
  口径落到闸门：**「读下来 n 页，一共要画 N 页的图（含走不到的那一支）」**。
- 数字来自 `lib/story-shape.ts`（与 `problems` **同一个** `buildTree`）：路长是**区间**
  （共读版两条路，两支差 1 页是常态），`drawPages` 是全表节点数。
  ★ 两个数一样时（独读版）那一行**不出现**——同一句话说两遍是噪音。
  ★ 树建不起来（这一版有错）时它是 `null`：那时候屏幕上有问题清单在说话。
  ★ 不承诺倍数：多出来的张数取决于选择点落在第几页、两支各多长（实跑那次 `--pages=8`
  长出 14 个节点、选择点在第 6 页）。
  ★ 它不数封面那一张：封面两种形态都要画，而这一行要说的是**分支多出来的那一部分**。

## 三、画桌标出岔路（已做）

- `plan-ready` 多一个 `branchPages: { a, b }`（两条支各自的页码）。
  ★ **为什么进事件而不是让画桌读草稿**：那一层的纪律是"一张桌子只取决于事件流"；
  从草稿读的话同一串事件会折出两张桌子，而**重放**（从书架进来，没有草稿）什么都不标。
  ★ 可选字段：2026-10-18 之前落盘的日志没有它，读的时候不标——**不是标错**。
- `frames.ts` 的 `Frame` 多一个 `via`，**先整串扫一遍再折**（`plan-ready` 之前到的
  `illustration` 会先造格子，边扫边记的话那一格永远是 null）。
- `Desk` 给那几格挂一条窄色带（左边，`--beam`）+ 一颗 A / B 角标，整排上面说一句
  「标着 A / B 的是岔路那几页——两条路各是一个完整的结尾，孩子只会读到其中一条」。
  ★ 归属**不是**"第 N 格之后都算岔路"：验证夹具里 a 支那一页就排在 b 支那几页前面。

## 验收

- [x] 闸门改一个 `spoken` → 问题清单清空/更新正确 → 「就按这个画」真的按改后的走
      （实测：清空 A 的「念出来的」→ 当场出现「第 5 页的选择点：选择点写了一半…」、
      按钮变灰并把这句写进 `title`；填回去 → 清单清空、按钮亮、自动保存说"改的已经存上了"）
- [x] ★ 把某个 `spoken` 改空：闸门**当场**说清是哪一格（不是等服务端 400）
      （那句话与那一组框一起出现，就在缺的那两个框旁边。★ 用词是引擎那句**原话**——
      它同时是给模型的重试提示，界面照搬、不另翻一遍；缺的是哪两格在框里一眼看得见）
- [x] 闸门显示的两个数（路长 / 要画的张数）与 `book.json` 里的真值相等
      （实测那本共读版闸门说「读下来 7 页，一共要画 9 页」；`book.json` 的 `tree` 由
      **同一个** `buildTree` 从**同一份草稿**派生——`engine/index.ts` 那一行注释写着）
- [x] 画桌上两支的格子看得出属于哪一支，且**不是**靠位置猜的
      （实测：`data-branch="a"` / `"b"` 落在第 4 / 5 格上，色带与角标都在；
      `frames.test.ts` 另有"图比 plan-ready 先到""旧日志没有 branchPages"两条）
- [x] 静止/`busy` 时那几格只读
      （新加的 7 个控件全都带 `disabled={busy}`，与这一屏原有的框**同一个 prop**。
      ★ **这一条是按构造算通过的，没有单独量**：`busy` 只在那两个请求期间为真，
      而探针两次往返之间它已经结束了——量到的是"已经 settle"的界面。
      要真量得在同一个 eval 里点完立刻读，或者故意让请求挂着。）

## 怎么验的

- 闸门那一屏：隔离 dev server（`.next-form` / :3351）+ 真后端，登录演示账号，
  走 `/create?book=<共读版那本>`。判据取**屏幕上那几个元素**（`.ss__shape` 的原话、
  `.ss__choice` 里的 `.ss__bad`、`.gr__composer-acts` 最后一颗的 `disabled` 与 `title`），
  不是客户端 state。
- 画桌那几格：`node scripts/engine-run.mts --mode=stub`（零成本）跑出一本共读版，
  把它的 `eventsRaw` 写成 `events.jsonl` 放进 store 再 `/create?book=` 回放——
  这样量到的 `data-branch` 是**事件流**折出来的，不是手写的。跑完把那本清掉了。
- ★ 顺带验到一件本来没打算验的：**共读版走一遍「让 AI 重写一版」是通的**
  （重写后仍是 9 页、一个选择点、两个新选项，闸门无问题、数字行还在）。

## 边界（写下来免得下一个人以为是漏了）

- **不做"加一个 / 删掉一个 / 搬一个选择点"**：那是改树的结构（`from` / `via`），
  另一个量级。这一单只让**已经存在**的那个选择点可改。
- 不做树形可视化（spec §五 四 那句"W5 材料"照旧）。
- 结构类问题（父节点序号不合法这类）仍旧落在「情节」那一格下面：界面上没有 `from`
  这一格可改，所以那句话今天只能是一句"服务端会拒绝"的说明。把它做成可改是另一单。
- ★ 闸门那一行数字**不承诺**"约多一倍"那种倍数（理由见二）。
