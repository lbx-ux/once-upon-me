# 03 · 选择点的三段配音

Status: done（2026-10-18）
依赖：[01](01-shape-and-prompt.md)

## 做什么

`narrate.ts` 今天只念 `node.body`，所以 `choice.prompt`（给家长念的引导提问）与
`options[].spoken`（给耳朵听的那句）**没有人念**——而产品定义里选项走
「**大图标 + 语音朗读**双通道」。

1. **`Narration` 加一个可选的片段字段**（`part`，缺省 = 正文）。
   ★ 可选是刻意的：盘上已有的书与随仓库提交的演示书都没有它，
   "缺省 = 正文"让它们一本不受影响——与 `Book.status` 那条"缺省 = 成品"同一类迁移决定。
2. **落盘名**：`page-3-prompt-a1.mp3` / `page-3-opt-a1.mp3` / `page-3-opt-b-a1.mp3`
   （沿用 `page-<no>-a<take>` 那套，`extensionOf(mime)` 跟着供应商走）。
3. **去重键一个字不改**（`(voiceId, textHash)`）：两支的选择点写出一模一样的口语句子时
   复用同一份录音——`narrate.ts` 规则 1 的现成好处。
4. **`narrateAll` 的输入**从"节点表"扩成"节点表 + 它们的选择点"；`index.ts` 组装时传进去。
5. **文本口径只有一处**：`narrationTextOf(node)` 旁边加同形的
   `choiceNarrationTextsOf(node)`（返回 3 条：prompt / option-a / option-b），
   空串的跳过（与"没有正文就不合成"同一条）。

## 验收

- [ ] 跑一本共读版，`narrations` 里选择点那条有 3 个片段，`asset.path` 各不同
- [ ] 同一段 `spoken` 出现在两个选择点时只合成一份（`reused: true`）
- [ ] `voiceId` 缺席时三段都不合成，事件里那条非致命的"这本书没有朗读"照旧
- [ ] 单页重配（`rerunNarration`）不受影响——它按 pageNo 重配**正文**那一份

## 边界

- **不做**浏览器 `speechSynthesis` 念选择点：免费离线，但**声音不是父母的**，
  而这本书的主张是"用你的声音讲出来"。详见 spec §三·四。
- `mood` / `pronunciation` 仍然不传（供应商那边还没接，见 `qwen-speech.ts` 文件头第 5 条）。

## Comments

**2026-10-18 · 收口**

做之前先把消费者摸了一遍，撞到一个**必须一起修的坑**：

> `index.ts` 的 `replaceByPage` 按 `pageNo` 删条目，而一页现在最多四段——
> **"重配这一页"会把同一页的另外三段一起删掉**。症状是"换了音色之后，
> 提问与两个选项凭空不见了"，而那种缺失没人会去查。

所以拆成两个函数：`replaceByPage`（一页一条的那几种）与 `replaceNarration`
（键是 `(pageNo, part)`，按 正文 → 提问 → 选项A → 选项B 排）。`rerun.test.ts` 里那条
`★★ 重配选择点那一页不会把另外三段弄丢` 就是这么来的——**把 `replaceNarration`
换回 `replaceByPage`，它当场红**。

**三处按"最小惊讶"定的口径**：

1. **正文那一档的文件名与加共读版之前逐字节相同**（`page-3-a1.mp3`，后缀是空串），
   所以盘上已有的书、以及所有拿旧名字做的断言都不受影响。
2. **`Narration.part` 是可选、缺省 = 正文**：与 `Book.status` 那条"缺省 = 成品"
   同一类迁移决定（盘上的书没有这个字段，不能为它批量重写清单——清单是资产）。
3. **单页重配把这一页的每一段都重录一遍**，不只正文。只重录正文的坏法很具体：
   重配最常见的原因是**换了音色**，于是正文是新声音、选择点那三句还是旧声音——
   同一页里两个讲述者，而界面上写着"已换"。
4. **报错要点名是哪一段**（`NARRATION_PART_LABELS`）：只说"这一页没配上音"，
   家长不知道缺的是哪一句——正文缺了他自己能念，选项缺了孩子就选不了。

**顺带修的**：`book-source.ts` 的 `readerPages` 原来用 `new Map(...map(pageNo → narration))`
取这一页的录音，一页四段之后"**后写的赢**"，而赢的是哪一个由数组顺序决定——
症状是"这一页念出来的是选项那句话"，听起来像内容错了，其实是取错了条目。
现在显式只挑 `body` 那一档。

**验收**：`narrate.test.ts` 新增 5 条（四段各落各的文件名 / 两个选项同一句话共用一份字节
但 `part` 各是各的 / 报错点名哪一段 / 空页照旧跳过），`rerun.test.ts` 新增 1 条。
四道闸门：`format:check` ✓ · `lint` ✓ · `typecheck` ✓ · `pnpm test` **943 条**（01 之前是 935）。

★ **没验到的一条，如实记**：真跑一本共读版、看 `book.json` 里选择点那一页真有
四个 `Narration`（三条 `part` 各不相同）——那要一次完整出图，而这一天的出图被网络掐掉了
（见 [01](01-shape-and-prompt.md) 的收口记录）。单测覆盖的是同一条代码路径，
但"盘上真有一本书长这样"这句话还没有实测。
