# 01 · 树的形状与提示词：恰好一个选择点，两支各自收尾

Status: done（2026-10-18；02 的图标是它的下游，可以并行等图）
依赖：无（02 可并行）

## 做什么

1. **`engine/domain.ts`**：加 `CHOICE_ICONS` 词表（"盘上有图的那几个 key"，与 `LOOK_TAGS` /
   `MOODS` 同一处）。它**不是**枚举校验，是**美术清单**——理由见下面的"一处与 spec 不同"。
2. **`schemas/story.ts`**：`iconKey` **保持宽容**（`withDefault(string({max:24}), 'generic')`
   不动），只把值域写进注释并指向 `CHOICE_ICONS`；`nodeDraftCodec` 其余字段不动。
3. **`engine/tree.ts`** 加共读版专属判据（会 red 的那种）：
   - **恰好一个选择点**（0 个已有判据；多出来的报"这一版只支持一个选择点"）；
   - **两支深度差 ≤ 1**（从选择点的两个孩子各自向下走到叶子，取最长链）；
   - "选择点不能是最后一页"由现有"必须是 2 条分支"覆盖，不重复加。
4. **`prompts/story-plan.ts`**：`FORM_RULES.shared` 重写（见下），`STORY_PLAN_VERSION`
   升 `story-plan@v3`。
5. **`engine/tree.test.ts`** 补三条新用例（2 个选择点 / 支深差 2 / 现有那些继续绿）。

## `FORM_RULES.shared` 重写（现在那句与结构矛盾）

现在写的是「两条分支都要能走回**同一个结尾附近**」——**做不到**：`tree.ts` 的
"单父 + 选择点恰好两子"让**汇合无法被表达**（汇合节点要两个父，或挂回选择点）。
改成如实的话：

- 整条路读下来约 `{pages}` 页，**恰好一个**选择点，放在约 60%–80% 处；
- 两条路各自往下走、**各有一个完整的结尾**，页数相差不超过 1 页；
- 两个结尾要落在**同一个落点与同一种情绪**上（同一场景回环、同一句主题）——
  孩子选哪条读到的都是讲完了的故事，不许有一条像被截断；
- `choice.prompt` 是**给家长念的引导提问**；`label` 给眼睛（≤8 字）、
  `spoken` 给耳朵（一句完整的话，会被朗读）；
- `iconKey` 从词表里挑（把 `CHOICE_ICONS` 拼进提示词）。

## 一处与 spec 不同（办的时候想清楚才改的）

spec §四 写的是"schema 用 `enumOf(CHOICE_ICONS)`"。**不改了**，理由是钱：
`planStory` 的重试是**整篇重写**（`plan.ts` 的循环重发同一个 prompt），所以一个
**装饰性字段**（图标名）不合枚举 ⇒ 整本故事重新生成一次。而 `withDefault` 恰好
已经是宽容的（`result.ok ? result : ok(fallback)`），所以今天的形状本来就是
"对上就用图、对不上露 emoji"——与两枚云图、第三屏插画**同一个机制**。
词表仍然只有一处（`CHOICE_ICONS`），提示词与"哪个 key 有图"都从它取。

## Comments

**2026-10-18 · 这一单的账：从 17% 到 90%，以及一路上被打脸的三个判断**

第一件事是**"引擎侧已经支持 shared"这句话从来没有对着真模型验过**。
`--mode=stub` 那份共读版剧本是**手写的**，所以"已支持"只证明了代码能跑通一条手写的剧本。
第一次真跑（3 本 × 3 次规划）**全军覆没**，同一个症状：

```
nodes[4].choice.options：数量不足（0 < 2）
```

### 三个被推翻的判断，按被打脸的顺序

1. **"schema 用 `enumOf(CHOICE_ICONS)` 才叫判据只有一处"** → 改掉了。
   `withDefault` 的实现是 `result.ok ? result : ok(fallback)`，它**本来就吞掉失败**；
   而 `planStory` 的重试是**整篇重写**（`plan.ts` 循环重发同一个 prompt），
   所以让一个装饰性字段不合枚举去触发整本故事重生成，是拿最贵的动作换最便宜的东西。
   词表改成"美术清单 + 提示词给值域 + 对不上露 emoji"。

2. **"失败是因为预算被截断"** → 不是。失败回包只有 **512 字符**、末尾出现
   `{"choice": {}, "}": "]"}`（模型把 JSON 的结构符号当成键），看着像截断。
   直接打一次接口量：`finish_reason: stop`、正文 3407 字符、`completion_tokens` 1690 ——
   离 4096 的预算还远。**那是模型自己的退化输出**，不是预算。

3. **"把图标词表写进用户提示词那句散文里就行"** → 不行，而且是我写的 bug。
   第一版写成 `iconKey 从这几个里挑最接近的一个：dino / ship / … / drum`，模型的回包是

   ```
   "choice": { "dino / ship / rocket / … / drum": null }
   ```

   ——**它把整串词表当成了 JSON 的键**。形如数据的碎片就该写成数据：
   现在它在**系统**提示词里，写成 `JSON.stringify(CHOICE_ICONS)` 的数组字面量，
   并说清"原样照抄一个"。（顺带一句：`choice` 那三个字段的小标题下面列了四项
   ——`prompt` / `label` / `spoken` / `iconKey`——后三项其实属于 `options[]`，
   模型照着标题把它们**拍平进了 `choice`**。标题说错形状，模型就照着错的写。）

### 修法：线格式拍平，领域类型一个字段都不动

加了 JSON 范例之后仍然只有 2/4，于是不再猜、按 W1 的纪律**把失败分档量**：

```
单次尝试通过率：2/12 = 17%（ok 2 · shape 8 · tree-other 1 · criterion 1）
```

8 次 `shape` 里有 7 次是同一个症状：**`options` 交回一个空数组**。
而整个 schema 里**唯一的"对象数组"就是 `options`**（`body` 是字符串数组，从没出过错）
——这正对上 `schemas/story.ts` 文件头早就写着的那句话：「模型写嵌套结构的失败率明显高」。

所以把**线格式**拍平（`ask` / `labelA` / `spokenA` / `iconA` / `emojiA` / …/ `emojiB` 九格
平铺在节点上），领域类型 `StoryChoice` 一个字段不动，由 `tree.ts` 的 `toChoice()` 组装。
这条路本来就是这张表的既定招式（扁平表 + `from` → 树在**解析之后**由 `tree.ts` 校验并组装），
只是 `choice` 那一处当初没照着走。

**同一把尺子再量一次**（同 12 个主题、同 `--parallel=4`）：

```
单次尝试通过率：9/10 = 90%（ok 9 · tree-other 1 · call-failed 2）
```

剩下那一条是另一类病（"选择点有 6 条分支"——模型让选择点长了六个孩子），
重试提示会点名它，三次里兜得住。两条 `call-failed` 是并发打接口的 `ECONNRESET`，
按纪律**不进分母**。

### 顺带修掉的两处

- **范例的内容会被抄走**。第一版范例用的是"两朵云 / 恐龙背 / 船肚子"，
  于是两本题材完全不同的书（"送走丢的小猫回家"、"怕黑的孩子"）的岔路**全都问
  "该上哪一朵云"**——形状修好了，内容被搬走了。范例换成一只**不相干的猫**
  （阿橘在路口挑路），并明说"只抄形状，里面的话一个字都不要抄"。
  修完之后两条岔路都从各自故事里长出来（"画恐龙 / 数星星"、"恐龙云 / 月亮船"）。
- **漂移要能自动红**：`CHOICE_CELLS` 只有一份（`schemas/story.ts`），
  `story-problems.ts` 靠它把 `nodes[4].labelA` 翻回界面上那一组框。
  `story-problems.test.ts` 里有一条拿 `planJsonSchema()` 逐个核对的用例——
  名字对不上时的症状不是报错，是**在错的格子里读到一句关于别处的话**。

### 留下来的两把量具（都不进仓库，在 `.out/`）

- `.out/measure-shared-plan.mts` —— 单次尝试通过率，**按失败原因分四档**。改提示词之后拿它量一遍。
- `.out/diag-choice-shape.mts` / `.out/diag-usage.mts` —— 打原始回包看模型到底写了什么
  （形状错的时候，失败清单只说"options 缺失"，说不出它把选项写成什么了，
  而那是唯一能决定怎么修的东西）。

★ 教训一条，与 W1 那四类错同源：**"引擎侧已经支持"是一句关于代码的话，
不是一句关于模型的话**。手写的 fixture 能让一条流水线跑通，也能让一个
