# 决赛前优化方案（11/10 制定，11/18 提交）

> 依据三样：预指导 90 分与那句评语「儿童AI故事创作创意独特，水彩风格精美温暖；建议增加插画自动生成」；
> 官方评分标准（`D:\school\compete\传智杯AI-Web赛道_官方规则与评分标准.md`）；
> 2026-11-10 对线上站与仓库的实测。
>
> 每条都写了判据。做不到的会写明没做到，不写成"已优化"。

## 0. 一句话

功能不缺，缺的是**评审在第一分钟看不见它**。这一轮的优先级不是加功能，是把已经在跑的东西前置，
并让一个新账号真的能跑完一遍。

## 1. 评语判读（实测，不是猜）

线上站 `https://lbx99.xyz`，演示账号 `123456` / `123456`，2026-11-10 读数：

| 事实                             | 读数                                                             | 怎么量的                                              |
| -------------------------------- | ---------------------------------------------------------------- | ----------------------------------------------------- |
| 一本 12 页独读（12 页 + 1 封面） | 事件跨度 **134.3 s**                                             | `GET /api/books/kid-rnp95e-sheet-f5736dca385b/events` |
| 一本 19 页共读                   | **277.8 s**                                                      | 同上，`kid-rwuhzo-sheet-fa242cde622b`                 |
| 一本 8 页独读                    | **104.7 s**                                                      | 同上，`kid-rf0bs2-sheet-fe1d5f439116`                 |
| 出图并发                         | **3 路**                                                         | 事件里第 1/2/3 页同时 `stage begin`                   |
| 单张图记账                       | **0.20 元**                                                      | `illustration` 事件的 `costCny`                       |
| 一致性比对                       | **12/12 `pass`**，score **0.55**，threshold **0.50**             | `consistency` 事件                                    |
| 画面审核                         | **12/12 `pass`**                                                 | `review` 事件                                         |
| 检索                             | 一本 `examples 3 / avoids 3 / topScore 4.92`；另一本 `0 / 0 / 0` | `retrieved` 事件                                      |
| 新账号额度                       | **0**                                                            | `AuthService#createUser` → `ensureAccount(..., 0)`    |
| 页数档位                         | 5 / 8 / 12 / 20，默认 8                                          | `src/lib/creation/state.ts`                           |

**自动插画在跑，而且一本 12 页的书 2 分 14 秒就画完。** 文档里「20–35 分钟」那句是旧口径
（`技术文档 §4.7` 已经改过 154 s/页那条，但别处的"几十分钟"没跟着改）。

那评语从哪来？只剩两种可能：

1. **评审没走到「就按这个画」那一步。** 到这一步之前，屏幕上一个字都不缺、一张图都没有：
   首页 → 登录 → 写一句话 → 编故事（约 9 s）→ 故事闸门（纯文本）→ 才开画。
   闸门这一屏设计上就是"先看字、再花钱"（成本结构决定交互结构），评审停在这是合理的。
2. **走到了，但没看见过程。** 画桌要等两分钟，而"它真的在画"只存在于那一屏。

两种可能是同一处病：**证据在流程后半段，评审只给前半段的时间。**

另外两件只有扒事件日志才看得见、但不该被评审看见的事：

- 我抽到的第一本书，12 页 score 全是 **0.55**，每页都记着「眼睛/头发不像」，**全部放行**。
  0.55 > 0.50 是写明的取舍（`illustrate.ts` 文件头第 4 条），但把档案摊开之前，这句得先想好怎么说。
  另一本 8 页的分数是 0.55 / 0.82 / 0.90 混的——说明不是全站退化，是**有些卡的分辨力不够**。
- 新注册账号额度是 0。演示账号 20 本，任何自己注册的人一本都画不了。

还有一件小的：`/api/auth/me` 报 `configured.vision: false`，但事件里有 12 条一致性 `pass`。
引擎那边 `visionProviderOf` 会回落到 `LLM_API_KEY`，而这个接口只认 `VISION_API_KEY`。
——**报数口径和引擎口径不一致**，评审要是打开管理页会看到"视觉未配置"，而它其实在跑。

## 2. 目标（验收就按这几条）

1. 一个没登录的人，从首页到看见「逐页出图 + 一致性判定 + 安全审核」的真凭据：**≤ 2 次点击、≤ 30 秒**。
2. 一个刚注册的账号，不兑换也能画完一本 **3 页**的书（**≤ 5 分钟**从注册到读完）。
3. **每一本成品**都有一份能打开的生成档案，数字与 `book.json` / 事件日志逐条对得上。
4. 提交材料里的"自动插画"不再需要读者相信——有一页能点开看。

## 3. 改动清单

### P0-1 `GET /how`：一本真书的生成档案（公开，静态）

**做什么**：新页面 `/how`，把一本真书的一整轮摊开：逐页出图时间、attempt、一致性分数与阈值、
哪几条锚点没对上、画面审核结论、总耗时与总花费；页面自身按真实时间戳把页图一张张放出来
（静态回放，不联网、不调模型）。

**为什么**：这是对那句评语最直接的回答，也是 Agent 8% 唯一不靠"信我们"的证据。

**怎么落**：

- `scripts/make-trace.mts --base=https://lbx99.xyz --account=… --book=<id> --out=public/demo/trace/<id>/`
  登录 → 拉 `/events` + `/api/books/<id>/pages` → 写 `trace.json`；页图走 `?w=640` 取下来转 WebP。
  静态文件随仓库提交，页面不碰线上接口（评审期间站点挂了这一页也还在）。
- `src/app/how/page.tsx` + `src/components/how/TraceReel.tsx`（服务端读 JSON，客户端做回放）。
- 文案要诚实：0.55 那几页照实写「眼睛/头发这条不像，仍放行；家长可以手点重画」，
  不挑一本全 0.9 的来冒充典型。

**判据**：

- 断网刷新 `/how` 仍能播完（网络面板里没有任何 `/api/` 请求）。
- 档案里的页数、attempt 总数、分数集合与源事件逐条一致（比对脚本 `--check`）。
- 手机上不横向溢出，页图按 100% 宽。

**成本**：零模型调用；仓库多约 0.4–0.8 MB 图。

### P0-2 新账号送 2 本；页数加一档 3 页

**做什么**：`AuthService#createUser` 里 `ensureAccount(userId, 0, "开户")` 之后补一句
`ensureGrantOnce(userId, WELCOME_BOOKS(2), "welcome", "新账号开户赠送")`；`PAGE_CHOICES` 改成 `[3, 5, 8, 12, 20]`。
额度这一半 2026-11-10 已经做完（后端 98 个测试全绿）。

**为什么**：现在评审自己注册 = 一本都画不了，只能去翻文档找演示账号。
3 页档一本**估** 40–60 秒画完（按 8 页 104.7 s 外推，没实测），是"点一下就能看到完整过程"的规模。

**判据**：

- 新账号余额 2，不兑换能走到「就按这个画」并画完。
- 同一个账号重启、重复登录不重复送（`refNo = welcome` 幂等）。
- 3 页独读、3 页共读各跑通一本（共读版下限正好 3 页，`plan-shared.ts` 已允许）。

**风险**：被薅。限 2 本、单个手机号、站长可关；比"评审画不了"便宜。

### P0-3 `configured.vision` 与引擎口径对齐

**做什么**：`src/app/api/auth/me/route.ts` 改成
`Boolean(env['VISION_MODEL'] && (env['VISION_API_KEY'] || env['LLM_API_KEY']))`。

**为什么**：管理页与 `/me` 是评审唯一能看见"配了什么"的地方，报错等于自己拆台。

**判据**：只配 `LLM_API_KEY` + `VISION_MODEL` 时 `configured.vision === true`，与
`visionProviderOf` 同一条判据（加一条单测钉住）。

### P0-4 首页给一条去 `/how` 的路

**做什么**：在**不改 `.hero__copy` 子元素顺序**的前提下加一个入口（追加为最后一个子元素，
或放在第二屏末尾）。理由见 CLAUDE.md：文案层入场错峰写在 `nth-child(2..4)` 上，插在中间就静悄悄错一格。

**判据**：入场节奏与现在逐帧一致（`chk-run-motion` 复跑）；手机档仍是两节、12 张封面一张不取
（`chk-mobile` 判据 7 两头都量）。

### P1-1 每本书的「生成档案」入口（11/14）

**做什么**：`/trace/[bookId]`，服务端读 `book.json` + 事件日志，渲染与 `/how` 同一个组件。
入口放在阅读器与书架上（"这本书怎么来的"）。

**为什么**：把 `/how` 从"一张宣传页"变成"每一本都有的东西"，也顺手把 Agent 证据做进产品。

**判据**：任一成品都能打开；档案里的 `firstPassCount` / `redrawCount` 与 `book.json.stats` 一致；
未登录/别人的书 404（与阅读器同一条口径）。

### P1-2 一致性判据：先量，再决定说不说（11/15）

**做什么**：拿 2 张卡各跑一本 8 页，阈值 0.50 与 0.70 两档，记 pass 率、重画次数、总花费，
并人眼判 0.55 那几页"是不是同一个孩子"。**量完再决定**是改阈值、改锚点文案，还是维持并如实说明。

**为什么**：现在 0.55 + 两条硬锚点不像却放行，是这套系统最容易被一句话戳穿的地方。
在 `/how` 把它摊开之前，必须知道它到底意味着什么。

**判据**：两档的（首次通过率、重画率、单本成本、人眼判定）四列数字进 `docs/known-tradeoffs.md`；
阈值若改，`illustrate.test.ts` 与 README 的同一条数字一起改。

**注意**：这是改引擎行为，按 CLAUDE.md 的规矩，没重新测过不许改。

### P1-3 RAG 进档案（11/15）

**做什么**：`retrieved` 事件已经在日志里，档案多一行：这一轮检索到几条正例、几条反例、最高分。
`examples: 0` 时如实写"这一轮没有检索到正例"。

**为什么**：RAG 6% 现在只能靠文档自述；一行真数比一段形容词有用。实测已经出现过 0/0/0。

**判据**：同一句话开/关 `retrieve` 各跑一次，档案里能看出差别。

## 6. 不做的事

- **不加新功能**：多角色配音、实时对话、视频导出，这一轮都不做。8 天不够，而且都不解决那句评语。
- **不造假进度**：前端不许为了"看起来在画"编一条自己会走的进度条。项目里写过"不编进度"，
  这次也不破例。3 页档的意义就是让真实过程足够短。
- **不动首屏那三个咬合的数**（`HANDOFF_START` / `--out-start` / `smoothstep` 区间）。
  要加入口就追加在末尾，不插队。
- **不在量之前改阈值**。0.55 放行看着扎眼，但改成 0.70 会让重画率与成本一起变，必须两档都量过。

## 7. 风险

| 风险                      | 应对                                                           |
| ------------------------- | -------------------------------------------------------------- |
| 新账号送额度被薅          | 只送 2 本、幂等键 `welcome`、站长可关；被薅的上限是每人两本    |
| `/how` 摊开 0.55 反而扎眼 | 先做 P1-2 的量；文案照实写放行策略，不挑好看的书               |
| 改首页碰坏入场节奏        | 只追加、不插队；`chk-run-motion` + `chk-mobile` 两头复跑       |
| 静态档案与线上不一致      | 导出脚本带 `--check`，提交前比对一次；不一致就重新导出，不手改 |
| 另一个会话在同一个工作区  | 定点编辑，不整文件重写；提交前看 `git status`                  |

## 8. 本方案自己没做的事

- 没有真跑一次生成（花钱、耗时），所以"一本 12 页 134 秒"是读线上事件日志得出的，不是本机复跑。
- 没有在手机上手动点过 `/how`（页面还不存在）。
- 没有核对演示账号里每一本书的观感；只抽了 3 本的事件。
