# 03 · 第二屏：最后一页翻开了，书却不在中间

Status: done
Spec: ../spec.md
创建：2026-10-12（用户第 5 条要求）

## 症状

"最后一页展开完整了，绘本不是在中间。" 截图上书的顶边被切掉一截，下面空一大片。

## 根因（是量出来的，不是猜的）

`enter-exit` 这个量程**天生把最后 23% 留给"书离开屏幕"**：

```
stage 从 y=T 起钉住，到"本节底边贴住视口底"被顶出去：y = T + H − V
rangeTop = T − V，span = H + V      ⟹  被顶走那一刻 p = H / (H + V)
H = 340vh、V = 100vh                ⟹  p = 0.7727
```

1440×900 下在浏览器里量的 `pAtPushOutStart = 0.7727`，与推导一致（`clamped=false`，
因为下面还有第三屏）。而 `P_Q` 把最后一个跨页排在 **p=0.86** 才翻开：

| p                      | 那一刻 stage 顶边 | 书顶边                     |
| ---------------------- | ----------------- | -------------------------- |
| 0.86（最后一页刚翻开） | −346px            | **−166px（被切掉 166px）** |
| 1.0（滚到底）          | −900px            | 整本书在视口上方           |

**最后一页的整个停留段，都发生在书已经往屏幕外走的路上。**

## 改法

不是把 340vh 加大 —— `H/(H+V)` 涨得极慢（要 p=0.9 得让本节高到 900vh）。
是**把每一个要让人读的停顿都排到 0.7727 之前**，整表重排：

- 最后一个跨页现在在 **p=0.68** 翻开，之后到 0.7727 还有 **367px** 的滚动
  里书**始终正居中**（实测 `offCenter = 0`，1440×900）。
- 0.7727 → 1.0 明确是"退场"，不再假装是"停在最后一页"。

顺带修掉两处同源的问题：

- 选择点窗口原先收到 p=0.78，比"开始翻走"还晚，而且已在退场段里 → 现在收口 0.615。
- 刻度点最后一格跳的是 `P_AT[4]`，原来算出 **0.902**，落在退场段：
  **点一下"最后一页"会把书推到屏幕外去** → 现在 0.708，仍在钉住区间内。

## 为什么注释没拦住这个 bug

`StorybookFlip.tsx` 文件头**早就写着**"最后一页的停顿要早于 0.773 开始"。
表还是排到了 0.86。所以这次不是把注释再写一遍，而是：

- `PUSH_OUT_P` 变成一个常量（带推导），`P_Q` 最后一档直接用它；
- 加开发期断言：任何一次翻页排在 `PUSH_OUT_P` 之后 → `console.error`；
  选择点窗口收口越界同样报错。

**两个手写的数各改一处，只有断言拦得住。**
