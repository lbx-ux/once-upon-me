# 05 · 轮播不环：第 1 条的左边应该是第 5 条

Status: done
Spec: ../spec.md
创建：2026-10-12 深夜（用户第 8 条，看着改版后的实屏提的）

## 症状

用户截图圈出第三屏左边那一大片空：**"这个是轮播图啊，第一页的前面是第五页。"**

## 根因

`reelState` 算的是 `offset = index - active` —— **一条直线，不是环**。
`active = 0`（第 1 条居中）时五张卡的偏移是 `[0, 1, 2, 3, 4]`：

- 左边**零个卡位** → 空一大片；
- 第 4、5 条堆在右边缘外，被 `.hl` 的 `overflow: hidden` 裁掉。

自动播用 `wrapActive` 绕回，所以 `active` 一直是环着走的；
**但卡片在环上的位置从来不是环**。两套逻辑一半环一半不环，
这就是"看着像轮播、其实不是轮播"的全部原因。

## 改了什么

1. `reel.ts` 新增 `ringOffset(from, to, count)` —— 环上带符号的**最短**位移，
   结果永远在 `(-count/2, +count/2]`；`reelState` 改用它。
   `active = 0` 现在是 `[0, 1, 2, -2, -1]`，左右各两张，任何时刻都对称。
2. `reel.ts` 新增 `reelJumped(prev, next, count)` —— 谁这一拍跨过了接缝。
   判据 `|Δ| > count / 2`：环上短的那条路不超过半圈，超过半圈的一定是跨界那张。
3. 组件据此给那一张加 `data-jump`，CSS 一条 `.hl__slot[data-jump] { transition: none }`。
   **不关会看到一张模糊的卡从最左横穿到最右** —— 补间是连续插值，它必然经过正中间。
   关掉之后它在最左消失、在最右出现，而那两处都在舞台半径外、本来就被裁着。
   ★ 必须在**渲染时**算好、与新的 `--hl-offset` 同一个 commit 交出去；
   等 effect 跑完再关过渡就晚了，浏览器已经看见"旧位置 + 有 transition"。
4. 键盘 ← → 从 `stepActive`（夹两端）改 `wrapActive`（环形）。
   既然画面是环，按键就该绕回去。**`stepActive` 连同 4 条测试一起删掉** ——
   它存在的理由是"箭头按钮到头要 disable"，而那排按钮上一轮已经删了，
   没有调用者的函数不留着"以后可能用得上"。

## 我写错过的一条测试（值得留着）

第一版我给 `reelJumped` 写了一条"普通一步（不绕回）谁都不该被判成跨界"。**这条前提就是错的**：
环上**每前进一格**都恰好有一张卡从最左绕到最右，跟"走到第 5 条再回第 1 条"是同一件事。
跑出来红了才发现自己想的是"直线 + 偶尔绕回"，而实现已经是"环"。
现在那条改成断言"每一步恰好一张跨界，且前进时是原来 -2 那张、后退时是原来 +2 那张"。

      环形不变量 1 条、两侧可点 1 条；删掉 stepActive 4 条）
- [x] ★ 环形不变量：**任何一张当当前卡，左右各恰好两张、恰好一张在 0 位** ——
      这条是上面那个 bug 的通用形式，单点断言挡不住"只有某一张才出现的问题"
- [x] 浏览器实测（1440×900，active=0）：01 居中 dx=0、02 在右 dx=+525、
      **05 在左 dx=−525 且 `onScreen: true`**、03/04 在 ±971（舞台外，被裁）
- [x] 浏览器实测：点第 2 条 → 偏移变 `[-1,0,1,2,-2]`，且 `data-jump` 落在**第 4 张**

- [x] 浏览器实测：`data-jump` 那张的 transform **当场落到新位置**，

- [ ] **横穿那一下在肉眼里确实没有** —— 见下面这条测量限制
- [ ] **绕回那一拍的"瞬移"在宽屏上看不看得出来**（≥2000px 时 ±2 位会露出一点边）

## 一条测量限制，别当成"验过了"

上面第 2、3 条是在**后台文档**里量的。后台里 CSS transition 的时间线不走：
元素的属性与样式已经是新值，但 `getBoundingClientRect()` 会**停在旧位置**。
所以"其余四张仍在补间里"这句，准确说法是"它们的位置还没动"，
**不能**读成"我看见它们在平滑地动、而那张没有"。
`data-jump` 那张读到的是新位置 —— 这个对比是有效的（说明它的 transition 确实没生效），
但"平滑"本身要前台看一眼才算数。
