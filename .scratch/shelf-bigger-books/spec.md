# 书架：把书放大一点（156 → 192）

**Status:** claimed（工单见 `issues/01-bigger-books.md`）

## 起因

2026-10-17，用户看着 `/shelf` 的截图圈住那本「新建故事」的虚线书说：

> 我觉得书架的书可以放大一点

不是"再排紧凑些"、也不是"换个大书架"——就是**一本书本身小**。所以这一单只有一件事：
把 `--book-w` 抬上去，连带把跟着它咬合的那几个数一起抬。

## 为什么是 192，不是"挑个好看的数"

`--book-w` 在这个文件里是**唯一的输入**（`shelf.css` 文件头那句）：封面高、行高、
板的位置全部由它 `calc` 出来，所以"改一个数"看起来是零成本的。它其实不是——
**上限被缩略图档位钉死了**：

```
--book-w 192px  ×  2 倍屏  =  384  ←→  thumbs.ts 档位表里的 384
                                ←→  library.ts 的 SHELF_COVER_WIDTH
```

再往上只有两条路，都不是改一个数：

1. 继续拿 384 的图去铺更宽的框 → 封面发虚；
2. 把 `SHELF_COVER_WIDTH` 抬到 512 → 一屏五本，**每本都换一张更重的图**。

所以 156 → 192（+23%）是**这一档能给的满额**：先用满已经付过钱的那一档，
真要越过它再单独谈换档。这条要写进注释（`shelf.css` 与 `library.ts` 各一处），
否则下一个人只会看到"还能再大"，然后顺手把它改虚。

## 一起抬的四个数（都是咬合的）

| 变量                | 旧    | 新    | 为什么跟着动                                                             |
| ------------------- | ----- | ----- | ------------------------------------------------------------------------ |
| `--book-w`          | 156px | 192px | 主角（上限见上）                                                         |
| `--book-gap`        | 22px  | 24px  | 缝是按比例看的；封面大了缝不动会显得挤。**列数不变**（1180 栏宽下 5 列） |
| `--label-h`         | 54px  | 58px  | 书名条是书的"腿"，腿不动就是封面浮高了一截                               |
| `.shelf__name` 字号 | 13px  | 14px  | 书大了而名字不动，读起来是"书变大了、字没变"                             |

`--cover-h` / `--row-h` / `--board-top` **一个都不用改**——它们本来就是 `calc(--book-w …)`，
这正是"唯一输入"这条设计要的效果（改漏一个就会红在探针的判据 ①）。

## 不动

- `SHELF_COVER_WIDTH = 384` 与请求 URL `?w=384`：192 正好是这一档的天花板，**请求一个字不变**。
- 搁板怎么画（两张平铺背景、`repeat-y`、通长板）：这一单不碰。
- 窄屏那个 104px 下限：它有独立的出处（375 视口两本并排），与上限无关。
- 已冻结的 `.scratch/shelf-bookcase/`、`shelf-on-sky/`、`shelf-edit/` 一律不回头改；
  它们记的 156 是**当时的真值**，不是错字。

## 判据

1. 真浏览器上量 `--book-w` 的**实际像素**（不是读声明）：1440 宽下应为 192，
   375 宽下应仍为 104（下限不动）。量法用现成的 `probe-shelf.mts` 那套
   （注入一个探针元素去 `getBoundingClientRect`）。
2. 书仍然**立在板上**：书的底边 y 与 `--board-top` 差 ≤ 1px（探针判据 ①，
   改 `--book-w` 漏改咬合量时这一条最先红）。
3. 封面请求仍是 `?w=384`（探针判据 ③）——这条证明"只吃满现有档位、没换档"。
4. 375 无横向溢出（探针判据 ⑤）。
5. 1440 与 375 各留一张截图给用户看。
