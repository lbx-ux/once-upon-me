## 要做的事

- [ ] 新建 `src/lib/plan-tools.ts` + `plan-tools.test.ts`，绑到 `{store, owner, card}`：

  | 工具                             | 答什么                         | 复用谁                                          |
  | -------------------------------- | ------------------------------ | ----------------------------------------------- |
  | `search_past_stories(query, k?)` | 翻以前写过的相近段落           | `lib/rag/retrieve.ts`（**不新开一条检索实现**） |
  | `read_shelf()`                   | 这个孩子已经有哪些书、什么主题 | `lib/library.ts`                                |
  | `check_draft(text)`              | 这段正文过不过红线与适龄字表   | `reviewText`（`engine/review.ts`）              |
  | `character_brief()`              | 画师会拿到的角色段与核对清单   | `promptFragmentOf` / `checklistOf`              |

- [ ] ★ `check_draft` 是这一组里最值钱的一条：它把「写完被 `illustrateBook` 整本拒发」
      变成「模型自己改回去再来」。这是「拦下来」与「自己改回去」的区别。
- [ ] ★ `search_past_stories` **必须**复用 `retrieve.ts` 的同一个函数。
      另写一条检索实现的话，B1 量出来的那套参数（k / `minScore` / 硬过滤）
      就只对其中一个消费者成立。
- [ ] `read_shelf` 回的是**这个孩子**的（按 `theme` / `form` 筛），不是整个账号的——
      模型要避的是"这个孩子读过什么"。
- [ ] 每条的 `description` 要写得让模型知道**什么时候该调它**，
      而不是只描述它返回什么。

## 验收

- [ ] `plan-tools.test.ts`：四条各一条用例，用内存 store 造数据（不打网络、不打真盘）
- [ ] `check_draft` 的判据是**双向**的：一段越线的正文要**指出具体条款号**，
      一段正常正文**一条都不报**（这个项目在「空值算不算错」那节付过假拦的学费）
- [ ] `search_past_stories` 在**空语料**上回 `[]` 且**不报错**——
      「这次没翻到」是合法结果（`retrieve.ts` §二那条），不是失败

### 两处刻意的形状

1. **`character_card` 回的不是八条锚点原文**——锚点本来就在规划提示词里，
   再回一遍等于没说。它回的是**只有这里才看得到的另两样**：派生的角色段
   （每一页出图 prompt 的开头）与核对清单。模型要写画面描述，需要知道"画师手上是什么"。
2. **`query.text` 在上下文里被删掉了**。第一版留着它，而工具实际用的是
   模型在参数里给的那个 `query`——一个声明了却没人读的字段，是这个仓库最不喜欢的东西
   （它会让下一个读的人以为"这里还有一条查询串").现在上下文里只有检索的**硬过滤**键：
   年龄档 / 主题 / 形态。

### 一处测试自身的坑（记下来防复发）

`ToolDef.run` 的签名是 `Promise<string> | string`，所以**它可以是同步的**。
`await expect(tool.run({})).rejects.toThrow(...)` 接不住同步抛出——错误在拿到 promise
之前就落地了，现场变成"测试自己写错了"。包一层 `Promise.resolve().then(...)` 两种都接得住。
