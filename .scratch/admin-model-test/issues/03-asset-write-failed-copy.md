# 03 · `asset-write-failed` 那一句原来只说了一半

Status: done

## 撞见的经过

「测试连通」的图像那一支，有一次在隔离栈上回的是：

```
下载媒体网络错误：TypeError: terminated · ECONNRESET — 连接被对面掐断（可能已经处理过了）
——**这一种重试不一定是安全的**（主机 tokenrhythm-prod-backup-oss.oss-cn-beijing.aliyuncs.com）
```

而屏幕上那一句是「**资产没法落盘（磁盘满了或目录不可写）** / 清一点磁盘空间再试」——
磁盘是空的。**这一句比"没说"更坏**：它给了一个具体、可执行、且与故障无关的下一步。

## 为什么

`assets/engine/providers/http.ts` 的 `fetchBytes`（把图**下回来**那一步）在非 2xx 与
网络异常两种情况下都报 `asset-write-failed`，与"**写下去**那一步失败"（磁盘满、目录不可写、
路径越界）**共用同一个码**。`asset-scope.ts` 文件头写过这个复用是**刻意**的
（路径越界那种"永远不该有用户读到的文案"）。于是 `provider-messages.ts` 里那句按码取文案的话
就只剩下后一件的意思。

## 改了什么

只改那一句文案，让它在两种情况下都说得对：

- 「这张图没进到这本书里（要么没下回来，要么没写下去）」
- 「两种常见原因：下载那一步被掐断（网络 / 代理 / 签名地址过期），或者
  磁盘没空间、目录不可写。下面那句原文会说是哪一种。已经画好的图不会因为这一条被丢掉。」
  ★ 这一句**不用 `**` 加粗**：它是当纯文本画在屏幕上的（旁边那几句用了，于是屏幕上真的
  多出几个星号——那是既有的小毛病，见 2026-10-18 那次实测，不该再添一处）。

★ **没有**去给引擎加一个新的错误码。理由是那要动 `ErrorCode` 那份词汇表与它的所有调用点，
而这一轮的目的是管理页那一屏；把码拆开是更好的做法，但它是一件独立的事
（真做的话：`fetchBytes` 报 `asset-fetch-failed`，`byCode` 各给一句）。

## 判据

- 没有测试钉着旧文案（`grep` 过 `资产没法落盘` / `磁盘满了或目录不可写`，只有那一处）。
- 新的那句是这次真故障的**原文回放**：同一份失败（`asset-write-failed` +
  「下载媒体网络错误…ECONNRESET」）现在读到的第一句是"要么没下回来，要么没写下去"。
