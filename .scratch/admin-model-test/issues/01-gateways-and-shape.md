### 2026-10-18（第二轮）· 候选从 `datalist` 换成真的挑选框

- **用户报的**：「你这里写的拉取到了，可是我点击下拉款（框）没有啊」——
  那一行明说拉到 26 个，点开那一格却只剩一个 `qwen3.8-flash`。
- **病根是 `datalist` 的原生过滤**：Chrome 拿输入框里**现有的字**去筛候选，
  而这一格平时就是填好的（`qwen3.8-flash`），26 个里只有它自己匹配得上——
  于是"拉到 26 个"与"点开只有一个"**同时成立**，两句都是真话。
  也就是说：这个控件在字段**空着**的时候才可用，而它恰恰不会空着。
- **改法**：`<input list>` + `<datalist>` 换成**真的 `<select>`**
  （`.adm__model-pick`），`value=""` 钉死，所以挑完自己弹回占位项；
  值仍然由上面那格**自由文本框**拿着（图像在用的 `wan2.7-image` 不在那 26 个里，
  不能把这一格做成强制选择框）。那一行灰字跟着改成
  「…（下面那颗「挑一个」里是全的，也可以直接填）」。
- ★ **它是「下面」不是「右边」**（同一轮里改过一次，值得记）：第一版 CSS 写的是
  `flex: 0 1 190px`（挤在输入框右边），而这一屏最宽 1120px、三个字段一行各 ~341px，
  1440 窗口下量到那一行只有 **298px**——输入框（192）+「拉取模型列表」（92）
  已经把它占满了，190px 的选择框必然折到第二行。于是**排版在下面、灰字写着"右边"**，
  两句里有一句是假的。现在钉成 `flex-basis: 100%`（独占一行、与那一行同宽），
  灰字说「下面那颗」，方向词与量出来的排版对得上。
- 量到的（`scripts/chk-admin-model.mjs` 新增的「候选」那一节，判据取**那颗 `<select>` 的
  `options.length`**——还是 datalist 的话这一项当场是 `null`；"挑完之后值真进了文本框"；
  以及"它是不是真占了一整行、真在输入框下面"）：

  ```
  候选: {"有候选下拉":true,"条数":27,"占位项":"挑一个（26）","挑的是":"seed-2.1-turbo",
        "挑之前输入框":"qwen3.8-flash","挑选框占一整行":true,"它比输入框低":true,
        "宽":{"那一行":298,"输入框":192,"挑选框":298},
        "挑之后输入框":"seed-2.1-turbo","挑之后下拉自己弹回去了":true}
  语音那一路：有候选下拉 false（那个接口地址底下没有 /models，拉不到就不画这颗控件）
  四张卡的形状：候选下拉条数 = 27/27/27/null（文字 / 图像 / 视觉 / 语音）
  页面上那一行（直接问 DOM，不看截图）：
    文字对话：从接口地址拉到 26 个模型候选（下面那颗「挑一个」里是全的，也可以直接填）
  ```

- ★ 27 = 26 个候选 + 1 个占位项「挑一个（26）」。
- ★ 踩到的三个坑，都写进脚本注释了：
  1. 等"拉取落定"的判据必须是**非空且不是「正在…」**（只在"不是正在拉"上判，
     循环会在第一帧——还没开始拉——就退出，量到的是一个**还没到**的状态）；
  2. "挑之前的值"要**在派发 `change` 之前**读（React 对离散事件是同步刷新的，派发之后再读已经变了）；
  3. "占一整行"要拿**那一行**的宽度当基准，不是拿输入框——输入框那一行还与按钮分宽度，
     用它比会把 `true` 判成 `false`（第二版就是这么误报的）。
