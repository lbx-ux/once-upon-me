# Spec · 书架那一屏：把柜身从天上撤下来

创建：2026-10-16 · 用户口述 + 一张圈了右半边的截图

前情：`.scratch/shelf-bookcase/`（那一册已冻结，不回头改）。这一册只记第二轮。

## Problem Statement

第一版书架把书与板圈进一块 `--card-paper` 的暖纸里（`.shelf__case`，参考图里那格
木头书架就是这么个形状，20px 圆角 + `--hairline` 细边 + `--sheet-shadow`）。

用户发了 `/shelf` 的截图，**用红笔圈住右半边**（那块空着的背板，以及包着它的暖色柜身），
写了一句话：「和背景有点突兀把」。

这句话指两件事，得先问清楚是哪一件——问的是
「是**空**（柜身该收到贴住书）还是**色**（暖色压在天上太硬）」。

## Solution

用户选了**色的那头**：预览图里柜身整个不见，书与板直接落在天光上。

于是第二版：删掉 `.shelf__case`，**没有东西顶上来**。

## 一、只解决"色"，没解决"空"

两个读法各自对应一处改动，用户只挑了其中一个，所以另一个**故意留着**：

| 读法           | 改什么                                     | 用户选了吗              |
| -------------- | ------------------------------------------ | ----------------------- |
| **色**（选中） | 撤掉 `--card-paper` 的柜身，书与板落在天上 | ✅ **暖色压在天上太硬** |
| **空**（没选） | 搁板缩到最后一本书下面，右半边不留空板     | ❌ 没选，**板仍然通长** |

★ 所以现在右半边那条光秃秃的板**不是漏改**，是"另一个读法、用户没选"。
这一条要在报告里说出来，也要留一行注释在代码里——否则下一个人看到截图里那片空板，
会当成没做完。

★ 顺带记一笔：撤掉柜身之后那条空板的暴露感**变强了**（原来有暖色块兜着，现在直接
是板压在天光上）。这是选"色"这条路本来就要付的代价，不是新出现的问题。

## 二、撤掉之后不补 padding

`.shelf__case` 带着内边距 `clamp(18px,2.6vw,30px) clamp(16px,2.4vw,28px) clamp(26px,3.8vw,42px)`。
撤掉它，这一屏的上下左右靠的是 `studio.css` 里 `.studio` 那层
`clamp(28px,5vh,52px) … 64px` ——**其余三屏同样只靠它**，柜身那层内边距是套在里面的
第二层。

**不补一个"看起来差不多"的 padding**：那是在把撤掉的东西偷偷加回来。
`ShelfDashboard.tsx` / `shelf.css` 里都留了这条说明。

## 三、判据要能识别"撤干净了"

`scripts/probe-shelf.mts` 加了三条（见 [issues/01](issues/01-remove-case.md)）：

- `.shelf__case` 查不到
- 架子自己的 `background-color` 是透明的（板是 `background-image`，底色必须是空的）
- 书架顶边落在 `--sky-h`（1120px）以内——这是"压在天光上"这件事成立的前提，
  也是下一次有人改 `--sky-h` 时唯一会响的地方

★ 这三条是**有判别力的**：留个 `background: var(--paper)`、或者只把类名换掉不删样式，
都会红。
