# backend-auth —— 真后端（账号 / 短信 / 权限）与整站上云

`Status:` **claimed**（2026-10-16 开工；工单见 `issues/`）

## 要做什么

把三件原本"假着"的事变成真的，并把整个站搬到云服务器上：

1. **登录不再是模拟**。`src/lib/auth/client.ts` 那一层从"等 320ms 就返回"换成打真后端
   （Java / Spring Boot / MySQL），短信走阿里云号码认证的真通道。
2. **密钥由站长分配**。用户不再看见任何 api-key（ADR-0008 反过来，见 ADR-0009）；
   能不能用由四个能力开关决定，没有权限时点「开始创作」明说
   「当前用户没有权限，请联系管理员」。
3. **整个站上服务器**（`123.56.148.105`）：Nginx + Next 生产 + Spring Boot + MySQL 同机，
   作品与账号都在那儿——换一台机器打开也能看见。
   而服务器**只租 6 个月**，所以本机必须同时留一份**自带足的镜像**。

## 架构（一张图）

```
公网 ──:80──> Nginx ──┬── /          ──> Next.js 生产  127.0.0.1:3000
                      │                    │ 引擎 / 密钥 / 作品（ASSET_ROOT）
                      │                    └── BFF ──> Spring  127.0.0.1:8080
                      └── /backend/ ──> Spring（同一进程，要 X-Internal-Token）
                                              └──> MySQL 127.0.0.1:3306
```

★ **Java 只管「你是谁、你能用什么」**，引擎与作品一行都不搬：
`assetRoot()` 本来就是环境变量驱动的，所以"作品上服务器"只换一个 `ASSET_ROOT` 的值。

## 验收（每条都要有判别力）

见 `.scratch/backend-auth/issues/` 各张工单的"怎么算做完"，总判据三条：

1. **换一台机器**（手机 / 别的电脑）打开 `http://123.56.148.105`，能看到你现有的书。
2. 新注册的号**零权限** → 点「开始创作」看到那句话 → 管理员勾上之后，
   **同一个人不用重新登录**就能开始生成。
3. 本机跑 `pull` 之后 `verify-mirror` 通过：**镜像里每本书清单引用的每个资产都在本机**。

## 这一轮不做

双向同步（镜像只从服务器往本机拉）；头像上传；找回密码 / 改手机号；token 黑名单；
HTTPS 与域名（要备案）；对象存储；把书与角色卡搬进 MySQL；服务器上跑 Docker。

## Comments

- 2026-10-16 开工。第一件事是把 `server/` 挂起来：本机 Maven 仓库里已有
  Boot 3.3.5 / MyBatis-Plus 3.5.7 / jjwt 0.12.6 / `dypnsapi20170525:2.0.0`
  （最后一个正是文档里那个坐标），所以 `mvn package` 不必把整个 Spring 世界重下一遍。
- 实测撞到并修掉的两处（都写进代码注释了）：① 管理员账号原来配成 `admin`（字母），
  而登录那一栏只收 6–11 位数字 —— **库里会有一个永远登不进去的管理员**，
  现在由 `StartupChecks` 在启动时挡下来；② `SmsRateLimiter` 有两个构造器而没标
  `@Autowired`，Spring 找不到无参构造器，启动报的是一句听起来像代码写错了的
  "No default constructor found"。
