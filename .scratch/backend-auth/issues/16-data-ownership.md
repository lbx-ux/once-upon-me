# 16 —— 角色卡 / 声音 / 绘本挂到账号上

`Status:` **done**（2026-10-17 实现；验证记录见 Comments 最后两条）

## 要做什么

用户问的是「现在用户生成的角色卡和声音和绘本要和用户关联起来，这个应该怎么做，
MinIO 可以存储图片但是录音该怎么存储」。

**先回答存储那一问**：录音没有特殊问题，MinIO 也不是"图片存储"。朗读音频走的是和
图片**同一个** `store.put()`（`lib/engine/narrate.ts`），扩展名由 `extensionOf(mime)`
决定，那张表里 mp3 / wav / m4a 三条早就在了。所以录音就是"另一个 key"。

**真正缺的是归属**。现在整个 `ASSET_ROOT` 是平铺的，`books/`、`cards/`、`children/`、
`kids.json` 没有一处记着 userId。唯一一处"跟人不跟号"的是「我录的音色」（浏览器
localStorage）——而它恰恰**没有音频字节**：clone 那条路的设计是样本**从不落盘**，
只回一个 `voice_id`。所以"声音跟账号走"的答案是**一张三列的表**，不是存储问题。

**分两步，不把"归属"和"存储选型"绑在一个改动里**（用户选了第一步）：

- **第一步（现在）**：MySQL 记归属 + 磁盘加 `u/<userId>/` 前缀 + **三处按人判**：
  - `/api/assets/<path>` —— 它现在只认前缀（`cards/ books/ assets/`），**不认人**。
    ★ **这一步不做，整件事等于没做**：id 猜出来就能看别人的书。
  - `listBooks` / `listCardItems` / `listWallItems` —— 它们现在数的是"这台服务器上的全部"。
- **第二步（部署那一步）**：把 `createFsStore` 换成 S3 兼容实现。
  ★ 现在就是可换的：`AssetStore` 是 `providers/types.ts` 的接口，
  `createFsStore` 与 `createMemoryStore` 已经是它的两个实现——上 MinIO 是
  "加第三个实现 + 一次迁移"，不是重写。

## 怎么算做完

- 两个账号各做一本，**互相看不到**（不是"列表里过滤掉了"，是拿对方的书 id 打
  `/api/assets` 也拿不到）。
- 老数据要能搬进 `u/<userId>/`（或者明确说明这一轮只对新生成的东西生效）。
- 语音样本**仍然不落盘**这条不许被这次改动动摇。

- 2026-10-17（实现）：两条口径先钉死，再动手——
  **归属记在哪**：磁盘上 `u/<userId>/` 这个**前缀就是归属的唯一记录**。不加 books
  镜像表：引擎写文件、Java 写库，两者之间没有事务，镜像表迟早与盘上的字节不一致
  （"行说是你的、字节不在"或反过来），而那种不一致最难查。管理页「作品」那一列
  的数因此也是**数路径**算出来的（`lib/admin/usage.ts`），不经过任何表。
  **音色**：一并挂到账号上。它没有字节（样本从不落盘），磁盘挂不上，
  所以进 MySQL：`voices(user_id, voice_id, name, model, chosen, created_at)`，
  唯一键 `(user_id, voice_id)`；"当前用哪一个"用 `chosen` 那一列，不另开一张表。
- 2026-10-17（实现）：**缝是 `AssetStore`**（`lib/asset-scope.ts`）：第三个实现
  `scopedStore(base, userId)`——物理路径带前缀、返回给调用方的 `ref.path` 去前缀，
  于是引擎里那二十来处路径表达式一个字节没改，`book.json` 里记的仍是逻辑路径。

  `userSliceRoot(root, userId)`，拼出来是同一个目录。★ `requireUserId` 那道闸：
  没有 userId 就当场炸——防的是**我们自己忘了那道闸**，症状从"悄悄串号"
  （所有人共用 `u/undefined/`，而它看起来是通的）变成"500 + 一句说清的话"。
- 2026-10-17（实现）：租约与存在性跟着换了口径，两条都是**跨账号撞书号**逼出来的——

- 2026-10-17（实现）：**单元测试先照出一个真洞**。`u/3/` 这个前缀一加，
