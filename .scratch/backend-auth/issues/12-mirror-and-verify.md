# 12 —— 本机那一份：单向镜像 + 自足性校验

`Status:` **done**（2026-10-17；★ 作品那一段要到工单 10 上有作品之后才能在真服务器上端到端跑，见 Comments）

## 要做什么

★ 服务器**只租 6 个月**（到期 2027-04-15）。所以"数据在服务器上"不是终点：
本机必须有一份**能独立撑起来**的副本，三件东西合起来才叫搬得回来——
**作品镜像 + 数据库快照 + 本仓库代码**（代码在 git 里，天然有）。

- `scripts/pull-from-server.sh`：**按书为单位增量拉**（`ssh` 列一下服务器上有哪些书，
  本机缺哪本就拉哪本）。★ 本机实测**没有 rsync**（只有 `tar`/`gzip`/`scp`），
  而"缺就拉"本身是幂等的——一本书的目录写下去就不再改。
  `cards/`、`children/`、`kids.json` 同理；**`thumbs/` 不拉**（派生物，能重算）；
  每次顺带一份 `mysqldump`。**本机永远不往服务器写**。
- `scripts/verify-mirror.mts`：**自足性校验**——逐个读镜像里的 `book.json`，
  把每页引用的资产与封面都比一遍，缺一条就报出来。
  写法照 `scripts/export-demo-book.mts` 那段现成的 `missing[]` 收集。
  **判据是"每本书清单引用的每个资产都在本机"，不是"目录非空"。**
- 镜像放**项目目录之外**（`LOCAL_MIRROR_DIR`，例如 `D:\xiaozhujue-data\`）：
  项目目录会被 `git clean`、误删、重克隆，而这份是 6 个月后唯一的凭据。
  ★ 数据库快照里有手机号与密码哈希，**绝不能进仓库**（公开仓库）。
- `docs/local-standby.md`：到期后搬回本机的一页核对清单（装 MySQL 8 → 灌 dump →
  `java -jar` 起后端 → `pnpm dev` 起前端 + `BACKEND_URL`/`ASSET_ROOT` 两个环境变量）。
  ★ 最上面一句写清：**本机那份是"拉过才算"的那一份**，
  两次 `pull` 之间生成的东西只在服务器上；到期前必须最后跑一次 `pull` + `verify`。

## 怎么算做完

- 线上做完一本新书 → 本机 `pull` → 那一本出现在镜像里；`verify-mirror` 通过。
- 把本机 dev 的 `ASSET_ROOT` 指向镜像 → **本机能打开线上做的那本书**
  （图、缩略图、朗读都在）。★ 这一条是"能独立撑起来"的判据，不是"文件拉下来了"。
- 拉下来的 dump 能在本机临时库灌进去并查到用户。

- 2026-10-17（实现）：三件交付物都在，但**没有照抄本单原文**——原文写于工单 16 之前，
  那时资产根是平铺的（"ssh 列一下服务器上有哪些书"）。加了一处**硬约束**：
  · ★ **镜像里必须保住 `u/<userId>/` 那一层**。工单 16 之后代码只认 `u/<id>/`
  底下那一片，拉回来一棵平铺的树等于**搬丢了**——而且搬丢的方式是静默的：
  书架空着、界面不报错。这条写进了 `pull-from-server.sh` 的文件头第 2 条。
  · 同理 `verify-mirror.mts` 的判据是"**这本书自己那一片**里有这个文件"，
  不是"全树里找得到一个同名文件"——后者会把别人那张同名图当成自己的。
- 2026-10-17（实现）：`scripts/pull-from-server.sh`——**只读**（对本机写，对服务器
  只发 `ls` / `tar` / `backup.sh`），按书增量（判据是每个单元的"文件数 + 总字节"指纹），
  `--full` 强制全量。`thumbs/` **不拉**（派生物，应用按需重算）。
  ★ 打到一个 `.partial` 名再改名：半个目录顶着真名 = "看着有、其实是残的"。
  · 数据库快照走服务器上的 `backup.sh` 再 `scp` 回来 → `$MIRROR/db/`。
  ★ 镜像在**项目目录之外**（缺省 `D:/xiaozhujue-data`）：dump 里有手机号与密码哈希，
  而项目目录会被 git clean、误删、重克隆。
- 2026-10-17（实现）：`scripts/verify-mirror.mts`——逐个读 `book.json`，
  把**封面 + 每一页的插画 + 每一段朗读**的路径一条条比，缺一条就报出来（退出码 1）。
  草稿（只有 `story.json`）单独数出来念一句，不算缺。
- 2026-10-17（验证）：★ 这个脚本的**第一版查错了字段**，而且它是"绿"的——
  它读 `book.pages`，而 `book.json` 里根本没有 `pages`（真身是 `tree.nodes` /
  `illustrations` / `narrations`），于是它把封面之外的所有引用都跳过了，
  报了一句"每一本清单引用的资产都在本机 ✓"，**实际只比了 3 条封面**。
  露馅的是我顺手打的那个数（"比过 3 条资产引用"太小）。
  ⇒ 改对字段之后 **19 条**（3 封面 + 5 + 3 + 8 页图），并加了两条闸：
  ① "一条引用都没比过 / 一本都没查到"**不是通过**；② 每本书逐行报
  "计划 N 页 · 出图 x · 朗读 y · 失败 z"。
  还加了一条"自相矛盾"的判据：计划 N 页、出图 M < N、而 `errors` 是空的
  → 那本书在自己说自己完整，而它缺页（镜像照实标出来）。
- 2026-10-17（验证）：判别性判据各做了一次**反证**：
  · 删掉清单**真正引用**的那一页图 → 报"u/1/<书号> 的第 3 页的插画"并退出 1；
  · 把**同一个逻辑路径**的文件放进别人那一片（`u/9/...`）→ **仍然报缺**。
  ★ 顺带踩到一次自己的量具错误：第一次删的是 `page-1-a1.png`，而清单引用的是
  `page-1-a3.png`（第 3 次尝试的那一版）——被淘汰的尝试留在盘上、清单不引用它，
  所以校验器报"✓"是**对的**。这条记在这里，因为"镜像里那些没人引用的文件"
  是个会反复出现的疑问：判据只认清单引用的那些（阅读器要的正是它们）。
