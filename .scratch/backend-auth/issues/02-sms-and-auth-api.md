# 02 —— 短信与认证接口（含频控与测试账号）

`Status:` **done**（2026-10-16）

## 要做什么

按用户给的那份《2.短信验证码》把真通道接上，并实现全部登录接口：

| 接口                                                              | 说明                                                                              |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `POST /api/auth/sms/send`                                         | 发码。**三层频控**（同号 60s/3 每小时/10 每日；同 IP 5/小时、20/日；全局 300/日） |
| `POST /api/auth/sms/verify`                                       | 核验。老用户直接给会话票；新用户给一张 5 分钟的**设密码票**                       |
| `POST /api/auth/password`                                         | 带票设密码（**票只在已核验的会话里有效**，且只够设一次）                          |
| `POST /api/auth/login`                                            | 密码登录（含演示账号），连错 5 次锁 10 分钟                                       |
| `GET/PATCH /api/auth/me`                                          | 看自己、改昵称                                                                    |
| `PATCH /api/auth/me/avatar`                                       | 换默认头像（只收一个 id）                                                         |
| `POST /api/auth/logout`                                           | 只记一笔；真正的注销是 BFF 删 cookie                                              |
| `GET /api/admin/users`、`PATCH /api/admin/users/{id}/permissions` | 管理页那两件（仅 ADMIN）                                                          |

三条关键判断：

1. **账号分两种，判据是"它是不是手机号"**：11 位 1 开头 = 手机号（走短信），
   其它 6–11 位数字 = 短账号（只能密码登录）。演示账号 `123456` 是后者 ——
   "给一串不是手机号的数字发短信"因此是**结构上不可能**的，而不是靠某个 if 记着。
2. **账号在"设密码那一刻"才建**，不是"验证码通过就建"：一个人发一次码又走了，
   不该在库里留下一行——管理页上那个"有多少用户"要是个真数。
3. **权限不进票**：管理员改完开关，下一次 `GET /api/auth/me` 就看得见。
   代价是每个请求一次查库，换来"不用等 7 天票过期"。

## 怎么算做完

- `mvn test` 全绿，其中 `AuthFlowIntegrationTest` 走完整条路（发码 → 核验 → 设密码 →
  登出 → 用密码登回 → 管理员发权限）。
- 真发一条短信到手机（要用户的 AccessKey；本地开发默认走开发模式那一档，码固定 123456）。

## Comments

- 2026-10-16 完成。`mvn test`：**41 条全绿**
  （`AccountRulesTest` 14 / `AuthFlowIntegrationTest` 12 / `JwtServiceTest` 7 /
  `LoginAttemptGuardTest` 5 / `SmsRateLimiterIntegrationTest` 2 / `SmsGlobalCapTest` 1）。
- ★ 频控那三个类**各自一个内存库**：条数是共享状态，共用一个库就会互相把对方数进去，
  于是"单独跑绿、一起跑红"——那不是代码的错，是测试写错了。
  按 IP 那一层与全局每日硬顶因此各有自己的类（后者把上限压到 3，验的是"第 N+1 条被挡"）。
- ★ `SmsRateLimiterIntegrationTest` 里那条同时验了两件事：按 IP 那层有效，
  **以及**服务端认的是 `X-Forwarded-For` 而不是永远为 127.0.0.1 的 remoteAddr。
  后一件不成立的话，"按 IP 限流"在上线那一秒就退化成"所有人共用一个额度"。
- 真发那一条要等 AccessKey；在那之前"真发"这条路只有单元测试与代码审查验过，
  **没有实测过一条真短信**——这一点在工单 12 收尾时要确认。

- ★ 2026-10-16 **真通道实测通了**（这一条是这一轮最要紧的验收项）。过程与结论：

  | 量法                                                                          | 结果                                                                                     |
  | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
  | 短信服务 `QuerySmsSignList`（站长自己的 AccessKey）                           | `totalCount=0` —— **这个账号一条签名都没有**                                             |
  | 短信服务 `SendSms`（模板 `SMS_337215196`）                                    | `isv.SMS_SIGNATURE_ILLEGAL`（"该账号下找不到对应签名"）                                  |
  | 号码认证 `SendSmsVerifyCode`（签名 `恒创联众` / 模板 `100001`，文档里那对值） | `code=OK success=true`，**真短信到了手机**                                               |
  | 号码认证 `CheckSmsVerifyCode`（核验手机上那个码）                             | `verifyResult=PASS`                                                                      |
  | 走**本站**的 `POST /api/auth/send-code`                                       | `200 {"ok":true,"devMode":false}`，手机上又收到一条                                      |
  | 紧接着重发                                                                    | `429 sms-rate-limited`「刚发过一条，请等 60 秒再试」——**是我们自己的频控挡的**，不是厂商 |

  ★ 教训（写给下一个读这段的人）：我一度只凭一张**模板**截图就把实现从号码认证换到了短信服务，
  而那个账号根本没有签名——两张截图（模板有、签名空）差着一个接口的距离。
  探针在 `.out/aliyun-probe/`（未进仓库），要复现就 `ALI_ID=… ALI_SECRET=… java ProbeSms2 <号码>`。
  ★ 结论：**用户给的那份文档是对的**，实现现在与它一致，只在核验那一处更严
  （模板参数传具体的码、核验在本地，换来"一个码最多试 5 次"）。
