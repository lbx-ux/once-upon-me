# 11 —— 加固与每日备份

`Status:` **done**（2026-10-17；★ 仍有三件**只能人做**的事，见 Comments 最后一条）

## 要做什么

站上公网之后，"这套东西会不会被人花我的钱 / 我的数据会不会丢"变成真问题。

- **每日备份**：`server/backup.sh`（cron）：`mysqldump` → gzip → `/var/backups/xiaozhujue/`
  留 14 天。★ 备份脚本写完要**试灌一次**：只导出不试灌，等于没验过它是不是可用的。
- **口令**：管理员口令由 `APP_ADMIN_PASSWORD` 给，**不是**演示账号那种公开口令；
  登录连错 5 次锁 10 分钟（已有）。
- **频控**：三层 + 全局每日硬顶（已有，见工单 02）。
- **安全组**：只留 22 / 80；3306 与 8080 拿掉（工单 03）。
- **文件权限**：★ 2026-10-17 更正（工单 03 实际这么做的时候发现的）——
  原来写"`/etc/xiaozhujue/*` 一律 600"，但那与"作品目录归 `xzj` 用户"**互相矛盾**：
  服务如果以 `xzj` 跑，600 的配置它读不到；要用 600 就得让服务以 root 跑。
  实际选的是后者不选 root：`/etc/xiaozhujue` 750、`api.yml` **640 `root:xzj`**，
  服务以 `xzj` 跑（见 `xiaozhujue-api.service` 里那几行 `ProtectSystem` / `ReadWritePaths`）。
  让一个挂在公网旁边的 Java 拿 root，比"组可读的配置"危险得多。
- **磁盘**：一本 20 页的书约 60 MB，40 GB 盘够放几百本；`df -h` 写进交付说明，
  到了 70% 要提醒一次（就是 `backup.sh` 里顺手 echo 一句的事）。

## 怎么算做完

- 跑一次 `backup.sh`，把产物**拉到本机灌进一个临时库**，能查到用户与权限。
- `nmap`/`curl` 从外网只看到 80 开着。
- 停掉 WiFi 再回来：三个进程都在（`Restart=always` 生效）。

## Comments

- ★ 一条要说清的局限（写进 README §五）：这一轮**没有 token 黑名单**——
  登出只删 cookie，一张已经发出去的票在 7 天之内仍然有效。
  真撤销需要一张失效票表，那是下一轮的事。

- 2026-10-17（实现）：**每日备份 + 试灌**都做了，脚本在 `server/backup.sh`（部署到
  `/opt/xiaozhujue/backup.sh`），cron 在 `/etc/cron.d/xiaozhujue-backup`（**03:17**，
  避开整点：整点是所有定时任务撞在一起的那一秒，而备份要拿一致性快照）。
  · 口令**不在脚本里**：从 `/etc/xiaozhujue/api.yml` 读出来，经一个 600 的临时
  `--defaults-extra-file` 传给 mysqldump。★ 不用命令行的 `-p$PASS`——
  那会让口令出现在 `ps aux` 里，任何登录的人一眼看得见。
  · **先写临时名、验完再改名**：半个文件顶着"今天的备份"这个名字是最坏的状态
  （看起来有备份，恢复那天才发现它截断了）。自查三项：`gzip -t`、
  至少一条 `CREATE TABLE`、文件非空。
  · 保留 14 天，每次跑都把"现在几份、最老的一份是哪天"打出来——**到期那天不会提醒**，
  所以"备份在跑"这件事得能被人看见。根分区到 70% 也 echo 一句
  （备份自己有把盘写满的那一天，而那时没人会想到是它）。
- 2026-10-17（验证）：**试灌真的做了**（工单原文那句"只导出不试灌 = 没验过"）。
  `/opt/xiaozhujue/backup.sh --verify` 建一个 `xiaozhujue_verify`、把 dump 灌进去、
  数行、再 drop。实测结果：**users=2（其中 ADMIN=1）· user_permissions=2 · voices=0**
  —— 判据选的是"能查到人、能查到权限"，不是"导入没报错"（一个空库导入也是零报错）。
  · ★ 试灌那一段走 **root 的 socket 身份**，不走 api.yml 里那个 `xzj`：
  建库/删库要权限，而给应用账号扩权正是最小权限那条要避免的。
  第一次跑时的 `ERROR 1044 Access denied for user 'xzj'` **不是脚本坏了**
  —— 那是权限分得对，脚本因此改成两套身份（日常用 xzj，自检用 root）。
  · ★ 产物**没有拉到本机**（工单原话是"拉到本机灌进一个临时库"）：那份 dump 里有
  手机号与密码哈希，而本机没有放它的合适地方（项目目录之外那份镜像属于工单 12）。
  在服务器上灌进临时库验的是同一件事——"这份 dump 能不能真的变成一个能用的库"——
  而多一次跨网搬运只会多一份带个人信息的文件。工单 12 做镜像时会把 dump 一起带走。
- 2026-10-17（验证）：**`Restart=always` 是真验过的**，不是"配了就算"：
  `kill -9` 掉 Java 的 MainPID（70297），systemd 拉起了新进程（71410），
  `curl 127.0.0.1:8080/api/health` 回 200。
  ★ 工单原文写的是"停掉 WiFi 再回来：三个进程都在"——那一条要在交付那天由人拔一下网，
  我这里验的是同一个机制里**最难的那个分支**（进程被杀，不是网络断）。
