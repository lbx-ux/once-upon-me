# 07 · 「让 AI 重写一版」按下去之后，屏幕上要有一句真话

Status: **done**（2026-10-18）
对应 [spec.md](spec.md) §二（闸门那一屏的重写那一段）

## 用户原话

> 当我输入这个是，前端什么反馈都没有，只是文字我输入文本框的文字消失了，
> 这样用户怎么知道有没有重新生成故事呢，这个点优化一下

（附一张截图：闸门那一屏，第 1 页的正文是"今天天气真好呀。/ 小满要下楼去玩。"）

## 那一天真的发生了一次重写，只是屏幕没说

盘上的证据（`.out/web/u/1/books/xiaoman-r1-638df001b4e9/`）：

```
events.jsonl        6 条事件，首尾差 101.48 秒
  seq 1  stage(begin, planning, 第 1 / 3 次)
  seq 2  retry  第 1 次：故事结构不对（1 处）
  seq 3  stage(begin, planning, 第 2 / 3 次)
  seq 4  retry  第 2 次：故事结构不对（1 处）
  seq 5  stage(begin, planning, 第 3 / 3 次)
  seq 6  plan-ready：《小满会飞了》，16 页，1 个选择点
story.json          planMs 101483 · attempts 3 · 写入时间 22:38:47
```

**而屏幕上那 101 秒里一个字都没多。** 用户截图那张就是这个状态：按钮还是「让 AI 重写一版」、
「想让故事怎么变」那一格已经空了、主句还是"故事写好了，先看一遍"。
唯一的"变化"是他自己写的那句话没了——那不是反馈，那是被拿走。

## 坏在哪儿（三处，各自独立）

1. **按钮忙起来的样子是"变淡"**。`disabled` 让它只剩 `opacity: 0.5`。
   变淡读起来是"这一颗不能用了"，而它明明在做事——与 `CreateLanding` 那颗优化按钮
   踩过的是同一个坑（当时用户的原话是"一会浅色一会原色，还以为没成功"）。
2. **家长写的那一句一点就清**（`onRewrite(note); setNote('')`）。
   重写失败时他要重打一遍；而"字没了"恰恰是他唯一看得见的变化。
3. **引擎自己那两句话一个读者都没有**。`desk.stageLine`（"正在编故事…"）与
   `desk.planning`（"这一版故事没通过校验，正在重写（第 k / N 次）：…"）**早就算好了**，
   可它们的读者是画桌（`Desk.tsx`），而闸门这一屏**不渲染画桌**（`atGate`）。
   于是那 101 秒里最有用的两句话躺在内存里，没上过屏幕。

★ 顺带发现一条**死代码**：`GenerationRun` 里原本写着
`{phase === 'story' && !atGate && '正在重写这一版故事…'}`——写这句话的人要说的
正是这件事，但 `atGate` 的定义里就含 `story !== null`，而重写全程 `story` 都在手上，
所以它**一次也上不了屏幕**。话是对的，位置错了。

## 改了什么

- `StorySheet.tsx`
  · 按钮 `data-busy` + `aria-busy` + 文字换成「重写中…」；
  · `onRewrite` 改成**回一个 Promise**（`true` = 真的换成了新的一版），**成了才清那一格**；
  · 按钮旁边新加 `.ss__rewrite-live`（`role="status"`），摊的是引擎自己那句话
  （新 prop `busyLine`，由 `GenerationRun` 从 `planning ?? stageLine` 取）。
- `story-sheet.css`
  · `[data-busy='true']`：实心橙 + 一圈荡出去的光（`ss-rewrite-ring`）+ `cursor: progress`；
  `:disabled:not([data-busy='true'])` 那一截留着管"还没写字"那一档；
  · `@media (prefers-reduced-motion: reduce)`：动画关掉，**停在实心橙 + 一圈固定的光晕**上
  （终态，不是"不播就没信息"）。
- `GenerationRun.tsx`
  · 主句在重写那一段换成"正在按你说的重写这一版故事——写好了这一屏会自己换过来，
  你刚写的那句还留在框里。"（并删掉那条死代码）；
  · `rewrite()` 回 `Promise<boolean>`，且**把流里那条 `fatal` 帧也算失败**
  （原来只看 promise 成没成，而服务端出错时流是**正常收尾**的——那会一路走到"换成新的了"）；
  · `setDirty(false)` 从"出发时"挪到"成功时"：失败时家长手改的那些字还在屏幕上，
  `dirty` 一归零自动保存就再也不会去存它们；
  · `SaveState` 多一档 `'rewritten'`：成功之后这一屏说一句"重写好了——上面这一屏已经是新的一版"；
  · `rewrite()` 里把**客户端那一份事件日志也截断**（服务端第一步就是 `log.truncate`），
  否则 16 页重写成 10 页之后，点「就按这个画」会按 16 页摆格子、留下 6 个永远填不上的空框
  （`deskOf` 的 `total` 只增不减，那是为乱序与重放写的）；
  · 阶段轨的「编故事」在重写期间**按 `working` 说**：`railOf` 只认 desk 里的事实，
  而重写时书名的两个来源都指向上一版（那条旧 `plan-ready` + 手上这份 `story`），
  于是它一直写着"已完成"，而屏幕上正在做的恰恰是它。

## 读数（`.out/probe-rewrite.mjs`）

```bash
node .out/probe-rewrite.mjs http://127.0.0.1:3353          # 等待 / 成功，15 / 15
MODE=fail node .out/probe-rewrite.mjs http://127.0.0.1:3353 # 失败，11 / 11
CONTROL=1 node .out/probe-rewrite.mjs http://127.0.0.1:3353 # 11 / 11
MODE=reduced node .out/probe-rewrite.mjs http://127.0.0.1:3353 # 8 / 8
```

判据不是"按钮变好看了"，是**这段等待里屏幕上有没有一句真话**（都在"请求还没回来"的那一段量）：

| 量                        | 读数                                                                  |
| ------------------------- | --------------------------------------------------------------------- |
| `data-busy` / `aria-busy` | `true` / `true`（10 / 10 次采样都是）                                 |
| 按钮文字                  | `重写中…`                                                             |
| 按钮底色 / 动画           | `rgb(194, 65, 12)` / `ss-rewrite-ring`（不是变淡）                    |
| 主句                      | "正在按你说的重写这一版故事——…你刚写的那句还留在框里。"               |
| 阶段轨                    | `编故事:now 逐页画:todo 配音:todo 装订:todo`                          |
| 家长写的那一句            | 还在框里（`结局改成他带着全班一起下楼`）                              |
| 帧到了之后按钮旁那句话    | "这一版故事没通过校验，正在重写（第 1 / 3 次）：故事结构不对（1 处）" |
| 成功之后                  | 那一格才清空；`重写好了——上面这一屏已经是新的一版`                    |
| 失败之后（`MODE=fail`）   | 那句**还在**、屏幕上说得出为什么、按钮回到可按                        |

★ **判据会红**（`CONTROL=1`：把界面按修之前的写法摆回去再量一遍）——
底色退回白、动画 `none`、主句退回"故事写好了，先看一遍…"、阶段轨退回 `编故事:done`，三条全红。

★ 探针把那条 `POST …/story/rewrite` **拦在浏览器里**（真服务端一个字节都没收到，
`postData` 里就是那句家长写的话），所以这一跑**不花一次模型调用、也不动盘上那一份草稿**；
跑完 `story.json` 的 mtime 还是 22:38:47。

★ 探针自己第一版写错过一次，而它**红得对**：我把引擎事件当 data 发了出去，
漏了外面那层 `{kind:'engine', event}`，于是 `decodeBookFrame` 一条都不认，
"按钮旁边那句话"当场是 `null`（14 / 15）。这条留在这里，因为它是"判据有没有判别力"的正面例子。

## 没做的（写在这里，免得下次当成漏了）

- **没有加"已用时 37 秒"那种计时器**。这一版给的是三样会动的真东西：按钮在呼吸、
  主句换了一句、引擎那句话会自己更新（"第 1 / 3 次"…）。再加一个秒表是另一个决定，
  要加也该先问一句"家长真需要知道过了多少秒吗"。
- **`setDirty` 那一条是读代码推的，没实测**：它要真跑一遍得先手改一个字段（会写进盘上那份草稿），
  而草稿是用户的。写在这里，别当成量过。
- 一次都没跑过**真**重写（`MODE=ok` 用的是探针自己造的帧）。真实那一次的读数
  来自 `events.jsonl` 而不是来自这套判据——判据量的是"界面有没有话说"，不是"模型跑得对不对"。
