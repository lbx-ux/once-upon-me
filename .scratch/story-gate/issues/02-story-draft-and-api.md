# 02 · 故事草稿与三条接口

Status: done（2026-10-17）
依赖：[01](01-engine-split.md)
对应 [spec.md](spec.md) §四

## 改了什么

```
POST /api/books                     开一本：**只做①编故事**（SSE）。职责收窄，URL 不变
POST /api/books/<id>/story/rewrite  按家长写的那句话重写一版（SSE）
GET  /api/books/<id>/story          读故事草稿
PUT  /api/books/<id>/story          把改过的存回去（自动保存用）
POST /api/books/<id>/illustrate     ②–⑦（SSE），请求体 = 家长改过的那份 `{title, nodes}`
```

新增 `src/lib/story-draft.ts`（存读 + `StoryInput` / `StoryRequest` 的两次转换，
与 `story-draft.test.ts`）、`src/lib/story-problems.ts`（判据，与 `story-problems.test.ts`）。
`BookStreamFrame` 的 `status` 帧多一个可选 `bookId`。

## 四处不显然的

1. **`status` 帧上的 `bookId`**。①**没有** `book-ready` 事件（这一本连一页都还没画），
   而客户端从那一刻起就要书号——取故事、写 `sessionStorage` 都要它。
   放在 `status` 上是它唯一的位置：这一帧本来就是"这次跑在哪儿"的传输层事实，
   而且它**不落盘**（重放那条路书号本来就在 URL 里）。
2. **PUT 只校验信封，不校验内容**。家长把一页正文删空、正要重写的那几秒里，存盘不该失败
   ——失败的话一次刷新就抹了他的改动，而那正是这道闸门要防的事。内容合不合法由
   「就按这个画」那一关说了算。读的那一侧（`readStory`）用**同一个判断**。
3. **重写一版先截断日志**（序号从 1 重来）。不截的话，12 页重写成 8 页之后，
   `deskOf` 的 `total` 只增不减会留下 4 个永远填不上的格子。
   同时 `editedAt` 清掉（盘上那份是模型刚写的）、`createdAt` 不动（这一本从哪一刻开始做）。
4. **`illustrate` 门前四道闸**：内容过不了校验 → 400 + 逐条问题；`book.json` 已在 → 409
   （一次误点会**再画一遍整本**）；`story.json` 不在 → 404；拿不到租约 → 409。
   能力闸门也跟着拆：①要 `['text']`，②要 `['image']`。

## Comments

- 2026-10-17 **一条改掉的老行为**：`POST /api/books` 碰到"这个主题已经有一本了"原来会
  **静悄悄重跑整本**（覆盖上一本的书页图、再付一次钱）。现在回 409 + 一句人话。
  代价讲清楚了：同一个主题做不出第二本（换一个字的主题就是另一个书号）。
- 2026-10-17 自动保存是**必须的**，不是加分项：没有它，"关掉标签页也找得回来"这句承诺
  只对"一个字没改"的人成立。（`StorySheet` 的静默 1.2s，见工单 03。）
- 2026-10-17 **端到端实测**（隔离 dev server 3341，真模型，两本：5 页与 3 页）。
  三条**只有真做才会不同**的判据，都过了：
  1. **闸门真的拦住了钱**：停在闸门那一屏时 `books/<id>/` 里**只有** `story.json` 与
     `events.jsonl`（`ls` 过，一张 `page-*.png` 都没有）；点「就按这个画」之后才出现
     `page-1-a1.png`。
  2. **改过的正文真的进了书**：把第 1 页正文改成一句独特的句子（带 ★ 的），画完之后读
     `book.json` 的 `tree.nodes[0].body[0]` —— 就是那一句，不是模型原来那句。
     五页的 `body` / `scene` / `imagePrompt` 与 `story.json` **逐字段相等**
     （"写回的是归一化过的那一份"那一条没有把任何值改掉，因为它本来就已经归一了）。
  3. **改过的书名也跟着走**：把书名改成《云上蚂蚁家·改过的书名》之后画出来的那一本，
     `book.json` 的 `tree.title` 就是这个改过的名字（不是 `plan-ready` 里那个）。
  - `PUT /story`：`editedAt` 落盘、`createdAt` 与 `planMs` 一个都没动；`reload()` 之后再进闸门，
    屏幕上那两个框里是**盘上那一份**（改过的书名与正文都在）——"读盘"这件事是重挂之后量的，
    不是从内存里读的。
  - `status` 帧上的 `bookId`：这条路唯一一次拿到书号就是从它来（①没有 `book-ready`）。
- 2026-10-17 **「重写一版」也实测了一遍**（另起一本 3 页的，没碰正在画的那一本——
  重写会**截断日志**，所以它在拿不到租约时回 409 `book-busy`，这一条也是看代码确认的）。
  家长写的是「结局改成小蜗牛带着全班同学一起爬到海边看日出，路上别下雨了」：

  |                       | 重写前             | 重写后                               |
  | --------------------- | ------------------ | ------------------------------------ |
  | `doc.title`           | 小乐去看海         | **小蜗牛去看海**                     |
  | `createdAt`           | 1792226886172      | 1792226886172（**没动**）            |
  | `editedAt`            | 无                 | 无（新那一版是模型刚写的）           |
  | `planMs`              | 13029              | **8574**（这一版自己的①）            |
  | `events.jsonl`        | 2 条，seq `[1, 2]` | 2 条，seq **`[1, 2]`**（截断后重数） |
  | 日志里的 `plan-ready` | nodeCount 3        | nodeCount 3、书名《小蜗牛去看海》    |
  | 末页正文              | —                  | 「到了海边，看日出。」               |

  三条判据都成立：新故事**跟着那一句话走**（末页落到"看日出"，标题也换了）、
  日志**真的截断**（`plan-ready` 是新的那一条，不是叠在旧的后面）、页数与
  `doc.nodes.length` 一致（3 = 3）。
  ★ 一句如实的话：那一句话里的「带着全班同学」**没有**出现在这三页里——
  重写指令给的是"方向"（怎么发展、怎么收），不是逐条照办；提示词那一层要不要更强，
  是另一件事。另外这一版把原稿里的"它"改成了"他"，于是"把壳擦得亮亮的"读起来落在
  小乐身上（原稿就有点含糊）。两件都是模型输出的事，不是代码的，记在这里以免下次
  当成新 bug 查。

- 2026-10-17 一条**不属于本单**的观察，如实记下来：5 页那一本每一页的核对**首轮都没过**
  （score 0.4 / 0.3 / 0 / 0.3 / 0.2，`firstPassCount: 0`、`redrawCount: 5`、`imageCalls: 15`），
  其中 score 恰好 0 的那两页是重画两次都还是 0。另一边，另有几页重画一次就过了（0.9 / 0.75）。
  这不是这一轮改出来的（②是整段搬过去的），3 页那一本也是同一个样子。数字留在这里，
  要不要调门槛 / 调提示词是另一件事。
