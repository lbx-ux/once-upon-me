## 实测推翻计划的两处（记录下来，免得下次又按旧计划走）

1. **A1 的范围比计划大**：原计划只把 `.dk__branches-a` 改掉、保留 B 的 `--accent`。
   量下来 `--accent` 压在天空带上也只有 **3.32–3.78**，两个词都破。所以两个都改，
   "颜色是给眼睛的第二次机会"改由角标与色带承担。
2. **`--fix` 的判据要按值比对**：第一版规则是"「面与墨」位置上出现任何字面量就报"，
   一跑 27 处，其中大半是遮蔽层与薄膜（`rgba(255,255,255,.62)` 那种），
   它们本来就该用裸 rgba。改成"只有当一个字面量**与某颗令牌完全同色**时才算绕过"
   之后，报出来的 22 处每一处都是真的。（另：`border` 简写必须一起查，
   否则全站最常见的 `border: 1px solid rgba(ink, .1)` 整个从闸门底下走过去。）

## 刻度迁移（C3）

5 档 α 常量：`--accent-a1..a5 = 0.06 / 0.12 / 0.25 / 0.45 / 0.92`。

**迁移了 45 处，不是计划里写的 38 处。** 计划那张表只统计了 `--accent-rgb`；
逐处清点（`.out/c3-census.mjs`）下来 `--pf-accent-rgb` 是 **7 处**（计划写"3 处"）。
两处合起来 45 = 38 + 7，五档的分配与计划表逐条吻合（10 / 6 / 4 / 13 / 1）：
计划那张表**对 `--accent` 是准的**，只是漏算了 `--pf-accent` 的分量。
`--select-rgb` 确实只有 0.92 与实心，未动（与计划一致）。

| 现值                       | 归入      | 处数   |
| -------------------------- | --------- | ------ |
| 0.045 / 0.06 / 0.07 / 0.08 | a1 = 0.06 | 10 + 2 |
| 0.1 / 0.12 / 0.13          | a2 = 0.12 | 6 + 3  |
| 0.25 / 0.28                | a3 = 0.25 | 4 + 1  |
| 0.4 / 0.45 / 0.5           | a4 = 0.45 | 13 + 1 |
| 0.92                       | a5 = 0.92 | 1      |
| **0.35 ×3 / 0.55 ×1**      | **例外**  | 4      |

**0.35 与 0.55 是显式例外，每处都写了理由。**

- 0.35（3 处）：`.gr__node[data-state='done']::before`（已走过那段的连线）、
  `.gr__error` 与 `.ss__problems`（**同一张"提醒卡"的同一档描边**）。
  ★ 计划里把 0.35 说成"进度条那类的中间档"——只对第一处成立。另两处是**同一种**
  可命名的东西（提示卡描边），而它用了三次。这条已经踩在"重复三次以上那就是一档"
  的线上：**再来第 4 处就该升成第六档，而不是继续加例外**（这条要求写在
  `generation-run.css` 的注释里）。
- 0.55（1 处）：`settings-dialog.css` 的选中描边，全站唯一一处 ——
  它服务的是"选中"这个**状态**，不是"面/边"这个位置，所以不属于刻度要覆盖的三类。

**光效与渐变里的 α 一个都没动**（16 处：`box-shadow` ×11、渐变 ×3、`background-image` ×1、
外加 `storybook-flip.css` 那两条跨行的渐变色标）。那些是"光"，不是"层级"。

### 真机判据（`.out/probe-c3.mjs`，5 条全绿）

| #   | 判据                                           | 读数                                                                                                                      |
| --- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |

| d   | 五档在浏览器里解出来的 α                       | 0.06 / 0.12 / 0.25 / 0.45 / 0.92 逐个相符                                                                                 |
| e   | 网线上五档被消费的**总数**                     | **41** 次，逐档 a1=12 / a2=9 / a3=5 / a4=14 / a5=1；「面与边」上没剩任何映射表里的裸 α                                    |

★ 判据 a 有判别力，是因为 `rgba(var(--x-rgb), var(--y))` 里 **α 也是 var**：
流水线（Lightning CSS）若把这种嵌套 `var()` 压坏，症状是整条声明被丢掉，
而**源文件看起来完全正常**。所以这一条必须读发出来的字节，不能读源文件。
★ 判据 c 第一次跑**红了**，读到的是禁用态（`border-color: var(--hairline)`）——
`.login__send` 在 `/^1\d{10}$/` 不成立时是 `:disabled` 的。改成先按真人的办法把
号码填进 `#phone`（走 React 认的原生 setter + 派 `input` 事件，并在**同一轮 JS 里**
查 `__reactProps$` 确认已 hydrate）之后才对。**"红了"那次是探针的错，不是代码的错。**
